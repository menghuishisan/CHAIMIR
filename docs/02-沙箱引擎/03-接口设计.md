# M2 沙箱引擎 — 接口设计

> 风格:RESTful + WebSocket(终端/进度)。鉴权沿用 M1 JWT。
> 接口分两类:**内部调用接口**(供 M3/M7/M8 调用,服务间鉴权)与 **用户交互接口**(供前端工作台)。
> 最后更新:2026-11-27

---

## 1. 通用约定

进度订阅按生命周期优先解释阶段：`paused` 显示“环境已暂停”，提示恢复后继续；`destroyed` 显示“环境已释放”；只有 `recycling` 显示释放中。启动阶段不覆盖暂停或终态，客户端进入权限仍按服务端生命周期及阶段判断。

工作台请求绑定发起时的工具、运行时、动作与参数；目标或能力集合变化后不展示旧结果，执行期间锁定本次参数。查询目标、对象参数、完整 argv 白名单及就绪条件由相应接口校验。

工具登记按本节类型分别校验必填、允许与禁填字段；通用表单与错误交互遵循[前端规范](../总-前端设计规范.md)。

- Base:`/api/v1/sandbox`
- 成功响应体:`{ "code": 0, "message": "ok", "data": {} }`;错误响应体:`{ "code": 22001, "message": "实验环境准备失败,请稍后重试", "trace_id": "..." }`,错误时不返回 `data`。
- `[内部]` 接口在模块化单体内优先通过 `internal/contracts` 调用;需要 HTTP 暴露时仅走内网路由,必须服务间鉴权,并强制传 `tenant_id`、调用方模块、`source_ref` 与 trace 上下文。
- 错误码段:`2xxxx` 沙箱引擎(21xxx 运行时/22xxx 沙箱/23xxx 工具/24xxx 配额)。
- 用户交互入口按沙箱持久化 `source_ref` 经 M1 检查实验/竞赛模块是否开放，覆盖文件、终端、工具、链操作和进度连接；用户归属校验保留。内部资源创建、已受理判题执行与回收沿用受信服务契约，不因关闭模块遗留运行资源。

## 2. 运行时与镜像管理 `[平台管理员]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/runtimes` | 运行时列表(含适配器层级、自检状态与可用镜像版本数 `available_image_count`,一次分组计数取出,供列表卡片算接入进度;详情页另有完整镜像列表,单条读取不带该字段) |
| GET | `/runtimes/{id}` | 运行时详情，平台管理员读取完整登记配置 |
| POST | `/runtimes` | 注册运行时(提交 L1 清单 + 能力实现/插件引用) |
| PATCH | `/runtimes/{id}` | 更新运行时配置 |
| POST | `/runtimes/{id}/selftest` | 触发接入即测(起链→部署→查询→重置) |
| GET | `/runtimes/{id}/selftest` | 查询自检结果 |
| POST | `/runtimes/{id}/images` | 登记镜像版本 |
| GET | `/runtimes/{id}/images` | 该运行时的镜像版本列表，平台管理员读取 |
| DELETE | `/runtimes/{id}/images/{img}` | 停用镜像版本并删除对应预拉取 DaemonSet |
| POST | `/runtimes/{id}/images/{img}/prepull` | 按请求中的已发布 `composition_digest` 触发该组合闭包的 DaemonSet 全节点预拉取;缺少 digest 不允许执行 |
| GET | `/runtimes/{id}/images/{img}/prepull?composition_digest=` | 查询指定组合快照的预拉取状态与节点进度 |
| GET | `/tools` | 工具列表 |
| POST | `/tools` | 注册工具定义 |

运行时登记按 `code` 幂等：先由唯一约束确保记录存在，再锁定该行读取最新状态并更新；首次并发登记也遵守此顺序。未指定状态时保留当前状态，只改展示字段不得覆盖自检批次或重新启用已停用的运行时。按 ID 编辑只更新已有行，不通过 upsert 创建记录。
管理页“教师可选”和接入完成进度必须同时满足可用状态、自检通过、无当前不可用原因及至少一个可用镜像。镜像结果读取中或失败时，不显示“教师可以选用”；停用最后一个镜像后应提示登记镜像，不能用历史自检证明替代当前可用条件。

工具登记同样在确保记录存在后锁行比较最新执行声明，再更新与撤销预拉取证明。比较、保存和失效必须在同一事务完成；不能用加锁前的旧值判断是否发生变更。新工具没有既有引用证明，不因首次登记撤销其他组合。

运行时、镜像、工具与配额变更及其审计同事务提交，执行声明变化导致的证明失效也属于该事务。自检和预拉取的最终结果与结果审计同事务提交；写入、审计或提交失败均不得留下本次通过证明，执行失败原因仍保留在错误链中。加入已有预拉取的请求不改执行状态，单独记录本次观察审计。自检结果事件在完成事务提交后发布；发布失败保留执行与投递错误，已提交结果仍可通过 GET 查询，M3 在启动及周期协调时按 M2 当前状态恢复目录。

镜像停用先在事务内锁定镜像、写入停用状态、撤销组合预拉取证明并写审计，再清理 DaemonSet。数据库或审计失败不得删除资源；清理失败保留停用状态并返回错误，重复停用可继续清理。已接受的预拉取结束时锁行复核镜像状态，已停用则拒绝回写并清理迟到资源；不能恢复旧成功证明。

登记镜像时先确认运行时存在;同一运行时的镜像地址及版本号由数据库唯一约束裁决重复,冲突返回21025,不额外实现应用层查重。运行时不存在返回21001,其余读取或保存失败返回21026并在日志保留原始错误链;不能把保存异常映射为镜像不存在。签名/扫描证明门禁保持在写入前校验。

平台管理端必须按运行时和工具类型提供字段级编辑器，并由前端从受控字段生成 `adapter_spec` / `resource_spec`；不得要求管理员手写原始 JSON，也不得用空对象作为可提交默认值。自检完成后的目录刷新不得重建已打开的配置或镜像登记表单，保留未提交输入。编辑现有资源时，页面只提交请求契约字段，不能把 ID、自检状态等只读响应字段回传。服务端仍是最终校验边界。

预拉取请求体固定为 `{ "composition_digest": "sha256:..." }`。服务端必须确认摘要对应已冻结快照，复用创建、恢复的组合装载逻辑校验全部运行时身份、镜像版本与准入证明，以及全部工具和基础设施身份、可用状态，再从快照读取完整 `image_closure`。预拉取允许接入中的运行时准备镜像；发布与执行仍要求自检通过。预拉取结束后再次复核全部成员，期间失效则写为失败，不能只检查请求指定的镜像。请求不得携带运行时、工具、镜像 URL、命令或任意 WorkloadSpec。业务发布、漏洞题预验证和判题准备均通过 M2 内部 `PrepareCompositions` 使用同一摘要入口;平台管理员接口只用于手动重试与查询。

管理端触发预拉取复用 SDK 既有 `postWithoutClientTimeout`，不受普通页面请求的短超时截断；结果由独立 GET 有界查询。进行中“查看进度”和完成后“刷新进度”均只调用GET,不能再次POST或重置尝试。页面状态只属于当前运行时、镜像和准确组合摘要；切换运行时或编辑摘要后清除旧查询状态,操作期间固定摘要并阻止重复触发。查询窗口结束仍在进行时明确提示稍后查看,不能显示已完成或失败；离开页面后停止后续轮询和界面写回,不取消服务端已接受的任务。

运行时接入自检在认领批次前锁定所选主镜像，并复核它及适配器全部协同、初始化和辅助镜像的当前准入证明，复用创建与恢复的镜像校验；证明撤销时不写入进行中状态，也不创建资源。完成事务按运行时、所选镜像的顺序锁行；执行期间该镜像已停用时，自检写为未通过并保持接入中，不能借用其他可用版本的资格写回通过。

运行时自检使用同一触发与观察规则:POST的迟到完成响应仍须被当前观察流程接收,不能因两次GET之间漏过进行中状态而丢失本次终态；确认本次触发结果或观察到进行中之前,不采纳上次终态。触发错误与查询错误分开处理,查询恢复后清除旧查询错误。操作期间禁止重复自检与并发读取。结果与观察流程属于当前运行时执行声明和可用镜像集合；声明或集合变化时一并重置，旧请求不得再写回或提示成功。普通刷新和仅改名称保留已读取详情，离页后停止观察。通过、未通过和仍在进行使用各自对应的用户提示。

`selftest_status=1`同时用于尚未自检与自检进行中,管理端必须结合公开`detail.result`区分:`running`表示已启动,`pending`或空详情表示尚未执行；不能把初始待检状态作为本次触发已接受的证据。服务端已由GET确认进行中后,原POST的传输失败不能单独推翻该任务状态,观察窗口结束时仍须提示后续读取结果。

镜像登记请求必须携带不可变 digest;Cosign 签名与 Trivy/Harbor 扫描结论由后端启动时加载的 `PLATFORM_IMAGE_ATTESTATIONS_JSON` 受控证明清单校验,请求体不得直接提交签名/扫描结论:
```json
{
  "image_url": "registry.chaimir.io/runtime/evm-hardhat@sha256:...",
  "version": "sha256-<digest-prefix>",
  "digest": "sha256:...",
  "genesis_baked": true
}
```

web-embed 与 command-tool 工具注册必须在 `resource_spec.components[].image_url` 使用带 digest 的不可变镜像引用,并逐个组件命中受控证明清单;terminal/platform-builtin 工具不得声明组件镜像。 两类工具均须为每个组件提供 `components[].prepull_command` 参数数组；登记表单按参数填写并回显。命令必须能在该镜像中完成独立自检。
网页工具编辑器的服务端口读取 `services[].ports[].port`；服务端口名可与容器端口名不同，依靠 `target_port` 关联，代理路由引用服务端口名。编辑不得将三者强行同名或截断未管理的端口；复杂服务与多端口声明按只读展示。工具已有的组件端口 `service_port` 不由该服务端口输入重写，工具发现以显式 Service 为准。
command-tool 工具必须只声明唯一 `command` 组件,不得声明 Service、route 或网络规则;`command_policy.allowed_argv` 是完整 argv 白名单,请求数组必须逐项完全命中其中一项,不得提交 shell 字符串或追加未登记参数。

命令数组在表单回填、登记、冻结、闭包比较及执行中逐项保留原值；参数首尾空白属于输入，不做 trim、丢弃或拆分。空项、纯空白项及 NUL/CR/LF 按统一命令校验拒绝，不通过清洗改成另一条命令。不同 argv 的自检分别保留，不共享通过结论。
platform-builtin 工具必须在 `resource_spec.builtin_endpoint` 中声明平台端点模板,模板必须以 `/api/v1/sandbox/sandboxes/{sandbox_id}` 开头,由 M2 挂载时渲染实际沙箱 ID;此类工具不创建 sidecar,也不得落入 `/tools/{code}` HTTP 反向代理。
L2 按 `capability_impl` 解析服务端注册的能力实现，L3 按 `plugin_ref` 解析注册插件，两类引用不能互相代替。L2 未指定实现时由完整命令声明确定内置 `sandbox-exec`；选中此实现也必须保留完整命令。命令方式必须在 `adapter_spec.capability_commands` 中声明 `deploy`、`tx`、`query` 三个受控命令及各自 `exec_target=pod/container`;链不能在线恢复创世态时使用 `reset_strategy=recreate_runtime`,由 M2 清空对应实例账本卷、重注入初始化材料并恢复消费者,禁止返回固定成功值。只有生态原生提供可验证 reset 命令时才声明 `reset`。命令通过 stdin/stdout 交换 JSON，超时为 0 或留空时使用服务端配置的默认值，负数和非整数无效。`adapter_spec.workspace_ops` 必须声明学生安全入口的 `exec_target`,`private_archive_ops` 必须声明非学生入口的解包目标;精简 runtime 不得隐式承担通用归档解包,由平台声明的非学生归档 sidecar 显式写入 `judge-private`;运行时初始化资产若存在,必须由独立非学生 sidecar 通过 `init_asset_ops` 写入已声明的 `runtime-state/public-assets`,不能复用私有判题域写权限;服务端不得默认选择任一 runtime 容器或学生容器承载隐藏资产。

组合中的 `init_chain_steps` 按顺序声明 `runtime_instance`、`op` 和对应 `payload` 或 `target`，动作仅限 `deploy/tx/query/reset`。编译时校验实例、动作参数与运行时能力，并将步骤纳入组合摘要。首次启动在恢复代码、执行初始化脚本后执行链初始化，完成后才开放工具和用户入口；任一步失败走现有失败终态。暂停与快照恢复不重放初始化。初始化复用冻结运行时和链能力，不放宽用户执行门禁。

组合及完整快照摘要对全部结构化内容（含原始适配器、组件规格）采用同一精确 JSON 规范化：忽略对象键序和等价数字写法，保留数组顺序及不同数值。JSONB 将指数改为十进制写法时，摘要不变；规范化不使用 float64。

运行时和工具的执行规格按同一 JSON 语义比较；等价数字写法不撤销自检或镜像预拉取证明，实际数值变化必须撤销。镜像清单的自定义解析也复用严格解码，保留配置 Schema 的精确数值。

实验/题目组合请求中的 `init_assets` 每项必须包含 `name`、`source_ref`、明确的 `target_runtime_instance`、`target_domain` 和完整 `expected_sha256`。教师追加材料在编译时校验为本租户代码或附件桶对象；平台审核素材由已自检运行时清单带入，存于相同受控桶的 `0/` 前缀，可随冻结组合供各租户按摘要读取。平台自检也只能读取平台素材。普通工作区恢复和教师脚本不获得共享目录权限。M2 在发布时冻结素材声明，首次启动及链重置前校验实际内容摘要，再由独立非学生资产 Pod 写入对应实例的 `runtime-state` 或 `public-assets`，回收后才启动消费者。学生请求和投影不得包含素材引用。Chainlink job/合约 fixture、Hyperlane base config、OP-Stack rollup/checkpoint 等材料通过该资产闭包或平台 Secret 绑定进入组合；缺失、摘要不符或跨租户时拒绝启动，不把材料写入镜像或全局共享卷。

初始化脚本在 `workspace_ops` 中独立声明 `script_exec_target=pod/container`,指向挂载工作区但不允许学生进入、独享临时目录的容器。`run_script` 命令从标准输入接收原始脚本字节,只在容器私有临时目录执行并清理,不接受工作区脚本路径。`clean_workspace` 经同一非学生目标在首次启动、暂停恢复和快照恢复开放前清除精确根副本。缺失私有执行目标或命令时拒绝启动/恢复,不得复用学生 `exec_target`。文件 API 拒绝根 `.chaimir-init-script` 及其子路径,目录不返回该项;保存和恢复归档时移除该私有保留条目,不影响其他学生文件。

平台运行时登记与编辑共用字段表单,必须可显式维护上述执行目标、开放前清理命令、私有归档目标/解包命令,以及各容器的学生访问、工作区挂载、数据域读写和临时目录。链能力逐项维护执行目标与超时,重置明确选择命令或 `recreate_runtime`。卷域访问、持久化和快照策略用中文选项提交服务端规定的唯一枚举,不要求管理员手写枚举文本。编辑时保留未修改的其余结构化声明,不得重建 `workspace_ops` 或链命令时丢失已有执行目标,也不得为新登记隐式选择学生/私有容器。执行字段与打开表单时相同时，提交原始适配清单；只改展示字段不得补写空命令、默认权限或空列表而撤销原自检状态。

### 2.1 编排目录 `[教师/学校管理员/平台管理员]`

课程依赖复制使用仅供 M7 的 `SandboxCompositionCloneService`，不新增 HTTP 入口。输入必须等于 M2 已登记冻结快照；仅将来源租户初始化对象复制到目标学校并改写引用，保留平台素材、镜像摘要、连接和执行配置，重新计算完整快照摘要。保存操作只能借用目标普通租户事务登记快照，与课程和实验原子提交；失败补偿只删除本次对象。不得重新编译成最新目录版本或放宽外校素材读取。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/catalog` | 可编排的运行时、工具和基础设施能力摘要与参数 schema |
| POST | `/catalog/composition-preview` | 根据当前声明返回组件依赖与连接候选,不创建或发布快照、不执行预拉取 |

教师编排实验环境、竞赛对抗环境和漏洞题预验证环境时要选择能力组件、参数和连接,而 §2 的管理接口是平台面(`RequirePlatformIdentity`),把它放开给教师会连带暴露 `adapter_spec` 的容器编排清单、镜像 digest 地址、`command_policy.allowed_argv` 与自检详情 —— 这些是平台运维资产,不是编排输入。故单独出一条只含编排必需字段的目录接口,由同一份 `runtime`/`runtime_image`/`tool` 数据投影:

```json
{
  "runtimes": [{ "code": "evm-hardhat", "name": "EVM Hardhat", "capabilities": ["evm.rpc"], "parameter_schema": {}, "access_profiles": ["experiment", "contest-solve"] }],
  "infra": [],
  "tools": [{ "code": "code-server", "name": "在线 IDE", "kind": 3, "capabilities": ["workspace.editor"], "parameter_schema": {}, "access_profiles": ["experiment", "contest-solve"] }]
}
```

目录返回已通过接入自检且 `status=可用` 的运行时、其 `status=可用` 的镜像版本，以及可用的工具和基础设施。它提供编排候选，不证明任意组合已准备就绪。`genesis_baked` 是镜像是否携带固化创世材料的元数据，不是所有运行时进入目录的统一门禁；动态初始化的完整性由具体运行时和组合校验。

教师先声明组件、参数与连接，由 M2 编译并冻结完整组合；正式发布前按该快照的准确摘要和镜像闭包执行预拉取。创建或恢复沙箱前必须校验当前准入和该摘要的成功证明，不能借用同一镜像参与的其他组合证明，也不能以尚未生成的组合证明阻断目录选择。预拉取失败时记录该组合的失败原因并拒绝发布或启动。

目录返回运行时、工具和基础设施的 `code`、展示名、能力摘要、参数 schema、约束摘要和允许的访问配置，不返回 `tool_codes`、原始 WorkloadSpec、镜像 digest 地址、命令白名单、自检详情或生态标签本身。工具能否加入当前组合必须由 M2 组合编译器复核，不能由前端切换运行时后自动注入。平台管理端仍走 §2 的完整管理接口，不改用目录。

连接预览请求为 `{runtimes, workspace_runtime_instance, infra, tools, links}`。`infra/tools`只提交显式选择及其参数,上次快照中的`selection=auto`不作为新声明重新提交。预览与最终编译共用目录解析、依赖展开、能力冲突与数量上限校验，以及端点解析;返回`infra`依赖闭包、`bindings[]`连接要求及其`options[]`（展示名与完整`link`）、已选`links`和`complete`。候选必须同时满足能力、端点与协议;仅提供同名能力但缺少要求端点或协议不匹配的目标不进入该绑定的候选,不能使其它合法候选失效。目录的重复端点、无效端口及绑定声明错误仍明确报错。唯一候选可预选,多个候选必须由教师明确选择;没有候选时不能把未连接环境加入草稿。预览只读取目录,不返回镜像地址、工作负载、命令或Secret,不产生摘要或执行资源。它不决定题库正文的场景访问配置;保存/发布仍经原编译器检查完整访问边界、安全、网络和冻结规则。

实例别名、运行时编码、镜像版本及工作区引用必须非空且不含首尾空白；预览和编译在读取目录前使用同一校验，不隐式改名。表单更名只在名称有效且唯一后迁移引用；参数值中的空白按原内容保留。

运行时与工具的 `requires` 使用同一依赖展开规则：必须由另一个运行时或组件提供能力，不能自我满足。未选择的依赖只从可用的沙箱基础设施中解析；唯一候选自动加入并冻结，多候选须显式选择，没有候选则拒绝。自动依赖继续递归展开，并使用同一参数 schema 校验；缺少必填参数时必须改为显式选择和配置。

实验环境、题库实操题、漏洞预验证及判题配置使用同一连接选择界面,不在浏览器维护组件配对表。读取中、失败、选项变化或连接未完成时,当前声明不可提交;重试不得丢弃教师输入,迟到预览不得覆盖新选择。连接随声明经服务端保存,重开从服务端恢复,冻结快照只读。

`bindings[].multiple` 表示目录是否允许同一绑定选择多个目标；为 true 时至少选一个，前端显示复选组，唯一候选可预选，多个候选不自动全选。选中的每个目标仍是完整 `link`，共享绑定标识；最终编译将地址按序编码为一个 JSON 字符串数组环境变量，逐目标生成网络规则和启动前置。重复目标、单目标绑定提交多个目标，以及将多目标绑定作为卷来源均拒绝。

`bindings[].optional=true` 表示组件可在没有该连接时独立工作，不触发依赖补齐，也不自动选择唯一候选。预览将 `optional` 和面向用户的 `title` 随候选返回；教师可以保持未连接或撤销选择。未连接时不注入地址、不放行网络、不阻断保存；选中后沿用同一端点、能力、协议、重复目标及启动顺序校验。可选连接不能作为必需挂载的卷来源。必需连接保留原有完整性约束。

在线 IDE 声明到索引器部署、索引状态、查询和 IPFS 上传接口的四项可选连接。它们仅提供本沙箱服务地址与对应端口的网络访问，不共享数据库密码、POI token 或链账本；不开放公网和浏览器直连。教师选择并冻结连接后，学生在 IDE 终端使用镜像已有 Node HTTP 能力调用原生接口；编译后的 subgraph 材料由工作区提供，不在运行时下载工具或依赖。

预览保留当前闭包中仍合法的明确连接,移出闭包的连接失效;仍选中组件的未声明绑定、重复连接或与运行时实例别名重名的组件必须拒绝。多目标选择后再次经同一编译器校验,不能只在浏览器标记完成。实验草稿从读取投影恢复时同样剥离自动依赖和摘要,未编辑环境也不重提`auto`项;保留原参数、资源、网络及初始化声明。

四个编排入口还必须共用目录驱动的参数表单。当前目录参数为字符串、数值、布尔值及枚举,复用现有输入框和选择框渲染;字段展示名和说明来自`config_schema.properties`的`title/description`,不把内部键或环境变量映射作为标签。未填写的可选项不写入`params`,明确填写的`false`和`0`必须保留,不自动注入schema默认值。修改运行时或组件参数后撤销旧连接证明,预览通过后才能提交;离开重开恢复服务端参数。

参数安全校验由M2预览和最终编译共用`github.com/santhosh-tekuri/jsonschema/v6`完成,替换原手写类型/枚举校验,统一执行类型、枚举、必填、范围、长度、格式模式和未知属性约束。只接受当前目录内的schema,禁止通过`$ref`读取外网或本机文件。参数只经manifest明确的非敏感环境变量映射注入：已声明的可编辑字段可以替换该变量的默认值，未填写时保留默认值；不能覆盖Secret、未开放的固定配置或连接生成的不同地址，同一变量不得由多个参数同时写入。监听地址、固定服务端口和网络隔离开关不作为可编辑参数，连接地址只由link生成。校验详情只进原错误链日志。前端不增加第二套schema验证器。

参数对象按参数名稳定遍历，新增环境变量的顺序不依赖对象插入或 map 迭代顺序；已有环境声明保留原序并原位替换默认值。相同参数与连接须生成相同工作负载及摘要，不能通过重排命令、初始化步骤或原有环境声明来归一化。

运行时实例更名时同步改写links、工作区归属和已有初始化材料的目标实例,不丢材料引用。仍有关联初始化材料的实例不能直接移除,需先调整材料声明;不得通过删除实例静默丢弃初始化材料或留下悬空引用。


预拉取响应:
```json
{
  "image_id": 88,
  "composition_digest": "sha256:...",
  "prepull_status": 4,
  "desired_nodes": 6,
  "ready_nodes": 3,
  "image_count": 12
}
```

`prepull_status=2` 只表示该 `composition_digest` 的完整闭包在目标节点真实完成拉取。每次触发生成唯一 `attempt_id`,开始前锁定镜像并读取已冻结快照,结束时仅允许同一 `attempt_id` 从进行中写回最终状态;期间发生运行时或组件执行契约变更时,旧尝试不得覆盖新的失效状态。失败时返回用户向提示,节点、事件与镜像拉取错误只进入日志和组合预拉取明细。

进行中节点数来自编排器最近一次真实轮询，复用当前预拉取记录保存；只有同一 `attempt_id` 且仍在进行中才可更新，相同节点进度不重复写库。进度写入失败使本轮失败，不能继续返回成功。触发、加入等待与 GET 共用响应投影；`image_count` 按完整镜像 URL 去重，不把同一镜像的不同自检命令重复计数。保存进度不结束尝试，最终状态与结果审计仍同事务提交。

运行时执行声明变更时，撤销自身镜像名下及所有引用它的冻结组合的预拉取证明，包括挂在同组合其他运行时镜像名下的进行中和已完成证明；不影响未引用它的组合。旧执行者须被原有批次条件拒绝，不能恢复组合成功状态。

闭包比较与工作负载使用同一收集规则：镜像、命令和保持用途相同的条目合并临时挂载。同一镜像供多个运行时或工具使用时，不因来源或临时目录不同拒绝合法组合；命令、用途或合并后的挂载不一致仍须拒绝。

运行时接入自检使用同一批次条件写回原则:启动时锁定待测运行时镜像和当前能力证明,将运行时置为接入中并记录唯一 `attempt_id`;结束时仅允许批次一致且仍处于接入中的记录写回。并发修改执行契约、停用运行时或后发自检后,旧结果必须被拒绝,不得恢复过期配置的可用状态。

`GET /runtimes/{id}/selftest` 和自检完成响应的 `data.detail` 只返回 `result`、`stage`、`reason`、`trace_id`;`attempt_id` 仅保存在服务端用于并发写回校验,不得下发。`reason` 必须是平台已登记的用户向原因,不得携带命令输出、堆栈、连接串或 Secret。

运行时自检阶段使用 `prepare/workspace/toolchain/capability/recycle` 表示资源准备、私有初始化清理、声明命令、原生能力与资源清理;前端统一映射为用户向文案。选取自检镜像只要求版本可用,不以适用于部分链的`genesis_baked`作为通用门禁;创世状态仍按各运行时声明初始化,镜像证明与教师组合可调度门禁保持原契约。

## 3. 沙箱生命周期 `[内部]`

暂停与回收按校验摘要后的原冻结快照保存工作区、制作快照和释放资源，不依赖当前目录可用性、自检或预拉取证明。目录撤销不得阻止已有环境清理；归档执行必须持有当前有效资源租约，只挂载原工作区卷且只读，不重启业务计算或开放工具。快照损坏、租约失效或保存失败时停止后续释放，保留资源供重试。创建、恢复和用户执行继续使用当前准入规则。

平台私有判题组合编译同时接收私有 sidecar，完整校验后将其加入快照、镜像闭包与最终摘要，在同一事务中只登记最终快照；失败不得留下中间记录。普通组合不传私有 sidecar。编译不删除任何其他摘要，已冻结组合可继续被原消费者使用。

创建、恢复及进程重启后的启动任务只传递租户和沙箱编号。执行者取得创建态资源租约后，重新校验当前记录中的冻结快照及当前运行时、镜像、工具、供应链证明和准确摘要的预拉取结果；通过后才创建资源。受理后发生目录撤销或快照损坏时，在所属租约下进入失败处理，不使用请求阶段缓存的执行计划。

### 3.1 创建沙箱

同一次启动或重置中，相同对象与 SHA-256 的初始化归档只读取、校验和重打包一次，各链实例及卷域仍按原声明注入。准备后的字节只读共享，不跨操作保留；不同摘要不得复用，来源、归属与归档限制仍须通过原校验。
`POST /internal/sandboxes` `[内部]`

请求体只包含：

| 字段 | 约束 |
| --- | --- |
| `composition_snapshot` | M2 编译并登记的完整冻结快照；摘要为 `composition_snapshot.digest`，初始化引用和访问配置取其 `spec` |
| `owner_account_id` | 所属租户账号，使用十进制字符串 ID |
| `authorized_account_ids` | 可省略的授权账号字符串 ID 数组 |
| `scope_ref` | 本次运行的生命周期作用域 |
| `keep_alive`、`snapshot_enabled` | 可省略，默认 `false` |
| `keep_alive_minutes`、`snapshot_retention_minutes` | 可省略，默认 `0`；启用对应能力时为正数 |

租户与稳定来源只取服务签名上下文，请求体不接受 `tenant_id`、`source_ref`。M7/M8/M3 在模块化单体内直接使用 `internal/contracts.SandboxCreateRequest` 传递已授权身份和同一冻结快照；不使用浏览器 SDK 调用内部 HTTP。

响应为受理快照，ID 使用字符串，例如 `{ "sandbox_id": "9001", "phase": 1, "status": 1, ... }`。

> 新创建在事务提交后返回已受理快照：沙箱编号、冻结运行时、工具与能力完整，阶段为分配中、状态为创建中，工具为准备中，资源用量为 `null`；这不表示执行环境已就绪。响应在提交前构造，提交后不再查询详情，避免后台已启动却因读取失败返回创建失败。启动异步推进，后续通过现有详情与 §3.2 进度观察；幂等重复请求返回已有沙箱的当前状态，不重建资源。
> `composition_snapshot.digest` 必须来自 M2 编译器已登记的不可变快照，完整内容须与该摘要及存储记录一致。M2 按快照中的全部命名 runtime 实例、依赖闭包、工具、连接、资源和安全策略创建 WorkloadSpec;请求不再单独传 `composition_digest`、初始化引用、`access_profile`、`runtime_code`、`runtime_image_version`、`tools`、命令、端口或 NetworkPolicy。普通实验、解题赛、对抗赛、预验证和判题分别使用快照中的 `access_profile`,不存在当前默认镜像或默认工具回退。
> 创建沙箱的后端调用方只能通过 `internal/contracts.SandboxService` 使用 M2,不得 import `internal/modules/sandbox` 内部包或复制 M2 校验逻辑。
> `keep_alive` 与 `snapshot_enabled` 默认必须为 `false`;只有业务需求明确要求保活或快照时才能开启。开启 `keep_alive` 必须同时提交正数 `keep_alive_minutes`;开启 `snapshot_enabled` 必须同时提交正数 `snapshot_retention_minutes`;未开启对应能力时分钟数字段必须为 `0`。调用方不得依赖隐式默认时长或上游模块私有默认值绕过 M2 配额校验。

> `authorized_account_ids` 是用户侧沙箱共享访问主体的输入集合。M2 创建事务单独写入 `owner_account_id`,并把调用方提供的正整数账号去重、剔除 owner 后写入 `sandbox.shared_account_ids`;单人、判题和预验证场景可省略。成员更新先规范化并校验共享账号，在沙箱行锁内读取旧集合、计算差集并替换；提交后只关闭被移除成员的连接，owner 和保留成员不撤权。M7 小组实验必须传入当前小组全部成员;M8 跨校队伍必须由 M8 先完成参赛主体授权后传入。M2 不解析 `source_ref`/`scope_ref` 反查业务成员,也不依赖 M7/M8,从而保持模块依赖单向且不重复存 owner。

### 3.2 启动进度(WebSocket)
`WS /sandboxes/{id}/progress`
服务端校验调用账号是 `owner_account_id` 或存在于 `shared_account_ids` 后订阅 `tenant:{tenant_id}:sandbox:{sandbox_id}:progress`,禁止使用旧式 `sandbox:{tenant_id}:{sandbox_id}:progress` 主题。
浏览器原生 WebSocket 不能设置 `Authorization` 头时,前端必须先通过 M1 `POST /api/v1/auth/ws-ticket` 为该 WS path 换取短时路径绑定票据,再追加 `ticket=<ws_ticket>` 查询参数;后端校验票据路径和服务端会话,不得向沙箱 Pod 或事件 topic 透传 access token。
推送:`{ "phase": 2, "stage": "环境就绪", "message": "节点已就绪,可进入" }`
阶段:1分配环境 → 2环境就绪(可进入)→ 3个性化初始化中 → 4完全就绪。
失败推送示例:`{ "phase": 1, "stage": "准备失败", "message": "实验环境准备失败,请稍后重试", "trace_id": "..." }`。用户消息不得包含 Pod、Namespace、SQL、镜像拉取等技术细节。

### 3.3 查询 / 控制 / 销毁
- 生命周期读取以租户内沙箱记录和准确校验摘要后的冻结组合为准；当前目录停用、重新自检或暂时不可读，不得阻断已创建沙箱的阶段、状态和原运行时身份投影。读取事实不代表准许执行：文件、终端、工具、新建、恢复及需要重建计算资源的归档仍校验当前准入。创建中记录因服务重启需要重新调度时，准入失败须带租户、沙箱、trace和完整错误链记录日志，保持已持久化状态，等待原流程具备条件后重读，不启动未获准的资源，也不以调度失败覆盖状态读取。
- `GET /sandboxes/{id}`:状态、阶段、资源用量、工具接入地址;用户响应不得包含 Namespace、Pod、Service 等集群内部资源名。资源用量必须包含
  `cpu_usage_milli`、`memory_usage_mib`、`cpu_request_milli`、`cpu_limit_milli`、
  `memory_request_mib`、`memory_limit_mib`、`storage_bytes`;实时 CPU/内存用量来自
  Kubernetes `metrics.k8s.io` API。`resource_usage` 为该完整摘要或 `null`：未到采样阶段、采样不完整或基础设施暂不可读时明确返回 `null`，不使用零值冒充未知，也不阻断同一响应中的生命周期、授权及能力。采集使用 `SANDBOX_RESOURCE_USAGE_TIMEOUT_SECONDS` 独立有界预算，原始失败链含租户、沙箱和trace写入日志；工作台提示“资源用量暂时无法读取”，沿现有详情刷新恢复，不新增用量接口。
  申请量和限制量按 Pod 有效资源汇总，与配额预检共用 Kubernetes 计算口径，包含初始化峰值、原生 sidecar 和 Pod overhead；不能只累加普通容器，也不把这些声明值当作实时用量。
- `POST /sandboxes/{id}/pause` / `POST /sandboxes/{id}/resume` `[内部]`:暂停/恢复(可选;默认空闲超时回收)。
  恢复先核对所有必须保留的 PVC；缺卷只有在已提交快照域中才允许从该快照重建，其他缺卷或正在删除的卷明确失败。首次分配允许创建空卷，恢复不得用空卷替代工作区或已初始化材料。
  切换到 `creating` 前，在新建也使用的租户配额行锁内核对当前生命周期与容量。暂停环境已占用配额，不重复增加；已销毁快照恢复须重新占用一个环境的并发及 CPU/内存容量。读取失败或容量不足时保持原状态，不启动计算资源。
- `DELETE /sandboxes/{id}` `[内部]`:主动销毁。
- `FindSavedSandboxWorkspaceArchiveBySourceRef` `[内部契约]`:调用方完成业务归属校验后，M2 按租户、稳定来源和最近沙箱创建顺序读取已保存的公开归档，包括已销毁记录；无保存返回空引用，查询错误显式失败。与按沙箱编号读取归档共用对象引用构造，均不暴露给用户 HTTP。已销毁记录与内容归档保留供显式重建恢复，不将初始模板冒充用户已保存代码。
- `POST /internal/sandboxes/recycle` `[内部]`:请求体只含 `scope_ref` 与可选 `reason`，租户和 `source_ref` 取服务签名上下文；按 `scope_ref` 批量级联回收(来源结束时调用)，稳定来源只作身份校验，不得作为批量范围。模块内调用使用 `contracts.SandboxRecycleRequest`。
- `RestoreSandboxArchive` `[内部契约]`:把调用方已保存的公开代码/参战物归档安全恢复到 `workspace` 子目录。M2 必须校验对象引用属于当前租户的代码或附件桶;请求携带 `expected_hash` 时,M2 必须按对象实际内容计算 SHA-256 并逐字匹配;随后复用初始化归档安全原语重打 TAR,并只解包到调用方传入的相对目录。该能力不得用于隐藏测试、答案、flag 或判题私有资产。
- `PutSandboxPrivateArchive` `[内部契约]`:M3 注入隐藏测试、flag、答案摘要或评分脚本时只能调用该契约,目标域必须是 `judge-private`;M2 在后端用统一归档安全原语校验并重打 ZIP/TAR,拒绝目录穿越、绝对路径、Windows 盘符、重复条目、软/硬链接、特殊文件和炸弹包,随后只解包到 `judge-private` 卷域。声明 `judge-private` 的运行时不得把 `runtime_container` 标记为学生可进入容器;学生终端必须走单独 sidecar,避免隐藏资产与学生 shell 处于同一容器。该能力不提供用户 HTTP 接口,也不会触发工作区 S3 对象存储 持久化。
- **回收事件**:沙箱因任何原因进入回收(空闲/最长生命周期/就绪超时/主动)时,M2 发布 `sandbox.recycled` 事件(eventbus,携带 sandbox_id、source_ref、scope_ref、原因),来源方(experiment/contest)订阅后同步实例状态。**用事件而非反向接口回调,避免引擎层反向依赖业务层(见工程目录设计 §3.1.1)**。

回收请求:
```json
{
  "scope_ref": "experiment:2026:instance:55:run:1",
  "reason": "source_finished"
}
```

回收必须在代码保存、快照处理、K8s 资源删除、DB 标记 `destroyed` 后才发布 `sandbox.recycled`。删除失败时不得发布完成事件。

## 4. 沙箱交互 `[用户]`

### 4.1 终端(WebSocket)
`WS /sandboxes/{id}/terminal?container=<name>`
- 后端代理 K8s exec PTY;前端 xterm.js 双向流。
- 终端加载完成后才换票建连；发送回调始终使用当前连接，连接启停和重试不得重新挂载终端或清空缓冲区。切换标签保留会话，切换沙箱或环境失去可操作性时释放。
- PTY 输入输出均使用 WebSocket 二进制消息逐字节传输。普通键盘输入用浏览器标准 `TextEncoder` 编码为 UTF-8，xterm 的二进制输入保留原始字节；输出按顺序直接交给 xterm 流式解码，不逐消息解码。
- 同一终端连接的文本消息只承载 Kubernetes `TerminalSize` JSON：`{"Width":93,"Height":29}`，两个值均为 1–65535 的整数。终端首次连接、重连后立即发送当前行列数，随后跟随 xterm `onResize`；不能把尺寸消息写入 shell。Hub 严格解析尺寸，连续变化只保留最新待处理值，经 client-go `TerminalSizeQueue` 传到 exec；非法消息结束连接并保留内部原因，连接取消必须唤醒尺寸等待。owner 与 M8 受控主体共用此路径，进度/业务 JSON 不受影响。不保留终端文本输入旧协议，也不建立第二条连接。
- 终端输出在Hub有界队列中等待实际网络写入,缓冲暂满时背压到上游PTY,不能丢块或在尾块尚未发出时结束连接。断连、写入失败、撤权或连接替换必须取消关联exec;owner和受控主体入口均使用Hub的连接context,不只依赖升级前的HTTP请求context。网络写入沿用统一写超时,不新增终端专用队列、阈值或重试连接。
- 终端执行正常结束且连接仍有效时,Hub在尾块写入确认后发送正常关闭控制帧,再释放底层连接;不把正常退出当作传输异常。执行失败、已断开或已取消时仍保留各自原因并走统一清理,控制帧发送失败不静默忽略。
- 终端目标解析只校验授权、生命周期和学生入口,不更新活跃状态或记录执行事件。WebSocket 成功升级并登记唯一会话后,再次校验的受控主体才能在同一事务登记活跃并记录执行事件;无效容器、伪造目标、失败升级或会话绑定失败不得延后空闲回收。
- owner 终端绑定会话后重验账号仍是 owner/共享成员；M8 终端绑定后重验相同 grant 编号与版本。撤权先提交权威授权，再广播到所有在线副本关闭已有会话；不能依赖单副本本地踢线。
- 浏览器客户端使用 M1 签发的短时 `ticket=<ws_ticket>` 建立 WebSocket;服务端完成票据路径和会话校验后只把租户/账号身份写入请求上下文,不得把 access token 传入容器环境或命令行。
- 支持多容器切换(query 指定 container),但目标容器必须在运行时声明中显式标注 `chaimir.io/student-access=true`。
- 未传 `container` 时,M2 只选择第一个显式学生入口容器;没有安全入口容器则拒绝连接。禁止默认进入运行时主容器,避免通过 shell 读取 `runtime-state`、`judge-private`、Secret 或控制面凭据。
- 终端/进度重入复用平台Hub的会话替换流程:新连接登记成功后,已断开的旧连接清理失败不能被当作新连接越权或执行失败。原连接退出不得撤销后来的连接;初始化失败撤销自身登记,完整原因仅记带trace的运维日志。此约定不放宽票据、账号归属和容器安全入口校验。

### 4.2 文件操作
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/sandboxes/{id}/files?path=` | 列目录/读文件 |
| PUT | `/sandboxes/{id}/files?path=` | 写文件(触发防抖持久化 S3 对象存储) |
| POST | `/sandboxes/{id}/files/save` | 立即持久化当前代码 |

文件路径必须相对 `workspace_dir`,服务端拒绝绝对路径、`..` 逃逸和符号链接逃逸。`files/save` 成功响应返回 `code_storage_key` 与 `code_hash`。文件操作接口只能访问 `workspace`,不得读取或写入 `runtime-state`、`judge-private`、Secret、隐藏测试、答案或 flag。

文本编辑器只接收成功解码的 Base64 与合法 UTF-8，保留原 UTF-8 BOM。解码失败走已有读取错误提示，保留当前文件和未写入编辑；不得替换成空文件或替换字符后继续保存。单文件写入与保存工作区共用一次带版本校验的写入逻辑，写入失败时不继续生成归档。

环境状态读取失败时保留已打开文件与未写入内容，关闭文件操作及保存快捷键；恢复后才允许继续。已发出的请求不等于已取消，但旧操作不得在失去可操作性后继续归档、回调提交引用或覆盖当前编辑状态。按钮与快捷键共用一个写入/归档流程及相同门禁，页面禁用状态不能代替异步步骤间的校验。

工作区写入使用沙箱级 `workspace_revision` 乐观并发控制:读取响应返回当前版本,写入请求必须携带 `expected_revision`;版本不一致返回冲突且不覆盖他人内容。成员授权集合变更会关闭被撤销账号在该沙箱上的终端与进度长连接。

版本领取、活跃更新和写入事件登记共用现有沙箱事务；版本冲突不更新活跃时间，事件登记失败不执行容器写入。容器执行报错时回滚本次数据库变更。内部命令的目标校验也必须先于活跃登记。

文件读取与公开文件写入、归档保存共用现有租户沙箱行锁;服务端在同一事务中读取文件字节和对应修订号,锁内复核命名空间与冻结组合未变化,执行时间复用已有命令预算。owner和竞赛授权入口复用唯一读取实现。前端不能用详情轮询或归档保存返回的版本替换尚未重读的文件版本,发生冲突后保留编辑,由用户选择重新读取再编辑,不得自动提升版本覆盖其他成员修改。

立即保存返回的`code_storage_key`和`code_hash`绑定本次净化后的归档内容,后续保存不得覆盖该内容;`workspace_revision`来自同一次持锁保存,不能在保存结束后读取另一个版本填入。owner和M8授权入口共用该语义,各自公开投影保持不变;防抖、提交和暂停/回收前保存复用同一串行持久化实现。

写文件的 `content_base64` 必须显式提供字符串,空字符串表示合法的零字节文件,用于新建空文件或清空已有内容;字段缺失、`null`、非字符串或非法Base64均拒绝。owner与竞赛授权网关采用同一规则,解码后统一经过M2的路径、归属和版本校验及原子写入,空内容不绕过这些门禁。私有初始化脚本和私有归档仍要求非空,不与公开文件内容混用校验。

账号写文件的请求体只含路径、内容和预期修订号；链部署/交易只含 `runtime_instance` 与 `payload`。两者均不接收 `tenant_id`：账号归属取会话，内部链调用取已验证服务身份和来源，资源归属校验仍在 M2 执行。

### 4.3 Web 工具代理
`ANY /sandboxes/{id}/tools/{tool_code}/*`
- HTTP 反向代理到沙箱内工具端口(code-server/Remix/blockscout 等),iframe 嵌入。
- owner 与竞赛授权代理都传递当前工具相对路径，由 M2 按冻结路由的路径段选择最长前缀；根路由 `/` 可匹配任意路径，`/api` 只匹配自身及其子路径。声明顺序不影响结果，未匹配请求不登记活跃、不触发保存观察；转发保留相对路径和查询参数。跨模块目标直接使用已解析的内部 URL，不重复构造、字符串封装或重新解析。
- 入口只在当前沙箱可操作且该工具 `tool_access[].status=ready` 后开放。工具启动期间继续读取沙箱详情,不提前申请票据或加载代理;工具失败明确展示状态及重读入口。命令工具使用同一工具就绪门禁。owner 和业务 principal 保留各自授权，授权后的 argv 白名单、stdin 解码、超时上限、执行及事件记录共用一个实现；非法请求不触发执行活跃状态。
- 工具代理目标在登记活跃前必须能从冻结组件解析到有效 Service、命名空间与端口;未就绪或无效目标不更新沙箱活跃状态。owner 与 principal 完成目标校验后沿用统一工作区防抖保存观察。
- `tool_access` 的集合、类型和地址从校验摘要后的冻结组合推导，不另建挂载表；动态状态只以本次读取的生命周期和真实工作负载为准。HTTP详情、Web代理及命令入口共用同一判断:按沙箱冻结快照解析组件,组件Pod必须Running且Ready、未进入删除,Web工具声明的Service还必须具有指向这些Pod当前UID且非终止的Ready EndpointSlice端点。端点尚未收敛时保持准备状态；Pod、镜像拉取或容器明确失败、已退出及当前 Pod 超过既有启动/探针预算时显示失败，资源恢复后重新推导，不保留上一轮失败。不得将一次Ready永久当作当前可访问。查询失败显式报错,不沿用旧Ready;工具后来恢复可在下次重读恢复入口。owner与业务principal入口使用同一实现。
- 页面存在网页或命令工具时持续读取详情,就绪回退后关闭对应工作面;首次打开网页面板在换票前重读详情确认可操作和工具Ready,不从旧标签状态直接取票。工具状态读取失败提供重试,不自动反复创建iframe或重复换票。
- 网页工具从非就绪状态恢复时开始新的访问会话，重新确认当前状态并换票后再创建 iframe；不能在异步确认期间复用上一次就绪的地址。仅切换标签继续保留当前会话。
- 多组件状态按整组判断，准备中的组件不能遮蔽其他组件的明确失败；任何组件查询失败均显式报错。Web 工具还须核对当前 Service 未删除、声明端口未漂移；EndpointSlice 必须属于该 Service 的当前 UID，端口号、协议和当前 Pod UID 均匹配冻结声明，不能只看端口名相同。
- 浏览器首次打开工具前先调用 M1 `POST /api/v1/auth/browser-ticket`,请求 `{ "path": "/api/v1/sandbox/sandboxes/{id}/tools/{tool_code}" }`;M1 返回有效期由 `JWT_PATH_TICKET_TTL_SECONDS` 声明、绑定该路径前缀的 `ticket`。前端只把 `ticket` 放入首次 GET query,不得把 access token 放进 URL。M2 校验票据、服务端会话、用户、租户与 owner 后重新签发 access token,写入当前工具路径受限的 HttpOnly Cookie,再重定向到无 ticket 的同一路径。后续工具 HTML、静态资源、WebSocket 或 API 请求只能通过该路径受限 Cookie 经过平台代理鉴权,不得裸连 Service 或把票据、平台 Cookie、内部服务签名转发给工具容器。
- 代理必须重写同源 `Location` 到 `/api/v1/sandbox/sandboxes/{id}/tools/{tool_code}` 前缀,并把上游 `Set-Cookie` 限定到当前工具路径,避免不同工具或平台同域 Cookie 混用。
- 上游 Cookie 使用 Go 标准库解析与序列化，清除 Domain；缺省、根路径和非绝对 Path 使用当前工具前缀，其他绝对 Path 挂到该前缀内，已受当前工具路径边界限制的 Path 不重复添加前缀。无效 Cookie 丢弃，原生过期、删除和安全属性保持有效。
- `Location` 重写包含 `//上游authority/path`；当前工具路径带 query 或 fragment 时不重复拼接前缀。URL 的转义路径、query、fragment 均保留，外部 authority 和相对 URL 保持原有语义。
- 平台自有工具页面从以 `/` 结尾的工具入口加载，API 和静态资源使用相对 URL；不得请求站点根路径而绕出当前工具的鉴权和路由前缀。代理不修改工具 JavaScript。

### 4.4 受控命令工具
`POST /sandboxes/{id}/command-tools/{tool_code}/run`
- 命令面板支持可选的标准输入文本，按 UTF-8 编码为已有 `stdin_base64`，完整保留空白与换行；空输入不提交该字段。实验和竞赛共用同一面板及网关契约。
- `tool/zk-prover` 使用唯一白名单命令 `node /opt/chaimir/zk-prover/run.mjs`，标准输入为 `{tool: "circom2" | "snarkjs", args: string[]}`；调度器只解析这两个官方入口，保留原始参数、输出和退出状态，不拼 shell、不实现第二套证明算法。电路、材料与结果均在沙箱工作区，工具无私有状态、Secret 或网络权限。新分类必须重新构建及取得证明，不能借用原基础设施镜像的 digest。
- 只允许沙箱 owner 调用已挂载且 Ready 的 command-tool。
- 请求:`{ "command": ["slither", "."], "stdin_base64": "", "timeout_sec": 30 }`。
- 工作台复用逐参数输入组件，每个输入框对应一个数组元素，原样保留参数中的空格和引号，不重新分词。复用登记表单的参数完整性校验，空项和控制字符明确报错，不删除空项后发送另一条命令；完整数组仍由服务端白名单校验。
- 响应:`{ "stdout_base64": "...", "stderr_base64": "..." }`。
- 后端通过 `internal/platform/k8s.Exec` 执行,不自建 K8s 客户端;只记录工具 code 和入口命令,不记录 stdin/stdout 内容。

## 5. 链上能力 `[内部/用户]`(L2 标准能力的 HTTP 暴露)

供 M3 判分、工具浏览器使用:

| 方法 | 路径 | 对应 L2 动作 |
| --- | --- | --- |
| POST | `/sandboxes/{id}/chain/deploy` | Deploy(code) 部署合约/链码,请求体必须包含 `runtime_instance` |
| POST | `/sandboxes/{id}/chain/tx` | SendTx(tx) 发起交易,请求体必须包含 `runtime_instance` |
| GET | `/sandboxes/{id}/chain/query?runtime_instance=&target=` | Query 查账户/区块/交易/合约状态 |
| POST | `/internal/sandboxes/{id}/chain/reset?runtime_instance=` | Reset() 指定 runtime 实例恢复创世就绪态，仅内部服务 |

部署、交易和查询允许已验签服务，或当前租户的学生/教师/校管；用户操作仍核验沙箱拥有者/共享授权、生命周期、访问配置和目标实例。重置只走内部服务入口，用户角色不能直接重置。

> 这四个接口是跨运行时统一的;底层由请求指定的 runtime 实例 L2 能力实现器适配(EVM JSON-RPC / Fabric SDK 等),不允许默认路由到组合中的其他实例。

工作区与链操作共用冻结实例解析和当前准入检查：核对组合摘要，再按实例绑定的运行时及镜像 ID 检查目录身份、运行时可用且自检通过、镜像版本与 digest 地址一致且可用。检查请求指定的实例，不能用工作区实例的准入替代另一条链；失效时不调用能力、不登记执行活跃。执行仍使用冻结适配声明，不采用目录后来修改的命令。

部署、交易和重置持有原有单沙箱事务锁，锁内沙箱读取、目标准入、活跃更新及重建计划读取显式使用同一个事务，不另租连接；查询保持独立的读取执行流程。owner 的租户模块授权在持锁前检查，锁内再次校验当前账号归属、来源和生命周期。数据库事务不回滚外部链上的动作，执行错误仍明确返回，不能自动重发交易。

竞赛链操作由 M8 每次校验当前业务授权；M2 校验受控主体结构后直接进入同一链操作流程，在该流程内检查来源、生命周期和指定实例准入。不再预先装载工作区运行时，也不能因另一实例的镜像停用而拒绝当前链操作；操作目标失效仍须拒绝。工作区相关操作继续检查工作区实例。

竞赛主体读取详情和订阅进度只校验受控主体与沙箱来源，不要求当前目录允许执行；准备、暂停、失败和已释放状态均可观察。详情基于同一次授权读取的沙箱生成冻结能力和当前观测，进度不登记执行活跃；执行入口仍分别检查所属实例的当前准入。

沙箱摘要的 `capabilities.file_workspace`、`terminal` 只描述 `workspace_runtime_instance`，不能从其他运行时借用入口。`command_tools` 描述已选命令工具；`chain_operations` 是实例到非空操作数组的映射，例如 `{"left":["deploy","tx","query"],"right":["query"]}`，无链能力时返回 `{}`。实验与竞赛工作台直接按该映射提供实例与操作选择，不保留全局操作并集，也不显示没有链操作的实例；切换实例保留输入，只显示该实例的执行结果。

链重置与接入自检使用同一执行流程；`recreate_runtime` 停止目标账本消费者、重建该实例账本卷并重新注入已审核初始化材料，保留共享工作区和其他实例数据。控制面重建或原生重置完成后，仍须在同一有界窗口内通过声明的原生查询。已注册插件直接使用其能力接口，不依赖声明式命令字段。执行或查询失败均返回失败，不能以 Pod Ready 代替原生能力恢复。

EVM `deploy`/`tx` 的签名来源必须显式给出:外部或需保密的账户使用请求 payload 中的 `private_key` 或运行时专用 Secret;平台托管的隔离 Anvil 可使用 payload 中的 `from` 地址走节点已解锁账户。`from` 模式不得用于未受平台控制的远程 RPC,运行时接入自检使用公开的 Anvil 测试账户地址,不得把测试私钥持久化到 `adapter_spec`。

教学钱包签名完成后，工作台向选定的 Geth、Foundry 或 Hardhat 实例提交 `{"runtime_instance":"所选实例","payload":{"raw_transaction":"0x..."}}`。此模式只接受非空、完整字节的十六进制原始交易，不得混入其他交易字段；运行时原样广播、不读取签名密钥，仍须取得成功回执并受原有执行时限约束。广播错误不能自动改用平台账户重发。该流程需要用户把钱包输出填入链交易参数，不存在 iframe 自动提交。

## 6. 配额 `[学校管理员/平台管理员]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/quota?tenant_id=` | 查看配额与当前用量:校管读本租户(忽略客户端传入的 `tenant_id`),平台管理员必须显式传 `tenant_id` 指定目标租户 |
| PATCH | `/quota` | 调整配额:平台管理员在请求体传 `tenant_id`,校管只能改本租户(服务端覆写为会话租户) |

配额字段必须包含 `max_concurrent_sandbox`、`max_cpu`、`max_memory_mb`、`idle_timeout_min`、`max_lifetime_min`、`max_keepalive_min`、`max_snapshot_retention_min`。

校管只能操作会话租户：GET 忽略 `tenant_id` 查询参数；PATCH 仍按统一 JSON 规则解析请求体，提供 `tenant_id` 时必须是合法字符串 ID，解析后覆写为会话租户。平台管理员的 GET/PATCH 必须明确指定目标 `tenant_id`，缺失直接返回参数错误，不隐式落到任意租户。

## 7. 调用时序(典型:M7 实验启动)

```
M7 → M2 编译、冻结 CompositionSpec，按准确摘要完成组合准备
M7 → SandboxService.CreateSandbox(完整 composition_snapshot + 已授权主体 + scope_ref)
M2 → 返回 sandbox_id, phase=1；异步启动
前端 → 换路径票据并订阅进度
M2 → 无个性化初始化时 phase=2；有初始化时直接 phase=3，完成后 phase=4
前端 → 仅在生命周期可执行且 phase=2/4 时开放工作面；工具另验 Ready
学生 → 终端、文件、链操作与已授权工具
M3 → 按锁定规则调用链能力判分
实验结束 → M7 经内部契约按 scope_ref 回收
```
