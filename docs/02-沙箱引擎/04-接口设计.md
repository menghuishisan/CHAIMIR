# M2 沙箱引擎 — 接口设计

> 风格:RESTful + WebSocket(终端/进度)。鉴权沿用 M1 JWT。
> 接口分两类:**内部调用接口**(供 M3/M7/M8 调用,服务间鉴权)与 **用户交互接口**(供前端工作台)。
> 最后更新:2026-08-23

---

## 1. 通用约定

- Base:`/api/v1/sandbox`
- 成功响应体:`{ "code": 0, "message": "ok", "data": {} }`;错误响应体:`{ "code": 22001, "message": "实验环境准备失败,请稍后重试", "trace_id": "..." }`,错误时不返回 `data`。
- `[内部]` 接口在模块化单体内优先通过 `internal/contracts` 调用;需要 HTTP 暴露时仅走内网路由,必须服务间鉴权,并强制传 `tenant_id`、调用方模块、`source_ref` 与 trace 上下文。
- 错误码段:`2xxxx` 沙箱引擎(21xxx 运行时/22xxx 沙箱/23xxx 工具/24xxx 配额)。

## 2. 运行时与镜像管理 `[平台管理员]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/runtimes` | 运行时列表(含适配器层级、自检状态) |
| POST | `/runtimes` | 注册运行时(提交 L1 清单 + 能力实现/插件引用) |
| PATCH | `/runtimes/{id}` | 更新运行时配置 |
| POST | `/runtimes/{id}/selftest` | 触发接入即测(起链→部署→查询→重置) |
| GET | `/runtimes/{id}/selftest` | 查询自检结果 |
| POST | `/runtimes/{id}/images` | 登记镜像版本 |
| DELETE | `/runtimes/{id}/images/{img}` | 停用镜像版本并删除对应预拉取 DaemonSet |
| POST | `/runtimes/{id}/images/{img}/prepull` | 按请求中的已发布 `composition_digest` 触发该组合闭包的 DaemonSet 全节点预拉取;缺少 digest 不允许执行 |
| GET | `/runtimes/{id}/images/{img}/prepull?composition_digest=` | 查询指定组合快照的预拉取状态与节点进度 |
| GET | `/tools` | 工具列表 |
| POST | `/tools` | 注册工具定义 |

平台管理端必须按运行时和工具类型提供字段级编辑器，并由前端从受控字段生成 `adapter_spec` / `resource_spec`；不得要求管理员手写原始 JSON，也不得用空对象作为可提交默认值。编辑现有资源时，页面只提交请求契约字段，不能把 ID、自检状态等只读响应字段回传。服务端仍是最终校验边界。

预拉取请求体固定为 `{ "composition_digest": "sha256:..." }`。服务端必须确认摘要对应已发布快照、快照中每个 runtime image 与当前平台证明一致，再从快照读取完整 `image_closure`;请求不得携带运行时、工具、镜像 URL、命令或任意 WorkloadSpec。

镜像登记请求必须携带不可变 digest;Cosign 签名与 Trivy/Harbor 扫描结论由后端启动时加载的 `PLATFORM_IMAGE_ATTESTATIONS_JSON` 受控证明清单校验,请求体不得直接提交签名/扫描结论:
```json
{
  "image_url": "registry.chaimir.io/runtime/evm-hardhat@sha256:...",
  "version": "sha256-<digest-prefix>",
  "digest": "sha256:...",
  "genesis_baked": true
}
```

web-embed 与 command-tool 工具注册必须在 `resource_spec.components[].image_url` 使用带 digest 的不可变镜像引用,并逐个组件命中受控证明清单;terminal/platform-builtin 工具不得声明组件镜像。
command-tool 工具必须只声明唯一 `command` 组件,不得声明 Service、route 或网络规则;`command_policy.allowed_argv` 是完整 argv 白名单,请求数组必须逐项完全命中其中一项,不得提交 shell 字符串或追加未登记参数。
platform-builtin 工具必须在 `resource_spec.builtin_endpoint` 中声明平台端点模板,模板必须以 `/api/v1/sandbox/sandboxes/{sandbox_id}` 开头,由 M2 挂载时渲染实际沙箱 ID;此类工具不创建 sidecar,也不得落入 `/tools/{code}` HTTP 反向代理。
L2 运行时若不使用服务端注册的 `capability_impl` 或 `plugin_ref`,必须在 `adapter_spec.capability_commands` 中声明 `deploy`、`tx`、`query` 三个受控命令及各自 `exec_target=pod/container`;链不能在线恢复创世态时使用 `reset_strategy=recreate_runtime`,由 M2 重建对应 runtime 实例的计算 Pod,禁止返回固定成功值。只有生态原生提供可验证 reset 命令时才声明 `reset`。命令通过 stdin/stdout 交换 JSON。`adapter_spec.workspace_ops` 必须声明学生安全入口的 `exec_target`,`private_archive_ops` 必须声明非学生入口的解包目标;服务端不得默认选择任一 runtime 容器或学生容器承载隐藏资产。

### 2.1 编排目录 `[教师/学校管理员/平台管理员]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/catalog` | 可编排的运行时、工具和基础设施能力摘要与参数 schema |

教师编排实验环境、竞赛对抗环境和漏洞题预验证环境时要选择能力组件、参数和连接,而 §2 的管理接口是平台面(`RequirePlatformIdentity`),把它放开给教师会连带暴露 `adapter_spec` 的容器编排清单、镜像 digest 地址、`command_policy.allowed_argv` 与自检详情 —— 这些是平台运维资产,不是编排输入。故单独出一条只含编排必需字段的目录接口,由同一份 `runtime`/`runtime_image`/`tool` 数据投影:

```json
{
  "runtimes": [{ "code": "evm-hardhat", "name": "EVM Hardhat", "capabilities": ["evm.rpc"], "parameter_schema": {}, "access_profiles": ["experiment", "contest-solve"] }],
  "infra": [],
  "tools": [{ "code": "code-server", "name": "在线 IDE", "kind": 3, "capabilities": ["workspace.editor"], "parameter_schema": {}, "access_profiles": ["experiment", "contest-solve"] }]
}
```

目录只回已通过接入自检且 `status=可用` 的能力摘要;运行时镜像版本还必须满足 `status=可用`、创世状态已固化,并且该版本参与的已发布组合快照已经在目标节点预拉取成功。没有可调度组合的能力不进入目录;教师不能选到“看似可用、发布或启动时才被拒绝”的版本。目录返回运行时、工具和基础设施的 `code`、展示名、能力摘要、参数 schema、约束摘要和允许的访问配置,不返回 `tool_codes`、原始 WorkloadSpec、镜像 digest 地址、命令白名单、自检详情或生态标签本身。工具能否加入当前组合必须由 M2 组合编译器复核,不能由前端切换运行时后自动注入。平台管理端仍走 §2 的完整管理接口,不改用目录。


预拉取响应:
```json
{
  "image_id": 88,
  "composition_digest": "sha256:...",
  "prepull_status": 4,
  "desired_nodes": 6,
  "ready_nodes": 3,
  "image_count": 12
}
```

`prepull_status=2` 只表示该 `composition_digest` 的完整闭包在目标节点真实完成拉取。每次触发生成唯一 `attempt_id`,开始前锁定镜像并读取已发布快照,结束时仅允许同一 `attempt_id` 从进行中写回最终状态;期间发生运行时或组件执行契约变更时,旧尝试不得覆盖新的失效状态。失败时返回用户向提示,节点、事件与镜像拉取错误只进入日志和组合预拉取明细。

运行时接入自检使用同一批次条件写回原则:启动时锁定待测运行时镜像和当前能力证明,将运行时置为接入中并记录唯一 `attempt_id`;结束时仅允许批次一致且仍处于接入中的记录写回。并发修改执行契约、停用运行时或后发自检后,旧结果必须被拒绝,不得恢复过期配置的可用状态。

`GET /runtimes/{id}/selftest` 和自检完成响应的 `data.detail` 只返回 `result`、`stage`、`reason`、`trace_id`;`attempt_id` 仅保存在服务端用于并发写回校验,不得下发。`reason` 必须是平台已登记的用户向原因,不得携带命令输出、堆栈、连接串或 Secret。

## 3. 沙箱生命周期 `[内部]`

### 3.1 创建沙箱
`POST /sandboxes` `[内部]`
请求:
```json
{
  "composition_digest": "sha256:...",
  "init_code_ref": "minio://.../student-code",
  "init_script_ref": "minio://.../deploy.sh",
  "owner_account_id": 1001,
  "authorized_account_ids": [1001, 1002],
  "source_ref": "experiment:2026:instance:55",
  "scope_ref": "experiment:2026:instance:55:run:1",
  "access_profile": "experiment",
  "keep_alive": false,
  "snapshot_enabled": false,
  "keep_alive_minutes": 0,
  "snapshot_retention_minutes": 0
}
```
响应:`{ "sandbox_id": 9001, "phase": 1 }`

> M2 立即返回,异步推进启动阶段;前端通过 §3.2 订阅进度。
> `composition_digest` 必须来自 M2 编译器已发布的不可变快照。M2 按快照中的全部命名 runtime 实例、依赖闭包、工具、连接、资源和安全策略创建 WorkloadSpec;任何请求不得再传 `runtime_code`、`runtime_image_version`、`tools`、命令、端口或 NetworkPolicy。普通实验、解题赛、对抗赛、预验证和判题分别使用文档规定的 `access_profile`,不存在当前默认镜像或默认工具回退。
> 创建沙箱的后端调用方只能通过 `internal/contracts.SandboxService` 使用 M2,不得 import `internal/modules/sandbox` 内部包或复制 M2 校验逻辑。
> `keep_alive` 与 `snapshot_enabled` 默认必须为 `false`;只有业务需求明确要求保活或快照时才能开启。开启 `keep_alive` 必须同时提交正数 `keep_alive_minutes`;开启 `snapshot_enabled` 必须同时提交正数 `snapshot_retention_minutes`;未开启对应能力时分钟数字段必须为 `0`。调用方不得依赖隐式默认时长或上游模块私有默认值绕过 M2 配额校验。

> `authorized_account_ids` 是用户侧沙箱共享访问主体的输入集合。M2 创建事务单独写入 `owner_account_id`,并把调用方提供的正整数账号去重、剔除 owner 后写入 `sandbox.shared_account_ids`;单人、判题和预验证场景可省略。M7 小组实验必须传入当前小组全部成员;M8 跨校队伍必须由 M8 先完成参赛主体授权后传入。M2 不解析 `source_ref`/`scope_ref` 反查业务成员,也不依赖 M7/M8,从而保持模块依赖单向且不重复存 owner。

### 3.2 启动进度(WebSocket)
`WS /sandboxes/{id}/progress`
服务端校验调用账号是 `owner_account_id` 或存在于 `shared_account_ids` 后订阅 `tenant:{tenant_id}:sandbox:{sandbox_id}:progress`,禁止使用旧式 `sandbox:{tenant_id}:{sandbox_id}:progress` 主题。
浏览器原生 WebSocket 不能设置 `Authorization` 头时,前端必须先通过 M1 `POST /api/v1/auth/ws-ticket` 为该 WS path 换取短时路径绑定票据,再追加 `ticket=<ws_ticket>` 查询参数;后端校验票据路径和服务端会话,不得向沙箱 Pod 或事件 topic 透传 access token。
推送:`{ "phase": 2, "stage": "环境就绪", "message": "节点已就绪,可进入" }`
阶段:1分配环境 → 2环境就绪(可进入)→ 3个性化初始化中 → 4完全就绪。
失败推送示例:`{ "phase": 1, "stage": "准备失败", "message": "实验环境准备失败,请稍后重试", "trace_id": "..." }`。用户消息不得包含 Pod、Namespace、SQL、镜像拉取等技术细节。

### 3.3 查询 / 控制 / 销毁
- `GET /sandboxes/{id}`:状态、阶段、资源用量、工具接入地址;用户响应不得包含 Namespace、Pod、Service 等集群内部资源名。资源用量必须包含
  `cpu_usage_milli`、`memory_usage_mib`、`cpu_request_milli`、`cpu_limit_milli`、
  `memory_request_mib`、`memory_limit_mib`、`storage_bytes`;实时 CPU/内存用量来自
  Kubernetes `metrics.k8s.io` API,若集群未安装或暂不可读取 metrics-server,返回 `22031`。
- `POST /sandboxes/{id}/pause` / `POST /sandboxes/{id}/resume` `[内部]`:暂停/恢复(可选;默认空闲超时回收)。
- `DELETE /sandboxes/{id}` `[内部]`:主动销毁。
- `POST /sandboxes/recycle` `[内部]`:按 `scope_ref` 批量级联回收(来源结束时调用);`source_ref` 只作稳定身份校验,不得作为批量范围。
- `RestoreSandboxArchive` `[内部契约]`:把调用方已保存的公开代码/参战物归档安全恢复到 `workspace` 子目录。M2 必须校验对象引用属于当前租户的代码或附件桶;请求携带 `expected_hash` 时,M2 必须按对象实际内容计算 SHA-256 并逐字匹配;随后复用初始化归档安全原语重打 TAR,并只解包到调用方传入的相对目录。该能力不得用于隐藏测试、答案、flag 或判题私有资产。
- `PutSandboxPrivateArchive` `[内部契约]`:M3 注入隐藏测试、flag、答案摘要或评分脚本时只能调用该契约,目标域必须是 `judge-private`;M2 在后端用统一归档安全原语校验并重打 ZIP/TAR,拒绝目录穿越、绝对路径、Windows 盘符、重复条目、软/硬链接、特殊文件和炸弹包,随后只解包到 `judge-private` 卷域。声明 `judge-private` 的运行时不得把 `runtime_container` 标记为学生可进入容器;学生终端必须走单独 sidecar,避免隐藏资产与学生 shell 处于同一容器。该能力不提供用户 HTTP 接口,也不会触发工作区 MinIO 持久化。
- **回收事件**:沙箱因任何原因进入回收(空闲/最长生命周期/就绪超时/主动)时,M2 发布 `sandbox.recycled` 事件(eventbus,携带 sandbox_id、source_ref、scope_ref、原因),来源方(experiment/contest)订阅后同步实例状态。**用事件而非反向接口回调,避免引擎层反向依赖业务层(见工程目录设计 §3.1.1)**。

回收请求:
```json
{
  "scope_ref": "experiment:2026:instance:55:run:1",
  "reason": "source_finished"
}
```

回收必须在代码保存、快照处理、K8s 资源删除、DB 标记 `destroyed` 后才发布 `sandbox.recycled`。删除失败时不得发布完成事件。

## 4. 沙箱交互 `[用户]`

### 4.1 终端(WebSocket)
`WS /sandboxes/{id}/terminal?container=<name>`
- 后端代理 K8s exec PTY;前端 xterm.js 双向流。
- 浏览器客户端使用 M1 签发的短时 `ticket=<ws_ticket>` 建立 WebSocket;服务端完成票据路径和会话校验后只把租户/账号身份写入请求上下文,不得把 access token 传入容器环境或命令行。
- 支持多容器切换(query 指定 container),但目标容器必须在运行时声明中显式标注 `chaimir.io/student-access=true`。
- 未传 `container` 时,M2 只选择第一个显式学生入口容器;没有安全入口容器则拒绝连接。禁止默认进入运行时主容器,避免通过 shell 读取 `runtime-state`、`judge-private`、Secret 或控制面凭据。

### 4.2 文件操作
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/sandboxes/{id}/files?path=` | 列目录/读文件 |
| PUT | `/sandboxes/{id}/files?path=` | 写文件(触发防抖持久化 MinIO) |
| POST | `/sandboxes/{id}/files/save` | 立即持久化当前代码 |

文件路径必须相对 `workspace_dir`,服务端拒绝绝对路径、`..` 逃逸和符号链接逃逸。`files/save` 成功响应返回 `code_storage_key` 与 `code_hash`。文件操作接口只能访问 `workspace`,不得读取或写入 `runtime-state`、`judge-private`、Secret、隐藏测试、答案或 flag。

工作区写入使用沙箱级 `workspace_revision` 乐观并发控制:读取响应返回当前版本,写入请求必须携带 `expected_revision`;版本不一致返回冲突且不覆盖他人内容。成员授权集合变更会关闭被撤销账号在该沙箱上的终端与进度长连接。

### 4.3 Web 工具代理
`ANY /sandboxes/{id}/tools/{tool_code}/*`
- HTTP 反向代理到沙箱内工具端口(code-server/Remix/blockscout 等),iframe 嵌入。
- 浏览器首次打开工具前先调用 M1 `POST /api/v1/auth/browser-ticket`,请求 `{ "path": "/api/v1/sandbox/sandboxes/{id}/tools/{tool_code}" }`;M1 返回有效期由 `JWT_PATH_TICKET_TTL_SECONDS` 声明、绑定该路径前缀的 `ticket`。前端只把 `ticket` 放入首次 GET query,不得把 access token 放进 URL。M2 校验票据、服务端会话、用户、租户与 owner 后重新签发 access token,写入当前工具路径受限的 HttpOnly Cookie,再重定向到无 ticket 的同一路径。后续工具 HTML、静态资源、WebSocket 或 API 请求只能通过该路径受限 Cookie 经过平台代理鉴权,不得裸连 Service 或把票据、平台 Cookie、内部服务签名转发给工具容器。
- 代理必须重写同源 `Location` 到 `/api/v1/sandbox/sandboxes/{id}/tools/{tool_code}` 前缀,并把上游 `Set-Cookie` 限定到当前工具路径,避免不同工具或平台同域 Cookie 混用。

### 4.4 受控命令工具
`POST /sandboxes/{id}/command-tools/{tool_code}/run`
- 只允许沙箱 owner 调用已挂载且 Ready 的 command-tool。
- 请求:`{ "command": ["slither", "."], "stdin_base64": "", "timeout_sec": 30 }`。
- 响应:`{ "stdout_base64": "...", "stderr_base64": "..." }`。
- 后端通过 `internal/platform/k8s.Exec` 执行,不自建 K8s 客户端;只记录工具 code 和入口命令,不记录 stdin/stdout 内容。

## 5. 链上能力 `[内部]`(L2 标准能力的 HTTP 暴露)

供 M3 判分、工具浏览器使用:

| 方法 | 路径 | 对应 L2 动作 |
| --- | --- | --- |
| POST | `/sandboxes/{id}/chain/deploy` | Deploy(code) 部署合约/链码,请求体必须包含 `runtime_instance` |
| POST | `/sandboxes/{id}/chain/tx` | SendTx(tx) 发起交易,请求体必须包含 `runtime_instance` |
| GET | `/sandboxes/{id}/chain/query?runtime_instance=&target=` | Query 查账户/区块/交易/合约状态 |
| POST | `/sandboxes/{id}/chain/reset?runtime_instance=` | Reset() 指定 runtime 实例恢复创世就绪态 |

> 这四个接口是跨运行时统一的;底层由请求指定的 runtime 实例 L2 能力实现器适配(EVM JSON-RPC / Fabric SDK 等),不允许默认路由到组合中的其他实例。

EVM `deploy`/`tx` 的签名来源必须显式给出:外部或需保密的账户使用请求 payload 中的 `private_key` 或运行时专用 Secret;平台托管的隔离 Anvil 可使用 payload 中的 `from` 地址走节点已解锁账户。`from` 模式不得用于未受平台控制的远程 RPC,运行时接入自检使用公开的 Anvil 测试账户地址,不得把测试私钥持久化到 `adapter_spec`。

## 6. 配额 `[学校管理员/平台管理员]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/quota?tenant_id=` | 查看配额与当前用量:校管读本租户(忽略客户端传入的 `tenant_id`),平台管理员必须显式传 `tenant_id` 指定目标租户 |
| PATCH | `/quota` | 调整配额:平台管理员在请求体传 `tenant_id`,校管只能改本租户(服务端覆写为会话租户) |

配额字段必须包含 `max_concurrent_sandbox`、`max_cpu`、`max_memory_mb`、`idle_timeout_min`、`max_lifetime_min`、`max_keepalive_min`、`max_snapshot_retention_min`。

租户归属一律取服务端会话:校管身份下 `tenant_id` 参数不参与解析,平台身份缺失 `tenant_id` 直接返回参数错误,不隐式落到任意租户。

## 7. 调用时序(典型:M7 实验启动)

```
M7 → 编译 `CompositionSpec` → POST /sandboxes(composition_digest+access_profile+source_ref+scope_ref)
M2 → 返回 sandbox_id, phase=1
前端 → WS /progress 订阅
M2 → phase=2 环境就绪(前端放行进入,展示工具工作台)
M2 → phase=3 个性化初始化(按钮置灰)→ phase=4 完全就绪(解灰)
学生 → WS /terminal 交互、/tools/* 用工具
M3 → /chain/query 判分
实验结束 → M7 调 /sandboxes/recycle(scope_ref)
```
