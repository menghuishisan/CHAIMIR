## 1. 总体架构

组合编译和冻结装载共用网络校验：每次只构建一份完整端口拓扑，供所有运行时和工具校验目标及传输协议；不按工具重复构建整个组合，也不保存跨请求缓存。

```
┌─────────────────────────────────────────────────────────┐
│  调用方:M7 实验 / M8 竞赛 / M3 评测                          │
│  调用:创建沙箱(组合快照, 访问配置, 生命周期范围)              │
└───────────────────────────┬─────────────────────────────┘
                            │ (统一 API)
┌───────────────────────────▼─────────────────────────────┐
│  M2 控制面(Go,client-go / operator)                      │
│  ┌──────────┬──────────┬──────────┬──────────────────┐  │
│  │ 运行时    │ 沙箱      │ 工具接入  │ 持久化/回收        │  │
│  │ 适配器    │ 编排器    │ 网关      │ 调度器            │  │
│  └────┬─────┴────┬─────┴────┬─────┴────────┬─────────┘  │
└───────┼──────────┼──────────┼──────────────┼────────────┘
        │          │          │              │
┌───────▼──────────▼──────────▼──────────────▼────────────┐
│  Kubernetes 数据面(SaaS:K8s / 私有化:k3s)               │
│  每沙箱 = 独立 Namespace + Pod(s) + NetworkPolicy        │
│  Harbor 镜像仓库(DaemonSet 预拉取) + S3 对象存储(代码持久化)   │
└─────────────────────────────────────────────────────────┘
```

**四个控制面组件:**
- **运行时适配器**:管理"什么链",三层粒度(见 §3)。
- **沙箱编排器**:创建/管理 K8s 资源,执行分层启动(见 §2)。
- **工具接入网关**:终端代理、Web 工具反向代理(见 §4)。
- **持久化/回收调度器**:代码持久化、状态重建、空闲回收(见 §5)。

M2 service 拥有异步启动和防抖保存的进程内生命周期：受理时在同一锁内登记任务，退出时关闭登记并用标准库 `sync.WaitGroup` 等待已登记工作完成。组合根按[部署退出顺序](../总-部署架构设计.md)等待入口、周期回调和事件处理器退出后，才调用 `Service.Close`；最终保存与失败事件发布完成前保留事件及数据连接。部分装配失败同样释放已创建的 service。启动、回收和防抖保存的操作失败与失败状态或诊断事件写入失败共同返回；恢复扫描与关闭等待保留两类原因，不能只记录补偿错误后将其丢弃。失败状态事务提交成功后才广播进度和业务事件，失败业务事件的发布错误也返回；已失去状态或租约归属时不改写其他执行者。周期回收在恢复、自检、候选回收和快照清理的阶段与记录之间响应取消，停止尚未开始的任务、资源操作及独立失败写回；空批次也返回取消原因，并保留此前阶段失败。已开始的补偿沿用原有界预算，未处理记录留给后续扫描。已受理启动不随发起请求断开而取消，仍受既有就绪和持久化预算约束；退出后新建的持久化启动记录由原恢复扫描接续，不另建内存任务队列。关闭不删除业务记录或 Kubernetes 资源，执行、失败补偿与回收仍由原状态机及租约控制。

`service_k8s_namespace.go` 集中管理 Namespace 的创建、归属核对、按版本删除和自检补偿；资源物化继续由编排器负责。创建与删除复用同一份不可变归属标签，删除不依赖当前目录准入或安全策略标签。

Pod 创建响应和已有对象复用执行同一核对：名称、命名空间、UID、未删除状态、归属标签及完整执行规格必须成立。比较在副本上归一化官方等价默认值，仅排除调度器分配的节点、RuntimeClass 注入的开销和兼容账号字段；网络、进程命名空间、凭据、调试容器与调度规则不能被遗漏。镜像拉取凭据显式写入 Pod，不依赖 ServiceAccount 的隐式补齐。

启动依赖、运行时重置、资产写入与工作区归档共用就绪等待：固定创建或复用响应的 Pod 身份及执行规格；状态轮询允许正常 resourceVersion 变化，拒绝同名替换、规格或归属变化、删除中及已终止对象，不借用其 Ready 条件继续后续操作。

Service 的创建响应与复用也核对完整声明，只忽略服务器分配的集群地址与地址族，并归一化等价默认值；外部地址、无头服务、未就绪端点发布、会话亲和及流量策略变更不能被接受。

### 1.1 组合编译器与连接图

运行时主容器和附加容器各有唯一执行声明，`pods[].containers` 只按名称引用；默认拓扑与显式拓扑使用同一规则。参数和连接注入后，冻结、预拉取与启动均从该声明解析容器，不复制一份执行配置到 Pod 中再分别更新。

引用按完整结构校验，除名称和空集合外，不接受任何执行字段；密钥、卷写权限、自检用途或探针中的独立字段同样拒绝，不能在解析引用时静默丢弃。

M2 提供唯一的 `CompositionSpec` 编译器,供 M7 实验、M8 解题赛/对抗赛和 M3 私有判题环境复用。调用方提交声明式组件和 `access_profile`,M2 完成能力约束、依赖展开、参数校验、连接图校验、资源汇总、NetworkPolicy 生成和镜像闭包计算,然后返回可审阅的编译结果及诊断信息。

每个环境必须指定一个或多个带唯一 `instance_code` 的 runtime 实例;工具和基础设施不能隐式替换或创建 runtime。一个业务定义可以包含多个环境,但环境间只能通过显式类型化 `links` 连接。连接至少声明源/目标组件及端点、协议、是否为启动前置条件、访问范围和配置绑定;未声明的互访、代理、端口、Secret 和外网出口一律拒绝。连接图存在环、端点不存在、协议不匹配、权限超出访问配置或资源超额时,编译失败。

组合编译有且仅有以下状态链:草稿声明、校验通过、发布锁定、按 digest 启动、按生命周期范围回收。发布快照包含完整组件闭包、连接图、访问配置、资源/网络策略和镜像 digest;启动和恢复只能使用该快照。运行时能力身份同时冻结`adapter_level`、`capability_impl`和插件实现引用`plugin_ref`；状态观察按快照投影能力,实际执行还须比对当前目录身份与准入,不能从当前目录补出未冻结的插件引用。所谓高级视图只读展示编译后的部署详情,不能直接编辑原始 WorkloadSpec 或镜像运行参数。

访问配置固定为:

| 配置 | 用途 | 学生权限 |
| --- | --- | --- |
| `experiment` | 实验交互环境 | 按实验成员开放工作区、终端和已授权工具 |
| `contest-solve` | 解题赛答题环境 | 从 M5 锁定题目版本派生,不接受学生提供镜像或初始化参数 |
| `contest-battle` | 对抗赛正式匹配环境 | 系统私有,参赛者只获得题目规定的受控入口 |
| `vulnerability-prevalidate` | 漏洞题作者预验证/固化 | 仅作者和平台服务可用,外网仅限白名单预验证阶段 |
| `judge-private` | M3 判题执行 | 仅判题服务可用,答案、flag、隐藏测试和判题配置不向学生挂载 |

该编译器是最终实现口径,不得并行保留按 `eco_tags` 推导工具、运行时默认工具、业务模块自建组合器、原始 WorkloadSpec 编辑器或旧请求字段的兼容路径。

## 2. 机制一:分层启动优化

**目标**:简单实验 ≤5s 可用,复杂多节点 ≤15s。不做预热池(见 §2.4)。

### 2.1 三层优化

| 层 | 优化 | 消除的等待 |
| --- | --- | --- |
| L1 镜像层 | DaemonSet 全节点预拉取镜像 | 拉镜像的几十秒 |
| L2 链状态层 | 镜像内固化创世状态(创世块/账户/已编译依赖) | 现场初始化链的时间 |
| L3 个性化层 | 基础环境与个性化初始化分阶段反馈 | 及时展示进度；初始化完成前保持执行门禁 |

### 2.1.1 镜像预拉取闭环

自检身份包含镜像、完整命令、常驻用途和临时挂载集合。只有四者相同才能去重，挂载声明顺序不影响身份；不同挂载环境必须分别执行，不能合并目录后以一次执行替代。主运行时、辅助组件和私有判题容器共用此规则，主容器的挂载与常驻用途必须完整进入快照消费和失效比较。

闭包内每项自检均由普通 initContainer 执行，包括各运行时声明的保持镜像。全部自检成功结束后，才使用首个保持镜像启动只执行 `sleep` 的保持容器；不得把未结束的自检放在无就绪探针的普通容器中。每个 runtime 仍须声明且只能声明一个保持 sidecar；多 runtime 组合允许多个保持候选，不能因不同运行时使用不同保持镜像而拒绝整个闭包。各项自检的工作区、临时目录和额外挂载使用独立 emptyDir，不能通过前项自检的文件残留影响后项结论。

预拉取 DaemonSet 创建或更新的受理响应必须与本次请求的完整执行规格一致：覆盖选择器、模板标签与完整摘要、Pod 安全/调度/容器/卷配置、更新策略及就绪等待。只允许 Kubernetes 等价默认值，模板中的固定节点和资源开销仍须比较；受理响应改变或删除自检时直接失败，不能以随后该对象报告 Ready 作为成功证据。

沙箱 Namespace、资源配额、默认资源限制和网络策略在首次创建及重试复用时共用受理校验：名称、命名空间、UID、非删除状态及管理标签均须有效；资源配额、限制和网络策略须匹配请求规格，Namespace 须保留本次声明的清理期限。创建成功本身不能代替对这些保护边界的核验。

镜像预拉取由 M2 控制面使用 Kubernetes API 创建受控 DaemonSet 完成,不能只更新数据库字段。`sandbox_composition_prepull.status=2` 的含义是指定 `composition_digest` 快照的完整镜像闭包已在目标沙箱节点就绪,不是只拉取运行时主镜像,也不是按生态标签批量拉取工具。`runtime_image` 本身不再承载组合级预拉取状态。

执行规则:
- 预拉取资源运行在平台受控命名空间，命名为 `chaimir-prepull-{runtime_image_id}-{composition_digest前16位}`；标签标明平台、模块、管理者、镜像编号及摘要前缀，`chaimir.io/composition-digest` annotation 保存完整摘要。同名资源必须核对归属与完整摘要，禁止覆盖其他对象或前缀碰撞的组合。
- DaemonSet 使用冻结组合快照中的全部 runtime 实例、显式基础设施、依赖自动展开的基础设施、显式工具及其 init/sidecar 镜像启动短生命周期容器,`imagePullPolicy=IfNotPresent`,资源限制使用平台配置的预拉取 requests/limits。
- 目标节点默认为全部可调度沙箱节点;如部署配置声明 sandbox node selector/toleration,预拉取必须使用同一选择器。
- M2 轮询 DaemonSet 状态,仅当控制器已观察当前 `generation`、`desiredNumberScheduled == numberReady == numberAvailable == updatedNumberScheduled`、`numberUnavailable=0`、`numberMisscheduled=0` 且无拉取失败事件时,才写指定 `sandbox_composition_prepull` 记录为已完成;旧模板残留的 Ready 数字不得作为新闭包证明。
- 更新绑定已读取的 UID 和 resourceVersion，创建或更新响应的 UID、generation 与执行规格固定为本轮等待目标；轮询发现替换、规格变化或正在删除时失败，不借用另一对象的就绪证明。Pod 失败仅归入 controller ownerReference 指向该 DaemonSet UID 的任务。
- 任一节点出现 `ImagePullBackOff`、签名校验失败、调度失败或超时,必须写 `sandbox_composition_prepull.status=3` 与 `detail`,并返回/记录可定位错误;禁止吞错或保留成功标记。
- `sandbox_composition_prepull.detail` 必须记录本轮组合快照 digest、镜像数量和镜像 URL 列表,用于验收确认组合闭包中的工具/infra 镜像没有在沙箱启动时临时拉取。
- 预拉取成功后保留 DaemonSet,用于新节点加入时自动补拉;运行时镜像停用或删除时由 M2 删除对应 DaemonSet。
- 编排器仅在节点进度变化时向服务层回报，服务层按当前尝试条件写入既有记录，供 GET 读取真实进度；写入失败中止等待，撤销后的尝试不能再更新。
- 停用清理只列出平台管理且属于该镜像的 DaemonSet，全部目标先核验完整摘要、名称及删除身份，再按 UID/resourceVersion 回收；冲突保留错误供重试，NotFound 为幂等成功。
- 部署期 seed 只负责幂等同步运行时、工具和能力声明。实际执行契约未变化时必须保留自检/可用状态;组合快照或其镜像闭包未变化时必须保留预拉取状态。能力约束、镜像 digest、自检命令、常驻用途、临时目录、连接或安全策略变化必须使受影响组合快照失效;名称等展示字段不得触发重拉。
- `SANDBOX_PREPULL_TIMEOUT_SECONDS` 必须覆盖最慢目标节点顺序拉取完整镜像集合并执行全部自检命令的冷启动时间,不能按单个镜像估算。生产基线为 900 秒,`HTTP_WRITE_TIMEOUT_SECONDS` 必须在此基础上保留响应余量;超时只允许标记本轮失败,不得删除仍在补拉的新节点 DaemonSet。

### 2.1.2 接入即测清理边界

运行时接入即测会创建独立自检沙箱。执行预算统一由 `SANDBOX_SELFTEST_TIMEOUT_SECONDS` 覆盖资源准备、私有初始化清理、全部声明命令与原生能力验证;资源清理另用 `SANDBOX_SELFTEST_RECYCLE_TIMEOUT_SECONDS`,终态写回另用 `SANDBOX_READY_TIMEOUT_SECONDS`。三段使用各自有界 context并保留 trace/tenant,请求断开或前一段耗尽不能取消后续清理/写回。`HTTP_WRITE_TIMEOUT_SECONDS` 必须严格大于三段预算之和。资源准备、私有初始化、命令、原生能力、清理和终态写回分别记录阶段、耗时、剩余预算、运行时/沙箱/命名空间与实际exec目标,不记录完整argv、脚本或凭据;预算耗尽后不再启动下一项。Pod就绪轮询严格使用 `SANDBOX_READY_POLL_INTERVAL_SECONDS`,不在代码中压缩为200ms。清理失败必须保留完整错误链及可排查 Namespace,本次自检不能通过。

### 2.2 两阶段启动(关键)

基础环境完成后，无个性化初始化的组合发布 `phase=2`；有初始化的组合直接进入 `phase=3`，完成后发布 `phase=4`。初始化期间可观察进度，工作面不可操作。生命周期、资源租约与工具就绪共同决定入口权限，具体转换由[状态机](05-业务流程与状态机.md#1-分阶段启动流程)定义。

### 2.3 分阶段进度反馈

前端进度条分明确阶段:`分配环境 → 启动节点 → 加载链状态 → 就绪`(阶段二再显示 `初始化依赖…`)。每阶段有文案,学生不焦虑。

### 2.3.1 异步启动调度

内部创建契约（HTTP 为 `POST /internal/sandboxes`）只完成参数校验、配额占用、DB 记录创建与启动任务提交,随后立即返回 `phase=1`。启动任务由 M2 内部调度器推进,并把每一步写入 `sandbox_event` 与进度 WS。

启动任务必须闭环:
- 创建 Namespace、ResourceQuota、LimitRange、NetworkPolicy、PVC 与 Pod 组任一步失败,沙箱进入 `error`,释放已占配额,写明失败阶段到日志与 `sandbox_event`。
- 阶段一超时进入 `error` 并触发回收,前端用户文案只显示"实验环境准备失败,请稍后重试"及 `trace_id`。
- 阶段二个性化初始化失败保留失败 `phase` 并统一置为 `error`，工作面不可进入；失败明细进入 `sandbox_event` 和日志，使用同一 `sandbox.failed` 事件通知来源。来源沿已有重建入口恢复已保存的代码和进度，不自动重放私有脚本或放宽阶段门禁。

### 2.4 启动优化边界

不建设预热池，不在数据模型和接口保留池化占位。个性化初始化、多租户公平性和突发负载由上述三层优化、配额与有界调度处理；是否达到启动目标须用真实组合计时验证。

## 3. 机制二:运行时三层适配器

**目标**:标准链零代码接入,接入时完成真实能力验证。

### 3.1 三层粒度(定制量从外到内递减)

```
L1 声明式清单(YAML,零代码)        ← 大多数 EVM 兼容链只需这层
   镜像 / 启动进程 / 端口 / 资源配额 / 健康检查 / 能力声明
        │
L2 标准能力接口(实现 4-5 个动作)    ← 非标准链需实现
   部署合约 / 发交易 / 查账户·区块·交易 / 重置链
   (EVM 用 JSON-RPC,Fabric 用 SDK,各链自实现)
        │
L3 深度定制插件(可选)              ← 极少数特殊机制链才写
   特殊共识数据采集 / 特殊交互
```

### 3.2 L2 标准能力接口(刻意最小化)

平台只定义最小动作集,降低每条链接入成本:

| 动作 | 用途 | 消费者 |
| --- | --- | --- |
| `Deploy(code)` | 部署合约/链码 | M7 个性化初始化、M3 判分 |
| `SendTx(tx)` | 发起交易 | 工具、M3 |
| `Query(target)` | 查账户/区块/交易/合约状态 | M3 链上断言、区块链浏览器工具 |
| `Reset()` | 链恢复到创世就绪态 | 沙箱重用、重建 |

> 接口仅包含 M3 判分和工具所需的统一链上操作。

### 3.3 接入即测(堵住"宣称支持"的坑)

每个适配器必须附带**自检套件**,接入时自动跑:

```
起链 → 部署样例合约 → 查询验证 → 重置 → 通过判定
```

镜像/WorkloadSpec 基础自检全绿即可标记该运行时镜像“可部署”；若原生 `deploy`/`tx`/`query` 闭环未完成，只关闭对应动作并在能力面明确显示“动作待接入”。它仍可作为节点、RPC、peer 或 REST 能力提供者参与组合。只有动作自检全绿才开放平台原生动作，不能把动作门禁扩大成镜像全局禁用。

### 3.4 L1 声明式清单(adapter_spec)口径

> `runtime.adapter_spec` 是 **控制面直接执行的 SSOT**。字段必须稳定、显式,禁止运行时实现各自发明隐式约定。
> 运行时、工具、判题和后端计算复用统一的 WorkloadSpec 字段语义:组件(component)、服务(service)、路由(route)、卷域(volume domain)、资源(resources)、探针(probe)和网络规则(network rule)。M2 只消费沙箱类 WorkloadSpec,不得把 M3/M4 的执行器私有协议硬编码进沙箱模块。

字段约束:
- `workspace_dir`:沙箱公开代码工作目录。文件接口、授权工具和初始化脚本生成的公开产物使用该目录;初始化脚本原文不得写入该目录。
- `workspace_runtime_instance`:组合显式指定的工作区运行时实例。文件、终端、共享工作区 PVC 和初始化脚本均使用该实例声明的 `workspace_ops`,其中学生操作走 `exec_target`,私有脚本只走独立的 `script_exec_target`,不得按运行时数组顺序隐式选择。只有共享工作区要求跨实例契约一致，其余域由各实例独立声明。
- 运行时资源命名:实例标识遵守 Kubernetes DNS 标签约束。目录编码最长 64 字符，自检实例沿同一摘要截短规则生成合法标识，目录身份不变。派生 Pod、内部 Service、卷名限制在 63 字符内,超长部分使用完整原名的摘要区分;重复物化不得改变冻结名称,执行目标和网络规则必须同步指向该名称。实例化只修改返回值，不改写输入清单的 Pod、网络规则或启动顺序；同一清单可独立生成多个实例。不同实例或组件产生同名 Pod 时在编译或资源操作前拒绝,不能让后创建者复用前者。
- 工具 Pod 使用沙箱归属和唯一 `pod-role` 标签，Service 与网络策略沿同一角色选择；不重复写入没有消费者的工具编码和组件标签，避免 64 字符目录编码超出标签限制。
- `volume_domains`:沙箱卷安全域声明。M2 必须按安全域分别创建和挂载卷,禁止把运行态、判题私有数据或教师答案混入 `workspace`。
  - 首次分配允许创建空 PVC；恢复先核对所有未纳入已提交快照的保留卷，再创建缺失快照卷。缺失保留卷或删除中的 PVC 必须失败，不新建空卷、不重放首次初始化来掩盖数据丢失。PVC 创建响应及保留对象须核验名称、命名空间、UID、管理标签和完整卷规格；仅允许文件系统模式默认值、未显式指定的存储类及绑定卷名。新建卷必须保留本次快照来源，等价的 `dataSource`/`dataSourceRef` 可互相补齐，来源不一致或跨命名空间改变必须拒绝。保留卷（含并发创建后已存在的卷）只读核对归属与规格，不修改其原始快照来源。
  - CSI 快照的首次创建与重试复用均须核验对象身份、来源规格和保留策略；就绪轮询绑定已受理的 UID，继续核对归属与规格后才检查内容双向绑定。未指定快照类时允许控制器选择默认类，首次观察到类名后固定该选择；控制器补齐规格导致的代次变化本身不视为替换。被替换、删除或改变来源的同名快照不能提交为成功。失败只清理本轮新建且身份已确认的对象，删除条件固定为原 UID，不清理复用快照或同名替代对象。
  - `workspace`:学生代码工作区,允许文件接口和授权工具读写;对象存储只持久化该域。
  - `public-assets`:公开题面素材或公开依赖,只读挂载给学生可进入容器。
  - `runtime-state`:链节点数据库、账本、缓存、共识状态等运行态。默认临时卷,学生文件接口不可见;仅 `snapshot_enabled=true` 且通过配额/能力校验时才纳入 CSI VolumeSnapshot。
  - 同一所有者的域由多个 Pod 使用时，M2 使用该所有者独立 PVC；统计包含初始化容器，同一 Pod 内的容器仍可共享临时卷。不同所有者的同名域互不共享。每个 Pod 只声明实际挂载的卷，不附带其他 Pod 的 PVC 或缓存。默认使用 `ReadWriteOnce`，不假定集群具备 `ReadWriteMany`。
  - PVC 消费者按当前命名空间、沙箱编号和受控消费者标签要求共节点；首个消费者匹配自身，后续消费者跟随，不固定等待另一个运行时 Pod，避免与启动依赖相互阻塞。只使用临时卷的 Pod 不加入该调度组。采用 [Kubernetes 自亲和调度规则](https://kubernetes.io/docs/concepts/scheduling-eviction/assign-pod-node/#scheduling-a-group-of-pods-with-inter-pod-affinity-to-themselves)，不自行选择或保存节点。
  - `judge-private`:隐藏测试、flag、答案、评分脚本、教师私钥等私有域,永不挂载到学生可进入容器,也不允许被终端、IDE、Web 工具间接读取。
  - `student_access` 仅允许 `none`、`read_only`、`read_write`;学生可进入容器只能挂载 `read_only/read_write` 域,且文件 API 永远只以 `workspace_dir` 为根。
  - `snapshot_scope` 仅允许 `never`、`always`、`snapshot_enabled`;默认重建路径不得依赖 `runtime-state` 快照。
  - `object_storage_code` 只允许用于 `workspace`；`persistence=snapshot` 不得同时声明 `snapshot_scope=never`，避免承诺持久化却没有保存路径。私有判题域仍不得进入快照。
  - 登记表单禁用与当前卷域不相容的保存选项；未填写完整或策略矛盾的行须提示并阻止提交，不能通过过滤空名称静默丢弃编辑内容。最终校验仍由服务端执行。
 - `runtime_container`:运行时主容器。镜像地址来自 `runtime_image.image_url`,此处只声明**如何启动与探活**。主容器默认不是学生终端目标;只有显式声明 `labels["chaimir.io/student-access"]="true"` 且不挂载 `student_access=none` 卷域时,才允许作为 `terminal?container=` 目标。平台通用运行时主容器不挂载 `judge-private`;M2 的隐藏归档注入固定由显式声明的非学生归档 sidecar 执行,并由 `private_archive_ops.exec_target` 指向该 sidecar。若某个 runtime manifest 额外声明自身需要写入 `judge-private` 的组件,该组件仍必须保持非学生入口并显式声明写权限;判题命令如声明独立 judger sidecar,该 sidecar 必须显式只读挂载同一 `judge-private` 域;需要学生 shell 时必须使用单独的学生入口 sidecar。
- `infra_sidecars`:运行时自带的协同容器(如 graph node、Chainlink node 等真实链下组件),由运行时 manifest 显式声明。教师脚本、题目固化资产或链上依赖合约即可表达的轻量模拟能力应放入 `init_assets` 或初始化脚本,不作为平台必需模拟服务镜像。协同容器可为无端口执行类 sidecar,但必须仍声明资源、安全标签和预拉取自检命令。
- `infra_sidecars[].labels["chaimir.io/student-access"]`:只有显式为 `"true"` 的协同容器才允许作为 `terminal?container=` 目标;未声明或为 `"false"` 时只能由平台控制面/工具代理按端口访问,不得开放学生 shell。学生可进入容器只能挂载 `student_access=read_only/read_write` 的卷域,不得挂载 `runtime-state`、`judge-private`、Secret 或控制面凭据。
- `infra_sidecars[].prepull_command`:该 sidecar 镜像的预拉取自检命令,必须来自对应 `images/<category>/<name>/manifest.yaml` 的 `selftest.commands[0].command` 或同等受控声明。不得复用运行期 `command` 冒充自检;缺失时组合预拉取不得标记为完成。
- `infra_sidecars[].prepull_hold`:标记该 sidecar 镜像是否可用作预拉取 DaemonSet 的常驻保持容器。每个 runtime 实例必须且只能有一个 `prepull_hold=true` 的 infra 镜像；工具镜像不得声明保持用途。闭包内所有镜像的 `prepull_command` 均在 initContainer 中真实执行；全部成功后只使用首个候选镜像常驻，多实例不要求保持候选相同。
- `pods`:声明一个 runtime 实例的 Pod 组。未声明时,M2 按 `runtime_container + infra_sidecars` 生成单 Pod 拓扑;声明后,M2 逐个创建 Pod,等待组合中所有 runtime Pod Ready 后才进入阶段二。`pods[].containers[].name` 必须引用本清单中的 runtime 主容器或协同容器声明;runtime 主容器仍以对应 `runtime_image.image_url` 为唯一镜像来源,不得在 `pods` 中重复写 `image_url`;协同容器必须声明带 digest 的 `image_url` 并命中签名/扫描证明。每个 Pod 内容器名和容器端口必须唯一。校验与编排共用同一拓扑展开函数，展开引用、补充容器与实例名称不得改写原声明。
- `services`:声明组件的集群内 Service,用于工具、infra、运行时 RPC 和受控代理访问。Service 名遵守 DNS-1035 标签约束，在同一沙箱内必须唯一，包含运行时派生入口与全部工具、基础设施入口；`component` 必须引用已声明组件或 Pod,`target_port` 优先引用端口名，传输协议必须与目标容器端口一致，省略时均为 TCP。组合编译、冻结装载和资源创建共用 Service 清单生成规则，统一检查名称、目标及端口；非法清单须在创建 Namespace、卷或初始化资产前拒绝，不留运行时与工具两套创建路径。
- `routes`:声明平台代理入口。运行时通常为空;Web 工具可声明多个 path prefix 到不同组件,例如 `/api` 到 backend、`/` 到 frontend。按路径段匹配最长前缀，与声明顺序无关，`/api` 不匹配 `/apix`；转发保留工具相对路径和查询参数，不剥离所选路由前缀。前缀只表示绝对路径，不含查询或片段，不得重复；Web 路由只能引用 TCP Service 端口，没有匹配项时拒绝访问。路由只生成平台代理可达入口,不暴露直连 Service。
- `network_rules`:声明同一沙箱内不同组件或 Pod 之间的最小网络互通。默认 deny-all 下,组件之间也不可互访;只有这里显式声明 `from`、`to` 和目标端口名/端口号时,M2 才生成对应 ingress/egress NetworkPolicy。规则只能引用已存在组件/Pod 和目标已声明端口,禁止用空端口、通配或整命名空间互通表达。
  运行时和工具的连接目标从完整组合的真实 Pod 及端口解析，支持运行时连接基础设施。所有有工作负载的工具和基础设施均按声明生成双向策略，包括无 Web 入口的 command-tool；网络准入不能由是否提供 iframe 决定。
  连接地址使用目标 Service 的名称和入口端口，网络规则使用其 `target_port` 指向的容器端口；两者的名称和数字可以不同。清单中的命名网络端口在编译及冻结装载时共用解析规则，生成策略前必须解析为目标 Pod 已声明的容器端口，不得仅验证名称后仍使用未解析的数字。
  组合连接仅支持 `TCP`、`HTTP`、`HTTPS`、`WS`、`WSS`、`GRPC`，其他协议在编译阶段拒绝；不能因两端声明相同协议就接受当前连接模型无法表达的传输。
- `init_assets`:初始化归档随组合快照冻结来源、安全域及必填 `expected_sha256`。运行时清单内的素材归属该运行时实例，不重复声明实例字段；教师在组合中追加素材时必须指定 `target_runtime_instance`。平台素材由平台审核，存于受控代码或附件桶的 `0/` 前缀，平台自检与租户组合均可按冻结摘要读取；教师追加素材只能引用本租户前缀。普通工作区恢复和初始化脚本仍只读本租户对象。首次启动及链重置时，M2 校验实际内容摘要并重打安全归档，经独立非学生资产 Pod 写入所属实例的 `runtime-state` 或 `public-assets`，回收后才启动消费者；不得包含密钥、答案或 flag，不进入镜像层、workspace 或学生素材引用投影。示例桶名由环境配置替换。
- `ports[].name`:同一清单内唯一,探针与能力实现按名称引用,禁止写死数字端口。
- `resources`:缺失时回退到系统默认 `LimitRange`;声明时必须同时给 `requests` 与 `limits`。
- `readiness_probe` / `liveness_probe.type`:仅允许 `tcp` / `http` / `exec` 三种,避免运行时私有探针语义。
- `readiness_probe` / `liveness_probe` 未声明 `period_seconds` 或 `failure_threshold` 时,默认值必须来自 `SANDBOX_PROBE_DEFAULT_PERIOD_SECONDS` 与 `SANDBOX_PROBE_DEFAULT_FAILURE_THRESHOLD`,不得在编排代码中硬编码。
- `workspace_ops`:声明文件读写、目录浏览、归档、终端和工作区自检命令,通过 `exec_target=pod/container` 指向显式学生入口容器。目标必须挂载工作区且不能读取运行态、私有判题域或 Secret。`run_script` 和开放前的 `clean_workspace` 单独通过 `script_exec_target=pod/container` 指向非学生 `init-script` 容器,从 stdin 接收脚本,在独占 `/tmp` 中执行和清理,仅共享公开工作区产物;不与学生容器共享进程命名空间或临时目录。平台runtime自检也必须实际执行私有清理命令,不能只用学生helper自检证明支持新契约。M2 不允许缺失声明时回退到任一 runtime/学生容器。
  - `selftest`:接入即测的最小样例参数。L2 自检统一执行“起链 → deploy → query → reset”;如该链需要额外 `tx` 校验,可补 `tx_payload`。Bitcoin 等非合约生态的 `deploy` 必须映射为该生态真实、可验证的可部署对象,例如 regtest 脚本模板或钱包策略,不能返回伪造合约地址;不具备合约模型的生态必须声明等价的原生可部署对象和验证查询,不能只填版本探活命令。
- `capability_commands`:声明式链能力命令集合。L2 按 `capability_impl`、L3 按必填 `plugin_ref` 解析服务端注册表；L2 未指定实现时由完整声明确定内置 `sandbox-exec`，此实现始终要求完整命令。执行目标必须是包含对应生态原生适配器的非学生入口，stdin/stdout 交换 JSON，底层错误只进入日志。动作、默认超时和按实例重建账本的规则统一见[接口设计](03-接口设计.md) §2；禁止用占位命令或固定成功值代替真实能力。
- `startup_order`:只保存 `required_at_start=true` 连接涉及的组合组件编码，按依赖拓扑排序；编码不随运行时内部 Pod 名称物化。未参与的组件先创建，不加入依赖就绪等待。运行时实例或工具的全部 Pod 作为一组创建，再一起检查就绪，不能等待同组尚未创建的节点。依赖组失败时不启动后续组；创建与链重置共用此规则。循环依赖直接拒绝发布。
- `runtime_container.prepull_command`:每个 runtime 实例镜像的真实最小自检,只证明该镜像内节点/工具链可启动;工作区 helper 和其他协同镜像分别使用自身组件的 `prepull_command`。接入即测仍必须在真实沙箱中继续执行工作区和 L2 原生能力,二者不能互相替代。

### 3.5 运行时原生能力执行契约

运行时 manifest 的 `runtime.native` 是 L2 能力的唯一装配来源。每个 `adapter_level: 2/3` 的运行时必须同时声明以下字段:

```yaml
runtime:
  eco: <manifest-eco>
  adapter_level: 2
  native:
    helper: /usr/local/bin/<runtime-native-helper>
    profile: <runtime-native-profile>
    exec_target: sandbox/runtime
    reset_strategy: recreate_runtime
    actions:
      deploy: [/usr/local/bin/<runtime-native-helper>, deploy]
      tx: [/usr/local/bin/<runtime-native-helper>, tx]
      query: [/usr/local/bin/<runtime-native-helper>, query]
```

- `helper` 必须是运行时镜像内实际存在的原生 CLI/RPC 适配器,不是学生工作区镜像中的通用占位命令; `exec_target` 必须显式指向包含该 helper 和原生节点工具的非学生容器。
- `profile` 是该生态的原生可验证对象定义,必须在 helper 中实现 `deploy`、`tx`、`query` 三个动作。合约生态使用真实合约/链码/Move 包;不以合约为核心的生态使用该链原生可查询对象,并在 manifest 说明对象类型,不得只执行版本或健康探针。
- `reset_strategy: recreate_runtime` 表示由 M2 重建请求指定的运行时计算 Pod 并保留工作区 PVC。目标实例从业务请求显式传到编排器，自检显式传入本次被测实例；缺失或不存在的目标必须在资源操作前拒绝，不得默认重置整个组合。此时 `capability_commands` 不得生成伪造的 reset 命令。
- 业务调用和接入自检共用重置流程：控制面重建或调用已注册能力的 `Reset`，随后以声明的 `selftest.query_target` 等待原生查询就绪；重置与查询共用一个就绪超时窗口。插件不要求重复声明本地 reset 命令。参数或配置无效时不执行重置，重置或复验失败不能返回成功。查询就绪只证明能力恢复，账本创世状态还必须另行验证。
- 重置前先生成完整重建配置，生成失败时保留现有节点。创建、依赖启动和重置复用同一 Pod 就绪检查，逐轮检查全部目标，任一 Pod 明确失败即返回其原因，不能被排在前面的未就绪 Pod 遮蔽到超时。
- helper 通过标准输入接收 JSON、通过标准输出返回 JSON;私钥、助记词、签名原文和运行态配置只能留在 `runtime-state` 私有域,禁止出现在响应、工作区、日志或学生可访问容器。
- 能力命令 stdout 必须是单个 JSON 对象；空输出、`null`、非对象及多个 JSON 值均视为协议错误，不补造空对象作为成功结果。
- 动作超时只在接入校验时补齐平台配置并冻结；执行器直接使用已确认的正数超时，缺失或非法时拒绝执行，不另设默认值。
- 迁移装配时若 `adapter_level: 2/3` 的 helper、profile 或显式执行目标缺失,只关闭平台原生动作并记录动作门禁原因；镜像本身仍按基础 WorkloadSpec 门禁决定是否可部署。不能以查询成功、镜像已拉取或 Pod Ready 冒充动作能力证明。

## 4. 工具接入协议

**目标**:工具可插拔,不绑定单一 IDE。终端复用 K8s,不自研。

### 4.1 工具类型

| 类型 | 接入方式 | 例子 |
| --- | --- | --- |
| `terminal` | K8s exec PTY + WebSocket 代理,只能进入显式学生入口容器 | 命令行终端 |
| `web-embed` | HTTP 反向代理 + iframe 嵌入 | code-server、Remix、区块链浏览器、Jupyter |
| `command-tool` | 无端口工具 Pod + 受控 argv 执行接口 | Slither、Mythril、gas-profiler |
| `platform-builtin` | 平台直供,无需额外镜像 | 文件管理、日志、状态面板 |

### 4.2 工具声明(可插拔)

每个工具声明:`类型 + WorkloadSpec + 适用链生态`。新增工具 = 加一份工具定义,平台代码不改。工具表不再单独保存镜像或端口字段;单组件工具也必须在 `resource_spec.components`、`services` 和 `routes` 中声明入口,避免单容器/多容器两套逻辑并存。

工具就绪使用同一实时检查:Pod Running/Ready且未删除,Web工具还需声明的Service端口存在当前Pod UID的Ready、非终止EndpointSlice端点。启动等待、沙箱详情、owner与principal访问入口均复用它;持久化工具状态不能替代当前检查。访问规格从沙箱不可变快照解析,不得因目录更新改变既有实例的组件/端口/命令。动态命名空间的backend工作负载Role增加`discovery.k8s.io/endpointslices`只读list权限,不向学生ServiceAccount开放。组件HTTP健康路径由manifest声明,code-server使用其现有`/healthz`路由,不让工作台首页加载参与周期探活。

整组组件先完成当前状态查询：查询错误不能伪装成准备中，明确失败不能被前序未就绪组件遮蔽。Web Service 必须当前存在且未删除，公开端口、目标名及协议与冻结声明一致；EndpointSlice 的 Service 所有者 UID、目标 Pod UID、目标端口号与协议须同时匹配。Service 重建后遗留的同名切片不得开放入口。

运行时同样遵守冻结规格边界:创建、暂停/快照恢复、工作区访问及平台自检均从空结构解码冻结AdapterSpec,同时使用冻结adapter_level与能力声明;当前目录只作撤销/可用性校验,不得把后来新增的私有执行目标或字段混入旧快照。拒绝创建/恢复时,内部错误链需保留runtime/image ID、准确composition_digest及状态检查或查询失败原因,用户响应仍使用稳定错误码和友好提示。实验组合与竞赛各访问配置的摘要分别核验预拉取证明,不能因使用相同镜像就共用另一摘要的成功结果。

发布校验、新建、恢复和平台自检共用冻结计划装载规则：运行时和镜像必须当前可用，私有脚本目标有效，工具连接须在全部冻结运行时、工具和基础设施中解析。不能要求工具的每条连接同时存在于每个运行时，也不能只检查工具自身。目录选择阶段不解释尚未编译的跨组件连接；最终编译与执行准入校验完整组合。发布前模板校验不要求已完成预拉取，实际新建、恢复和平台自检仍须校验准确组合摘要的成功证明。

平台编译器同时接收私有执行 sidecar，在同一事务中生成包含 `private_sidecars` 的完整快照、镜像闭包和最终摘要，只登记最终快照，不再登记并删除基础中间快照。运行期只从冻结快照装载私有 sidecar，参与准入校验；创建请求不再另传一份 sidecar。首次创建与恢复必须运行同一份冻结计划，不能出现请求执行规格与保存快照不同的情况。暂停与回收共用冻结计划解析，但不检查当前目录准入或预拉取证明；持当前有效租约，只读归档原工作区，保存失败则保留资源，不重新开放业务计算或工具。

`tool.resource_spec` 统一结构:

```json
{

    {
      "name": "web",
      "image_url": "registry.chaimir.io/tool/code-server@sha256:...",
      "mount_workspace": true,

      "command": ["code-server"],
      "args": ["--bind-addr", "0.0.0.0:13337", "--auth", "none", "/workspace"],

      "ephemeral_mounts": [
```

约束:
- `kind=terminal`:终端协议由平台直供,默认复用 K8s exec/PTY;是否需要额外 workspace sidecar 由 runtime 适配器声明,不由教师选择器隐式注入。若使用镜像-backed workspace,它必须作为 runtime 的私有 `infra_sidecars` 进入组合快照,而不是伪装成 `base/chain-tools` 或普通教师工具。
- `kind=web-embed`:必须声明至少一个组件、一个 Service 和一个入口 route。组件镜像必须携带 digest 并命中镜像准入证明。
- `kind=command-tool`:必须声明唯一 `components[].name=command` 的无端口容器、`mount_workspace=true` 和 `command_policy`;不得声明 Service、route 或 `network_rules`。容器长期执行 `keepalive_command`,用户触发时由 M2 通过统一 K8s exec 基础层执行白名单 argv,输入输出使用 base64,不暴露 Pod/Namespace。
- `kind=platform-builtin`:由平台直供(文件管理、状态面板等),不创建 sidecar。
- `components[].mount_workspace=true`:把运行时 `workspace_dir` 挂入该组件;不共享工作目录的组件必须显式写 `false`。区块链浏览器、索引器、数据库和代理类组件默认不得挂载 workspace。
- `components[].mount_domains`:显式声明所需安全域，并通过 `resource_spec.volume_source` 确定数据所有者（见 §5.2.2）。工具只读；基础设施写入必须声明 `writable_mount_domains`。跨 Pod 使用同一所有者的域时创建 PVC。学生入口不得访问 `runtime-state` 或 `judge-private`。
- `tool.runtime_config_required=true`:表示该工具自身镜像已经登记,但必须等运行时/实验编排提供连接配置、证书或配套服务后才能调度。Seed 必须把此类工具写成停用状态,不得因为镜像已通过扫描签名就误标为可用;当对应 WorkloadSpec 组合配置真实落地并通过验收后,再由同一数据源改为可调度。
- `components[].ephemeral_mounts`:组件在只读根文件系统下需要的临时可写目录,由 M2 编排为仅挂给该组件的 `emptyDir`;不得覆盖 `/workspace`、`/runtime-state`、`/judge-private`、`/var/run`、`/etc`、`/proc`、`/sys`、`/dev` 等工作区、私有域或系统敏感路径。
- 学生入口组件若需要编译器、解释器或工具缓存,必须通过 `ephemeral_mounts` 声明组件独占的临时目录,并将 `HOME`/缓存路径指向该目录;不得为获得可写缓存而挂载 `runtime-state`,也不得把缓存写入 `workspace`。
- `routes`:所有学生可访问 Web 工具必须经 M2 工具代理路由进入。Blockscout/Fabric Explorer 等 frontend/backend/proxy 组合应通过多 route 表达,后端不得按工具 code 写特判。
- `network_rules`:仅 `web-embed` 工具可声明,用于放行工具组件之间、工具组件到运行时 Pod 的必要端口。未声明时工具只能被平台代理访问,不能主动连接链节点或其他沙箱组件。
- `command_policy`:仅 `command-tool` 可声明,`allowed_argv` 是完整 argv 数组白名单,请求数组必须逐项逐字命中其中一项;不支持仅校验 executable 或追加任意参数。`default_timeout_seconds` 与 `max_timeout_seconds` 均为正数,并受平台执行超时上限再次约束。
- `env` 仅允许字面值;密钥/凭据不得放入工具定义,需由平台 Secret 注入的场景必须通过受控 infra 组件和 Secret 引用机制表达,不得塞入普通工具环境变量。

### 4.3 动态工作台

M2 提供能力目录与接入端点;前端按已编译组合快照中的工具清单**动态渲染**工作台。目录筛选可使用 `eco_tags`,但最终是否可用只能由组合编译器的能力、依赖、冲突、资源和访问配置校验决定,不得自动注入未选择的工具。

### 4.4 终端不自研

复用 K8s exec subresource(SPDY/WebSocket stream),控制面做一层 WS 代理把沙箱内 shell 接到浏览器。不重新发明终端协议。

## 5. 机制三:分层持久化(默认重建)

**目标**:代码持久化,链状态按需重建,快照与保活受配额约束。

### 5.1 区分三个真实需求

| 需求 | 解法 | 不用全量快照 |
| --- | --- | --- |
| 断点续做 | 持久化代码 + 重建环境 | ✓ |
| 防丢失 | 代码实时持久化 S3 对象存储 | ✓ |
| 评测取证 | 评测时实时读链上状态 | ✓ |

### 5.2 分层策略

```
学生代码  → 实时持久化(挂载卷 + 防抖保存 → S3 对象存储),代码量小成本低
链状态    → 不快照,记录代码+部署脚本,恢复时重放重建
运行态    → 默认不存;教师对"重建代价高"的实验(挖矿/长共识)可显式开启
            保活或磁盘快照,默认关,且有最长保活时长上限防僵尸
```

### 5.2.1 代码持久化闭环

沙箱工作目录以 PVC 挂载到运行时与工具容器。文件写入后 M2 在配置的防抖窗口内保存到 S3 对象存储，用户主动保存立即归档；暂停和回收先停止全部计算写入，再从原工作区 PVC 归档，具体顺序见[状态机](05-业务流程与状态机.md#2-沙箱状态机)。

停止计算在读取并核对 Namespace 归属后列出全部 Pod，先完成归属与 UID 预检，再逐个带 UID 前置条件删除，等待仅跟踪原 UID；最后复查没有新增 Pod 才允许归档或快照。普通计算、工具、初始化和归档 Pod 共用完整沙箱归属标签，不能只按编号批量删除或把未标注写入者当作环境已停止。
所有学生侧 IDE/Web 工具必须经 M2 工具代理访问;代理层记录工具访问活跃度并安排防抖保存,避免绕过 M2 的直连工具写入无法进入持久化闭环。禁止在生产环境暴露工具容器直连入口。

约束:
- S3 对象存储 key 统一为 `{tenant_id}/sandbox/code/{sandbox_id}/...`,与平台对象存储路径约定一致。
- 每次保存先净化归档再计算SHA-256,使用`{tenant_id}/sandbox/code/{sandbox_id}/{sha256}.tar`保存该内容;后续保存不得覆盖已被提交引用的不同内容。数据库只更新沙箱的当前代码指针,既有提交引用、对象和历史证据保留,不迁移或重写。上传失败不得更新当前指针;事务失败不得删除可能已被其它提交引用的同内容对象。
- 自动保存、主动保存、提交保存和暂停/回收前保存复用唯一持久化实现,在同一租户事务内锁定沙箱行后完成打包、上传和代码指针/事件写入;完整保存过程复用`SANDBOX_EXEC_TIMEOUT_SECONDS`预算,等待锁、执行及上传均可取消,不新增专用阈值。原公开文件写入的revision更新使用同一行锁,跨副本串行化,不能仅靠进程内锁。返回的工作区版本必须来自该次保存持锁时的版本,不得另读较新版本冒充已保存版本。
- 防抖回调开始时只认领仍属于自己的计时器；被替代或取消的回调不再保存，并释放该次任务登记。已经开始保存的回调不得取消后续写入安排的新计时器，主动保存只取消开始时尚未执行的任务。service 关闭时立即触发尚未开始的有效计时器，再等待待执行与执行中的保存完成；沿用原 `SANDBOX_EXEC_TIMEOUT_SECONDS`，不因退出跳过最终待保存内容。并发关闭等待同一结果；关闭期间的任务失败保留日志、技术事件和关闭错误链，不能以仅停止计时器冒充持久化完成。
- 文件路径必须在 `runtime.adapter_spec.workspace_dir` 下解析,禁止 `..`、绝对路径逃逸、符号链接逃逸。
- 文件接口、代码归档、对象存储保存和学生 IDE 只能访问 `workspace` 域;不得读取或打包 `runtime-state`、`judge-private`、平台 Secret、控制面日志、隐藏测试或答案。
- 工作区私有路径、脚本执行域及归档净化统一遵循[安全设计](06-安全设计.md#6-教师脚本安全个性化初始化部署脚本)。持久化只接收已校验的公开归档，缺少私有执行目标时拒绝脚本执行；冻结组合和提交对象保持不可变。
- 初始代码归档恢复不得把对象存储中的 tar/zip 直接交给容器内 `tar` 解包。M2 必须在后端先逐条校验归档成员名,拒绝绝对路径、`..`、Windows 盘符、重复条目、软/硬链接、特殊文件,并按 `SANDBOX_INIT_ARCHIVE_MAX_FILES`、`SANDBOX_INIT_ARCHIVE_MAX_UNPACKED_BYTES` 限制文件数和展开大小后重打安全 tar 再写入工作区。
- 回收时计算 Pod 已退出或缺失，仍从原 `workspace` PVC 创建只读归档 Pod 完成最终保存；不重启业务运行时、工具或初始化任务。原卷缺失或归档失败时保留资源并报错，不以旧对象归档替代当前内容。
- 防抖保存失败记录结构化日志，并保留 trace/tenant，使用独立于保存取消的 `SANDBOX_READY_TIMEOUT_SECONDS` 预算写入 `sandbox_event`；事件写入失败与保存失败共同进入关闭错误链，关闭等待写回结束。回收前最终保存失败时不得删除 Namespace，保持 `recycling`，由当前租约持有者记录错误并释放租约后等待重试。
- 代码引用由 M2 维护为权威,M3/M6/M8 只保存引用与提交时 `code_hash`,不复制代码正文。

### 5.2.2 保活与快照闭环

卷归属按实际数据所有者划分：`workspace` 是组合共享卷；其余运行时域按实例隔离，PVC 与快照域标识为 `runtime-<instance>-<domain>`。不同实例的同名账本域不再合并，挂载路径和保存策略可以不同。只有共享工作区要求契约一致，其挂载路径由 `workspace_runtime_instance` 决定。

卷归属、工具及资产准备 Pod 的派生标识超过 63 字符时，保留前缀并追加完整原标识的摘要后缀，保证稳定且能区分所有者。不同实例与域的组合若生成同名物理卷，编译和资源预检必须拒绝，不得静默合并。

工具或基础设施使用非工作区域时，`resource_spec.volume_source` 必须明确来源：`self` 表示组件自己的 `runtime-state`（固定路径 `/runtime-state`，禁止学生访问，开启快照时保存）；`binding:<name>` 表示使用该具名连接绑定指向的运行时；`workspace` 只允许读取工作区所属运行时的 `public-assets`，供 IDE 访问公开教学材料。编译器把运行时来源解析为 `runtime:<instance>` 后冻结，不从数组顺序或环境变量地址猜测所有者。目录转换器将学生工具声明的公开材料权限落实为 `workspace` 来源。组件自己的卷使用 `tool-<code>-<domain>`，不同组件不共用数据目录。需要读取链身份或共享受控材料的组件必须显式绑定该链，链间协议连接本身不共享账本。

首次创建时，先读取并校验全部初始化归档，再用独立的受控资产 Pod 写入目标域，成功退出后才启动链节点。资产域必须使用实例专属 PVC，不能借用学生容器或工作区。暂停和快照恢复不重复注入初始资产。

`recreate_runtime` 重置须先完成目标实例材料和 Pod 配置预检，停止其账本及待写资产域的全部消费者并等待退出，再删除并重建目标账本 PVC；新卷不得从旧快照恢复。重新写入已审核材料后，按声明顺序恢复消费者并验证原生查询。共享工作区、其他实例账本与无关组件数据保留；任何一步失败均返回失败。

重置预检同时核对 Namespace 归属及待删除 Pod、账本 PVC 的实际 UID；删除和等待只处理已观察对象，同名替换立即报错，不继续重建或注入。初始化资产 Pod 直接保留创建或复用响应中的身份，用于完成、失败及取消后的有界清理，不通过再次按名称读取决定删除对象。

保活和快照仅用于教师显式开启的高重建成本实验,默认关闭。实现采用 Kubernetes PVC 与 CSI VolumeSnapshot;部署基线必须安装可用的 VolumeSnapshot CRD 与支持快照的 StorageClass。没有快照能力的环境不能开启 `snapshot_enabled`,必须在创建时明确拒绝。

执行规则:
- `keep_alive=true` 只跳过空闲回收,仍受 `tenant_quota.max_keepalive_min`、`tenant_quota.max_lifetime_min`、租户并发与资源配额约束。
- `snapshot_enabled=true` 时,M2 在暂停、回收前或调用方要求保留运行态时创建 VolumeSnapshot,并把快照引用写入 `sandbox.snapshot_ref`、`snapshot_created_at`、`snapshot_expire_at`。
- 快照能力检测必须同时确认 CSI `VolumeSnapshot` API、显式配置的 `VolumeSnapshotClass` 和 `StorageClass` 可读取，且快照类的非空 `driver` 与存储类 `provisioner` 相同、删除策略为 `Delete`。未配置、驱动不匹配或不允许到期删除时，拒绝开启快照，不能只凭类名或 CRD 存在放行。
- 快照只覆盖 `volume_domains.snapshot_scope=always` 或 `snapshot_enabled` 且通过策略校验的域。`judge-private`、Secret、答案、flag、隐藏测试和控制面凭据不得进入学生沙箱快照;默认重建路径只恢复 `workspace` 后重放部署脚本。
- 快照使用统一沙箱管理标签声明创建方、租户、沙箱及卷域。Ready 后，绑定的 `VolumeSnapshotContent` 必须反向指向当前快照的 Namespace、名称与 UID；同名旧对象的绑定不能作为当前快照已可恢复的证明。旧快照清理只接受本沙箱完整归属且具有 UID 与 resourceVersion 的对象，先完成整批身份预检，再用两项原生删除前置条件逐个删除；当前快照组和其他归属的对象保留。创建失败仅补偿本次新建对象；重新读取并核对原 UID、归属及规格后绑定当前资源版本删除，避免控制器正常更新状态后沿用创建时的旧版本。
- 开启快照时，上述获准域必须从创建起使用 PVC，不能仍挂临时卷再声称已采集链状态。PVC 创建、Pod 挂载与快照范围共用同一持久卷判定；未开启快照且无共享或独立持久化需求的运行态继续使用临时卷。
- 快照保留时间不得超过 `tenant_quota.max_snapshot_retention_min`;由于 CSI `VolumeSnapshot` 与源 PVC 同属 Namespace,快照回收时不得立即删除 Namespace,必须先释放计算工作负载,到期再由回收调度器删除 VolumeSnapshot、PVC 与保留的快照 Namespace。
- 暂停及保留快照逐个删除已观察的本沙箱 Service 和平台同步临时 Secret，绑定 UID 与 resourceVersion，先完成全部删除目标身份预检；Secret 换新后由冲突中止本次清理并保留重试。PVC、VolumeSnapshot、网络策略、配额、容器限额及禁自动挂载令牌的工作负载身份保留至 Namespace 正常到期回收。删除无创建方的 ConfigMap 清理及批量删除路径，固定工作负载角色不授予 `deletecollection`；权限仍经单个动态命名空间 RoleBinding 生效。
- 恢复复用原 Namespace 和身份、容量、访问模式及存储类匹配的保留 PVC；已有卷的快照创建来源是历史事实，不随最新快照组变化。仅为缺失且被快照覆盖的卷设置恢复数据源，随后执行健康检查；失败进入 `error` 并保留原快照至过期。

### 5.3 断点续做流程

学生离开 → 空闲超时(默认 30min)回收沙箱(代码已存)→ 回来 → 新建环境 + 拉回代码 + 重放部署脚本 → 恢复到离开前的逻辑状态。

## 6. 沙箱生命周期与隔离

### 6.1 隔离

- 每沙箱 = 独立 K8s Namespace(`sbx-{sandbox_id}`)+ Pod(s)。
- NetworkPolicy **默认 deny-all**,按需放行;沙箱间、租户间网络完全隔离。
- ResourceQuota + LimitRange 限单沙箱资源;Pod Security Restricted。

### 6.2 资源配额

- 租户级:并发沙箱数 / 总 CPU / 总内存上限,防止单校占满集群。
- 单沙箱资源校验直接使用正式编排器生成的完整 Pod 计划，包含所有运行时、基础设施、延后工具、初始化容器及私有 sidecar。有效 requests/limits 复用与 client-go 同版本的 `k8s.io/component-helpers/resource`，不另建适配器合并或自写初始化容器计算；按 CPU、内存和 Pod 数分别与 Namespace 硬限比较，创建与恢复均执行。
- 超配额时排队或拒绝,并返回明确提示。

### 6.3 回收

三重回收保证无僵尸:
1. 空闲超时(默认 30min 无操作)。
2. 最长生命周期强制回收。
3. 来源结束级联(M7 实验结束/M8 竞赛结束,调用方通知 M2 批量回收)。

回收流程、最终归档标记与失败状态保留统一按[生命周期与回收流程](05-业务流程与状态机.md#2-沙箱状态机)执行。持沙箱行锁归档前先续租，租约窗口覆盖 `SANDBOX_EXEC_TIMEOUT_SECONDS` 与一个 `SANDBOX_READY_TIMEOUT_SECONDS` 缓冲，避免同行锁阻塞续租；Namespace 删除和快照保留清理各受 ready timeout 限制。正常环境最终归档成功后才释放资源；失败环境不重新解析损坏组合，也不创建新快照。终态、技术事件和 outbox 必须在持有效资源租约的同一事务中提交。回收事件在提交后按领取租约逐项投递与确认；单项失败继续处理其余项，本轮返回全部投递与回写失败。发布失败与失败标记写入失败并列保留，未确认记录由原租约和重试机制接续。

暂停、回收及过期快照清理以 `resource_lease_token/resource_lease_until` 互斥，执行期间复用 [background.WithRenewal](../总-后端层能力索引.md#internalplatformbackground)；续租 I/O 的截止时间统一由共享层按当前已确认租约窗口约束，不从发起续租时重新获得完整窗口；行锁归档仍可使用原租约内的剩余预算。所有返回及异常退出均取消并等待续租，之后才完成业务终态写回；panic 或 `Goexit` 不得留下续租阻止恢复。过期快照只有 `destroyed` 且已过期、无活动租约的记录可被原子认领；恢复通过条件更新确认 `snapshot_expire_at > now()` 且无活动清理租约后才能切换到 `creating`。删除成功须由租约持有者清空快照引用、域和过期时间；失败释放自己的租约并记录事件，进程中断则由租约过期恢复重试。清理任务和恢复任务均不跨 Kubernetes 操作持有数据库事务。

回收调度器是 M2 service 内部后台任务,由 `cmd/server/sandbox.go` 通过 `platform/background` 启动,不得反向调用上层业务模块。每轮只做本模块表扫描和 K8s 清理:
- `SANDBOX_RECYCLE_POLL_INTERVAL_SECONDS`:调度器轮询间隔。
- `SANDBOX_RECYCLE_BATCH_SIZE`:每轮最多扫描并处理的沙箱数量,领取通过短事务原子完成,不跨 K8s 操作持有数据库事务。
- `SANDBOX_READY_IDLE_TIMEOUT_SECONDS`:creating/ready 且用户未进入操作的沙箱超时回收阈值。
- `SANDBOX_SELFTEST_TIMEOUT_SECONDS`:运行时接入即测的完整执行预算,与资源清理独立。
- `SANDBOX_SELFTEST_RECYCLE_TIMEOUT_SECONDS`:运行时与判题器自检结束后的资源清理预算,不能用作运行时执行预算。

判题器平台私有自检的`TimeoutSec`覆盖临时资源创建、就绪等待和全部manifest命令，清理另用`SANDBOX_SELFTEST_RECYCLE_TIMEOUT_SECONDS`独立计时，原请求取消仍须清理。资源准备、每条命令和清理分别记录阶段、沙箱ID、namespace、冻结组合摘要、实际exec目标、命令序号、阶段耗时及剩余预算；不记录完整argv、私有脚本或凭据。前一步耗尽预算时不得再启动下一条命令。执行与清理均失败时保留两条原始错误链，任何清理失败都不能返回自检成功；不以重试或增加超时替代具体阶段诊断。

平台组合自检与保留环境恢复共用冻结工作负载的加载规则：运行时、工具、基础设施和私有 sidecar 均按快照生成计划，当前目录只检查身份与可用状态，不能覆盖冻结规格。全部镜像复核当前准入及该组合摘要的预拉取证明；遗漏、停用或失去证明的组件必须在资源创建前失败。执行和清理预算在入口验证，清理返回后也检查上下文期限，避免超时被报告为成功。

两类自检在创建 Namespace 时，以当前执行上下文的截止时间加初始化资产清理窗口（`SANDBOX_READY_TIMEOUT_SECONDS`）和最终清理窗口，写入 `chaimir.io/selftest-cleanup-after` 注解。后台仅在该时刻到达后补偿清理，同时核对平台所有权、零租户、名称与沙箱 ID。缺失或非法期限明确报错并保留资源，不能按 Namespace 年龄或当前配置推测旧任务预算。期限随资源创建固化，无需数据库记录或额外超时配置。

调度器候选包括:ready 超时、idle 超时、`expire_at` 最长生命周期到期、`keep_alive_until` 到期、没有活动租约的 `recycling` 沙箱,以及 `destroyed + snapshot_expire_at` 到期且没有活动清理租约的快照 Namespace/PVC/VolumeSnapshot 清理。空闲阈值使用 `tenant_quota.idle_timeout_min`;`keep_alive=true` 只跳过 idle 超时,不跳过 ready 超时、`keep_alive_until` 或 `expire_at`。

### 6.4 内部鉴权、模块边界与审计

- 模块化单体内,M3/M7/M8 等调用 M2 必须经 `internal/contracts` 中的 `SandboxService` 等接口,禁止直接 import `internal/modules/sandbox`。
- 若 `[内部]` API 需要通过 HTTP 暴露,只能在内网路由启用,必须使用服务间鉴权,并强制携带 `tenant_id`、调用方模块、`source_ref` 与 trace 上下文。
- M2 不能反向调用 M7/M8/M3。回收、失败、状态变化等反向通知统一发布 NATS 事件,如 `sandbox.recycled`。
- 运行时、镜像、工具、沙箱创建/控制/回收、配额变更等关键操作必须写 M1 `audit_log`;`sandbox_event` 只保存 M2 内部技术事件与阶段明细。

## 7. 多租户与私有化同构

- SaaS:K8s 集群,按租户 Namespace 前缀 + 配额隔离。
- 私有化:k3s 轻量部署,单租户,逻辑与 SaaS 一致(配额恒为本校全部资源)。
- 镜像分发:私有化用离线镜像包导入本地 Harbor。
