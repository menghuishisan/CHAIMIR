## 1. 全局对齐原则

### 1.1 单入口与角色落点

| 项 | 必须对齐的规则 |
| --- | --- |
| 浏览器入口 | 公共登录页和四角色功能由 `apps/web` 同一个 Web 应用承载,生产镜像只构建和托管这一份 SPA 静态产物。 |
| 角色路径 | 学生 `/student/`；教师 `/teacher/`；学校管理员 `/school-admin/`；平台管理员 `/platform-admin/`。 |
| 角色来源 | 登录成功后以前端保存的后端账号信息恢复路径；真正权限以后端会话和接口鉴权为准。前端不能让用户手动选择角色。 |
| 登录后落点 | 学生进入 `/student/courses` 我的课程；教师进入 `/teacher/courses` 课程管理；学校管理员进入 `/school-admin/users` 账号管理；平台管理员进入 `/platform-admin/schools` 学校管理。四端都没有仪表盘/工作台落地页，落点就是该端侧栏第一个真实功能页；看板类页面是侧栏普通功能项，不承担落地职责。 |
| 私有化部署 | 私有化无平台管理员；平台级功能在私有化下按本校范围由学校管理员承接，前端不得暴露跨租户平台入口。 |
| 个人中心位置 | 个人中心由顶栏头像菜单进入，四端一致；侧栏只放角色业务功能，不设「账户」分组。 |

已对齐的关键项：
- 学校管理员端 `homePath` 已对齐为账号管理，符合总纲“学校管理员登录直达用户管理页”。
- 教师端不承载平台级“仿真审核”通过/驳回入口；教师保留“仿真场景/仿真包提交与预览”，审核通过/驳回归平台管理端。
- 顶栏共享入口按端分化：任务与下载、个人中心四端都有；通知铃铛（站内信收件箱）只在学生/教师/学校管理端，平台管理端没有，见 §3.4。

### 1.2 API 与错误契约

| 项 | 前端必须遵守 |
| --- | --- |
| API 根路径 | `/api/v1`。由 `API_BASE_PATH` 和前端配置统一拼接，不在页面里硬编码散落路径。 |
| 响应信封 | 后端统一 `{ code, message, data, trace_id }`；前端只展示用户向 `message` 和必要的 `trace_id`。 |
| SDK 契约核对 | `frontend/packages/api-client` 变更后必须对照 `backend/api/paths/*.yaml`、后端公开 `dto.go` 和对应 `enum.go` 逐项核对路径、方法、`/internal` 暴露、`/api/v1` 硬编码和契约常量。 |
| 分页 | 请求 `page/size`；响应 `data: { list, total, page, size }`。列表页不得假定数组响应，除非 API 客户端方法类型就是数组。 |
| 鉴权 | `Authorization: Bearer <access_token>`；刷新走 `/auth/refresh`；未登录由 `AuthGate` 拦截。 |
| 技术错误 | 不向用户展示堆栈、字段名、SQL、error_code、pod、端口、Vite、null、undefined、timeout 等开发语义。 |
| 下载 | 导入导出、成绩单、审计导出等文件下载走 transfer 或对应模块的下载授权，不直接暴露对象存储直链。授权响应换到的字节流由 `/api/v1/storage/download` 统一发送，后端在该出口已写 `Content-Disposition`（`httpx.WriteAttachmentStream` 按对象 key 末段取名并做单段化与字符白名单），**保存文件名一律取自该响应头**，由 api-client 的 `getAttachment` 单点解析后随 Blob 一并返回；前端不自造文件名、不按多个业务字段依次取值。前提是浏览器能读到该响应头 —— 部署为同源（Ingress `/` 走前端、`/api` 走后端，后端不注册 CORS 中间件），拿不到响应头即说明响应不来自后端，按传输层失败处理而非编造名字。transfer 任务快照仍带 `artifact_file_name`，那是任务列表展示用的业务字段，不改变保存时以响应头为准这一口径。 |
| 实时 | 业务实时数据走 M10 `WS /api/ws` topic；沙箱终端、沙箱进度、判题进度、仿真 stream 走各模块自有 WS。浏览器连接前统一通过 `/api/v1/auth/ws-ticket` 为目标 WS path 换取短时 `ticket`，普通 WS URL 不携带 access token。 |
| 多步骤流程 | 已填内容刷新或关闭重开后必须还在。账号导入、实验编排、作业草稿、竞赛报名/出题/参战等有会话流程以服务端草稿为权威，本地只留未同步编辑态；学校入驻申请是匿名表单，无草稿接口，在本机保存已填字段即满足，提交成功后清除。 |

### 1.3 页面入口类型

不是所有功能都应该进入侧边栏。侧边栏只承载高频、稳定、角色主任务；其余页面按任务流进入。

| 入口类型 | 放置规则 | 典型页面 |
| --- | --- | --- |
| 侧栏主入口 | 角色每天高频使用、可独立理解的一级功能。 | 学生我的课程、实验实训、竞赛参赛、成绩中心；教师课程管理、实验编排、题库内容、赛事组织；学校账号管理、组织架构、成绩审核；平台学校管理、入驻申请、链运行时。 |
| 深层详情页 | 依赖上级资源编号，不能脱离列表或上下文独立使用。 | 课程详情、课时学习、作业作答、作业结果、课程编辑、章节课时、成员、实验详情、竞赛详情、学校详情、运行时详情。 |
| 流程编辑页 | 是创建、配置、审核、导入等流程的一步，应该从主资源页的按钮进入。 | 作业编辑、竞赛配置、竞赛出题、组卷编辑、账号编辑、账号导入、实验编排向导、入驻审核详情。 |
| 沉浸式工作台 | 需要全屏专注和实时状态，不进入日常侧栏列表。 | 实验工作台、仿真工作台、竞赛答题、对抗回放。 |
| 顶栏/共享入口 | 跨角色通用，和当前业务无关或弱相关。 | 任务与下载、个人中心（四端）；通知收件箱（学生/教师/学校管理端，平台管理端没有）。 |
| 行内操作/抽屉 | 只针对单条记录的轻量操作，不单独做页面。 | 标记已读、启停账号、处理告警、重判、下载授权、归档、置顶。 |

### 1.4 四端侧栏目标入口

侧栏应按下面目标入口组织；没有列入侧栏的页面不得强行塞进侧栏。本表是**侧栏名称与顺序的唯一真相源**：`frontend/apps/web/src/routes/sections/<role>Navigation.ts` 的菜单项名称与排列必须与本表逐字一致，分组标题用纯中文短词（学习区 / 学业区 / 教学 / 实践 / 资源 / 组织与成绩 / 用户与组织 / 概览 / 教务与成绩 / 系统配置 / 租户 / 运营 / 底层资源），不得出现代码用短名、文档用长名的双写。

| 教师 | 课程管理、批改中心、实验编排、赛事组织、实时监控、题库内容、试卷组卷、仿真场景、共享资源库、成绩报送、组织查看 | 课程编辑、章节课时、选课成员、课程讨论、作业管理、作业编辑、实验编排向导、竞赛配置、竞赛出题、防作弊审查、漏洞源管理、漏洞题转化、内容编辑、组卷编辑、题库分类、课程成绩、成绩申诉、通知收件箱、任务与下载、个人中心 |

**共享入口与公告的边界**（避免歧义）：
- **通知收件箱**（`{prefix}/notifications`）= 站内信 + 公告阅读 + 通知偏好，只经顶栏铃铛进入，只在学生/教师/学校管理端存在。
- **系统公告**（`{prefix}/announcements`）= 公告发布 + 已发布公告列表，是侧栏功能页，只在学校管理端与平台管理端存在。平台管理端没有收件箱，其公告阅读也在这一页。
- 两者不是同一个页面，也不互相替代：一个是「收」，一个是「发」。

### 1.5 当前实现收敛基线（2026-07-11）

- `frontend/apps/web` 的用户可达页面已覆盖 `frontend/packages/api-client/src/modules/*` 中全部公开异步能力；内部服务接口不进入浏览器 SDK。新增能力必须落到现有主入口、详情页、流程页、行操作或共享入口之一，不得仅为“接口覆盖”建立无业务入口的按钮。
- 实验与竞赛代码环境统一由应用层 `SandboxIdeWorkspace` 适配后端 M2,复用 `@chaimir/ide` 的 Monaco/xterm 生命周期能力与 `@chaimir/ui` 的 `WorkbenchShell` 槽位(引擎包不含 React 视图层,布局壳在阶段 5 按新设计系统落地);文件、Monaco、终端、进度 WS、命令工具、链操作和 Web 工具入口不允许在业务页面重复实现布局。M2 `SandboxResponse.capabilities` 是文件、终端、命令工具和链操作是否出现的权威来源,前端不得无条件建立连接或展示运行时未声明的动作。
- 仿真统一复用 `@chaimir/sim-sdk` 的 `SimWorkerClient` 运行时与 `@chaimir/ui` 的 `biz/TeachingFrameStage` 舞台,页面只做装配;公开分享使用无角色守卫的 `/sim/shared/:shareCode` 深链,不进入学生侧栏,且公开响应只含 `package_code/version/seed/init_params/actions`,匿名只能运行平台内置包(这是安全边界:扩展包 bundle 属所属租户教学资产,分享码不得成为跨租户取包凭据;`package_code` 非内置时页面只给确定性说明文案 + 单一「返回登录」动作,不引导换取运行授权、不降级渲染、不静默留白)。前端计算只按独立连续序列上报用户交互,不上报自动 `tick`;回放必须恢复元素 `target`。后端计算只在包声明 `compute=backend` 时连接模块 stream,交互经 WS 发给已注册适配器,服务端状态回到共享 Worker 渲染,不在页面复制 reducer、舞台、时间线或检查器。
- 全局业务事件统一使用 `eventWebSocketUrl()` 指向 `WS /api/ws`，沙箱、判题和仿真使用各模块专用 WS；所有连接统一经 `webSocketTicketProvider` 以目标 path 换取短时票据。
- 平台租户读取统一归 identity 的 `/platform/tenants`，不保留 admin 模块同义列表封装；实时事件 URL 同样不挂在 notify 业务模块下。
- 账号/组织导入、实验编排、课程草稿等多步骤流程继续以服务端预览编号、草稿或实例为权威；页面刷新后的恢复信息使用后端记录或 URL 中的资源编号，不以页面内临时状态冒充持久化。

## 2. 公共登录前页面

| 页面 | 前端路由 | 后端对齐 | 前端自有能力 |
| --- | --- | --- | --- |
| 学校用户登录 | `/auth/login` | 手机号密码 `POST /auth/login/phone`；学号/工号 `POST /auth/login/no`；短信登录 `POST /auth/login/sms`；短信发送 `POST /auth/sms/send` | 手机号是主流程，密码和短信验证码在主流程内切换；学号/工号与学校统一认证作为次级入口。后端返回 `need_select_tenant` 时只展示学校选择，不展示角色选择。 |
| 租户选择 | `/auth/tenant-select` | 由登录响应 `need_select_tenant` 与 `tenants` 驱动，二次提交带 `tenant_id` | 只选择学校，不选择学生/教师/管理员角色；没有待选登录上下文时返回登录页。 |
| 找回密码 | `/auth/forgot` | `POST /auth/sms/send`，`POST /auth/password/reset` | 验证手机号、学校数字编号、验证码、新密码；成功后引导回登录。 |
| 账号激活 | `/auth/activate` | `POST /auth/activate` | 输入激活码和新密码；后端只完成账号激活和密码设置，不签发登录会话。成功后应提示返回登录，不得假定可直接写入 token 或按角色跳转。 |
| 学校入驻申请 | `/auth/apply` | `POST /platform/applications` | 只面向学校，不是个人注册；表单应保留提交失败后的用户输入。 |
| 统一认证 | `/auth/sso` | CAS：`GET /auth/sso/{tenant_code}/login`、`GET /auth/sso/{tenant_code}/callback`；LDAP：`POST /auth/sso/{tenant_code}/ldap` | 学校短码、统一认证账号密码；CAS 跳转由后端返回 URL 驱动。 |
| 平台管理员登录 | `/auth/platform-login` | `POST /auth/login/platform` | 仅 SaaS 部署的平台管理员入口；不得与学校用户登录混成“选择角色”。 |
| 首次登录强制改密 | `/auth/change-pwd` | 登录响应 `must_change_pwd`；当前会话调用 `POST /me/password` | 登录成功后先保存受限会话并跳转改密页；改密完成后进入后端角色对应的首个功能页，改密前不能访问业务页面。 |

## 3. 四端页面与后端功能对齐

### 3.1 学生端 `/student/`

| 页面 | 入口 | 后端模块与接口 | 必须呈现的功能 |
| --- | --- | --- | --- |
| 我的课程 | 侧栏 | M6 `GET /teaching/courses?role=student`，`POST /teaching/courses/join` | 已加入课程、课程状态与学期学分、课程详情入口、邀请码加入课程。学习进度归课程详情（见下行原因）。 |
| 课程详情 | 深页 | M6 `GET /teaching/courses/{id}/outline`，`GET /teaching/courses/{id}/my-progress`，`GET/POST /teaching/courses/{id}/posts`，`POST /teaching/posts/{id}/like`，`GET /teaching/courses/{id}/announcements`，`POST /teaching/courses/{id}/review`，`GET /teaching/courses/{id}/assignments` | 大纲、章节课时、**本课程完成率与逐课时进度**、作业清单、讨论、公告、课程评价。完成率只在此页计算：`outline` 是唯一同时返回课时总数与进度的接口（`my-progress` 只回 `Progress[]`、缺总数算不出比例），列表页按课程逐个调用会产生 N+1，故完成率不进列表页。 |
| 课时学习 | 深页 | M6 `GET /teaching/lessons/{id}`、`POST /teaching/lessons/{id}/progress`、`POST /teaching/lessons/{id}/material/access` | 课时内容、学习进度上报,刷新后进度以服务端为准。五种形态各有确定链路:图文渲染 `content_ref.markdown`;视频经 `material/access` 换 `mode=stream` 授权在播放器内播放并按 `video_pos` 续播;附件经同一入口换 `mode=download` 授权取件;实验与仿真跳转对应工作台。 |
| 作业作答 | 深页 | M6 `GET /teaching/assignments/{id}`，`POST /teaching/assignments/{id}/draft`，`GET /teaching/assignments/{id}/draft`，`POST /teaching/assignments/{id}/submit` | 作业题面、草稿保存、提交作答；答案和判题配置不暴露（后端 `GetAssignmentForStudent` 经 `content.GetContentFace` 取题面，`full` 只对 service/teacher 开放，前端不做二次过滤）。 |
| 作业结果 | 深页 | M6 `GET /teaching/assignments/{id}/submissions`、`GET /teaching/submissions/{id}` | 历次提交、得分(自动/人工/最终)、教师评语、迟交标记、判题状态。该路由师生同用按身份分视角(学生只回本人提交),**判题任务详情与判题进度 WS 不对学生开放**:M3 `/judge/tasks` 与 `WS /judge/tasks/{id}/progress` 由 `RequireTenantAnyRole(教师/学校管理员)` 守卫,学生侧的判题结果只经 M6 提交记录的 `status` 与分数字段呈现。 |

## 5. 前端自有能力清单

这些能力不应该由后端替前端实现，但必须和后端契约配合。

| 能力 | 前端职责 | 不能做 |
| --- | --- | --- |
| 应用壳 | 深色框架、侧栏、顶栏、移动抽屉、通知铃、头像菜单、跳过链接、焦点管理。 | 不能新增独立工作台落地页或角色选择页。 |
| 路由 | 使用 Browser History 路由,同源 path 区分四角色及其页面；Nginx 对深链接统一回退根 `index.html`。详情页和沉浸页可隐藏于侧栏。 | 不能拆分四套静态应用,也不能把所有页面都强行放进侧栏。 |

| 表单 | 前端即时校验、提交 loading、防重复提交、首个错误聚焦、用户向错误文案。 | 不能信任前端校验替代后端校验。 |
| 多步骤流程 | 展示步骤、自动保存指示、恢复入口、冲突提示。 | 不能只存 localStorage；服务端草稿是权威。 |
| 沉浸工作台 | 实验、仿真、答题、对抗回放使用深色全屏工作台；移动端可堆叠或只读降级。 | 不能在小屏空白、横向撑破或假造进度。 |
| 可视化 | 图例、数值、表格替代、键盘可达、空/错/载态；PBFT、区块、回放必须绑定真实数据。 | 不能用装饰性雷达、假飞线、无来源动画代替真实过程。 |
| 实时 | 连接状态、重连提示、订阅 topic 展示、降级轮询或刷新入口。 | 不能把内部 WS token 暴露给工具容器或跨租户 topic。 |

| 动效 | 只表达因果关系：进入、提交、状态变化、加载、节点消息、时间轴推进；支持 reduced-motion。 | 除 loading 外不得无限装饰性动画。 |
| 响应式 | 375/768/1024/1440 四档；表格小屏转卡片或隐藏次要列；独立横滚区不能带动整页。 | 不能固定像素撑破、遮挡、整页横向滚动。 |
| 设计系统 | 墨玉体系(墨 · 玉 · 朱砂 · 宣纸)、底层曝光三态(全裸露认证页 / 光面日常页 / 沉浸工作台)、Lucide 图标、全令牌化颜色与间距(`docs/总-前端设计规范.md` 为唯一真相源)。 | 禁止 emoji、裸 hex、任意值、AI 紫粉渐变、无意义装饰页;朱砂不用于错误(错误用独立冷红)。 |

## 6. 实际代码复核记录

> 本节基于 2026-07-05 对当前后端与前端代码的复核，用于防止后续 UI 重做时只按想象补页面。后续修复前端时，以下偏差项必须逐一关闭。

### 6.1 后端实际能力边界

| 模块 | 代码证据 | 已确认的功能边界 |
| --- | --- | --- |
| M1 身份认证 | `backend/internal/modules/identity/api_auth.go`、`service_auth.go`、`dto.go` | 学校登录分为手机号密码、学工号密码、短信验证码三类；手机号密码一号多校时返回 `need_select_tenant + tenants`，只让用户选学校，不选角色；学工号登录必须带 `tenant_code`；短信登录必须解析到租户；`/auth/activate` 只激活账号和设置密码，不返回有效登录态。 |

### 6.2 前端应用层当前状态

| 范围 | 当前状态 | 重建约束 |
| --- | --- | --- |
| 应用层 | 采用唯一的 `apps/web` 单体 SPA + FSD 架构。 | 路由层按域拆清单：`routes/authRoutes.tsx`（认证公共页）、`routes/immersiveRoutes.tsx`（公开沉浸态深链）、`routes/roleRoutes.tsx`（四端角色区守卫 + 懒加载壳）、`routes/sections/<Role>Section.tsx` 与同名 `<role>Navigation.ts`（区内清单与导航数据，随区一起懒加载）。页面实现放在强映射后端 11 模块的 `features/<module>/pages/`。各角色的路径清单与栏目名只允许出现在自己的区壳打包块里，不得被入口包静态引用；不得恢复旧页面工厂、集中式 `lazy-pages` 清单或独立 `src/pages` 代理层。 |

### 6.5 阶段 4 打通学生取数入口的后端改动(2026-07-31)

> 判定口径:**一切以后端已有能力为准**。只有「后端已有该能力、但前端无从取得进入该能力的标识,导致功能无法闭环」时才动后端;动的是**既有接口的取数口径**,不是新业务能力。**优先改既有实现,不新开第二条同义路由** —— 同一份数据两条路由即双轨。以下逐条列出改法与理由,其余疑似缺口一律按 §6.6 记为明确不做。

| 改动 | 改法(为什么不新开路由) | 不改则什么闭不上 | 安全边界 |
| --- | --- | --- | --- |
| `GET /teaching/courses/{id}/assignments` 从 teacher 组移到 shared 组,按身份分视角 | 教师本来就需要课程作业列表,学生需要的是同一份数据的已发布子集。**同一路由 + 服务端按 `courseReadAccess` 判定视角**,复用既有 `ListAssignmentsByCourse`(原先只被课程克隆内部调用),SQL 加一个 `published_only` 参数;若为学生新开 `/student/assignments` 就成了同一张表两条查询两套 DTO | `GET /assignments/{id}`、`GET/POST /assignments/{id}/draft`、`POST /assignments/{id}/submit` 四条**已存在**的学生接口都以 `assignment_id` 为入口,而全平台没有任何接口向学生给出这个编号(大纲 `OutlineDTO` 只有章节/课时/进度,`LessonContentType` 枚举不含作业,teaching 模块从不发通知 ⇒ 模板里的 `assignment.published/due` 无人触发)。不改则学生永远进不了作业 | 学生只见 `status=published`;响应是作业外壳(标题/截止/次数/迟交策略),**不含题目与题面**,题面仍只经 `GET /assignments/{id}` 走 `content.GetContentFace` |

**用户向文案归属**:通知类型的中文名在前端 `apps/web/src/utils/labels/notify.ts` 维护(后端只给类型标识,不给界面文案),未登记类型给通用名不抛错。

**同一份判定只写一处**:课程可读性与「是否授课教师」原先分散在 `ensureCourseReadable`(布尔失败)与 `ensureTeacherOwned`(取课后单独判)两处,本次抽出 `courseReadAccess` 一次返回两个结论,`ensureCourseReadable` 成为它的薄封装 —— 上述两条分视角路由共用同一份校验,不各写一遍成员判定。

### 6.7 课时材料投放契约(2026-08-04 已实现)

M6 需求规格 §B2 要求课时支持「视频、图文(Markdown)、附件」三种形态。收尾前审查发现 teaching 模块缺少视频/附件上传与授权取件；现已按统一文件服务补齐,不新增材料表或私有下载出口。

契约与实现保持一致,前端按以下接口对接:

| 接口 | 归属 | 说明 |
| --- | --- | --- |
| `POST /teaching/lessons/{id}/material` | 教师 | multipart 上传,落 `{tenant_id}/teaching/material/{lesson_id}/{file_name}`,把 `object_ref`/`file_name`/`size`/`content_type` 写进 `lesson.content_ref` 并按文件类型置 `content_type` |
| `POST /teaching/lessons/{id}/material/access` | 师生(`courseReadAccess`) | 换取投放授权,响应 `{ token, mode, file_name, size, content_type, expires_at }`;`mode` 由课时 `content_type` 决定,不接受客户端指定 |
| `GET /api/v1/storage/download?token=` | 既有 | 新增 `mode=stream` 分支:inline 处置 + Range + 有效期内可重复消费,用于视频续播;`mode=download` 行为不变 |

**不新建表**:`lesson.content_ref` 就是为存引用 key 设计的(`docs/总-数据库表总览.md` §5「表存引用 key」);`content_type` 是单值,一个课时只有一种形态,多份材料靠多建课时表达。另建材料表会让同一事实存两处。

**不新开投放端点**:`mode` 进签名(客户端改不了),两种模式共用同一端点、同一 grant 构造器与签名器。新开 `/storage/stream` 会造成第二套验签与消费逻辑。

**视频与附件共用一个 `resourceType`**:`content_type` 已声明形态,再分 `video`/`material` 两个对象前缀是第二处冗余。

**前端取件收敛到 `api.storage`**:统一文件服务既然是全平台唯一投放出口,前端也只保留一个消费入口 —— `packages/api-client/src/modules/storage.ts` 的 `consumeGrant`(一次性取件)与 `streamUrl`(流式播放地址)。transfer 的产物下载改为调用它,不在各业务模块各写一遍 `/storage/download`。

### 6.8 单人实验实例幂等(2026-08-04 已实现)

收尾前审查发现 `service_instance.go CreateInstance` 只对**小组**实验幂等,单人实验重复进入会新建沙箱；现已补齐按 `owner_account_id` 的同事务幂等检查和创建锁。

**按同一口径补齐,不新开接口**:小组分支已经确立了「有活跃实例就复用」的语义,单人分支缺的只是一个按 `owner_account_id` 查活跃实例的 repo 方法。补上之后 `CreateInstance` 对两种协作模式行为一致,前端因此只需一个「进入实验」按钮,不做「开始 / 继续」二态判断,也不需要「查我的实例」这类新接口。

**活跃口径**:与实例状态文案同源 —— `creating`/`running`/`paused`/`released` 视为当前实验仍可复用或等待恢复,`finished`/`recycled`/`error` 不占用(前端 `utils/labels/experiment.ts` 的 `isExperimentInstanceActive` 用同一集合)。

### 6.9 竞赛加入队伍的路由归属(2026-08-04 已收敛)

`contest/service_team.go` 存在两个功能重叠的方法:

| 方法 | 入参 | 路由 |
| --- | --- | --- |
| `JoinTeam(contestID, inviteCode)` | 赛事编号 + 邀请码,按 `GetTeamByInviteCode` 定位队伍 | `POST /contest/contests/{id}/join-team` |
| `JoinTeamByID(teamID, inviteCode)` | 队伍编号 + 邀请码 | **已删除,不保留兼容路由** |

这是同一件事的两套实现,其中一套没有入口 —— 违反「重复即统一」。而且现存路由要求 `team_id`,学生手上只有队长分享的邀请码,前端只能让用户手填内部编号(旧前端被审查列为 P0 的「要求用户手输内部 ID」)。

**收敛口径**:保留按邀请码定位这一种语义,删除 `JoinTeamByID` 与其路由,把已有的 `JoinTeam` 接到 `POST /contest/contests/{id}/join-team`(请求体只含 `invite_code`)。理由:邀请码本就是「可分享的队伍凭据」,赛事编号页面上下文里已有;队伍编号对学生是不可知的内部标识。前端与后端现已按此契约实现。

### 6.10 按学年归档的路由归属(2026-08-04 已收敛)

`POST /accounts/batch/archive` 与 `POST /org/classes/archive` 的 handler 都直接调用同一个
`ArchiveClassesByAdmin`,请求体也都是 `{ enrollment_year }` —— 同一件事两条路由,是双轨。

**收敛口径**:保留 `POST /org/classes/archive`,删除 `POST /accounts/batch/archive` 与其 handler。
理由:该 service 在一个事务里做三件事 —— 归档班级、归档该学年学生账号、吊销这些学生会话,
其中两件是组织层面的,归到 `/org` 语义正确;而 `/accounts/batch/*` 的其余两条(disable/restore)
都按账号编号作用于选中账号,粒度是「这些账号」,与「这一届」不是同一回事,混在一组会让人以为
批量归档也接账号编号数组。前端组织架构页按 `/org/classes/archive` 实现批量归档,账号管理页只保留
按账号编号的批量停用与恢复;后端现已删除旧路由,前后端均只保留 `/org/classes/archive`。

### 6.11 平台端页面与校管端共用同一实现的三处(2026-08-03)

平台端与校管端有三件事是「同一个后端能力、同一套界面,只是作用范围或归属不同」。
这类情况按显式声明参数共用一份实现,不复制第二份页面(实现标准 §4「统一不兼容」):

| 共用实现 | 参数 | 两端差别 | 后端依据 |
| --- | --- | --- | --- |
| `features/admin/pages/system-alerts.tsx` | `scope` | 平台维护全局规则、看全平台事件;校管维护本校规则、看本校事件 | `ListAlertRules`/`ListAlertEvents` 按身份分叉,平台传非全局 scope 会被拒 |
| `features/notify/pages/announcements.tsx` | `publisher` | 平台只发全平台;校管发本校与定向角色 | `validateAnnouncementRequest` 对非平台身份拒 scope=平台;平台会话无租户,发本校范围会落到不存在的归属 |
| `features/contest/pages/vuln-source-form.tsx` | `global` | 平台写 `tenant_id=0` 全局源;教师写本校源 | 两条路由 `POST /contest/platform/vuln-sources` 与 `POST /contest/vuln-sources`,请求体与校验完全相同 |

三处都由调用方(区壳注册路由时)显式声明,页面不在运行时判角色枚举 —— 与通知铃铛归属、
个人中心换绑手机号、申诉页重算绩点同一处理方式。范围边界由后端守卫,前端只按声明渲染。

另外两条平台端页面的取数边界(与校管端不同,不能照抄):

- **平台审计不做「按操作者」筛选**:账号列表 `GET /accounts` 在租户组(要求学校管理员身份),
  平台身份调用会被拒,跨校账号姓名在平台侧无从解析。故平台审计按 `actor_role` 呈现操作者身份,
  并用 `GET /platform/tenants` 解析出「学校」一列;要查具体是谁,去那所学校的管理端审计页。
- **平台仿真治理不调仿真包列表**:`GET /sim/packages` 同样在租户组。审核记录本身就是平台侧的
  包窗口(每次提交产生一条,记录里带包编码、版本与当前状态),下架与重新上架据此定位包编号。

### 6.12 阶段 5 沉浸态的三条取数边界(2026-08-04)

沉浸态四条路由都只能用学生身份可达的接口,以下三处与直觉不同,实现时按此为准:

| 场景 | 直觉做法为何不成立 | 实际做法 |
| --- | --- | --- |
| 仿真工作台的会话 | `POST /sim/sessions` 在 `/internal` 组,学生不能建会话(§6.6 已记) | 学生自行进入的是**本机确定性推演**:Worker 内按 seed 复现,不上报动作、不出分享码。地址上带 `session` 时(由实验编排产生的会话)才上报用户操作、才可出分享码 —— 自动推进的 tick 不上报,它由 seed 决定、服务端可复算 |
| 实验工作台里的仿真 | 想在实验内直接跑仿真 | 学生投影 `StudentSimComponent` 只有 `{id, package_code, version}`,**没有 seed 与 params**(它们在 teacher 组的 `SimComponent` 里),没有这两项就无法确定性初始化。故实验工作台只列出本阶段的仿真场景与去处,不在实验内复制一套仿真运行时 |
| 对局回放的逐帧轨迹 | 想按帧回放对局过程 | M3 持久化 M2 链能力结果序列,M8 写入报告桶并只在 `GET /matches/{id}/replay` 返回可用状态;`POST /matches/{id}/replay/download-grant` 复用统一文件服务授权,消费仍走 `/storage/download`,页面按真实归档复盘,不做假动画 |

对局轨迹已经复用统一文件服务,不新增业务私有下载路由;对局列表只返回 `replay_available`,回放确认接口只返回 `available`,浏览器不拿对象存储地址。前端在同一回放页按需换取授权并下载真实归档。

### 6.13 时空回溯器:对局回放的呈现口径(2026-08-04)

对局回放页(创新②)用学生身份真实可达的三份数据做时间轴复盘,轨迹归档按需通过统一文件服务取件:

- `GET /contest/contests/{id}/battle/matches`:本队的全部对局,含 `result`、`score_delta`、`status`、
  `matched_at`/`finished_at`、`problem_id`、`entry_a_id`/`entry_b_id`;
- `GET /contest/contests/{id}/battle/entries`:本队历次参战物,含 `role`、`version_no`、`is_active`、`code_hash`;
- `GET /contest/contests/{id}/ladder`:当前天梯位次。

呈现口径:把对局按时间排成一条可拖动的时间轴,拖到任一时刻即按**该时刻之前已结束的对局**
重算当时的战绩(胜/负/平、累计得分变化)与当时生效的参战物版本 ——
状态一律由记录重算,不做插值、不做补帧。这是「时空回溯」的真实含义:回到那个时刻看当时的事实。

### 6.15 两条仿真接口在浏览器端不可达的原因(2026-08-04)

`GET /sim/packages/{code}/{version}/bundle` 与 `WS /sim/sessions/{id}/stream` 在 SDK 里保留,
但当前没有页面调用 —— 这不是遗漏,而是两条前提在本次范围内都不成立:

- **bundle 下载授权**:它是为「扩展仿真包在浏览器里运行」准备的。而扩展包的运行契约
  (bundle 怎么在隔离 Worker 里装配、怎么校验其确定性)尚未定档(见 `docs/总-前端设计规范.md` §9),
  `SimWorkerClient` 的入参也只接受平台内置包编码。故仿真工作台与公开回放都只运行内置包,
  不去换 bundle 授权 —— 换回来也没有装配它的路径,那才是"接口覆盖式"的假实现。
- **stream 实时流**:它只在包声明 `compute=backend` 时成立(§1.5)。当前 41 个平台内置包
  全部是 `compute: 'frontend'`,一个后端计算包都没有;而扩展包又受上一条限制。
  故没有任何一条真实路径会走到 stream,页面不预先建立一条连不到东西的连接。

两者都随「扩展包运行契约定档」一并接入:届时仿真工作台按包的 `compute` 分叉 ——
前端计算走 Worker(现状),后端计算连 stream 并由服务端状态驱动同一个舞台,
不在页面复制 reducer、舞台、时间线或检查器(§1.5 已定口径)。

### 6.17 漏洞题草稿录入的路由归属(发现的双轨,收敛口径已定)

`POST /contest/vuln-problems` 与 `POST /contest/vuln-sources/import` 绑的是同一个 handler
(`api.go` 两行都指向 `a.importVulnProblem`),请求体也都是 `ImportVulnProblemRequest` ——
同一件事两条路由,是双轨。

**收敛口径**:保留 `POST /vuln-problems`,删除 `POST /vuln-sources/import` 与其 openapi 条目、SDK 方法。
理由:请求体里的可选 `source_id` 已经表达了「这条草稿来自哪个来源」,再用路径区分
「手工录入」与「来源导入」是把同一份数据的一个字段抬成了两个入口;而 `/vuln-sources/*`
其余路径都作用于来源本身(配置、同步),把一条产出草稿的路由放在那里也不合语义。
前端漏洞题工坊按 `POST /vuln-problems` 实现录入,`source_id` 由表单里的来源选择给出。

### 6.18 阶段 5 收尾接上的四处不可达 SDK(2026-08-04)

沉浸态落地后复查 SDK 可达性,补上四处「后端有能力、前端没有入口」的:

### 6.19 竞赛答题的提交键契约(2026-08-04 已实现)

M3 接口设计 §答案提交明确:「Flag 提交值必须按 `flag_input_key` 直接放入 `extra_input`」。
M8 的 `POST /problems/{pid}/submit` 把请求体的 `content_ref` 原样当作判题 `extra_input`
(`SubmitSolve` → `JudgeSubmitRequest.ExtraInput`),也就是说**提交方必须知道这个键**。
但 `flag_input_key` 在题目的 `judge_config.expectation` 里,而 `judge_config` 是学生必须剥离的敏感字段 ——
学生客户端无从得知该用哪个键。这是契约缺口,不是刻意的答案黑盒边界(键名是表单字段名,不是答案)。

**定档口径**:竞赛题正文(`ContentType=竞赛题`)增加一个**非敏感**字段 `submit_key`,
含义是「学生输入的答案要放在提交体的哪个键上」,取值必须与该题 `judge_config.expectation.flag_input_key` 相同。
它随题面(`face`)下发,答题工作台按它构造 `content_ref = { [submit_key]: 学生输入 }`。

据此,答题工作台的三条分支是确定的,不猜键、不做兜底:

| 题目声明 | 工作台呈现 |
| --- | --- |
| 正文有 `runtime_code` | 起实操环境(`POST /problems/{pid}/env`,镜像版本留空即用该运行时默认镜像),保存工作区得到代码引用后提交 `code_storage_key`/`code_hash`,`content_ref` 传 `{}` |
| 正文有 `submit_key` | 给一个答案输入框,提交 `content_ref = { [submit_key]: 输入值 }` |
| 两者都没有 | 说明这道题还没声明作答方式,指引联系老师;不构造任何猜测的提交体 |

对抗题的环境参数不走 `submit_key`:它在 `battle_config` 里已有 `runtime_code`/`runtime_image_version`/
`tool_codes`(后端 `validateBattleConfig` 要求前两项必填),参战物提交走
`POST /battle/entry` 的 `artifact_ref`/`code_hash`,与解题赛不共用一条路径。

### 6.20 编排资源目录:教师取运行时/镜像/工具/判题方式的唯一入口(2026-08-05)

三个教师编排页(实验环境、竞赛对抗题、漏洞题预验证)与实验检查点都要选运行时、镜像版本、工具、
判题方式,而这些清单原先只有平台面接口:`GET /sandbox/runtimes`、`/sandbox/tools`、
`/sandbox/runtimes/{id}/images`、`/judge/judgers` 全挂 `RequirePlatformIdentity`。
教师页面调它们**运行期必被 403**,静态检查发现不了 —— 这是真实缺陷,不是权限设计。

**两条候选与取舍**:直接把平台接口的守卫放开给教师最省事,但会连带下发
`adapter_spec`(容器编排清单、网络规则、卷域、能力命令)、`image_url`+`digest`、
`tool.resource_spec.command_policy.allowed_commands`、`selftest_detail`、`judger.resource_spec`
(判题镜像版本、受控命令、执行组件)—— 这些是平台运维资产与判题私密面,不是编排输入。
故按**最小字段目录**新增两条只读接口,平台管理端仍走原完整接口:

| 接口 | 受众 | 只出 | 刻意不出 |
| --- | --- | --- | --- |
| `GET /sandbox/catalog` | 教师/校管/平台 | 运行时 `code`/`name`/`eco` + 其可用镜像 `version`/`is_default`;工具 `code`/`name`/`kind` | `id`、`adapter_spec`、`adapter_level`、`capability_impl`、`plugin_ref`、`selftest_*`、`image_url`、`digest`、`prepull_*`、`resource_spec`、`eco_tags` |
| `GET /judge/catalog` | 教师/校管/平台 | 判题方式 `code`/`name`/`type` | `id`、`executor_ref`、`resource_spec`、`runtime_required`、`default_timeout_sec`、`selftest_status` |

**不是双轨**:目录与管理接口的受众、字段集与用途都不同,前者是编排输入投影、后者是运维管理;
两者共用同一份 `runtime`/`runtime_image`/`tool`/`judger` 数据,没有第二处存储或第二套写入。
目录只回 `status=可用` 项 —— 状态过滤在服务端做,避免前端各写一遍 `filter(status===AVAILABLE)`
造成口径漂移;镜像随运行时内联返回,消掉原先「每换一次运行时打一次 images 接口」的 N+1。

前端收敛到 `features/sandbox/useOrchestrationCatalog`,三处编排页共用,不各写一遍取数与筛选;
`enabled=false`(解题赛题目不需要环境)时不发请求并给空目录,页面无需为此写第二套分支。

### 6.21 教师取学生名录的边界(2026-08-05)

课程成员、实验小组、实验报告三处都要显示学生姓名,而 `course_member`/`group_member`/
`experiment_report` 都只存 `student_id`。原先三处前端都调 `GET /accounts`(账号目录)自行匹配,
但该接口是 `RequireTenantAnyRole(RoleSchoolAdmin)` —— 教师调用**运行期必被 403**。

**收敛口径**(两件事分开处理,都不放开账号目录):

1. **显示姓名** = 业务模块随记录下发。M6 `MemberDTO`、M7 `GroupMemberDTO`/`ReportDTO` 增加
   `student_name`/`student_no`,由所属模块经 `contracts.IdentityService.BatchGetAccounts`
   一次批量解析(跨模块经接口取,符合铁律 3;批量取回避免 N+1)。取不到时给「已离校学生」
   确定性占位,不留空白让界面无从解释。
2. **挑选学生** = M1 新增 `GET /org/classes/{id}/students`(教师只读,只出 `id`/`name`/`no`)。
   组织结构本就对教师只读开放,班内名录是同一维度的下一层;而账号目录带手机号掩码、账号状态、
   角色,属学校管理员能力,不该为了「挑个人」整份放开。同一份查询另经
   `contracts.IdentityService.ListClassStudents` 供 M6 复用,不写两遍。

**顺带纠正一处契约与需求不符**:M6 需求 C1 写的是「教师按班级批量添加」,而
`POST /courses/{id}/members/batch` 原先收 `{ student_ids: [] }` —— 把「按班级」实现成了
「前端先按班级查出编号、再回传编号数组」,既依赖越权接口,也让内部标识进了请求体。
现改为 `{ class_id }`,学生由 M6 经契约解析,粒度与需求一致。

### 6.22 对局列表的师生视角(2026-08-05)

教师实时监控页需要看「本赛事哪一局卡住了」,而 `GET /contests/{id}/battle/matches` 原先在学生组、
service 里固定按 `currentAccountTeam` 过滤 —— 教师调用**运行期必被 403**(教师不在任何参赛队伍里)。

**收敛口径**:路由移到师生共享组,service 按身份分视角 —— 赛事组织者与学校管理员见本赛事
全部对局,其余账号退回本队对局,未报名者读不到任何对局。同一张表的分页查询仍只有一份 SQL
(按 `team_id` 是否为 0 分叉),与 §6.5 里作业列表、提交列表的处理方式一致;
不为教师另开 `/contests/{id}/battle/all-matches` 之类的同义路由。
回放取件边界不变:`authorizedBattleReplay` 仍限参赛队伍成员,组织者可见对局状态不等于可下载他人轨迹。

### 6.23 视频播放的鉴权载体(2026-08-05)

§6.7 定档课时视频走 `mode=stream` 授权、由 `<video src>` 直连统一文件服务。但
`GET /api/v1/storage/download` 原先挂的是 `authn.Middleware()`,它只读 `Authorization` 头 ——
而 `<video src>` 由浏览器自身发起、发不出该头,故**视频必然 401**,附件下载(XHR)不受影响。
`docs/总-API接口总览.md` 已写明本入口应接受「Bearer 头或路径受限 Cookie」,是实现没跟上文档。

**修法**:`auth` 包把工具代理已有的浏览器鉴权实现抽成共用底座,派生出
`FileAccessMiddleware`(接受 Bearer 或 `chaimir_access` Cookie,**不**接受 query token ——
`token` 参数位已被投放授权占用),统一下载入口改用它;M6 签发 `mode=stream` 授权时,
在同一响应里把已验证的会话凭据写成作用域限定 `/api/v1/storage` 的 HttpOnly Cookie。
Cookie 路径常量落在 `storage.DownloadCookiePath`,不让业务模块各写一遍字符串。
附件的 `mode=download` 仍是 XHR 取件,不写 Cookie。

### 6.24 「后端有能力、前端无入口」五处的收口(2026-08-05)

§6.18 曾把这些登记为"有理由的不可达",复查后判定其中四处的理由都不成立 ——
要么是前端缺功能,要么是接口本身就该删。按「不留历史冗余、该删就删」逐项收口:

| 能力 | 处置 | 依据 |
| --- | --- | --- |
| `content.getItemFace` | **接上**:共享资源库新增「预览题面」弹层 | 跨校克隆前得先看清题目内容。题面接口已剥离答案/判题配置/flag(`defaultSensitivePaths` + 作者声明),跨校可见的正是这一层 —— 原来的理由("学生题面由业务模块投影下发")只覆盖学生侧,漏了教师跨校选题这个真实场景 |
| `content.uploadAttachment` / `issueAttachmentDownloadGrant` | **接上**:题目表单新增正文附件区 | 附件键契约本轮定档为三类型共用 `body.attachments`(M5 架构 §2.2、接口设计 §6),后端上传、授权与正文引用校验早已完整 |
| `experiment.recycleInstance` | **删除**路由 + service + SDK + openapi 条目 | 它对学生是不可逆销毁、对教师会越过实例归属销毁他人环境,两侧都不该有;资源释放已有三条自动路径覆盖(`finish` 内部回收、后台超时回收、课程结束级联),留着就是一条没有正确调用者的危险入口 |
| `teaching.listChapters` / `listLessons` | **删除**路由 + service + SDK + openapi 条目 | 它们是 `GET /courses/{id}/outline` 的子集形态(outline 还多给进度),前端一直只用 outline。保留"以后可能按需读取"属于 YAGNI,且是同一份数据的第二套读路径 |
| `sim.getBundleGrant` / `getStreamWsUrl` | **保留**,维持不可达 | 见 §6.15:扩展包在隔离 Worker 内的装配契约与 `compute=backend` 的 stream 都未定档,接上就是接口覆盖式假实现 |

顺带补齐一处真缺口:M7 需求 D3 的「课程结束级联回收」此前只有文档、没有实现 ——
课程结束后课内实验实例会一直占着沙箱与仿真会话,直到空闲超时才被后台捡走。
现由 M6 发布 `teaching.course.ended`、M7 订阅后按课程回收(M6 与 M7 同在第 2 层,
同层不得互调,故走事件;逐实例回收 + 只取仍占资源四态,天然幂等可重投)。

### 6.25 内置仿真包的入库路径(2026-08-05)

`GET /sim/packages` 读的是 `sim_package` 表,而 41 个内置包的权威声明是前端
`@chaimir/sim-sdk` 的 TypeScript 源码 —— 两者之间原先**没有任何同步步骤**,于是生产环境的
`sim_package` 表里一个内置包都没有:学生的仿真实验室是空列表、实验编排选不到场景、
课时的仿真形态指向不存在的包。M4 的主体能力在生产完全不可达。

收口方式(详见 04 文档 §4.1 与 09 文档 §2):

```
frontend/packages/sim-sdk/src/builtin/**/package.ts     (唯一真相源)
  → node scripts/codegen/export-sim-builtin-catalog.mjs  (导出标准 sim-package.json 清单)
  → backend/internal/modules/sim/builtin_catalog.json     (go:embed 产物,已提交入库)
  → migrate-and-seed → sim.SyncBuiltinPackages            (幂等 upsert,直接落已上架)
```

三条配套约束:①导出脚本先跑与运行时同一套 `validateSimPackage`(它当场揪出 3 个
"视图未声明职责"的包 —— 这类包在学生打开场景那一刻才会抛错);②入库前走与扩展包
**完全相同**的 `parseBundleManifest`,内置包不因"是平台自己的"而跳过协议校验;
③`scripts/audit/sim-catalog-drift.mjs` 校验产物与源码一致,漏跑导出脚本会被静态检查拦住。

同时删掉验收夹具里手抄的第二份内置包清单(`acceptance_seed_rows.go`):它已漂移出
6 个缺失包和三个错键名(`max_nodes`/`max_ticks` vs 校验口径的 `nodes`/`max_tick`),
现在改为按 code 定位已入库的内置包。

## 7. 后续前端改造验收清单

- 公共认证路由覆盖 `/auth/login`、`/auth/forgot`、`/auth/sso`、`/auth/apply`、`/auth/activate`、`/auth/tenant-select`、`/auth/change-pwd`；SaaS 部署额外开放 `/auth/platform-login`，且没有“选择角色”。
- 四端路径存在且登录后落点正确：`/student/courses`、`/teacher/courses`、`/school-admin/users`、`/platform-admin/schools`；四端都没有仪表盘落地页。
- 侧栏只放主入口；详情、编辑、导入、审核、工作台、行级操作按上下文进入。个人中心不出现在任何一端的侧栏。
- 顶栏通知铃铛只出现在学生、教师、学校管理端；平台管理端顶栏只有任务与下载和头像菜单，其公告能力在侧栏「系统公告」页。
- 平台管理端个人中心只有资料只读、修改密码、登录会话；没有换绑手机号，也不展示手机号/学工号/职称/所属学校字段。
- 平台管理端漏洞题源页只做全局漏洞源的查看与新增/更新；同步与漏洞题草稿转化只在教师端。
- 每个页面的主操作能对应到本文列出的后端接口或明确为前端自有操作。
- 教师端仿真功能只做提交、预览、维护；平台端才做仿真审核通过/驳回。
- 学生端题面、作业、竞赛答题不读取答案、flag、判题配置或 M5 full 内容。
- 学生作业可从课程详情的作业清单进入，刷新后仍能回到本人历史提交；学生不出现申诉列表、判题任务、结果快照、实验报告列表等归属教师/管理员的入口。
- 学生课程列表只呈现课程列表接口真实返回的字段，完成率在课程详情由 outline 一次取回，不为列表逐门课补调用。
- 通知偏好只渲染 `GET /notify/preferences` 返回的类型，强制类型显示为不可关闭且说明原因，前端不硬编码类型清单。
- 所有导入导出和文件下载走任务或授权，不暴露对象存储直链。
- 实验、仿真、答题、对抗回放都进入沉浸式工作台，并绑定真实实例、会话、提交或回放数据。
- 业务实时数据订阅 M10 `WS /api/ws` topic；沙箱终端、判题、仿真 stream 使用模块自有 WS，并通过短时 `ticket` 建连。
- 每个列表页具备加载、空、错误、权限不足、处理中、成功、失败状态。
- 所有用户可见错误都面向用户，并在需要报障时只展示 `trace_id`。
- 小屏无整页横向滚动、遮挡、错位；表格可转卡片或隐藏次要列。
- 可视化具备图例、数值、空/错/载态、键盘或表格替代。
- 动效支持 `prefers-reduced-motion`，除 loading 外没有无限装饰动画。
- 新增功能先确认 `docs/总-API接口总览.md` 和对应模块接口文档；没有后端契约的功能不得虚构。
