# M6 教学 — 接口设计

> RESTful。鉴权沿用 M1 JWT。题目取自 M5、判题调 M3,M6 接口只管教学业务。
> 最后更新:2026-11-27

---

## 1. 通用约定

- Base:`/api/v1/teaching`
- 统一响应体同 M1。错误码段:`6xxxx`(61xxx 课程/62xxx 作业/63xxx 进度/64xxx 成绩)。其中 `62009` 表示自动判题服务未装配或暂不可用,不得复用 `62007` 动态改文案;封面三种失败各有稳定码:`61012` 格式不支持、`61013` 超出大小上限、`61014` 该课程还没有封面。
- 角色:教师建课/批改/管成绩;学生学习/提交。

---

## 2. 课程管理 `[教师]`

> **列表上的补充事实按当前页一次聚合**:课程卡片要显示授课教师、选课人数、本人进度,作业列表要显示提交情况。这些都由列表接口按当前页编号各一次聚合查询给出(教师姓名经 `contracts.IdentityService.BatchGetAccounts` 一次批量解析),不让前端逐门课取统计或逐份作业取提交 —— 一页 20 门课就是 20 个请求。口径:
> - `member_count` = 该课成员数;`my_progress` 只数未删除章节下未删除的课时,`completed_count` 是本人状态为「已学完」的课时数,与 `/outline` 同口径;还没有课时为 `0/0`。
> - `submission_stats` 按学生去重:`submitted_count` 是交过的人数,`pending_count` 是最近一次提交在等老师评分的人数,与批改中心「待批改」同口径(提交状态为「批改中」;自动判题还没回来的不算)。
> - `my_submission.attempts` 是本人已用次数,`latest_status` 是最近一次提交的状态(还没交为 `0`)。
> - 教师姓名读不到(账号已注销)时 `teacher_name` 为空串,页面不显示该项。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/courses?role=teacher&status=` | 我的课程;每门课带授课教师姓名 `teacher_name` 与选课人数 `member_count` |
| GET | `/courses/shared?keyword=&page=&size=` `[教师/校管]` | 课程库：发现其他租户当前共享的课程，返回受限目录投影(另带章节数 `chapter_count`,只给数量,见安全设计 §5) |
| POST | `/courses/cover` | 上传课程封面(multipart,字段 `file`),返回 `{ object_ref, file_name, size }`。**不绑课程 id**:新建课程时还没有 id,故先落到**上传教师自己的带上传编号暂存位** `{tenant_id}/teaching/cover/stage/{teacher_id}/{upload_id}/cover.{jpg\|png\|webp}`;同一教师的不同表单不会互相覆盖。随 `POST /courses` 或 `PATCH /courses/{id}` 提交时,服务端复制到不可变正式位 `{tenant_id}/teaching/cover/{course_id}/{upload_id}/cover.{ext}`。只有业务事务成功后才删除暂存对象;失败保留暂存引用供重试,附件桶生命周期负责回收过期暂存。只放行 JPEG/PNG/WEBP,校验复用 `platform/upload` 的三重嗅探(`BrandImageKindValid`);上限 `UPLOAD_COURSE_COVER_MAX_BYTES` |
| POST | `/courses/{id}/cover/access` | `[学生/教师/校管]` 按当前课程范围授权后换取封面投放授权(mode=stream,可重复消费),交给 `GET /storage/download?token=` 显示。封面只对能看到该课程的人可见,故必须鉴权,不做公开路径 |
| POST | `/courses` | 创建课程(草稿) |
| PATCH | `/courses/{id}` | 编辑 |
| POST | `/courses/{id}/publish` | 发布 |
| POST | `/courses/{id}/end` | 结束 |
| POST | `/courses/{id}/archive` | 归档 |
| POST | `/courses/{id}/clone` | 克隆 |
| POST | `/courses/{id}/share` | 共享到课程库 |
| DELETE | `/courses/{id}/share` | 取消共享,课程恢复私有 |
| POST | `/courses/{id}/invite-code/refresh` | 刷新邀请码 |

课程 `semester` 填写学校登记的完整学期名称。M6 保留课程学期文本，不反向读取 M11 学期配置；M11 报送与审核时通过课程只读契约取得该名称，在本租户配置中精确解析实际学期编号。课程表单不得给出与学校登记名称无关的固定季节示例，或暗示不同名称会自动映射。

课程表单按浏览器本地自然日编辑开始、结束日期，回显复用共享本地时间转换，不截取 UTC 日期；保存分别取当天 `00:00:00.000` 和 `23:59:59.999` 后转成 RFC3339。不存在的日期在表单就近提示，重复打开、保存不得使日期漂移。

创建课程、变更共享状态和课程状态时，业务写入、M1 审计与响应转换在同一租户事务内完成，失败均回滚。编辑基础信息和刷新邀请码也在提交前构造响应；失败只清理本次新封面，旧封面保留。学生邀请码选课先取得用于回显的本人档案，再提交成员关系，档案读取失败不得留下已入课记录。

课程状态变更先锁定课程并复核前置状态。手动结束、归档及到期自动结束均与课程行的 `ended_event_pending_at` 一起提交；请求成功表示状态及回收意图已保存，不等待消息服务。现有课程生命周期任务按 `TEACHING_COURSE_LIFECYCLE_BATCH_SIZE` 分批推进到期状态并投递待发事件，优先结束已到结束时间的课程。投递在单条课程锁内等待消息服务持久确认，确认并提交成功才清空待发时间；失败、进程中断或确认提交失败均保留请求供下轮重试。多个副本跳过其他副本持锁的课程，M7 对重复事件幂等回收；不保证数据库和消息服务恰好一次提交，不把已保存状态因暂时投递失败报告为接口失败。

共享与取消共享均仅限本租户课程负责人,返回更新后的同一课程 DTO并写统一审计；共享要求课程已发布,取消共享可对已共享课程重复执行。取消后仅将`visibility`恢复私有,课程内容、学生成员、成绩、邀请码和已经建立的独立克隆保留；后续跨租户克隆必须被拒绝。克隆在源课程行锁内校验权限并读取结构与材料；已经通过该校验的复制可在来源事务结束后继续准备依赖，取消共享阻止尚未通过校验的新复制。教师菜单按服务端`visibility`显示共享或取消共享,请求期间阻止重复动作,失败保留权威状态并显示错误。

教师“共享资源库”分别呈现题目与课程，两类列表各自从所属模块读取；课程目录使用普通租户只读事务及现有共享SELECT策略，仅查询`visibility=2`、非草稿、未删除且不属于当前租户的课程，关键词按课程名称和说明作不区分大小写的字面匹配。分页总量与列表使用相同条件，按更新时间和ID倒序。课程目录响应只包含`id/name/description/type/difficulty/semester/credits/updated_at/chapter_count`，不返回源课程邀请码、课时正文、成员、作业、提交或成绩。目录中“克隆课程”沿用现有`POST /courses/{id}/clone`，服务端重新检查当前共享状态和源课程锁；撤销发生后不得沿用旧列表授权。成功后进入目标租户新建的独立草稿，失败保留输入和可恢复提示；跨租户直接打开原课程详情仍被拒绝。

> **封面显示位**:课程详情页与课程编辑表单换取授权显示真实封面;**课程列表的缩略图固定用平台纸材质加题识,不逐行换授权** —— 一页 20 门课就要换 20 次授权,而列表接口早已按可见性筛过课程,逐行再换一次不产生任何新的鉴权判断,只是把一次列表渲染变成二十多个请求。
>
> **`cover_ref` 的三种入参各自明确,服务端不做猜测**:空串 = 不设封面(已有封面则清空);等于该课程当前引用 = 这次没动封面(编辑表单会把已有引用原样回传);其余只接受**本人带上传编号的暂存位**引用并复制到新的正式位。回传本课程已替换的正式引用，或保存期间当前封面发生变化时，返回编辑冲突；不将旧引用恢复为当前封面。正式位不可覆盖；失败时只清理本次新正式对象,暂存引用保留供重试。
>
> **暂存生命周期**:统一对象存储为附件桶维护 `chaimir-upload-state=temporary` 标签的过期规则，保留天数由 `UPLOAD_COURSE_COVER_STAGE_RETENTION_DAYS` 配置。上传时原子附带临时标签，正式复制明确清空标签，防止正式封面被误删；启动时不能配置该规则则明确失败，不静默跳过。提交成功立即清理暂存，失败保留至过期以便重试；不扫描全桶或增设业务表。过期后需重新上传。
>
> **克隆不继承封面**:正式对象归属来源课程，不能被副本共用；否则源课程换封面会删掉副本仍在用的图。克隆出的课程无封面，由新作者自行上传。

课程课时的视频和附件必须独立复制到目标租户、新课时的材料路径，保留文件名、类型和大小；未上传文件的材料课时仍保持空引用。复制时锁定源课时，验证原对象属于该租户和课时，防止源课程替换材料时提前删除。复制或事务回调失败时回滚目标课程并补偿本次对象；提交结果不明时保留本次材料，不以事后查询作为删除依据，源对象不变。克隆成功后用新课时签发普通材料授权，源课程后续换文件不能影响副本。

克隆仅允许本人课程或已发布的共享课程。本校来源在普通租户事务内读取；外校来源经受控 M6 事务读取并锁定，形成不含成员、提交和成绩的独立副本后结束来源事务。目标课程、章节、课时、作业、M5 引用和 M1 审计统一在目标学校的普通租户事务内提交；失败补偿只删除尚未尝试提交的本次材料，不开放特权事务跨模块借用。

来源读取、依赖准备与目标保存顺序执行，不嵌套申请数据库连接。M6 只在源课时锁内复制可被替换删除的材料；M5/M7 先在各自短事务中读取并校验来源快照，事务提交后再复制对象及调用其他模块。来源提交失败时不继续准备；来源素材随后消失时整体失败并补偿本次副本，不能保存缺失依赖的课程。模块准备只接受已授权课程产生的内部请求，不开放独立的跨校读取入口。

副本须包含完整依赖：作业题目由 M5 按来源学校与锁定版本复制为新作者的私有已发布版本，使用新编号并重算摘要，不能匹配目标校同名题。来源课程的实验及课时引用的未绑定课程实验由 M7 复制为新课程草稿；未绑定实验必须属于来源课程教师，其他课程的实验不能夹带。模板、检查点题目、隐藏套件和租户初始化素材同步本地化，课时改用新实验编号。各模块在自己的准备批次内去重引用。M2 保留冻结镜像闭包及链间连接，仅改写租户素材引用并重算、登记快照摘要；不读取最新镜像替代。M7 同时复制检查点输入、仿真参数与阶段常量中的来源租户代码或附件，保留平台素材，拒绝其他租户与桶；使用既有附件大小限制，不新增配置。M4 审核包为全局不可变版本，保留精确版本并校验目标学校可用性。依赖失败时不保存不完整课程；各模块的业务记录、引用、事件 outbox 与审计随目标课程同事务提交。
>
> **换封面即清理旧对象**:正式位按课程和上传编号分开,所以一个封面对象只被一门课程引用;`PATCH /courses/{id}` 成功提交后删除旧对象(校验它仍落在受控正式封面前缀内),失败不触碰旧对象,避免事务回滚后课程引用与对象内容不一致。

## 4. 选课与成员

邀请码加入要求非空邀请码，服务端按课程与成员准入核验；成功后重新读取当前课程列表。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/courses/join` `[学生]` | 邀请码加入，返回已加入课程的成员信息，与成员列表单条结构一致 |
| GET | `/courses?role=student` `[学生]` | 我加入的课程;每门课带授课教师姓名 `teacher_name` 与本人学习进度 `my_progress{lesson_count,completed_count}` |
| GET | `/courses/{id}/members` `[教师]` | 成员列表,每条含 `student_name`/`student_no` |
| POST | `/courses/{id}/members/batch` `[教师]` | 按班级批量添加,请求体 `{ class_id }` |
| DELETE | `/courses/{id}/members/{sid}` `[教师]` | 移除 |

批量添加的粒度是**一个班级**(需求 C1「教师按班级批量添加」):请求只带 `class_id`,由 M6 经
`contracts.IdentityService.ListClassStudents` 解析该班在校学生后逐个入课。不接受客户端回传学生编号数组 ——
学生编号是内部标识,而能取到全校账号目录的 `GET /accounts` 属学校管理员能力,教师端不该经它取人;
班内学生名录另由 M1 `GET /org/classes/{id}/students`(教师只读,只出编号/姓名/学号)提供,供小组编排等挑人场景使用。

成员姓名与学号由 M6 经同一契约批量解析后随成员下发(`course_member` 只存 `student_id`):
批改与编组界面必须显示人名,让客户端自己再拉一份账号目录既越权也会 N+1。

### 5.1 课时材料上传 `[教师]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/lessons/{id}/material` | multipart 上传课时视频或附件,写入 `{tenant_id}/teaching/material/{lesson_id}/{upload_id}/{file_name}` 并把 `object_ref`/`file_name`/`size`/`content_type` 落进 `lesson.content_ref` |

每次上传使用独立对象路径，保留原文件名；不能在数据库提交前覆盖已有材料。保存时锁定课时，按最新课程归属重新校验授课教师，材料引用、响应转换和 M1 审计同事务完成。课时编辑使用同一行锁，避免标题编辑恢复已被替换的引用。失败时先区分回滚与提交结果不明，后者保留本次对象，不以暂时查不到引用作为删除依据；成功后再清理旧对象。清理失败保留可定位日志，不能把已确认提交的替换报告为失败。

普通课时读取与上传响应不返回可直连的 `object_ref`;学生或教师取件统一调用 `POST /lessons/{id}/material/access`,由后端按课程权限签发视频 `mode=stream` 或附件 `mode=download` 授权,再交给统一文件服务。

`POST/PATCH lesson` 对视频、附件形态不接受客户端对象引用字段。同一材料形态仅编辑标题、排序时保留服务端已有引用;新建材料课时或切换到另一材料形态时必须随后调用上传接口,由服务端写入新引用。

上传后 `lesson.content_type` 按文件类型置为视频(1)或附件(3);同一课时重复上传即替换(`content_type` 单值,课时只有一种形态)。文件类型经 `upload.CourseMaterialKindValid` 校验:视频 `mp4`/`webm`,文档与图片沿用附件族;大小上限 `UPLOAD_COURSE_MATERIAL_MAX_BYTES`。

`/material/access` 是师生共用的投放入口,权限走 `courseReadAccess`(授课教师或课程成员),响应 `{ token, mode, file_name, size, content_type, expires_at }`;客户端拿 token 请求 `GET /api/v1/storage/download?token=`。视频的 `mode=stream` 支持 Range 与重复消费,配合 `lesson_progress.video_pos` 实现续播;附件的 `mode=download` 仍是一次性取件。

签发 `mode=stream` 授权时,本接口同时写入作用域为 `/api/v1/storage` 的路径受限 `chaimir_access` Cookie —— `<video src>` 由浏览器自身发起,发不出 `Authorization` 头(与 M2 浏览器工具代理同一处理,见 `docs/总-API接口总览.md` §统一文件服务)。`mode=download` 由 XHR 带 Bearer 头取件,不写 Cookie。

> 课时读取与上传响应均不返回材料对象引用，前端统一经授权接口取件，不拼接对象存储地址(见 `docs/总-API接口总览.md` §统一文件服务)。

| GET | `/assignments/{id}` | 学生仅读已发布作业;授课教师可读本课程草稿作业,题面取自 M5 且过滤答案 |
| GET/POST | `/assignments/{id}/draft` | 仅当前学生课程成员读写已发布作业的服务端权威草稿(自动每60s + 手动) |
| POST | `/assignments/{id}/submit` | 提交结构化答案;客观题经 M6 outbox 转 M3 判分 |
| GET | `/submissions/{id}` | 查看反馈(成绩/评语/判题详情) |

保存草稿成功响应固定为 `{ updated_at }`,只返回服务端实际落库时间;读取草稿仍返回完整草稿结构。前端不得自行拼装或用开放对象代替该响应。

学生的作业详情、草稿读取、草稿保存和正式提交都必须在服务端重新检查作业为已发布状态,不能把学生列表过滤当作按 ID 访问的授权。详情接口同时供教师编辑和批改使用,授课教师仅能按本课程权限读取未发布作业;学生访问未发布作业统一按不存在处理。

`POST /assignments/{id}/submit` 请求为 `{ "answers": { "<assignment_item_id>": <typed_answer> } }`。单选/简答答案为 string,多选/填空为 string 数组,判断为 boolean。答案键必须属于该作业锁定的理论题引用;不得提交代码存储引用、判题器代码或客户端选择的评分方式。题目满分与 M5 锁定版本一致。未作答允许省略对应键,客观题按零分判定。

创建、编辑、保存草稿、提交及评分入口均拒绝未知结构字段,不静默接受已删除的代码提交或评分模式字段。草稿与提交复用 `pkg/question` 的题型校验;填空数组用空字符串保留未作答的位置。数组元素须为字符串。教师批改面板必须展示按锁定题面组织的学生答案;简答分数为整数,不超过本次提交的简答题总分,与客观题分数合并后统一执行迟交扣分。

教师评分与自动判题事件处理均先锁定同一条提交记录,再读取分数并计算最终分,避免并发回写时使用旧的另一部分成绩。多个客观题事件按提交串行汇总,任何一题尚未完成时不得结算。

作业评分遵守课程锁分:即使客观题还在等待结果,也不能向已锁定课程写入人工分。人工评分及自动合分产生最终成绩时,分数更新与 `teaching_grade_event_outbox` 写入必须使用同一个 M6 事务;锁分校验或事件写入失败时一起回滚。事务提交后只负责尽快投递已持久化的事件,不能先提交分数再另开事务生成事件。

创建或编辑作业时,题目满分之和不得超过提交分数字段的有符号 32 位整数上限;在边界用宽整数累加后校验,避免每道题都合法而自动分、人工分合计溢出。

M3 执行失败与答案错误必须区分:失败事件记录原因并撤销本次提交的自动分、最终分,保留人工分,等待判题恢复;不得按零分结算。撤销后提交回到「已提交」;汇总自动分时,任一题记录了执行失败原因就不结算,直到重判给出结果。判题结果按完成时间幂等写入,允许重判的新结果替换旧结果,过期事件不覆盖较新结果。派发 worker 的结束确认也不得清除已写入的判题失败原因。

> 作业提交只接受 M5 锁定理论题的结构化答案,拒绝代码归档和对象存储引用。详情只返回学生答案、评分与评语,不返回内部判题任务引用、M5 标准答案或解析。

提交创建、批改、列表与详情共用同一分数契约:`auto_score`、`manual_score`、`final_score` 仅在对应数据库值非 NULL 时返回,合法 0 分必须返回数字 `0`。尚未评分时保持 NULL 并省略字段,不得先写最终 0 分或按是否大于 0 判断分数存在性;数据库行转换、领域对象和公开 DTO 必须完整保留该空值语义。

### 6.3 师生同路由、按身份分视角

这两条路由师生共用,服务端按「是否为本课程授课教师」决定视角,不为两种身份各开一条路由:

| 方法 | 路径 | 教师视角 | 学生视角 |
| --- | --- | --- | --- |
| GET | `/courses/{id}/assignments?page=&size=` | 含草稿的分页作业外壳,每份带全班提交统计 `submission_stats{submitted_count,pending_count}` | 只回已发布作业的分页作业外壳,每份带本人提交情况 `my_submission{attempts,latest_status}` |
| GET | `/assignments/{id}/submissions` | 该作业全部学生提交(批改列表) | 只回本人历次提交 |

`/assignments/{id}/submissions` 支持 `status` 筛选(省略或 0 表示不筛),筛选与 `total` 同口径 —— 批改台的「待批改/已出分」数量取这里的服务端 `total`,不由前端统计当前页。

教师评分成功后,提交队列及该作业的待批改/已出分/迟交统计必须同时重读。刷新期间显示未知数量,读取失败保留可恢复错误;不得只刷新提交状态而保留评分前统计,也不得在浏览器按一次评分本地增减全量数。该刷新复用全站异步资源的显式刷新次数,不新增统计接口或另一套缓存。

`/courses/{id}/assignments?page=&size=` 是**学生取得 `assignment_id` 的唯一入口**(课程大纲只含章节课时,`LessonContentType` 不含作业);`/assignments/{id}/submissions` 让学生刷新页面后取回 `submission_id`,再走 `GET /submissions/{id}` 看反馈 —— 否则提交编号只存在于上一次 `POST submit` 的响应里,刷新即丢(违反 FE-7)。两条都返回 `{list,total,page,size}`,且只返回作业外壳与提交记录,题目与题面仍只经 `GET /assignments/{id}` 走 M5 题面接口。学生视角的 `student_id` 由服务端会话填入,不接受客户端传参。

> 提交流程:M6 按 M5 锁定版本验证题型答案，同一事务写 submission、每道客观题的 judge outbox、清除本次作业草稿、写 M1 审计并构造响应，任一步失败都回滚；worker 将结构化答案派给 M3 J7。J7 在后端无容器判分并通过持久事件回写 M6；简答题留待教师评分。学生只看到 M6 评分结果，不接触 M5 答案。

创建作业的外壳、题目引用、M5 使用关系、M1 审计和响应同事务完成；编辑与发布也在业务提交前完成响应转换。不得在接口报错时留下已创建作业、已消费次数、待判任务或已清除草稿。

两种置顶入口共用显式目标状态契约:必须提供非空布尔`is_pinned`,允许`false`,缺失、null或非布尔拒绝。服务端不切换当前状态,也不默认置顶;重复提交同一目标状态保持一致。客户端按最新已读状态发送目标值,动作在途时禁用对应控件,成功后重读,失败保留原状态及可恢复提示。权限仍以当前租户的授课教师为准。

讨论采用同一分页流呈现主帖和回复,按置顶、创建时间及ID倒序排列,教师和学生共用读取、发帖、回复与点赞实现;只有授课教师显示置顶和删除。`POST /courses/{id}/posts` 使用 `{content,parent_id?}`;不传父帖为发帖,传入父帖为回复,父帖必须未删除且属于当前租户及当前课程。父帖读取与回复创建在同一事务内完成,不接受跨课程父帖或对已删除内容继续回复。

`GET /courses/{id}/posts?page=&size=` 返回 `{list,total,page,size}`,每条保留 `parent_id` 表示回复关系,并在父帖仍可见时返回只读投影 `parent_content`。父帖引用在同一查询中按租户、课程和未删除条件连接,不拷贝存储正文、不逐条查询;父帖删除后回复仍保留,前端显示“原讨论已移除”,不得重新暴露被删除正文。两端在回复卡上显示所回复内容,正文和引用均用React文本节点呈现。发布失败保留输入并就近显示错误,成功后清空输入并重读服务端分页;切换课程重新挂载讨论区,不携带另一课程的待回复目标。

评价读写统一要求当前租户课程已结课或已归档且本人为课程成员。GET只按服务端账号返回本人评价,响应为`{review: ReviewDTO|null}`;未评价明确为null,读取失败不得作为未评价创建空表单。POST仍按同一课程/学生更新唯一评价,返回保存后视图。页面离开、刷新或换设备后先恢复服务端评分/正文,已评价状态仍可更新;教师不经此入口读取实名评价。未加入、跨租户或未结束课程拒绝读写。

## 8. 单课程成绩 `[教师]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/PUT | `/courses/{id}/grade-weights` | 教师读取/设置权重配置(和=100%校验) |
| GET | `/courses/{id}/grade-sources` | 授课教师读取本课程完整可选成绩来源，返回 `{source_type,source_ref,title,max_score}` 数组；作业和考试均绑定本课程已发布作业/测验，实验取本模块的事件投影 |
| POST | `/courses/{id}/grades/compute` | 按权重计算全班成绩 |
| GET | `/courses/{id}/grades?page=&size=` | 成绩汇总,返回 `{list,total,page,size}` |
| PATCH | `/courses/{id}/grades/{sid}` | 手动调整(仅授课教师;M6 依据本模块写保护投影同步拦截已锁定成绩,申诉受理后的单课程改分仍由 M6 执行) |
| GET | `/courses/{id}/grades/export` | 创建成绩 Excel 导出任务并返回 transfer 任务快照 |
| GET | `/courses/{id}/grades` `[内部]` | M11 聚合只读取用(带 tenant_id) |
| `teaching.grade.updated` | 事件 | M6 成绩变更后发布,供 M11 重算 GPA |

> 权重保存和成绩计算均须核对作业来源属于当前租户、当前课程且未删除;不能仅凭来源编号读取其它课程提交。计算前须重新校验已保存权重非空、每项大于 0、无重复且合计为 100%,不满足时拒绝整次计算,不得写入零分或部分成绩。来源校验失败沿用成绩权重错误码,技术原因仅保留在日志错误链。

> 三类来源统一绑定真实对象。考试使用 M6 既有作业/测验的提交与批改，不将 M5 试卷当作考试成绩。同一作业不能同时按“作业”和“考试”重复计入；每项取学生已完成评分的最高得分，按该次权威满分归一为百分制后乘权重；未提交为零，仍待评分的提交阻断整次结算，不当作零分。既有成绩和提交不自动重算、删除或覆盖。

> M7 经统一事务 outbox 发布实验课程绑定与得分事件，M6 只写自己的 `course_experiment_source` 和 `course_experiment_score` 最小投影，不直接调用同层 M7 或读其表。绑定按定义的单调修订号处理，旧绑定不得恢复下架/移除的来源；同实例同学生的得分只接受更高 `score_revision`，重投和乱序不回退。协作实验事件带实际成员，满分包含该实例检查点与应交报告的总分，保留原始得分和对应满分后归一。保存、可选列表和计算共用同一租户/课程/发布/有效满分校验。

> 实验事件在来源行锁下按实例最新修订整体替换成员得分，旧事件不能重新插入已移除成员。已提交但未批改的报告保留为 `pending`；`64006` 提示完成评分后再结算。此时整次结算不写入部分课程成绩。

> 全班计算须按平台分页上限遍历全部提交和课程成员,不能把内部读取上限当成一个公开列表页而只计算前 100 条。所有分页读取、成绩写入及成绩事件 outbox 均在同一租户事务完成,任一页失败回滚整次计算。`TEACHING_COURSE_GRADES_MAX_ROWS` 仍只约束跨模块成绩读取,不截断全班计算。

> 成绩导出在校验课程负责人后，将 M6 请求中的 `course_id`、发起账号与 pending transfer 任务、M1 审计一起写入本校普通事务，提交成功后返回任务快照。M6 worker 按请求调用 transfer 的租约领取接口后分批读取 `course_grade` 生成真实 xlsx，产物经统一文件服务写入对象存储并完成任务；失败由 transfer 统一重试。客户端下载文件需调用 `/api/v1/transfer/tasks/{id}/download-grant` 获取短时授权；不得在 M6 接口直返 base64 文件体、对象存储直链或内部 SQL/批处理细节。

成绩导出每次租约使用独立对象路径；上传或生成失败时限时补偿，清理脱离请求取消并保留错误链。调用 transfer 完成登记后若结果不明，保留对象，由现有任务状态对账继续处理，不以报错作为删除依据。

成绩 XLSX 的 `course_id`、`student_id` 使用文本单元格保存完整十进制 ID，成绩仍使用数值单元格，人工覆盖和锁定状态保持布尔值。任务对账读取失败时仍安排下一次检查，并返回读取失败及调度失败的完整错误链；仅确认任务不存在或已终止时删除请求。

> **成绩锁定一致性**:审核流程状态仍由 M11 管理,但 M6 为了同步拦截改单课程成绩,在本模块 `course.grades_locked` 持有写保护投影。M11 审核通过、解锁回退、申诉受理与重审重锁均通过事件驱动 M6 更新该投影;M6 不反向查询 M11。申诉改分链路为:学生提交申诉 → M11 受理并发布事件驱动 M6 解锁写保护投影 → 授课教师在 M6 执行单课程改分 → M6 发布 `teaching.grade.updated` 事件 → M11 订阅后重算 GPA、复核预警并重审重锁,再发布事件驱动 M6 恢复写保护投影。
