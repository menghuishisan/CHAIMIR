# M6 教学 — 接口设计

> RESTful。鉴权沿用 M1 JWT。题目取自 M5、判题调 M3,M6 接口只管教学业务。
> 最后更新:2026-08-05

---

## 1. 通用约定

- Base:`/api/v1/teaching`
- 统一响应体同 M1。错误码段:`6xxxx`(61xxx 课程/62xxx 作业/63xxx 进度/64xxx 成绩)。其中 `62009` 表示自动判题服务未装配或暂不可用,不得复用 `62007` 动态改文案;封面三种失败各有稳定码:`61012` 格式不支持、`61013` 超出大小上限、`61014` 该课程还没有封面。
- 角色:教师建课/批改/管成绩;学生学习/提交。

## 2. 课程管理 `[教师]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/courses?role=teacher&status=` | 我的课程 |
| GET | `/courses/shared?keyword=&page=&size=` `[教师/校管]` | 课程库：发现其他租户当前共享的课程，返回受限目录投影 |
| POST | `/courses/cover` | 上传课程封面(multipart,字段 `file`),返回 `{ object_ref, file_name, size }`。**不绑课程 id**:新建课程时还没有 id,故先落到**上传教师自己的暂存位** `{tenant_id}/teaching/cover/{teacher_id}/cover.{jpg\|png\|webp}`(文件名按内容嗅探归一,同一教师反复上传互相覆盖),再随 `POST /courses` 或 `PATCH /courses/{id}` 提交,由服务端搬到该课程的正式位 `{tenant_id}/teaching/cover/{teacher_id}/{course_id}/cover.{ext}`。只放行 JPEG/PNG/WEBP,校验复用 `platform/upload` 的三重嗅探(`BrandImageKindValid`);上限 `UPLOAD_COURSE_COVER_MAX_BYTES` |
| POST | `/courses/{id}/cover/access` | 换取封面投放授权(mode=stream,可重复消费),交给 `GET /storage/download?token=` 显示。封面只对能看到该课程的人可见,故必须鉴权,不做公开路径 |
| POST | `/courses` | 创建课程(草稿) |
| PATCH | `/courses/{id}` | 编辑 |
| POST | `/courses/{id}/publish` | 发布 |
| POST | `/courses/{id}/end` | 结束 |
| POST | `/courses/{id}/archive` | 归档 |
| POST | `/courses/{id}/clone` | 克隆 |
| POST | `/courses/{id}/share` | 共享到课程库 |
| DELETE | `/courses/{id}/share` | 取消共享,课程恢复私有 |
| POST | `/courses/{id}/invite-code/refresh` | 刷新邀请码 |

课程 `semester` 填写学校登记的完整学期名称。M6 保留课程学期文本，不反向读取 M11 学期配置；M11 报送与审核时通过课程只读契约取得该名称，在本租户配置中精确解析实际学期编号。课程表单不得给出与学校登记名称无关的固定季节示例，或暗示不同名称会自动映射。

共享与取消共享均仅限本租户课程负责人,返回更新后的同一课程 DTO并写统一审计；共享要求课程已发布,取消共享可对已共享课程重复执行。取消后仅将`visibility`恢复私有,课程内容、学生成员、成绩、邀请码和已经建立的独立克隆保留；后续跨租户克隆必须被拒绝。共享读取在克隆事务内锁定源课程,取消共享与进行中的跨租户克隆按同一行锁顺序完成,不在撤销成功后沿用先前未授权的读取。教师菜单按服务端`visibility`显示共享或取消共享,请求期间阻止重复动作,失败保留权威状态并显示错误。

教师“共享资源库”分别呈现题目与课程，两类列表各自从所属模块读取；课程目录使用普通租户只读事务及现有共享SELECT策略，仅查询`visibility=2`、非草稿、未删除且不属于当前租户的课程，关键词按课程名称和说明作不区分大小写的字面匹配。分页总量与列表使用相同条件，按更新时间和ID倒序。课程目录响应只包含`id/name/description/type/difficulty/semester/credits/updated_at`，不返回源课程邀请码、课时正文、成员、作业、提交或成绩。目录中“克隆课程”沿用现有`POST /courses/{id}/clone`，服务端重新检查当前共享状态和源课程锁；撤销发生后不得沿用旧列表授权。成功后进入目标租户新建的独立草稿，失败保留输入和可恢复提示；跨租户直接打开原课程详情仍被拒绝。

> **封面显示位**:课程详情页与课程编辑表单换取授权显示真实封面;**课程列表的缩略图固定用平台纸材质加题识,不逐行换授权** —— 一页 20 门课就要换 20 次授权,而列表接口早已按可见性筛过课程,逐行再换一次不产生任何新的鉴权判断,只是把一次列表渲染变成二十多个请求。
>
> **`cover_ref` 的三种入参各自明确,服务端不做猜测**:空串 = 不设封面(已有封面则清空);等于该课程当前引用 = 这次没动封面(编辑表单会把已有引用原样回传);其余只接受**本人暂存位**的引用并搬到正式位 —— 否则教师就能把封面指向他人上传的对象或别的资源类型,而正式位一旦被替换又会连带删掉那个对象。
>
> **为什么不用后台任务清理无引用对象**:暂存位的文件名按内容类型归一,同一教师反复上传只覆盖同一个对象,表单被放弃时最多留下三个小对象且下次上传即被覆盖 —— 不随放弃次数增长。反过来,一个扫描对象存储的清理任务要么让地基层认识业务表(反向依赖),要么在每个模块各写一份(同类问题两套方案),两者都违反架构铁律。搬迁后的对象则一定有引用者:课程写库失败时本接口立即删掉刚搬过来的对象。
>
> **克隆不继承封面**:封面对象落在原作者的受控前缀下,跨租户克隆时目标租户拿不到投放授权;而让两门课共用同一对象,又会在任一方换封面时删掉另一方仍在用的图。故克隆出的课程无封面,由新作者自行上传。
>
> **换封面即清理旧对象**:正式位按课程分开,所以一个封面对象只被一门课程引用;`PATCH /courses/{id}` 检测到引用变化时删除旧对象(校验它仍落在本人受控封面前缀内),避免附件桶堆积。

## 3. 内容管理 `[教师]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/courses/{id}/chapters` | 创建章节 |
| PATCH/DELETE | `/courses/{id}/chapters/{cid}` | 更新/删除章节 |
| POST | `/chapters/{id}/lessons` | 创建课时 |
| PATCH | `/chapters/{id}/lessons/{lid}` | 更新课时标题、内容形态和引用;课时材料改走材料上传接口 |
| DELETE | `/chapters/{id}/lessons/{lid}` | 删除课时 |

> 章节与课时**没有独立的只读列表接口**:读取统一走 `GET /courses/{id}/outline`(§6),
> 它一次返回课程 + 章节 + 课时 + 本人进度。单开「只取章节」「只取某章课时」是同一份数据的
> 子集形态,会形成第二套读路径 —— 前端也确实一直只用 outline。

章节、课时和按班级添加成员的本地校验统一复用 `useFormValidation`：失焦或提交激活对应提示,修改后按当前值重算,不依赖再次提交。课时切换形态只移除不适用的仿真名称或文件错误,标题错误独立保留；原有材料未换形态时仍可不选文件。服务端保存和上传错误单独呈现,不把整个表单错误挂到标题字段。

## 4. 选课与成员

学生邀请码加入表单复用共享字段校验，失焦或提交后按当前输入更新必填提示；服务端拒绝独立展示。成功仍清空邀请码并刷新课程列表，不改变成员准入规则。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/courses/join` `[学生]` | 邀请码加入 |
| GET | `/courses?role=student` `[学生]` | 我加入的课程 |
| GET | `/courses/{id}/members` `[教师]` | 成员列表,每条含 `student_name`/`student_no` |
| POST | `/courses/{id}/members/batch` `[教师]` | 按班级批量添加,请求体 `{ class_id }` |
| DELETE | `/courses/{id}/members/{sid}` `[教师]` | 移除 |

批量添加的粒度是**一个班级**(需求 C1「教师按班级批量添加」):请求只带 `class_id`,由 M6 经
`contracts.IdentityService.ListClassStudents` 解析该班在校学生后逐个入课。不接受客户端回传学生编号数组 ——
学生编号是内部标识,而能取到全校账号目录的 `GET /accounts` 属学校管理员能力,教师端不该经它取人;
班内学生名录另由 M1 `GET /org/classes/{id}/students`(教师只读,只出编号/姓名/学号)提供,供小组编排等挑人场景使用。

成员姓名与学号由 M6 经同一契约批量解析后随成员下发(`course_member` 只存 `student_id`):
批改与编组界面必须显示人名,让客户端自己再拉一份账号目录既越权也会 N+1。

## 5. 课程学习 `[学生]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/courses/{id}/outline` | 章节课时目录 + 完成状态 |
| GET | `/lessons/{id}` | 课时内容(实验/仿真返回引擎拉起入口) |
| POST | `/lessons/{id}/progress` | 上报进度(视频位置/时长/完成) |
| POST | `/lessons/{id}/material/access` | 课时材料投放授权 `[师生]`:视频回 `mode=stream`、附件回 `mode=download`,由 `content_type` 决定,不接受客户端指定 |

### 5.1 课时材料上传 `[教师]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/lessons/{id}/material` | multipart 上传课时视频或附件,写入 `{tenant_id}/teaching/material/{lesson_id}/{file_name}` 并把 `object_ref`/`file_name`/`size`/`content_type` 落进 `lesson.content_ref` |

普通课时读取与上传响应不返回可直连的 `object_ref`;学生或教师取件统一调用 `POST /lessons/{id}/material/access`,由后端按课程权限签发视频 `mode=stream` 或附件 `mode=download` 授权,再交给统一文件服务。

`POST/PATCH lesson` 对视频、附件形态不接受客户端对象引用字段。同一材料形态仅编辑标题、排序时保留服务端已有引用;新建材料课时或切换到另一材料形态时必须随后调用上传接口,由服务端写入新引用。

上传后 `lesson.content_type` 按文件类型置为视频(1)或附件(3);同一课时重复上传即替换(`content_type` 单值,课时只有一种形态)。文件类型经 `upload.CourseMaterialKindValid` 校验:视频 `mp4`/`webm`,文档与图片沿用附件族;大小上限 `UPLOAD_COURSE_MATERIAL_MAX_BYTES`。

`/material/access` 是师生共用的投放入口,权限走 `courseReadAccess`(授课教师或课程成员),响应 `{ token, mode, file_name, size, content_type, expires_at }`;客户端拿 token 请求 `GET /api/v1/storage/download?token=`。视频的 `mode=stream` 支持 Range 与重复消费,配合 `lesson_progress.video_pos` 实现续播;附件的 `mode=download` 仍是一次性取件。

签发 `mode=stream` 授权时,本接口同时写入作用域为 `/api/v1/storage` 的路径受限 `chaimir_access` Cookie —— `<video src>` 由浏览器自身发起,发不出 `Authorization` 头(与 M2 浏览器工具代理同一处理,见 `docs/总-API接口总览.md` §统一文件服务)。`mode=download` 由 XHR 带 Bearer 头取件,不写 Cookie。

> 材料对象引用不直接出现在 `GET /lessons/{id}` 响应之外的任何位置,前端不得拼接 S3 对象存储 地址(见 `docs/总-API接口总览.md` §统一文件服务)。

## 6. 作业与测验

### 6.1 教师
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/courses/{id}/assignments` | 创建作业(从 M5 引用题目/组卷) |
| PATCH | `/assignments/{id}` | 编辑 |
| POST | `/assignments/{id}/publish` | 发布 |
| POST | `/submissions/{id}/grade` | 批改(主观题/报告:给分+评语);给分不得小于 0 或超过该作业题目总分 |

### 6.2 学生
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/assignments/{id}` | 作业详情(题面取自 M5,过滤答案) |
| GET/POST | `/assignments/{id}/draft` | 读取/保存服务端权威草稿(自动每60s + 手动) |
| POST | `/assignments/{id}/submit` | 提交;客观/编程题转 M3 判题 |
| GET | `/submissions/{id}` | 查看反馈(成绩/评语/判题详情) |

保存草稿成功响应固定为 `{ updated_at }`,只返回服务端实际落库时间;读取草稿仍返回完整草稿结构。前端不得自行拼装或用开放对象代替该响应。

> **提交响应字段过滤**:`GET /submissions/{id}` 与提交响应不得直接返回 `submission.content_ref` 原始对象。API 只返回过滤后的 `content`,必须移除 `code_storage_key`、`code_hash`、`object_key`、`storage_key`、`bucket`、`object_ref` 等内部存储实现细节;代码/报告等下载类能力必须另走受控短时授权接口,不得在响应中直返对象存储地址或内部存储字段。

提交创建、批改、列表与详情共用同一分数契约:`auto_score`、`manual_score`、`final_score` 仅在对应数据库值非 NULL 时返回,合法 0 分必须返回数字 `0`。尚未评分时保持 NULL 并省略字段,不得先写最终 0 分或按是否大于 0 判断分数存在性;数据库行转换、领域对象和公开 DTO 必须完整保留该空值语义。

### 6.3 师生同路由、按身份分视角

这两条路由师生共用,服务端按「是否为本课程授课教师」决定视角,不为两种身份各开一条路由:

| 方法 | 路径 | 教师视角 | 学生视角 |
| --- | --- | --- | --- |
| GET | `/courses/{id}/assignments?page=&size=` | 含草稿的分页作业外壳 | 只回已发布作业的分页作业外壳 |
| GET | `/assignments/{id}/submissions` | 该作业全部学生提交(批改列表) | 只回本人历次提交 |

`/assignments/{id}/submissions` 支持 `status` 筛选(省略或 0 表示不筛),筛选与 `total` 同口径 —— 批改台的「待批改/已出分」数量取这里的服务端 `total`,不由前端统计当前页。

教师评分成功后,提交队列及该作业的待批改/已出分/迟交统计必须同时重读。刷新期间显示未知数量,读取失败保留可恢复错误;不得只刷新提交状态而保留评分前统计,也不得在浏览器按一次评分本地增减全量数。该刷新复用全站异步资源的显式刷新次数,不新增统计接口或另一套缓存。

`/courses/{id}/assignments?page=&size=` 是**学生取得 `assignment_id` 的唯一入口**(课程大纲只含章节课时,`LessonContentType` 不含作业);`/assignments/{id}/submissions` 让学生刷新页面后取回 `submission_id`,再走 `GET /submissions/{id}` 看反馈 —— 否则提交编号只存在于上一次 `POST submit` 的响应里,刷新即丢(违反 FE-7)。两条都返回 `{list,total,page,size}`,且只返回作业外壳与提交记录,题目与题面仍只经 `GET /assignments/{id}` 走 M5 题面接口。学生视角的 `student_id` 由服务端会话填入,不接受客户端传参。

> 提交流程:M6 收提交 → 客观/编程题调 M3(`POST /judge/tasks`,带 M5 题目引用)→ M3 回写 → M6 记 submission。判题任务查询与判题进度 WS 属 M3 的教师能力,学生侧的判题结果只经 submission 的 `auto_score`/`manual_score`/`final_score`/`status` 呈现。

## 7. 讨论/公告/评价

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/courses/{id}/posts` | 讨论帖/回复 |
| POST | `/posts/{id}/like` | 点赞 |
| POST | `/posts/{id}/pin` `[教师]` | 设置或取消置顶,请求 `{is_pinned:boolean}` |
| DELETE | `/posts/{id}` `[教师]` | 删除违规帖/回复 |
| GET/POST | `/courses/{id}/announcements` | 公告;GET 支持 `page=&size=` 并返回 `{list,total,page,size}` |
| POST | `/announcements/{id}/pin` `[教师]` | 设置或取消公告置顶,请求 `{is_pinned:boolean}` |
| GET/POST | `/courses/{id}/review` `[学生]` | 读取本人评价/提交或更新课程评价 |

两种置顶入口共用显式目标状态契约:必须提供非空布尔`is_pinned`,允许`false`,缺失、null或非布尔拒绝。服务端不切换当前状态,也不默认置顶;重复提交同一目标状态保持一致。客户端按最新已读状态发送目标值,动作在途时禁用对应控件,成功后重读,失败保留原状态及可恢复提示。权限仍以当前租户的授课教师为准。

课程公告的标题、正文复用 `useFormValidation` 分别校验：失焦或提交后显示当前错误,修正标题不清除正文错误。发布失败独立显示并保留输入,编辑字段不表示服务端已恢复；取消不发写请求。

讨论采用同一分页流呈现主帖和回复,按置顶、创建时间及ID倒序排列,教师和学生共用读取、发帖、回复与点赞实现;只有授课教师显示置顶和删除。`POST /courses/{id}/posts` 使用 `{content,parent_id?}`;不传父帖为发帖,传入父帖为回复,父帖必须未删除且属于当前租户及当前课程。父帖读取与回复创建在同一事务内完成,不接受跨课程父帖或对已删除内容继续回复。

`GET /courses/{id}/posts?page=&size=` 返回 `{list,total,page,size}`,每条保留 `parent_id` 表示回复关系,并在父帖仍可见时返回只读投影 `parent_content`。父帖引用在同一查询中按租户、课程和未删除条件连接,不拷贝存储正文、不逐条查询;父帖删除后回复仍保留,前端显示“原讨论已移除”,不得重新暴露被删除正文。两端在回复卡上显示所回复内容,正文和引用均用React文本节点呈现。发布失败保留输入并就近显示错误,成功后清空输入并重读服务端分页;切换课程重新挂载讨论区,不携带另一课程的待回复目标。

评价读写统一要求当前租户课程已结课或已归档且本人为课程成员。GET只按服务端账号返回本人评价,响应为`{review: ReviewDTO|null}`;未评价明确为null,读取失败不得作为未评价创建空表单。POST仍按同一课程/学生更新唯一评价,返回保存后视图。页面离开、刷新或换设备后先恢复服务端评分/正文,已评价状态仍可更新;教师不经此入口读取实名评价。未加入、跨租户或未结束课程拒绝读写。

## 8. 单课程成绩 `[教师]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/PUT | `/courses/{id}/grade-weights` | 教师读取/设置权重配置(和=100%校验) |
| GET | `/courses/{id}/grade-sources` | 授课教师读取本课程完整可选成绩来源，返回 `{source_type,source_ref,title,max_score}` 数组；作业和考试均绑定本课程已发布作业/测验，实验取本模块的事件投影 |
| POST | `/courses/{id}/grades/compute` | 按权重计算全班成绩 |
| GET | `/courses/{id}/grades?page=&size=` | 成绩汇总,返回 `{list,total,page,size}` |
| PATCH | `/courses/{id}/grades/{sid}` | 手动调整(仅授课教师;M6 依据本模块写保护投影同步拦截已锁定成绩,申诉受理后的单课程改分仍由 M6 执行) |
| GET | `/courses/{id}/grades/export` | 创建成绩 Excel 导出任务并返回 transfer 任务快照 |
| GET | `/courses/{id}/grades` `[内部]` | M11 聚合只读取用(带 tenant_id) |
| `teaching.grade.updated` | 事件 | M6 成绩变更后发布,供 M11 重算 GPA |

> 权重保存和成绩计算均须核对作业来源属于当前租户、当前课程且未删除;不能仅凭来源编号读取其它课程提交。计算前须重新校验已保存权重非空、无重复且合计为 100%,不满足时拒绝整次计算,不得写入零分或部分成绩。来源校验失败沿用成绩权重错误码,技术原因仅保留在日志错误链。

权重和人工总评表单统一按当前输入校验：权重逐行核对来源、占比及重复,并独立显示合计错误；增删行或切换来源时重算适用错误,不通过清空公共错误隐藏其它问题。占比和人工总评以原始文本保留空白,提交前明确拒绝空白和非有限数字；人工总评允许显式0,权重仍要求每项大于0、合计100%。服务端失败单独呈现,不标记有效字段为格式错误,不因字段编辑自动消失。

> 三类来源统一绑定真实对象，删除自由名称和跳过计算分支。考试使用 M6 既有作业/测验的提交与批改，不将 M5 试卷当作考试成绩。同一作业不能同时按“作业”和“考试”重复计入；旧自由名称不能猜测映射或默认计零，教师必须重新选择。每项取学生已完成评分的最高得分，按该次权威满分归一为百分制后乘权重；未提交为零，仍待评分的提交阻断整次结算，不当作零分。既有成绩和提交不自动重算、删除或覆盖。

> M7 经统一事务 outbox 发布实验课程绑定与得分事件，M6 只写自己的 `course_experiment_source` 和 `course_experiment_score` 最小投影，不直接调用同层 M7 或读其表。绑定按定义的单调修订号处理，旧绑定不得恢复下架/移除的来源；同实例同学生的得分只接受更高 `score_revision`，重投和乱序不回退。协作实验事件带实际成员，满分包含该实例检查点与应交报告的总分，保留原始得分和对应满分后归一。保存、可选列表和计算共用同一租户/课程/发布/有效满分校验。

> 实验事件在来源行锁下按实例最新修订整体替换成员得分，旧事件不能重新插入已移除成员。已提交但未批改的报告保留为 `pending`；`64006` 提示完成评分后再结算。此时整次结算不写入部分课程成绩。

> 全班计算须按平台分页上限遍历全部提交和课程成员,不能把内部读取上限当成一个公开列表页而只计算前 100 条。所有分页读取、成绩写入及成绩事件 outbox 均在同一租户事务完成,任一页失败回滚整次计算。`TEACHING_COURSE_GRADES_MAX_ROWS` 仍只约束跨模块成绩读取,不截断全班计算。

> 成绩导出请求先在 M6 自有表持久化 `course_id` 与发起账号,随后创建 pending transfer 任务并立即返回任务快照。M6 worker 按请求调用 transfer 的租约领取接口后分批读取 `course_grade` 生成真实 xlsx,产物经统一文件服务写入对象存储并完成任务;失败由 transfer 统一重试。客户端下载文件需调用 `/api/v1/transfer/tasks/{id}/download-grant` 获取短时授权;不得在 M6 接口直返 base64 文件体、对象存储直链或内部 SQL/批处理细节。

> **成绩锁定一致性(A6 修复)**:审核流程状态仍由 M11 管理,但 M6 为了同步拦截改单课程成绩,在本模块 `course.grades_locked` 持有写保护投影。M11 审核通过、解锁回退、申诉受理与重审重锁均通过事件驱动 M6 更新该投影;M6 不反向查询 M11。申诉改分链路为:学生提交申诉 → M11 受理并发布事件驱动 M6 解锁写保护投影 → 授课教师在 M6 执行单课程改分 → M6 发布 `teaching.grade.updated` 事件 → M11 订阅后重算 GPA、复核预警并重审重锁,再发布事件驱动 M6 恢复写保护投影。
