# M1 身份与租户 — 安全设计

> 教育平台合规要求高。本文覆盖密码、令牌、PII、防爆破、越权、审计、租户隔离。
> 最后更新:2026-11-27

---

## 1. 密码安全

- 哈希算法:**argon2id**(salt 唯一,内存/迭代参数按部署环境调优);不使用 MD5/SHA1。
- 强度策略:最少 8 位,含字母+数字,禁弱口令字典;管理员可配置租户级策略。
- 首次登录:`must_change_pwd=true` 时强制改密后方可使用。
- 管理员重置:生成临时密码并置 `must_change_pwd`,不可见用户原密码(单向哈希)。
- 传输:全站 HTTPS,密码仅明文存在于传输层,落库即哈希。

## 2. 令牌与会话(双 Token)

| 项 | Access Token | Refresh Token |
| --- | --- | --- |
| 形式 | JWT(签名) | 不透明随机串 |
| 有效期 | 15 分钟 | 7 天 |
| 存储 | 仅前端内存，不进 Web Storage 或 URL | 浏览器 HttpOnly/Secure/SameSite=Strict Cookie；服务端仅保存哈希于 `auth_session`/`platform_auth_session` |
| 载荷 | 身份与会话标识；字段见[接口设计](03-接口设计.md#1-通用约定)，角色取服务端权威状态 | 无(仅作凭证) |

**关键策略:**
- **轮转(rotation)**:每次 `/auth/refresh` 签发新 Refresh 并吊销旧记录;旧 Refresh 再次使用 → 判定为重放,吊销该账号全部会话并告警。
- **单端登录**:登录时吊销该账号其余 `status=有效` 的会话。
- **并发边界**:登录、刷新和重放处理在账号行锁内串行执行，先锁账号，再读取当前会话和账号状态。刷新在同一事务重新检查学校有效期、学校账号或平台管理员状态；预认证快照不能作为签发依据。同一旧 Refresh 的并发刷新也按重放处理，吊销已轮转出的会话，并将吊销与重放审计原子提交；数据库或审计故障必须回滚。
- **吊销**:登出、改密、被踢、管理员强制下线均置会话失效。
- **签名**:JWT 统一使用 HS256 签名并固定校验算法，密钥经环境注入,不入库不入仓。
- tenant_id 写入 JWT 并签名,客户端不可篡改以越权访问他校数据。

## 3. PII 与敏感数据

- 手机号:`phone_enc`(对称加密,AES-GCM,密钥经 KMS/环境注入)+ `phone_hash`(HMAC,用于唯一约束与登录查询)。
- 日志脱敏:手机号在日志/响应中掩码(`138****1234`)。
- SSO/LDAP 配置中的 bind 密码等加密存储。
- CAS 登录与回调的 `service` 参数只能使用部署白名单 `IDENTITY_SSO_ALLOWED_SERVICE_ORIGINS` 中的 origin;后端不得接受任意第三方回调域,避免 CAS 票据被引导到非平台域名后换取本系统 Token。
- 验证码:仅存哈希;短信内容不落明文日志。

## 4. 防爆破与限频

| 场景 | 策略 |
| --- | --- |
| 密码登录失败 | 连续失败计数,达阈值锁定账号一段时间(`locked_until`) |
| 短信验证码 | 同号 60s 一条、单日上限;Redis 计数 |
| 验证码校验 | 限尝试次数,过期失效,一次性使用 |
| 接口限流 | 网关层按 IP / 账号限流,防撞库 |

短信登录、找回密码和换绑手机号共用验证码行锁：读取最新记录时锁行，错误次数提交后再返回业务拒绝，不能因账号变更事务返回错误而回滚次数；消费和账号变更则必须同成同败。验证码按创建时间和编号确定最新记录，到期时刻即无效。

激活码仅能把当前仍待激活的账号推进为正常；消费前复核学校状态与有效期并锁定账号，已使用、到期或并发消费未命中一行时均拒绝。账号密码、激活状态和消费记录同事务提交，激活不能恢复停用、归档、注销或已经开通的账号。

可归属学校账号的密码或短信登录验证失败，追加 `auth.login.failed` 审计（仅认证方式、账号和请求上下文，不含密码、验证码）。失败次数和审计在同一事务提交；返回认证失败不能回滚已经验证的错误尝试。验证码存储读取故障返回内部错误，不计作用户输错。M9 仅通过只读汇总契约按学校和时间窗口统计，未识别账号及平台登录不归入学校指标。

密码错误次数由数据库对当前值原子递增，在配置阈值处封顶并设置锁定期限；不能把认证前读取的旧快照写回，防止并发请求丢失次数或计数溢出。

## 5. 越权防护

- **租户隔离(横向)**:PostgreSQL RLS 读取事务内租户上下文，应用通过 `set_config('app.tenant_id', ..., true)` 注入已经服务端会话校验的租户；事务结束后连接池不保留租户值。
- **范围隔离(横向)**:教师/学生数据查询叠加 scope;学生强制命中本人 account_id。
- **提权防护(纵向)**:角色来自服务端会话,不接受客户端传参;敏感操作(授予管理员、重置密码)二次校验角色并记审计。
- **私有化**:禁用 `/platform/*`,无平台管理员越权面。
- **部署身份**:私有化的固定 `SchoolTenantID` 同时约束所有登录方式、激活、Refresh 和 Access/路径票据的服务端会话校验；其它学校和平台凭据均不得在该实例使用。SSO 在读取外部协议配置和发起外部认证前校验部署归属。
- **认证回跳**:只接受当前服务端角色允许的规范站内路径，登录和必要改密完成后消费；目标页继续鉴权。回跳目标仅按标签页保存非凭证地址，不传给外部认证方，主动退出时清除。

## 6. 审计日志

- 记录:操作人、角色、动作码、对象、变更详情(diff)、IP、时间。
- 覆盖:登录/登出、账号增删改、权限授予、导入、租户审核、配置变更。
- 审计日志只追加不可改;查询受权限控制(本校管理员看本校,平台管理员看平台级)。
- 单账号创建、档案编辑、授予或撤销学校管理员角色与对应审计在一个事务内提交；账号创建的一次性激活码随账号同成同败。编辑后的手机号解密和响应准备也在事务内完成，失败时回滚编辑。
- 账号导入的初始密码仅在上传校验过程中短暂使用；有效行在预览落库前生成标准密码哈希，无效行不保留密码或哈希。提交直接采用已校验行的哈希；批次历史只保存行号与用户向错误，不复制原始输入或凭据。预览消费成功时同事务清空原始行，公开预览始终只返回校验结果。
- 账号导入提交前重新读取当前学校开通策略；学校已关闭激活码时，仍依赖激活码的旧预览整批拒绝且不消费预览，全部有效行已有初始密码哈希的预览仍可提交。该校验使用提交事务读到的策略快照。
- 管理员角色变更与账号状态变更先取得本租户的管理员管理事务锁，再锁目标账号行并读取当前状态，串行校验管理员数量；独立管理作用域避免锁住租户父行而与登录持账号锁后的外键写入形成反向等待。授予只接受当前正常教师。撤销角色、停用、归档或注销（含批量）不能移除最后一名正常学校管理员，批量操作任一账号被拒绝时整批回滚。
- 学校配置、SSO配置、校徽引用、平台租户状态和申请驳回与审计同事务提交；响应字段解析在提交前完成。配置/SSO/校徽读取当前值并写回时持租户行锁，避免并发操作覆盖未修改字段。
- 校徽每次上传使用独立的受控对象路径，同名文件不能覆盖在用对象。对象上传失败或业务回滚时，复用统一补偿在独立时限内清理本次对象并保留原始及清理错误；提交结果不明时保留新对象和旧对象。只有引用替换成功提交后才清理旧对象，请求取消不取消清理。
- 登录会话替换、登出/强制下线、激活、改密、找回密码和换绑手机号与对应审计同事务提交。成功认证响应在事务内完成凭据签发准备，审计失败时不能保留新会话、撤销旧会话、消费一次性凭据或更改账号数据。
- 短信登录的验证码消费、SSO 首登的账号激活与正式登录共用同一事务。首登改密保留的会话必须在账号锁内重新校验归属、有效状态和有效期，不能让轮转前已通过中间件的旧请求继续改密。

## 7. 数据生命周期与合规

- 归档而非删除:学生毕业归档,数据保留可恢复。
- 注销:软删(`deleted_at`),按合规保留期后再清理。
- 备份与最小权限:数据库账号最小权限;平台级连接与租户连接分离。

---

## 8. 安全测试要点(供实现阶段验证)

- 跨租户访问尝试必须被 RLS 拦截(渗透用例)。
- Refresh Token 重放、并发刷新竞争。
- 越权调用管理接口(普通教师/学生调 `/accounts/*`)。
- 短信/登录接口压测限频有效性。
- JWT 篡改身份或会话声明必须签名校验失败；伪造客户端角色不能改变服务端权限。
