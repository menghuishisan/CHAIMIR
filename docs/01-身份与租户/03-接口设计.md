# M1 身份与租户 — 接口设计

> 风格:RESTful,JSON。鉴权:JWT 双 Token。所有租户内接口由网关注入 `tenant_id`,业务层不可越权。
> 最后更新:2026-08-05

---

## 1. 通用约定

**Base URL**:`/api/v1`

**请求头:**
- `Authorization: Bearer <access_token>`(需鉴权的接口)
- `X-Tenant-Code: <学校短码>`(登录前用于定位租户,如 CAS 跳转、备用登录)

**统一响应体:**

```json
{ "code": 0, "message": "ok", "data": {} }
```

- `code`:0 成功,非 0 为业务错误码。
- 分页:请求 `?page=1&size=20`,响应 `data: { list, total, page, size }`。

**错误码段(M1):**

| 段 | 含义 |
| --- | --- |
| 0 | 成功 |
| 1xxxx | 通用(参数/鉴权/权限) |
| 11001 | 未登录 / Token 失效 |
| 11002 | 权限不足 |
| 11003 | 越权访问(跨租户/跨范围) |
| 12xxx | 账号与认证 |
| 13xxx | 租户、组织与身份模块装配 |
| 14xxx | 导入 |

补充: `13021` 表示身份模块 HTTP 路由装配缺少必要依赖,属于服务端装配错误,详细原因只进入日志。校徽三种失败各有稳定码:`13022` 格式不支持、`13023` 超出大小上限、`13024` 已登记的校徽暂时读不出来。

**鉴权说明:**
- Access Token:JWT,有效期 15 分钟,载荷含 `account_id / tenant_id / plat`;角色从服务端会话/契约查询,不信任前端传参。
- Refresh Token:不透明随机串,租户账号哈希存 `auth_session`,平台管理员哈希存 `platform_auth_session`,有效期 7 天,轮转使用。
- 单端登录:新登录吊销该账号其余会话。

## 2. 认证接口 `/auth`

### 2.1 平台管理员登录(SaaS)
`POST /auth/login/platform`

请求:`{ "username": "admin", "password": "..." }`

说明:仅 SaaS 平台层启用;成功签发 `plat=true` 的平台级 Token,不进入任何学校租户。私有化部署关闭该入口。

### 2.2 手机号密码登录
`POST /auth/login/phone`

请求:`{ "phone": "138...", "password": "..." }`

响应(单租户匹配):
```json
{ "code": 0, "data": {
  "access_token": "...",
  "must_change_pwd": false,
  "account": { "id": 1, "name": "张三", "base_identity": 2, "roles": [3,2] }
}}
```

响应(一号多校,需选租户):
```json
{ "code": 0, "data": { "need_select_tenant": true,
  "tenants": [{ "tenant_id": 10, "name": "北大", "code": "pku" }] }}
```
→ 客户端带 `tenant_id` 重新请求 `POST /auth/login/phone`。

### 2.3 学号登录(备用)
`POST /auth/login/no`
请求:`{ "tenant_code": "pku", "no": "2021001", "password": "..." }`
说明:用学校短码 + 学号定位账号,响应同 2.1; refresh token 仍只通过 HttpOnly Cookie 下发。

### 2.4 短信验证码登录
`POST /auth/login/sms`
请求:`{ "phone": "138...", "code": "123456" }`,响应同 2.1; refresh token 仍只通过 HttpOnly Cookie 下发。

### 2.5 发送短信验证码
`POST /auth/sms/send`
请求:`{ "phone": "138...", "scene": 1, "tenant_id": "10" }`(1登录/2找回/3换绑;一号多校登录/找回短信必须带 `tenant_id`,单租户可省略;换绑手机号必须携带当前登录态,租户以服务端会话为准)
说明:Redis 限频(同号 60s、每日上限),返回 `{ "code": 0 }`。

### 2.6 刷新 Token(无感)
`POST /auth/refresh`
请求体固定为空 JSON `{}`; refresh token 只由后端写入并读取 `HttpOnly; Secure; SameSite=Strict` Cookie,禁止出现在请求体、URL、路由状态或 Web Storage。请求必须同时携带固定自定义头 `X-Chaimir-Refresh: 1`,用于阻断跨站表单伪造。
响应只返回短期 `access_token`;后端在响应 Cookie 中轮转新的 refresh token,旧 Refresh 立即失效并按重放策略处理。
失败:`code=11001`,要求重新登录。

### 2.7 登出
`POST /auth/logout`(需鉴权)→ 吊销当前会话。

### 2.8 找回密码
`POST /auth/password/reset`
请求:`{ "phone": "138...", "code": "...", "new_password": "...", "tenant_id": "10" }`(一号多校时必须带 `tenant_id`)

### 2.9 激活码开通
`POST /auth/activate`
请求:`{ "activation_code": "...", "password": "..." }`
说明:学校管理员启用激活码开通时,新增/导入账号返回一次性激活码;用户通过激活码自设密码并激活账号。

### 2.10 SSO 登录

CAS 与 LDAP 采用不同协议形态,不得用同一个回调接口伪装:

- `GET /auth/sso/{tenant_code}/login` → 根据该租户 CAS 配置生成 CAS 登录地址并返回 `redirect_url`,前端负责跳转。
- `GET /auth/sso/{tenant_code}/callback?ticket=...&service=...` → CAS 回调,校验 Service Ticket 后按 `sso_config.match_field` 匹配已导入名单;匹配成功签发 Token,失败返回"账号未在名单中"。
- `POST /auth/sso/{tenant_code}/ldap` → LDAP 账号密码登录,请求 `{ "username": "...", "password": "..." }`;服务端用学校 LDAP 配置完成绑定与目录查询,再按 `sso_config.match_field` 匹配名单并签发 Token。

SSO 配置要求:
- CAS 配置使用 `server_url`,可选 `username_attribute`;`service` 必须来自当前回调地址或前端提交的完整回调 URL,不得硬编码。
- CAS `service` 的 origin 必须命中部署配置 `IDENTITY_SSO_ALLOWED_SERVICE_ORIGINS`;未配置或未命中时拒绝生成登录地址与验票,避免租户配置或前端参数把票据回调导向非平台域名。
- LDAP 配置使用 `url / bind_dn / bind_password / base_dn / user_filter / match_attribute`;`url` 必须为 `ldaps://`,不允许跳过 TLS 证书校验。敏感字段保存时加密、读取给前端时脱敏。
- `match_field=1` 表示学号/工号匹配,`match_field=2` 表示手机号匹配;未命中已导入名单不得自动创建账号。
- 学校管理端必须按 CAS/LDAP 类型展示字段级配置表单并在提交前校验必填项与协议；不得暴露或要求管理员编辑原始 JSON。LDAP 密码读取时保持脱敏，修改配置时必须重新填写后再提交。

## 3. 平台管理员接口 `/platform`(仅 SaaS)

### 3.1 学校入驻申请(公开)
`POST /platform/applications`
请求:`{ "school_name": "...", "school_type": 3, "contact_name": "...", "contact_phone": "...", "contact_email": "..." }`
说明:无需登录,提交后状态为"申请中"。这是申请,不是注册。

### 3.2 申请列表 / 审核
- `GET /platform/applications?status=1`(平台管理员)
- `POST /platform/applications/{id}/approve` → 创建租户 + 分配短码 + 开通学校管理员账号(激活码)。
- `POST /platform/applications/{id}/reject`,请求 `{ "reason": "..." }`。

### 3.3 租户管理
- `GET /platform/tenants?page=&size=&status=&keyword=`、`GET /platform/tenants/{id}`
- `PATCH /platform/tenants/{id}`(改状态/到期时间)
- `GET /platform/tenants` 返回统一分页数据 `{ "list": [...], "total": 0, "page": 1, "size": 20 }`,不得退回数组或模块私有分页结构。
- 学校列表的**状态筛选与关键词搜索由服务端执行**(`status` 省略或 0 表示不筛,`keyword` 同时匹配学校名称与短名),`total` 与筛选同口径;前端不得对当前页做二次筛选 —— 那样翻页与总数会自相矛盾。

## 4. 租户配置接口 `/tenant`(学校管理员;`/tenant/brand` 免鉴权)

- `GET /tenant/config` / `PATCH /tenant/config`(展示名、功能开关、认证方式、激活码开关)。读取响应除 `logo_ref` 外另带 `logo_image`(校徽的 data URI),设置页据此显示当前校徽。**`PATCH` 不接受 `logo_ref`** —— 校徽由下面两条独立入口维护,配置更新只把它原样写回。
- `feature_flags` 仍是可扩展对象,但其中 `modules` 是前后端共同维护的封闭协议:仅允许 `teaching/experiment/contest/sim/grade` 且不得重复;字段缺失表示五项全部启用,显式空数组、非字符串元素或未知代码一律拒绝。前端模块开关和平台侧只读展示必须复用同一份登记表,不得各自维护默认集合。
- `GET /tenant/sso` / `PUT /tenant/sso`(配置 CAS/LDAP 参数)
- `POST /tenant/logo`(multipart,字段 `file`)→ 上传校徽,**同一请求内落 `tenant.logo_ref`**,响应即更新后的租户配置视图(含新的 `logo_image`)。校验复用 `platform/upload` 的扩展名 + 声明 MIME + 内容魔数三重嗅探(`BrandImageKindValid`),只放行 JPEG/PNG/WEBP;大小上限 `UPLOAD_TENANT_LOGO_MAX_BYTES`。
- `DELETE /tenant/logo` → 清空引用并删除对象,徽记位回落学校名首字。
- `GET /tenant/brand`(**免鉴权,无参数**)→ 返回 `{ display_name, logo_image }`,仅在 `deploy_mode=school` 下有内容;SaaS 形态返回空品牌。免鉴权且要读一次对象存储,故复用认证入口同一套来源限流。

> **为什么 `/tenant/brand` 不接受任何租户标识**:SaaS 登录页面对的是未确定的租户,本就没有校徽可显示;私有化部署只有一个租户,租户 ID 来自 `SCHOOL_TENANT_ID` 配置,没有可枚举的对象。带 `tenant_code` 的公开端点会成为一条比登录尝试更廉价、且不经限流与审计的租户枚举通道 —— 而它要解决的问题在 SaaS 侧并不存在。故该端点无参数,前端按部署层注入的 `/runtime-config.js` 中 `deploymentMode` 决定是否调用。
>
> **校徽为什么内联下发而不是走投放授权**:统一文件服务的下载授权在签发和消费两端都绑定登录账号(`BuildDownloadGrant` 要求 `account_id`,下载入口再比对会话账号),而校徽最主要的展示位就是**尚未登录**的私有化部署登录页,那里没有账号可绑。为一张登录页图片新开一条免鉴权二进制路由,等于绕开「所有授权只由统一入口消费」。故校徽按**页面内容**处理:服务端读出对象、按内容魔数判定 MIME、以 data URI 随品牌 JSON 下发;`img-src` 本就允许 `data:`,不需要放宽 CSP,体积由上传上限约束。课程封面相反 —— 它只对课程内成员可见、读者一定已登录,故仍走投放授权。同一平台里两种载体不是「这里一套那里一套」,而是两类资源的可见性本来不同。
>
> **校徽上传即生效,不做「先传对象、后由表单提交引用」两步**:学校管理员上传校徽时租户一定已存在(租户由入驻审核或私有化初始化创建,平台方不代传品牌资产),没有「对象先于记录」的时序问题;而两步提交一旦被放弃,对象就成了没有引用者的垃圾,还得再养一个扫描对象存储的清理任务。引用写库失败时本接口立即删掉刚写的对象,不把清理推给后台。
>
> **校徽不收外链**:`logo_ref` 存对象引用而非 URL。外链校徽会被生产安全头的 `img-src 'self' data: blob:` 拦掉,更重要的是违反《总体蓝图》§7「不外传数据」—— 每个查看者的 IP 与访问时间会暴露给那个站点。不得为此放宽 CSP。校徽对象固定落 `{tenant_id}/identity/logo/current/{file_name}`,读取前按该前缀校验,免鉴权的品牌读取口因此不可能被指向别的对象。
>
> **平台管理员不代传校徽**:租户由入驻审核或私有化初始化创建,两条路径都没有让平台方替学校选品牌资产的位置。校徽由学校管理员首次登录后在租户配置页上传 —— 与「首个学校管理员可暂缺 `account_profile`、登录后先维护真实组织架构」(见 `02-数据模型.md` §5.3)同一判断:平台不臆造学校自己的信息。
>
> **入驻申请阶段不收校徽**:该表单是全平台唯一的匿名表单,匿名写对象存储没有可追责归属,存储耗尽与恶意文件都无法定位到人;审核申请只需要文字信息。与 CLAUDE.md §9「匿名表单不开草稿接口」同一判断,文件比草稿更重。学校开通后由校管上传。

## 5. 组织架构接口 `/org`(读:教师/学校管理员;写:学校管理员)

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/org/departments` | 院系列表 |
| POST/PATCH/DELETE | `/org/departments[/{id}]` | 院系增改删 |
| GET | `/org/majors?department_id=` | 专业列表 |
| POST/PATCH/DELETE | `/org/majors[/{id}]` | 专业增改删 |
| GET | `/org/classes?major_id=` | 班级列表 |
| GET | `/org/classes/{id}/students?page=&size=` | 班内在校学生名录(只出编号/姓名/学号,返回 `{list,total,page,size}`) |
| POST/PATCH/DELETE | `/org/classes[/{id}]` | 班级增改删 |
| POST | `/org/import/preview` | 上传 Excel/CSV 组织结构文件并持久化预览 |
| POST | `/org/import/commit` | 确认提交组织结构导入 |
| GET | `/org/import/template?format=xlsx|csv` | 下载组织结构导入模板;`format` 省略时默认返回 Excel 模板 |
| POST | `/org/classes/archive` | 按学年归档班级 |
| POST | `/org/classes/promote` | 班级批量升级 |

- `POST /org/classes/archive`:请求 `{ "enrollment_year": 2022 }`,在同一租户事务内做三件事 ——
  归档该学年班级、归档该学年状态正常的学生账号、吊销这些学生的服务端会话。
  教师账号与停用/注销账号不受影响。整届毕业是一次动作,故账号侧不另开按学年归档入口。
- `GET /org/classes/{id}/students?page=&size=`:只回该班 `status=正常` 的学生,字段只有 `id`/`name`/`no`;统一分页信封为 `{list,total,page,size}`。
  它是教师侧挑选学生的唯一入口(如实验小组编组);`GET /accounts` 仍只对学校管理员开放 ——
  那是账号目录,带手机号掩码、账号状态与角色,不该为了「挑个人」把整份目录放开给教师。
  同一份查询另经 `contracts.IdentityService.ListClassStudents` 供 M6 按班级批量选课复用,不写两遍。

## 6. 账号与导入接口 `/accounts`(学校管理员)

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/accounts?role=&class_id=&status=&keyword=` | 账号列表(分页) |
| POST | `/accounts` | 单个新增(教师/学生) |
| PATCH | `/accounts/{id}` | 编辑(不含学号/工号等不可变字段) |
| POST | `/accounts/{id}/disable` | 停用 |
| POST | `/accounts/{id}/enable` | 启用 |
| POST | `/accounts/{id}/archive` | 归档(毕业/离校,可恢复) |
| POST | `/accounts/{id}/restore` | 恢复归档账号 → 正常 |
| POST | `/accounts/{id}/cancel` | 注销(终态软删,数据合规保留) |
| POST | `/accounts/{id}/force-logout` | 强制下线(吊销该账号全部会话,即时踢出) |
| POST | `/accounts/{id}/reset-password` | 管理员重置密码 |
| POST | `/accounts/{id}/grant-admin` | 授予教师"学校管理员"权限 |
| POST | `/accounts/{id}/revoke-admin` | 撤销管理员权限 |
| POST | `/accounts/batch/disable` | 批量停用 |
| POST | `/accounts/batch/restore` | 批量恢复归档 |

> 按学年归档不在本组:归档一届学生同时要归档其班级并吊销会话,是**组织层面**的一次动作,
> 入口是 `POST /org/classes/archive`(见 §5)。本组的批量动作都按账号编号作用于选中账号,
> 与按学年作用于一整届是两种不同粒度,不混在同一组。

### 6.1 导入流程(两步)
- `GET /accounts` 返回统一分页数据 `{ "list": [...], "total": 0, "page": 1, "size": 20 }`,不得使用模块私有分页响应。
- `POST /accounts/import/preview`:上传 Excel/CSV(`multipart/form-data`: `type=student|teacher`, `file=<csv/xlsx>`),服务端解析并暂存预览结果,返回逐行校验结果(成功/失败原因),不写账号。
  响应:`{ "preview_id": "9001", "total": 100, "valid": 95, "invalid": 5, "rows": [{ "line": 3, "error": "手机号格式错误" }] }`
- `POST /accounts/import/commit`:确认导入,请求 `{ "preview_id": "9001" }`,服务端读取暂存预览行,仅写入校验通过的行,返回 `import_batch` 结果;启用激活码开通且导入行未提供初始密码时,响应一次性返回激活码明文。
- `GET /accounts/import/template?type=student|teacher&format=xlsx|csv`:下载模板;`format` 省略时默认返回 Excel 模板。
- `GET /accounts/import/batches`:导入批次历史。

## 7. 个人中心接口 `/me`(全角色)

四条路径都只要求登录态,不额外限角色;**身份差异在服务层分叉**:

| 方法 | 路径 | 说明 | 平台管理员 |
| --- | --- | --- | --- |
| GET | `/me` | 个人信息(含学籍只读字段) | 可用,只返回 `id/name/roles/status`(`platform_admin` 表无手机号/学工号/职称/租户列) |
| POST | `/me/password` | 改密(旧密码校验 / 首登改密) | 可用(改后保留当前会话、吊销其他会话) |
| POST | `/me/phone` | 换绑手机号(短信验证码) | **不适用**,返回 403:平台账号用 `username` 登录,表中无手机号 |
| GET | `/me/sessions` | 当前会话信息 | 可用 |

⇒ 前端个人中心:租户账号 = 资料 + 改密 + 换绑手机号 + 会话;平台管理员 = 资料只读 + 改密 + 会话,不渲染换绑手机号表单,也不展示后端不返回的字段。

## 8. 审计日志:M1 只落库,不开查询接口

`audit_log` 是全平台唯一审计表,由 M1 持有并写入;**对外查询与导出统一由 M9 管理后台承担**,见 `docs/09-管理后台/*`:

| 方法 | 路径 | 归属 |
| --- | --- | --- |
| GET | `/api/v1/admin/audit` | M9,学校管理员读本租户、平台管理员读全平台 |
| GET | `/api/v1/admin/audit/export` | M9,同上范围,导出文件走 transfer |

M1 只通过 `contracts.IdentityAuditReadService` 向 M9 开放只读契约,自身不注册 `/audit` 路由,避免同一能力两条 HTTP 入口。
