# 后端层能力索引

> 本文给后续 AI 和开发者快速判断“已有能力在哪里、什么时候该复用”。它不是源码逐行说明,只记录跨层边界和通用能力入口。改动后端共享能力时,同步维护本文。

---

## 1. 使用原则

- 先看 `docs/总-工程目录设计.md`:模块间只走 `internal/contracts`,跨模块基础设施优先放 `internal/platform`,真正无业务且可外部复用的通用库才放 `backend/pkg`。
- 不要在模块里临时复制小工具。发现同类逻辑第二处出现时,先判断是否已有 `pkg` 或 `internal/platform` 能力可复用。
- 密钥、连接串、端口、超时和阈值不放 `pkg`;运行配置统一经 `internal/platform/config` 和环境变量进入。
- `pkg` 不访问数据库、Gin、NATS、K8s、对象存储和模块表;需要这些依赖的能力通常属于 `internal/platform` 或具体模块。

### 1.1 AI 接入前检查清单

后续 AI 在实现任一后端模块前,必须先按需求关键词查本文,确认是否已有统一入口:

- 跨模块调用、共享 DTO、事件主题/载荷:先查 `internal/contracts`,不要直接 import 其他模块 package,也不要在模块内复制契约结构。
- 错误码、用户向文案、内部错误链:先用 `pkg/apperr`,不要在模块内自建错误结构。
- HTTP JSON 响应、分页、`trace_id`、panic 收敛:先用 `internal/platform/response` 或 `internal/platform/httpx`,不要直接拼响应信封。
- 结构化日志、错误脱敏、关闭资源失败记录:先用 `pkg/logging`,不要裸写敏感错误字符串。
- 密码哈希、HMAC、AES-GCM、随机短码/凭证:先用 `pkg/crypto`,不要用 `math/rand`、模块私有随机函数或自定义加密格式。
- 手机号展示脱敏、凭据字段识别、用户可见结果敏感字段识别:先用 `pkg/privacy`,不要复制关键词表或切片掩码逻辑。
- BIGINT 主键生成:先注入 `pkg/snowflake.Generator`,不要用时间戳、随机数或模块私有序列。
- 链上状态断言:先用 `pkg/chainassert`,不要在 judge、contest、experiment 等模块各写一套断言解释器。
- 面向人的文本长度上限(入库前截断、下发前截断):先用 `pkg/textx.TruncateRunes`,不要在模块里各写一遍 `[]rune` 切片。
- 从不可信 JSON 对象里取字符串字段:先用 `internal/platform/jsonx.StringField`/`StringValue`(严格,不做数字宽松转换),不要在模块里各写一个 `stringField`/`stringValue`。

如果本文没有对应入口,再判断应放 `internal/platform`、具体模块私有实现,还是新增无业务 `pkg` 包;新增后必须同步更新本文。

## 2. internal/contracts

模块间接口契约、跨模块 DTO、事件主题和事件载荷的唯一入口。

- 用于:模块之间同步调用、聚合层只读查询、事件总线 payload、跨模块身份角色字符串与数据库/审计数字枚举。
- 需求关键词:跨模块调用、contracts、DTO、事件主题、source_ref、角色字符串、角色数字枚举、只读契约、接口注入。
- 关键能力:`IdentityService`、`SandboxService`、`JudgeService`、`SimService`、`ContentReadService`、`TeachingReadService`、`Subject*` 事件主题、`Role*`/`RoleNum*` 与 `RoleCode`/`RoleNumber`。通知与实时推送统一通过 `SubjectNotifySendRequested`/`SubjectNotifyPushRequested` 事件进入 M10,不保留未装配的跨模块直调接口。
- 约束:本层只定义接口、DTO、事件和必要的稳定身份角色映射;不访问数据库、HTTP 框架、K8s、NATS、对象存储或具体模块实现;不得把 `internal/platform` 的基础设施实现搬进来。
- 边界:`RolePlatformAdmin`/`RoleSchoolAdmin`/`RoleTeacher`/`RoleStudent` 是身份鉴权字符串;`RoleNumPlatformAdmin`/`RoleNumSchoolAdmin`/`RoleNumTeacher`/`RoleNumStudent` 是同一身份角色在数据库与审计中的数字枚举;审计系统任务 `actor_role=5` 属于 `internal/platform/audit`,不要在 `contracts` 里新增第二套系统角色语义。
- 序列化:导出的跨模块 DTO 字段必须带稳定 `json` 标签,避免内部 HTTP、事件消息、调试导出或未来拆服务时泄漏 Go 字段名。
- 内容复用:M5 `ContentReadService.ReplaceUsageRefs` 是内容引用统计唯一写入口;M6/M7/M8 等业务模块只能传稳定 `source_scope + source_ref` 和锁定版本 `ContentItemRef`,不得自增 `usage_count`、不得自建复用统计表、不得保留旧式 usage HTTP 上报分支。
- 学生档案:业务模块要显示学生姓名/学号时,统一用 `IdentityService.BatchGetAccounts` 批量解析后随自己的 DTO 下发(`course_member`/`group_member`/`experiment_report` 只存 `student_id`);按班级取学生用 `IdentityService.ListClassStudents`。不要让客户端自行调 `GET /accounts` 匹配 —— 那是学校管理员的账号目录,教师身份调用会被拒,且会把手机号掩码、账号状态与角色一并暴露。
- 依赖方向:业务模块依赖 `internal/contracts` 注入其他模块能力;`internal/platform` 和 `pkg` 可按工程目录规范提供基础能力,但不要为了方便在 `contracts` 中复制基础层能力。

## 3. backend/pkg

### `pkg/apperr`

统一应用错误体系和全平台错误码单一入口。

- 用于:模块、平台层和 API 边界返回稳定错误码、用户向文案和内部原因链。
- 需求关键词:错误码、用户提示、`code/message/trace_id`、`WithCause`、错误码段、失败场景。
- 关键能力:`New` 定义稳定错误模板,`WithCause` 包裹内部错误,`UserCode`/`UserMessage` 读取公开契约,`AsAppError`/`As` 把任意错误归一。
- 约束:错误模板的码和用户文案对包外只读,`errors.Is` 按稳定错误码识别包裹后的同类错误;新增失败场景先在对应 `*_codes.go` 定义专用错误码;不要动态替换同一错误码的用户文案;技术原因只进日志。
- 不要自己实现:模块内错误码常量、`code/message` 临时结构、把 SQL/内部字段拼进前端响应。

### `pkg/logging`

统一结构化日志、上下文字段透传和敏感信息脱敏。

- 用于:服务启动设置全局 `slog`,业务/平台层记录带 `trace_id`、`tenant_id`、操作上下文的错误日志。
- 需求关键词:日志、脱敏、trace、tenant、关闭资源、`slog`、敏感字段。
- 关键能力:`Setup`、`WithAttrs`、`AttrsFromContext`、`ErrorContext`、`CloseContext`、`SanitizeError`。
- 约束:错误链落日志前必须走脱敏;凭据字段名统一复用 `pkg/privacy.IsCredentialKey`,不得在日志包维护第二套关键词表;带错误返回的 `Close` 用 `CloseContext` 记录失败;不要裸写密码、token、密钥、手机号明文。

### `pkg/crypto`

通用安全原语:密码哈希、HMAC、AES-256-GCM、统一随机短码/凭证生成。

- 用于:M1 密码/手机号哈希/验证码/激活码,服务间签名,对象下载授权,内容完整性摘要等非业务安全原语。
- 需求关键词:密码、验证码、短信码、邀请码、激活码、Refresh Token、HMAC、签名、AES、加密、摘要。
- 关键能力:`HashPassword`/`VerifyPassword`、`HMACSHA256Hex`、`HMACHash`、`EqualHexHMAC`、`SHA256Hex`/`ValidSHA256Hex`、`NewCipher`、`RandomToken`。
- 约束:`RandomToken` 是 Refresh Token、激活码、邀请码、短信验证码等短码/凭证的统一入口,使用去歧义大写字母数字字符集和 CSPRNG 均匀抽样;不要用 `math/rand`、取模映射或模块私有随机函数生成安全凭证。
- 边界:密钥来源和轮换属于 `internal/platform/config` 与部署 Secret,本包只接收已加载的密钥字节。

### `pkg/privacy`

跨模块用户数据脱敏与敏感字段识别。

- 用于:用户向展示或日志脱敏时隐藏手机号,以及日志、配置保护、判题/链上结果摘要判断敏感字段。
- 需求关键词:手机号展示、手机号脱敏、日志手机号、敏感字段、凭据字段、flag、answer、secret、token。
- 关键能力:`MaskPhone`、`IsCredentialKey`、`IsResultSensitiveKey`、`ContainsResultSensitiveText`。
- 约束:凭据字段和用户可见结果字段语义不同,不要把 `flag/answer` 这类业务结果敏感词用于配置加密判断;非法手机号返回空字符串,避免误把原值展示给用户。

### `pkg/snowflake`

全平台 BIGINT 主键 ID 生成。

- 用于:模块 service 或装配层需要创建新主键时注入 `snowflake.Generator`。
- 需求关键词:主键、ID、雪花、`BIGINT`、生成器。
- 关键能力:`NewNode`、`Generator`、`Node.Generate`。
- 约束:节点号来自环境配置,生产多副本必须保证 `SNOWFLAKE_NODE_ID` 在同一部署内唯一;生成器会处理同毫秒序列耗尽和短时钟回拨,但节点号冲突只能由部署编排避免;模块不要自己用时间戳、随机数或数据库序列临时生成业务主键。

### `pkg/chainassert`

链上状态断言的通用判定能力。

- 用于:M3 判题和 M8 漏洞预验证对链上查询结果执行 `eq`、`ne`、`contains`、`exists` 等断言。
- 需求关键词:链上断言、判题断言、漏洞预验证、`eq/ne/contains/exists`、actual 摘要。
- 关键能力:`FromMap`、`Check`、`ShortJSON`。
- 约束:`FromMap` 只接受字符串形态的协议字段并校验目标与操作符,`Check`/`ShortJSON` 的序列化错误必须由调用方映射为所属模块错误,不得用空摘要继续判定;返回给前端的实际值会先按 `pkg/privacy` 的用户可见结果敏感规则脱敏再截断,避免泄露完整链上状态、判题期望结构、flag 或密钥;不要在 M3/M8 各写一套断言解释器或短 JSON 摘要函数。

### `pkg/textx`

面向人的文本长度边界。

- 用于:失败原因入库、摘要下发、审核报告字段等"文本来自不可信或不可控来源,长度必须有上限"的场景。
- 需求关键词:截断、长度上限、rune、摘要、失败原因、detail 列宽。
- 关键能力:`TruncateRunes`。
- 约束:按 rune 而不是 byte 截断(按字节切中文会切出半个字符);不追加省略号,省略号由展示层决定;
  具体上限值属于调用方的协议或列宽约束,不在本包内定义。
- 不要自己实现:模块内 `[]rune(text)[:limit]` 切片、`ShortXxx` 私有截断函数。

### `pkg/limitio`

面向不可信或不可控输出流的有界内存写入能力。

- 用于:Kubernetes exec、外部进程或其他流式输出需要在写入阶段限制单路内存占用,并在首次超限时立即中止上游写入。
- 需求关键词:`io.Writer`、stdout/stderr、流式输出、内存上限、资源耗尽、`ErrLimitExceeded`。
- 关键能力:`NewBuffer`、`Buffer.Write`、`Buffer.Bytes`、`Buffer.Len`、`Buffer.String`、`ErrLimitExceeded`。
- 约束:具体字节上限来自调用方配置;本包只返回无业务的超限哨兵,业务模块负责映射稳定错误码与用户文案。
- 不要自己实现:模块内 `limitedBuffer`、`boundedBuffer` 或先无界写入 `bytes.Buffer` 再检查长度。

## 4. 后续维护

- 新增 `pkg` 包时,必须说明它为什么是“无业务、可外部复用”,而不是 `internal/platform` 或某模块私有能力。
- 新增 `internal/platform` 通用能力时,在本文继续追加对应章节,说明它的唯一入口和模块不得重复实现的边界。
- 发现重复小功能时,先补索引再收口实现,让后续 AI 能从本文找到已有能力。

## 5. internal/platform

### `internal/platform/response`

统一 HTTP JSON 信封、分页结构、`trace_id` 贯穿和 panic 收敛。

- 用于:Gin API 层写成功/失败响应,以及请求入口注入 `X-Trace-Id`。
- 需求关键词:接口响应、分页、错误返回、panic、追踪编号、`X-Trace-Id`。
- 关键能力:`TraceMiddleware`、`RecoveryMiddleware`、`OK`、`OKPage`、`Fail`。
- 约束:API 层不要直接 `c.JSON` 拼 `{code,message}`;分页响应统一用 `Page` 形态;错误响应只输出用户向文案和 `trace_id`。
- 推荐路径:业务 API 通常优先用 `internal/platform/httpx.Write/Bind/PathID`,它最终复用本包信封。

### `internal/platform/httpx`

Gin handler 层通用绑定、ID/分页解析、附件响应和内嵌 Web 服务代理入口。

- 用于:API 文件绑定 JSON、解析路径 ID/查询整数、写统一成功/失败响应、输出小型附件,以及把集群内 Web 工具挂到统一 API 鉴权入口下。
- 需求关键词:handler、BindJSON、PathID、分页、附件下载、Content-Disposition、工具代理、反向代理、`X-Forwarded-Prefix`、Location 重写、Cookie Path。
- 关键能力:`BindJSON`、`BindJSONWithError`、`Write`、`WritePage`、`WriteAttachment`、`NewPrefixReverseProxy`、`SanitizeForwardHeaders`、`PathID`、`QueryInt`、`Page`。
- 约束:handler 不直接拼响应信封;模块需要绑定失败专用错误码时传稳定 `apperr` 模板,不要动态改用户文案;路径、查询和表单数字字段必须显式解析失败,不要把非法输入静默转成 0;附件响应统一带安全文件名和 `X-Content-Type-Options: nosniff`;业务模块只负责完成用户/租户/资源归属鉴权并提供目标地址和外部前缀,不得复制平台代理头清理、Location 重写或 Cookie 作用域规则;平台身份头、用户凭据和内部服务签名不得透传给工具容器。

### `internal/platform/auth`

JWT access token、短时路径票据、中间服务 HMAC 签名和角色守卫中间件。

- 用于:HTTP 鉴权、WebSocket 与浏览器工具短时路径票据鉴权、浏览器直连入口鉴权(内嵌工具代理、统一文件服务流式投放)、平台/租户角色守卫、内部服务回调验签。
- 需求关键词:JWT、Bearer、path ticket、WebSocket ticket、browser ticket、浏览器工具代理、视频直连播放、路径受限 Cookie、内部服务签名、HMAC、角色中间件。
- 关键能力:`Manager`、`IssueAccess`、`VerifyAccess`、`IssueWebSocketTicket`、`VerifyWebSocketTicket`、`IssueBrowserAccessTicket`、`VerifyBrowserAccessTicket`、`Middleware`、`AuthenticateAccess`、`BrowserAccessMiddleware`、`FileAccessMiddleware`、`VerifiedAccessToken`、`SetBrowserAccessCookie`、`WebSocketMiddleware`、`ServiceMiddleware`、`RequireTenantAnyRole`、`AuthorizePlatformOrAnyRole`、`ValidSourceRef`、`WithServiceIdentity`。
- 约束:刷新令牌当前由 identity 使用 `pkg/crypto.RandomToken` 随机串实现,不要在本包新增第二套 refresh JWT;内部服务 HTTP 请求必须带租户、source_ref、timestamp、trace_id 和签名;进程内跨模块契约调用如需系统身份,统一用 `WithServiceIdentity` 建立租户和 source_ref 边界,不要在模块里手写 `tenant.Identity{IsSystem:true}`。
- 浏览器直连的两个入口共用 Cookie 与会话校验底座,不得把 access token 放进 URL。工具代理用 `BrowserAccessMiddleware`:首次 GET 只接受 `/auth/browser-ticket` 签发的短时路径前缀票据,校验后由 auth 层重新签发 access token,业务 handler 用 `VerifiedAccessToken` 写入最小路径 Cookie 并重定向清掉 `ticket`;后续资源使用 Cookie。统一文件服务用 `FileAccessMiddleware`:只接受 Bearer 或已由业务授权接口写入的 Cookie,query `token` 只承载投放授权。调用方不得自行从 Header/Cookie/query 再验凭据,那会绕过会话有效性和 token 类型校验。

### `internal/platform/db`

pgx 连接池、RLS 会话变量和事务边界。

- 用于:repo/store 装配数据库事务,按租户写入 `app.tenant_id`,受控后台维护走特权事务。
- 需求关键词:pgx、事务、RLS、tenant_id、privileged tx、no rows。
- 模块跨租户维护事务必须经 `WithPrivilegedModuleTx`,部署期为每个模块创建不可登录且 `BYPASSRLS` 的维护角色,并仅授予该模块自有表权限;运行时先 `SET LOCAL ROLE` 再把事务交给模块 repo。模块名、角色名与表集合统一定义在 `platform/db`,禁止只传字符串标签却继续暴露全权限事务。
- 关键能力:`New`、`WithTenantTxID`、`WithAppTx`、`WithPrivilegedTx`、`WithPrivilegedModuleTx`、`IsNoRows`、`IsUniqueViolation`。
- 约束:service 不直接 import `platform/db`;只有 repo/store 构造和事务边界使用;跨租户维护任务只能在所属模块 repo 内使用特权事务读取本模块表。

### `internal/platform/background`

后台 ticker、panic recovery、结构化错误日志和 context 停止语义。

- 用于:模块 worker/scheduler 的通用运行壳,业务状态机仍保留在各模块 service 的 `RunXOnce(ctx)`。
- 需求关键词:后台任务、ticker、worker、panic、定时清理、轮询。
- 关键能力:`Task`、`Run`。
- 约束:间隔必须由配置注入且大于 0;空任务函数或非法间隔会显式记录结构化错误并停止;panic 日志必须保留脱敏后的调用栈,不要在模块里复制 ticker/recover 循环。

### `internal/platform/eventbus`

NATS 事件总线、消费重试和死信投递统一入口。

- 用于:模块间反向通知、事件发布、事件订阅、失败重试和死信。
- 需求关键词:NATS、Publish、Subscribe、事件重试、死信、trace_id、tenant_id。
- 关键能力:`Bus`、`New`、`Publish`、`Subscribe`、`Decode`。
- 约束:事件 payload 必须含真实 `tenant_id` 和 `trace_id`;空 subject、nil handler 会直接拒绝;handler panic 必须转为带脱敏调用栈的错误并进入同一重试/死信链路;业务模块不要自己建 NATS 客户端或绕过统一死信策略。

### `internal/platform/redis`

Redis 缓存、限频和计数原语封装。

- 用于:短信/通知限频、整数缓存、主动失效和就绪探针。
- 需求关键词:Redis、SetNX、限频、计数、缓存、TTL。
- 关键能力:`New`、`Ping`、`Close`、`SetNX`、`IncrWithTTL`、`Decr`、`GetInt64`、`SetInt64`、`GetBytes`、`SetBytes`、`Delete`。
- 约束:`IncrWithTTL` 用 Lua 原子设置首次 TTL,不要在模块里拆成 `INCR` + `EXPIRE`;不暴露底层客户端,新增 Redis 原语应先扩展本包。
- 结构化缓存:模块需要缓存 JSON/二进制结构时使用 `GetBytes`/`SetBytes`,由模块自行用 `jsonx` 等基础层工具做严格编解码和脏值失效;不要在模块里直接 import go-redis。

### `internal/platform/storage`

MinIO 客户端、统一文件服务、对象引用和短时下载授权。

- 用于:模块上传规划、对象 key/object_ref 生成、MinIO Put/Get、下载授权 token 和受控文件流。
- 需求关键词:MinIO、上传、附件、对象引用、object_ref、下载授权、文件服务。
- 关键能力:`Storage`、`NewServiceFromConfig`、`ObjectKey`、`ObjectRefString`、`ParseObjectRef`、`Service.PlanUpload(ctx, ...)`、`Service.IssueDownloadGrant`、`DownloadModeDownload`/`DownloadModeStream`、`DownloadCookiePath`、`VerifyDownloadGrantToken`、`RegisterDownloadRoutes`。
- 约束:对象 key 必须是 `{tenant_id}/{module}/{resourceType}/{resourceID}/...`;下载授权会把 `resourceID` 纳入完整前缀校验,业务模块还必须先验证账号对该具体资源及对象引用的访问权;bucket/key/object_ref 校验只有一套实现;组合根装配文件服务必须用 `NewServiceFromConfig` 收敛扫描器、扫描大小上限、普通下载 TTL、视频流 TTL 和签名密钥;所有短时授权只由 `/api/v1/storage/download` 消费,普通下载通过 Redis 原子限制一次使用,流式授权在较短有效期内允许 Range 重复取件,模块不得直接暴露 MinIO 直链、内部 `DownloadGrant` 结构、自己签 token 或自建下载 handler。平台级 transfer 任务使用 `tenant_id=0` 的平台作用域对象前缀,调用方必须显式传 `AllowPlatformScope`,普通租户上传/下载不得开启该标记。
- 流式投放的鉴权载体:下载入口挂 `auth.FileAccessMiddleware`(Bearer 或路径受限 Cookie,不接受 query token)。签发 `mode=stream` 授权的业务接口负责在同一响应里用 `auth.SetBrowserAccessCookie(c, storage.DownloadCookiePath, token)` 写 Cookie —— `<video src>` 由浏览器自身发起、发不出 `Authorization` 头,少了这一步视频必然 401。Cookie 作用域常量只有 `DownloadCookiePath` 一处,业务模块不要各写一遍路径字符串。

### `internal/platform/jsonx` / `pgtypex` / `timex` / `pagex` / `ids` / `netx` / `tenant`

- 关键能力:`jsonx.EncodeLineBytes`/`DecodeStrict`/`DecodeStrictKnownFields`/`ObjectBytes`/`AnyBytes`/`CloneObjectStrict`/`ValueFromPath`/`StringField`/`StringValue`/`StringFromAny`,`pgtypex.*`,`timex.Now`/`UTC`/`ParseRFC3339`/`ParseDate`/`RFC3339OrEmpty`/`DateOrEmpty`,`pagex.Normalize`,`ids.ID`/`Format`/`Parse`,`netx.ValidatePublicHTTPURL`/`NewPublicHTTPClient`/`PublicHTTPTransport`,`tenant.WithContext`/`FromContext`。
