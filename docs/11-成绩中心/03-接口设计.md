# M11 成绩中心 — 接口设计

> RESTful。鉴权沿用 M1 JWT。聚合只读 M6;M11 写自有审核/预警/成绩单元数据。
> 最后更新:2026-05-29

---

## 1. 通用约定

- Base:`/api/v1/grade-center`
- 前端和 API client 只能使用 `/grade-center/*` 当前路径;不得保留旧 `/grade/*`、`/grade/applications/*`、`/grade/transcript/*` 或告警 `acknowledge/handle` 旧接口。
- 统一响应体同 M1。错误码段:`B0xxx`(审核/GPA/申诉/预警/成绩锁事件同步)。`B0010` 专用于成绩锁定状态事件无法写入或发布,不得复用审核状态错误码。
- 带 `page/size` 的列表接口必须返回统一分页结构 `{list,total,page,size}`,不得退回裸数组。

## 2. 等级映射与学期 `[学校管理员]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST/PUT | `/level-configs[/{id}]` | 等级映射配置(分数段→等级→绩点) |
| GET/POST | `/semesters[/{id}]` | 学期管理 |

等级规则与预警阈值表单复用 `useFormValidation`：失焦/提交激活提示后按当前输入重算,名称、逐档下限/等级/绩点、覆盖与重复、预警两项阈值的错误独立保留。数字输入以原文本保存编辑态,空白不得转换成0；明确0仍按既有业务语义处理。档位下限为0到100、绩点为0到4,非最低档绩点必须大于0；不及格门数上限为非负整数,绩点下限为0到4。服务端保存失败单独显示,编辑字段不清除接口失败。

创建学期要求合法的 `YYYY-MM-DD` 起止日期、开始日不晚于结束日,并拒绝与本租户任一既有学期的闭区间重叠。失败返回 `B0001`,不插入学期、不改变当前学期。并发创建共用租户学期事务锁,校验通过后才切换当前标记和写入。

## 3. 成绩审核 `[教师/学校管理员]`

教师报送将课程必选提示、学期读取/匹配前置与接口失败分别展示。课程选择复用共享字段校验；学期前置按当前资源状态重算，读取恢复后不保留旧阻断文案。报送说明为可选字段，不能因课程或接口错误被标记为无效。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/reviews` `[教师]` | 提交课程成绩待审(引用 M6 课程) |
| GET | `/reviews?status=&page=&size=` `[管理员]` | 待审分页列表,响应 data 为 `{list,total,page,size}` |
| POST | `/reviews/{id}/approve` `[管理员]` | 通过 + 锁定审核状态 + 发布事件驱动 M6 同步写保护投影 → 触发 GPA 聚合 |
| POST | `/reviews/{id}/reject` `[管理员]` | 驳回 |
| POST | `/reviews/{id}/unlock` `[管理员]` | 解锁回退 + 发布事件驱动 M6 解除写保护投影 |

报送与审核共用学期解析规则：`semester_id` 可省略，报送时按 M6 课程的学期名称在本租户 M11 学期中精确匹配，并将解析出的实际编号写入审核记录、返回响应。学期名称受 `(tenant_id,name)` 唯一约束；不得按日期、当前学期或名称近似推断归属。课程学期为空、尚未登记、显式编号不存在或名称不一致时，报送前拒绝，不创建缺少归档学期的待审记录。返回 `B0002` 和可指引核对课程/学校学期的用户向提示，日志保留租户、课程及学期校验原因。

报送还须经 M6 只读契约确认该课程已有实际成绩记录。空集合返回 `B0002`，引导教师先完成成绩结算，不创建待审项；成绩读取失败保留原因链并拒绝报送，不能按空集合或成功处理。合法的零分记录属于实际成绩，不得据分数是否大于零判断能否报送。M11 不跨读 M6 表、不写入或补造单课程成绩。

审核通过时，显式选择优先于报送学期；两者均省略时仍调用同一课程学期解析规则。无论编号来自哪一处，都必须属于当前租户且名称与课程学期一致，再写审核状态与锁事件。教师报送表单显示课程学期，课程表单引导填写学校登记的完整名称；报送和审核的学期列表读取失败显示错误与重试，不替换为成功空列表，也不继续提交依赖该列表的操作。M6 不反向读取 M11 配置，不自动新增学期或改写已有课程、审核记录。

审核决定表单统一按当前输入校验驳回理由和解锁原因,通过审核仍允许说明为空。学期读取前置提示归属学期,资源恢复后同步消失,不挂到合法的审核意见上。接口失败单独展示,编辑意见或选择学期不得清除未解决的服务错误。

## 4. GPA 与聚合 `[学生/教师/管理员]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/students/{id}/grades?semester=&page=&size=` | 学生学期成绩(聚合读 M6 明细 + GPA),返回当前范围 GPA 摘要与 `{list,total,page,size}`;服务端按 M6 分页流式聚合,只保留请求页明细,不得把完整课程数组放入浏览器响应或摘要缓存 |
| GET | `/students/{id}/gpa` | 学期/累计 GPA |
| POST | `/students/{id}/recompute` `[内部/管理员]` | 重算 GPA(改分/申诉后) |

> 明细课程成绩实时读 M6;M11 不复制成绩。浏览器成绩接口只缓存 GPA、学分、总数和计算时间等标量摘要,不缓存 `CourseGrades` 明细;成绩单导出走独立的受控完整读取路径。学业概览缓存 TTL 由 `GRADE_SUMMARY_CACHE_TTL_SECONDS` 配置;成绩变更、审核通过/驳回/解锁、申诉创建/受理/驳回/完成和手动重算必须主动失效学生全量与对应学期缓存。

`total_credits` 表示当前查询范围内参与 GPA 加权的课程学分总和，包含未通过课程的学分，与 GPA 公式的分母一致，不表示已通过课程获得的学分。学生成绩概览统一显示“本范围学分”，说明“用于绩点加权，含未通过课程”；选择学期时沿用服务端该范围汇总，不按当前分页明细重新计算。

校管手动重算表单必须先成功读取学期列表,并从当前列表选择实际学期后才能提交。加载、读取失败或学校尚未登记学期时禁止发送重算请求;读取失败沿统一资源错误态展示用户向提示、后端报障编号和重新加载入口,不能显示成成功空列表。学期必填校验使用共享表单校验能力,在参与校验后随当前选择更新,不保留已经修正的旧提示;重算接口失败仍单独保留用户向错误。

## 5. 申诉 `[学生/教师]`

学生申诉表单分别校验课程与理由，失焦或提交后按当前值更新各字段提示。接口失败独立展示，不挂到理由字段。无可申诉成绩时仍禁用提交，成功后沿用原成功反馈。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/appeals` `[学生]` | 提交申诉(时效内) |
| GET | `/appeals?status=&page=&size=` `[教师/管理员]` | 申诉分页列表,响应 data 为 `{list,total,page,size}` |
| POST | `/appeals/{id}/accept` | 受理申诉并解锁审核状态,同时发布事件驱动 M6 解除写保护投影;等待 M6 改分事件触发重算 |
| POST | `/appeals/{id}/reject` | 驳回 |

同一学生同一课程存在待处理或受理改分中的申诉时,再次提交会被拒绝;受理/驳回只能从待处理状态进入,完成只能由 M6 成绩变更事件驱动从受理改分中进入。

受理/驳回共用的处理说明表单沿用共享表单校验能力:失焦或提交后显示必填提示,继续编辑时按当前说明重新计算,不能让已修正字段一直保持旧错误。接口处理失败与字段校验分开保存,不能把接口失败当作处理成功。

申诉列表和总数必须在分页前按服务端角色限制课程范围:教师仅能查看本人任教且未删除课程的申诉,学校管理员可查看当前租户全部申诉。教师课程范围只经 M6 的只读 `ListTeacherCourseIDs(tenant_id,teacher_id)` 契约取得,M11 不跨读课程表,不接收客户端声明的教师或全校权限。空授课范围返回空列表及总数 0;角色或课程范围查询失败显式返回错误,不得扩大范围或返回成功空态。列表与总数使用相同过滤条件,同一创建时间按申诉编号倒序稳定分页;受理/驳回仍独立核验当前课程归属。

## 6. 学业预警 `[管理员/学生]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/PUT | `/warning-rules` `[管理员]` | 预警规则(挂科数/GPA阈值);两个阈值均为必填,显式填写 0 表示关闭对应条件 |

学生尚无任何课程成绩时,成绩概览和分页接口返回 GPA、学分、总数均为 0 的正常空结果,不得因为学校尚未创建等级映射而返回配置错误。只有存在待计算成绩时才要求默认等级映射完整有效。
| GET | `/warnings?student_id=&status=&page=&size=` | 预警分页列表,响应 data 为 `{list,total,page,size}`;`status` 省略或 0 表示不按确认状态筛选,筛选与 `total` 同口径 |
| POST | `/warnings/{id}/ack` `[学生]` | 学生确认本人学业预警已知悉 |
| POST | `/warnings/scan` `[内部]` | 周期扫描生成预警(经 M10 通知) |

预警读取范围由服务端角色决定:学校管理员省略 `student_id` 或传 0 时查询本租户全校预警,传正数时筛选指定学生;学生省略或传本人编号时只查询本人,指定其他学生必须拒绝。教师等其他角色不因传入学生编号获得访问权。负数编号拒绝,租户范围始终由会话及 RLS 确定,列表和总数共用该范围。

`status`只接受0(全部)、1(待确认)、2(已知悉)。通知投递失败由服务端独立投递元数据记录并自动重试,不改变学生确认状态,不作为确认状态筛选项或公开给学生的内部投递细节。

## 7. 成绩单 `[学生/管理员]`

学生成绩单仅在单学期范围校验学期选择，复用共享字段校验；选定学期或切回全部范围后立即更新提示。生成、下载与取件失败独立保留，切换范围不能将接口失败隐藏为成功。

批量成绩单按当前选中学生数与范围校验:至少1人、单次最多200人,仅单学期范围要求选择学期。使用共享字段校验能力,纠正人数/学期或切回全部范围时更新对应提示,生成与下载接口错误单独保留。切换班级仍清空选中学生与本次结果,不把上一个班级的选中项带入新请求。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/transcripts` | 生成成绩单 PDF(学期/全部) |
| GET | `/transcripts/{id}` | 鉴权后返回统一文件服务短时下载授权 `{ token, transcript, expires_at }`,不由模块直接流式输出 PDF,不暴露对象存储直链或内部 grant 结构 |
| POST | `/transcripts/batch` `[管理员]` | 批量生成 |

## 8. 典型时序(成绩审核 → GPA)

```
教师 → POST /reviews(提交课程成绩)
管理员 → POST /reviews/{id}/approve(通过+锁定)
M11 → 读 M6 该课程成绩 + 学分 → 按等级映射算绩点
    → 更新 student_semester_grade(GPA)
    → 触发学业预警扫描 → 经 M10 通知
```
> 完整 GPA 聚合流程(读 M6、等级映射、Σ绩点×学分/Σ学分、累计重算、预警触发)见 `05-业务流程与状态机.md` §2;等级映射配置与绩点计算规则见 `02-数据模型.md` §2.1。

## 9. 申诉改分与锁事件发布 `[学生/教师]`

```
学生 → POST /appeals
教师/管理员 → POST /appeals/{id}/accept
M11 → 解锁该课程审核状态,发布锁事件驱动 M6 解除写保护投影,申诉进入"受理改分"
教师 → M6 PATCH /courses/{id}/grades/{sid} 执行单课程改分
M6 → 发布 teaching.grade.updated 事件
M11 → recompute 重算 GPA → 复核预警 → 重审重锁 → 申诉"已完成"
若 M6 未改分或事件未到达:申诉保持"受理改分"可继续处理,锁状态保持解锁
```
> 锁事件的可靠发布(先写 `grade_lock_outbox` 再发布 `grade.review.lock_changed`、失败重试、不裸调 NATS、与 `grade_appeal`/`grade_review` 同一租户事务原子写入)是数据模型契约,SSOT 见 `02-数据模型.md` §3.2;完整的跨模块解锁→改分→重审重锁回路见 `05-业务流程与状态机.md` §3。
