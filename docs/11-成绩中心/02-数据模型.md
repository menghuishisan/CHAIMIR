# M11 成绩中心 — 数据模型

> PostgreSQL,全部租户级(tenant_id + RLS)。M11 只存聚合/审核/预警元数据,单课程成绩在 M6。
> 建模遵循:消灭数据冗余、表合并有度。
> 最后更新:2026-05-29

---

## 1. 表清单总览

| 表名 | 用途 |
| --- | --- |
| `grade_level_config` | 等级映射配置(分数段→等级→绩点) |
| `semester` | 学期 |
| `grade_review` | 成绩审核记录 |
| `grade_lock_outbox` | 成绩锁定状态事件 outbox |
| `student_semester_grade` | 学生学期成绩聚合(GPA) |
| `grade_appeal` | 成绩申诉 |
| `academic_warning` | 学业预警 |
| `transcript_record` | 成绩单记录 |

> 消灭冗余/合并说明:
> - **单课程成绩不复制**:`student_semester_grade` 存聚合结果(学期 GPA/学分),明细课程成绩从 M6 实时读,不复制 M6 成绩到 M11。
> - **等级映射按学校配置**:`grade_level_config` 一校一套(或按学期),不写死。
> - **审核记录与聚合分表**:审核是流程流水,聚合是结果,分开。

| warning_rules | JSONB | 学业预警规则,如 {"fail_count":1,"min_gpa":2.0} |

### 2.2 semester — 学期

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| tenant_id | BIGINT | |
| name | VARCHAR(64) | 如 2025-2026-1 |
| start_date / end_date | DATE | |
| is_current | BOOLEAN | |

学期日期为包含起止日的闭区间,开始日不得晚于结束日。同租户学期间不得重叠,共用一个边界日也视为重叠;不同租户独立校验。创建学期先取得租户学期事务锁,在同一事务内读取既有区间、校验并写入,包括非当前学期。数据库另以 CHECK 约束保护起止顺序。

## 3. 审核与聚合

### 3.1 grade_review — 成绩审核

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| tenant_id | BIGINT | |
| course_id | BIGINT | 关联 M6 课程 |
| semester_id | BIGINT NULL | 报送时解析并保存的归属学期,审核通过时复核,供后续 M6 成绩变更事件重算 GPA;正常报送必须写入实际编号 |
| submitter_id | BIGINT | 提交教师 |
| reviewer_id | BIGINT NULL | 审核学校管理员 |
| status | SMALLINT | 1待审/2通过/3驳回 |
| is_locked | BOOLEAN | 审核状态是否已进入锁定态,供申诉/重审流程使用 |
| comment | VARCHAR(500) NULL | |
| submitted_at / reviewed_at | TIMESTAMPTZ | |

### 3.2 grade_lock_outbox — 成绩锁定事件 outbox

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| tenant_id | BIGINT | |
| review_id | BIGINT | 关联 `grade_review(tenant_id,id)` |
| revision | BIGINT GENERATED ALWAYS AS IDENTITY UNIQUE | 权威事务内产生的正修订;同课程先串行化状态变更,再分配修订 |
| course_id | BIGINT | M6 课程 ID |
| locked | BOOLEAN | true 锁定 / false 解锁 |
| reason | VARCHAR(64) | 事件原因,如 review_approved/appeal_accepted |
| trace_id | VARCHAR(128) | 原请求或事件链路编号 |
| status | SMALLINT | 1待发布/2发布中(持有租约)/3已发布/4发布失败待重试或重试耗尽 |
| retry_count | INT | 发布领取次数 |
| last_error | VARCHAR(255) NULL | 脱敏失败原因 |
| created_at / updated_at | TIMESTAMPTZ | |

> 成绩锁定状态变更必须与 `grade_review` 状态变更在同一事务内写入本表,再由后台任务发布 `grade.review.lock_changed` 驱动 M6 同步写保护投影。同课程审核/解锁/申诉受理/重锁事务先取得统一课程 advisory lock,再更新审核与写入 outbox,确保修订顺序对应已提交的状态变更。发布时使用原 revision 与 created_at,重试不重新生成修订或变更时间。M6 仅应用更大修订,重复与迟到解锁不会覆盖新锁定。发布失败只更新 outbox 状态并重试,不得在事务提交后裸调用事件总线作为唯一投递路径。

### 3.3 grade_update_cursor — 成绩事件消费游标

租户、课程、学生为复合主键,只保存已提交的最新 M6 成绩事件正修订。CAS只接受更大修订,与本次GPA/预警/申诉完成/重锁outbox同事务提交;回滚不推进游标。无审核记录属于报送前正常事件,仅失效该学生全量及学期缓存,不触发重试。修改同一学生聚合先取得学生advisory lock,课程状态变更仍先取得课程锁,避免跨课程同时覆盖聚合。

### 3.4 student_semester_grade — 学期成绩聚合

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| tenant_id | BIGINT | |
| student_id | BIGINT | |
| semester_id | BIGINT | |
| total_credits | NUMERIC(5,1) | 学期学分 |
| gpa | NUMERIC(4,3) | 学期 GPA |
| cumulative_gpa | NUMERIC(4,3) | 累计 GPA |
| computed_at | TIMESTAMPTZ | |

唯一约束:`(student_id, semester_id)`。

> 明细课程成绩从 M6 读;本表只存聚合结果,改分/申诉后重算。

## 6. 多租户与索引

- 全部表 `tenant_id` + RLS(同 M1)。
- 所有租户级 RLS policy 必须同时包含 `USING` 与 `WITH CHECK`,禁止只限制读而放开错误租户写入。
- 关键索引:
  - `grade_review(tenant_id, course_id, status)`
  - `grade_lock_outbox(status, created_at)`
  - `student_semester_grade(student_id, semester_id)` UNIQUE
  - `grade_appeal(tenant_id, student_id, status)`
  - `grade_appeal(tenant_id, student_id, course_id) WHERE status IN (1,2)` UNIQUE
  - `academic_warning(tenant_id, student_id, semester_id)`

### 学业预警的通知投递

`academic_warning`本身保存`notify_status`(1待投递/2租约中/3已确认发布/4失败待重试)、原trace、投递次数、租约、下次尝试时间及脱敏错误。预警与待投递状态同事务创建,不复制预警为第二套业务数据。GPA写入失败同时回滚。M11原outbox后台任务同时领取预警;失败或过期租约恢复后继续投递。请求编号固定为`grade:<预警创建年份>:warning:<warning_id>`,M10按该编号和收件人幂等写站内信。通知ACK只表示JetStream持久接收,不等于学生已读;学生确认与通知投递状态独立。
