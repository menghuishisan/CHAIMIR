# M4 仿真可视化引擎 — 接口设计

> RESTful + WebSocket(隔离容器执行仿真的状态推送)。鉴权沿用 M1 JWT。
> 内置包在浏览器运行,扩展包在后端隔离容器运行(见 02 架构设计 §8);后端接口服务:仿真包管理、
> 会话/操作序列持久化、隔离容器执行。
> 最后更新:2026-08-06

---

## 1. 通用约定

- Base:`/api/v1/sim`
- 统一响应体同 M1。错误码段:`4xxxx`(41xxx 仿真包/42xxx 会话/43xxx 审核)。
- `[内部]` 供 M6/M7 调用;`[用户]` 供前端。

## 2. 仿真包管理

### 2.1 查询与获取 `[用户]`
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/packages?category=&keyword=&status=published` | 仿真包列表 |
| GET | `/packages?mine=true&status=` | 当前账号作为作者提交的包(状态可选,缺省返回全部状态) |
| GET | `/packages/{code}/versions` | 某仿真的版本列表 |

`GET /packages` 有两种视角,同一路由按 `mine` 分叉,不新开第二条列表路由:

- **浏览可用场景**(`mine` 缺省或 `false`):`status` 只接受空或 `published`,其余取值返回 `A0004` —— 未审核、退回与已下架的包不对使用者开放。
- **查我提交的包**(`mine=true`):按 `author_type=2 AND author_id=<当前账号>` 过滤,`status` 可取 `draft/reviewing/published/archived/rejected` 任一值,缺省返回本人全部状态。作者边界取自服务端会话账号编号,**不接受客户端传作者参数**;教师因此能看到自己被退回或仍是草稿的包并继续修改,这是 `PATCH /packages/{id}` 的唯一入口来源。

**没有 bundle 下载授权接口。** 内置包由 sim-sdk 在浏览器 Worker 内按 `code` 装配,前端不需要取 bundle;
扩展包只在后端隔离容器内执行(见 02 架构设计 §8),bundle 字节从不下发到浏览器 ——
既没有前端装配路径,也不应该有:把外部代码送进浏览器 origin 正是要避免的事(见 07 安全设计 §2)。
原先为「扩展包在浏览器装配」准备的 `GET /packages/{code}/{version}/bundle` 已删除,不保留无消费者的授权入口。

### 2.2 扩展接入 `[教师/第三方]`
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/packages` | 提交仿真包(上传 bundle,状态=审核中) |
| GET | `/packages/{id}/preview` | 作者本人查看隔离预览报告与样例教学帧(审核前自测) |
| PATCH | `/packages/{id}` | 更新草稿/新版本 |

`POST /packages` 使用 `multipart/form-data`:元数据字段只允许 `code`、`version`、`name`、`category`、
`scale_limit`,文件字段为 `bundle`;出现未知字段、重复元数据字段或重复文件字段时必须拒绝。

**请求结构不含 `compute` 与 `backend_adapter`**:执行位置按代码来源派生 —— 教师与第三方提交一律
`compute=isolated` 且绑定平台的扩展包运行能力,`author_type`/`author_id`/code 命名空间(`teacher_<account_id>__`)
同样由服务端按登录账号强制。这消掉了「提交一个 `compute=browser` 的扩展包但平台没有任何路径能运行它」
这一整类无效状态,也不接受客户端伪造 `builtin__`、`org_` 或其他作者类型。

API 层必须用 streaming multipart 逐 part 处理,元数据字段累计大小由 `UPLOAD_SIM_BUNDLE_METADATA_MAX_BYTES` 控制,
bundle 文件正文大小由 `UPLOAD_SIM_BUNDLE_MAX_BYTES` 和 `internal/platform/upload.ReadBounded` 控制。
bundle 根目录或唯一顶层目录内必须包含 `sim-package.json`,其中:

- `meta` 必须与上传表单一致(`code`/`version`/`name`/`category`/`scale_limit`),并声明 `meta.entry` ——
  归档内的入口模块相对路径,供隔离容器装配。`entry` 必须是归档内真实存在的 `.mjs` 文件
  (只接受 `.mjs`:归档内没有 package.json 时 Node 按 CJS 解析 `.js`,而扩展包必须默认导出 SimPackage,
  允许 `.js` 会让「能不能装配」取决于打包方式),不得为绝对路径、不得含 `..`、不得指向归档外;缺失或非法即 `41002`。
- `interactions` 会提取为服务端操作白名单。
- `render.protocol` 必须为 `teaching-frame`,`render.patterns` 只能声明 1 到 3 个带稳定 `id` 的封闭模式,
  `roles` 只能取 `primary/evidence/timeline/metrics/trace/checkpoints`,不得再接受旧版区域字段。

后端必须计算 bundle sha256,不得信任客户端提交的 hash;同时执行危险调用静态扫描。
**静态扫描结果不再作为准入硬门禁的唯一依据**:它拦不住 `globalThis['fe'+'tch']` 这类拼接,
真正的边界是隔离容器(07 安全设计 §3),故扫描命中在报告中标注并提请审核人重点查看。
M4 在通过版本冲突、作者归属和包状态校验后才写入对象存储,避免业务校验失败留下孤儿 bundle;
若对象写入后仍失败,对应包会被显式退回并留下审核轨迹,不会以待审态悬挂。
对象存储删除能力统一归 `internal/platform/storage` 扩展,M4 不自建删除通道。

四项审核门禁里,`metadata_validation` 与 `static_scan` 由上传流程生成,`determinism_check`、
`worker_preview` 与 `preview_frames` 由 M4 自己的隔离预览任务写入 —— 它按
`SIM_PREVIEW_POLL_INTERVAL_SECONDS` 认领待审包,在隔离容器内同 seed 跑两遍比对(得确定性结论)、
渲出若干教学帧并按协议校验(得渲染结论与样例帧)。平台管理员只执行审核决策,不得手工回写预览结论;
`static_scan`、`bundle_hash`、`metadata_validation` 由上传扫描生成,预览回写只补动态字段、不覆盖它们。
`approve` 前必须满足 `metadata_validation=passed`、`static_scan=passed`、`determinism_check=passed`
且 `worker_preview=passed`,否则返回 `41005`。

**没有回写接口**:预览任务与包一样住在 M4 进程内,写自己的表不需要绕一趟 HTTP 自调用;
而一个能把两项门禁直接置为 `passed` 的服务签名入口,本身就是审核闸门的旁路,故不保留。
没有这个生产者,四项门禁中的两项永远为空,教师提交的包会永久停在待审 ——
审核链路必须闭合,不允许只有门禁没有执行者。

`GET /packages/{id}/preview` 仅允许教师包提交者本人读取自己的最新审核报告,响应含四项校验结论与
样例教学帧;平台管理员通过 `/reviews` 查看待审列表和同一报告。任意教师或学校管理员不得按 package id
横向读取其他作者的待审报告。

匿名公开回放 `GET /shared/{code}` **只运行内置包**:扩展包属所属租户教学资产,分享码只暴露可复现剧本;
且匿名请求不得触发隔离容器创建,那是零成本资源耗尽入口。分享剧本的 `package_code` 为扩展包时,
公开页明确不可回放,不降级渲染;完整回放走登录后的租户内授权路径。

### 2.3 审核 `[平台管理员]`
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/reviews?result=pending` | 待审核列表(含四项校验结论与样例教学帧) |
| POST | `/reviews/{id}/approve` | 通过 → 上架 |
| POST | `/reviews/{id}/reject` | 退回 + 意见 |

> 自动校验回答"能不能跑、是否确定性",回答不了"这个算法实现对不对"。故审核列表必须携带隔离容器渲出的
> 样例教学帧,让管理员有具体内容可判断,而不是只看两个 `passed` 徽章。

### 2.4 生命周期管理 `[平台管理员]`
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/packages/{id}/archive` | 已上架包下架,不删除历史会话与回放 |
| POST | `/packages/{id}/republish` | 已下架包重新上架 |

> 下架只影响新会话创建和普通列表可见性;历史会话、操作序列、分享剧本仍按会话权限与分享码读取。重新上架仅允许从已下架状态恢复,不得绕过审核把草稿、审核中或退回包直接发布。

## 3. 仿真会话 `[内部/用户]`

### 3.1 创建会话
`POST /sessions` `[内部]`
请求:
```json
{ "package_code": "builtin__pow-longest-chain", "version": "1.0.0",
  "seed": 20260529, "init_params": { "minerCount": 10 },
  "owner_account_id": 1001, "source_ref": "experiment:2026:instance:55" }
```
响应:`{ "session_id": 7001, "compute": "browser" }`
> `compute=browser`(平台内置包):前端在隔离 Worker 中运行仿真包内核,后端只记录会话与操作序列。
> `compute=isolated`(扩展包与重计算仿真):后端在隔离容器中执行,前端经 `WS /sessions/{id}/stream`
> 接收完整教学快照并只做渲染。响应不含 bundle 引用 —— 内置包按 `package_code` 在 Worker 内装配,
> 扩展包 bundle 从不下发到浏览器。
> 内部服务接口必须使用服务签名头携带 `source_ref`;单会话回收与检查点写入会校验该会话 `source_ref` 与签名来源一致,禁止调用方用合法服务签名篡改其他来源的会话。
> 创建 `compute=isolated` 会话时校验本租户并发上限,超限返回 `42005`。

### 3.2 上报操作 `[用户]`
`POST /sessions/{id}/actions`
请求:`{ "seq": 12, "at_tick": 34, "event_type": "launch-51", "payload": { "blocks": 6 } }`
> 前端运行时把用户操作异步上报,用于回放/分享/判分;不阻塞交互。
> `seq` 在同一会话内必须连续递增;重复上报同一 `seq` 且内容一致视为幂等成功,内容不同返回 `42004`。
> `compute=isolated` 的会话由服务端在执行成功后自行登记操作序列,前端不重复上报同一动作。

### 3.3 回放数据
`GET /sessions/{id}/replay`
响应:`{ "seed": 20260529, "init_params": {...}, "actions": [ ... ] }`
> 前端用 seed + actions 重放复现。

### 3.5 回收会话 `[内部]`
- `DELETE /sessions/{id}` `[内部]`:回收单个仿真会话(归档操作序列,释放隔离执行资源)。
- `POST /sessions/recycle` `[内部]`:按 `source_ref` 批量回收(来源结束级联,与 M2 `/sandboxes/recycle` 对齐)。
> 前端运行的内置包无后端常驻资源,回收主要归档会话状态;`compute=isolated` 的会话同时删除隔离执行命名空间。M7 实例回收时调用本接口释放其引用的仿真会话。

### 3.4 分享剧本
- `POST /sessions/{id}/share` → 生成分享码。
- `GET /shared/{code}` → 取 `(package, version, seed, init_params, actions)` 复现。
响应:
```json
{
  "package_code": "builtin__pow-longest-chain",
  "version": "1.0.0",
  "seed": 20260529,
  "init_params": {},
  "actions": []
}
```
> 公开分享剧本只返回复现所需的公开参数。`init_params` 和 action `payload` 中的答案、flag、token、密钥、凭据、私有字段以及 `_` 开头内部绑定字段必须过滤;完整回放仍只能通过租户内授权接口读取。

## 4. 隔离容器执行 `[用户]`(compute=isolated)

教师与第三方扩展包在后端隔离容器内执行,经 WS 推送完整教学快照。M4 只使用自有受控执行能力,
不直接调用 M2 沙箱接口,以满足《工程目录设计》中 `sim/sandbox/content` 同层互不依赖的边界。

能力目录由 `SIM_BACKEND_STDIO_ADAPTERS_JSON` 登记,当前一项:

| 能力编号 | 镜像 | bundle 投递 | 承载 |
| --- | --- | --- | --- |
| `sim-package-runner` | `sim/package-runner` | 会话建立时经 k8s exec stdin 推入归档字节,容器内校验 sha256 后按 `meta.entry` 装配 | 全部教师/第三方扩展包 + 隔离预览 |

同协议的重计算形态(算法固化在镜像内、无 `entry`)明确不做:没有任何包能引用它(见 04 数据模型 §2.1 的
复合 CHECK),登记一条无法被引用的能力等于让启动期证明校验为空转买单。启用条件见
`docs/前端后端功能对齐清单.md` §6.26。

标准适配器不接受教师自定义 `backend_config`;镜像、命令、受控环境变量、资源、超时和输入输出限制
只由能力目录控制。任何未登记能力或超出租户并发上限统一返回 `42005`,
不得以空适配器、回显实现或回落到前端执行兼容。

**没有运行能力查询接口**:执行位置与运行能力都由服务端按作者类型派生 —— 教师与第三方提交的包
一律绑定 `sim-package-runner`。
提交者没有任何可选项,一个「可用能力列表」对他没有可作用的内容,故不保留这条无消费者的查询入口。

`WS /sessions/{id}/stream`
- 浏览器客户端通过 M1 `POST /api/v1/auth/ws-ticket` 为该 WS path 换取短时 `ticket`,不得在 URL 中携带 access token。
- 客户端发四种受控命令,除此之外一律拒绝:
  ```json
  { "type": "step" }                                              // 推进一个推演时刻
  { "type": "event", "event_type": "...", "payload": {...} }        // 注入一次包内声明的交互
  { "type": "back" }                                               // 回退一步
  { "type": "restart" }                                            // 回到初始状态
  ```
  只有 `event` 过 `interaction_schema` 白名单,并在**容器执行成功后**才登记进操作序列 ——
  一条被包拒绝的事件不该留在只追加的记录里。时刻推进由 seed 决定、可复算,不入记录。
  `back`/`restart` 之后本连接不再登记新操作 —— 操作序列只追加,表达不了「撤回一步」,
  继续追加会让记录描述一个从未发生过的过程(与浏览器内置包同一条规则)。
- 服务端推:首帧 `ready` 带包自描述信息,其后 `snapshot` 只带快照
  ```json
  { "type": "ready", "event_count": 0,
    "descriptor": { "meta": {...}, "interactions": [...], "narrative": [...],
                    "codeTrace": {...}, "checkpoints": [...] },
    "snapshot": { "tick": 0, "state": {...}, "view": {...}, "current_step": {...},
                  "interaction_availability": {...}, "checkpoint_results": {...} } }
  ```
> **为什么首帧要带包自描述信息**:浏览器不执行扩展包代码,拿不到包内声明,而「可用操作」的名称与
> 参数字段、检查点标题、教学步骤总数都是渲染工作台的必要材料 —— 只推快照的话页面能画舞台却画不出操作面板。
> 它同样是不可信输出:服务端按已入库的 `interaction_schema` 逐项核对 `emits`、核对包身份与条目数量上限后才转发,
> 否则页面会渲出一个点下去必然被白名单拒绝的按钮。它只随首帧下发一次(静态声明不随 tick 变化)。
>
> **`event_count` 由服务端给**:过程由服务端持有(容器每次从初始状态重放),刷新重连后服务端会按已登记操作
> 把过程重放回上次位置,前端自己数不准,故回退按钮的可用性以服务端计数为准。
>
> **为什么推完整快照而非仅 state**:`render` 是仿真包自己的函数,扩展包的 `render` 属外部代码,
> 浏览器不得执行(07 安全设计 §2)。容器内完成 `reducer` + `render` + 叙事命中 + 检查点求值,
> 前端拿到的已是纯数据帧,交给平台自己的封闭模式渲染器绘制 —— 前端因此只有一条渲染路径,
> 不在页面复制 reducer、舞台、时间线或检查器。
>
> **快照是不可信输入**:服务端在转发前必须按 TeachingFrame 协议校验(`patterns` 1–3 个且带稳定 `id`、
> `mode` 属七类封闭集、`layout` 只引用当帧存在的 pattern `id`、规模字段不超包声明 `scale_limit`),
> 校验不过返回 `42011` 并终止会话,不把不合协议的帧透传给前端。

## 5. 检查点上报 `[内部]`

`POST /sessions/{id}/checkpoints`
请求:`{ "checkpoint_id": "cp-51-success", "answer": "能", "achieved": true }`

> 同一会话同一 `checkpoint_id` 重复上报按最新结果覆盖;M4 只保存结果快照,不判分、不保存正确答案。

## 6. 典型时序

### 6.1 内置包(浏览器运行)

```
M7 → POST /sessions(package+seed+params+source_ref)
M4 → session_id + compute=browser
前端 → 按 code 在 Worker 内装配内置包内核,本地运行状态机
学生 → 交互(滑块/按钮/注入攻击)→ 本地即时演化
前端 → 异步 POST /actions 上报操作序列
叙事设问 → POST /checkpoints → M3 判分
完成 → 会话归档;可 /share 分享剧本
```

### 6.2 扩展包(隔离容器运行)

```
教师 → POST /packages(bundle + meta,compute 由服务端派生为 isolated)
M4  → 计算 sha256 + 静态扫描 + manifest 协议校验 → 写对象存储 → 待审
M4 预览任务 → 隔离容器装配 bundle → 同 seed 跑两遍比对 + 渲样例帧
            → 写入 determinism_check / worker_preview / preview_frames
平台管理员 → GET /reviews 看四项结论与样例帧 → approve → 上架

M7 → POST /sessions → M4 校验租户并发上限 → session_id + compute=isolated
前端 → 换 ws-ticket → WS /sessions/{id}/stream
M4  → 建隔离命名空间 + Pod → exec stdin 投 bundle → 校验 hash → 装配
    → 按会话已登记操作重放到上次位置 → 推 ready 帧(含包自描述信息与完整快照)
学生 → 交互事件 → 服务端 schema 白名单 → 登记操作 → 容器执行 → 推 snapshot 帧
学生 → 回退/从头再来 → 服务端丢弃最近事件后重算 → 此后不再登记新操作
完成/超时/回收 → 删除会话命名空间
```
