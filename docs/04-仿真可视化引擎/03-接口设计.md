# M4 仿真可视化引擎 — 接口设计

> RESTful + WebSocket(隔离容器执行仿真的状态推送)。鉴权沿用 M1 JWT。
> 内置包在浏览器运行,扩展包在后端隔离容器运行(见 07-架构设计.md §8);后端接口服务:仿真包管理、
> 会话/操作序列持久化、隔离容器执行。
> 最后更新:2026-11-27

---

## 1. 通用约定

- Base:`/api/v1/sim`
- 统一响应体同 M1。错误码段:`4xxxx`(41xxx 仿真包/42xxx 会话/43xxx 审核)。
- `[内部]` 供已验签业务服务调用，HTTP 路径统一位于 `/internal`；模块内调用走 `internal/contracts`。`[用户]` 供前端。
- 业务发布前经 `SimService.ValidatePackage` 只读核验锁定包版本、租户仿真模块授权、已发布状态、执行位置及隔离适配器配置，与创建会话复用同一可运行包检查。不创建会话或执行资源、不占并发配额；实际创建重新校验当前状态，不代替运行时参数、资源和输出检查。
- 用户入口要求学校开放仿真模块；新建会话、操作上报、回放、分享和新隔离执行连接同时检查持久化来源的业务模块。匿名分享按分享记录所属租户检查，关闭后不能借分享码继续读取；检查统一经 M1 只读契约，既有归属、有效期和匿名不创建隔离容器的边界保留。

## 2. 仿真包管理

### 2.1 查询与获取 `[用户]`
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/packages?category=&keyword=&status=published` | 仿真包列表 |
| GET | `/packages?mine=true&status=` | 当前账号作为作者提交的包(状态可选,缺省返回全部状态) |
| GET | `/packages/{code}/versions` | 仅返回已上架（published）版本；本人草稿、待审和退回包走 `?mine=true` 列表 |

`GET /packages` 有两种视角,同一路由按 `mine` 分叉,不新开第二条列表路由:

- **浏览可用场景**(`mine` 缺省或 `false`):`status` 只接受空或 `published`,其余取值返回 `A0004` —— 未审核、退回与已下架的包不对使用者开放。
- **查我提交的包**(`mine=true`):按 `author_type=2 AND author_id=<当前账号>` 过滤,`status` 可取 `draft/reviewing/published/archived/rejected` 任一值,缺省返回本人全部状态。作者边界取自服务端会话账号编号,**不接受客户端传作者参数**;教师因此能看到自己被退回或仍是草稿的包并继续修改,这是 `PATCH /packages/{id}` 的唯一入口来源。已退回的包带 `reject_comment`(该包最近一次退回的审核意见,当前页一次查询),作者不用打开审核报告就能看到退回原因;其他视角不返回该字段。

**没有 bundle 下载授权接口。** 内置包由 sim-sdk 在浏览器 Worker 内按 `code` 装配,前端不需要取 bundle;
扩展包只在后端隔离容器内执行(见 07-架构设计.md §8),bundle 字节从不下发到浏览器 ——
既没有前端装配路径,也不应该有:把外部代码送进浏览器 origin 正是要避免的事(见 06-安全设计.md §2)。
原先为「扩展包在浏览器装配」准备的 `GET /packages/{code}/{version}/bundle` 已删除,不保留无消费者的授权入口。

### 2.2 扩展接入 `[教师/学校管理员]`

本节三个入口均允许租户教师和学校管理员，作者绑定当前账号；第三方作者包由平台受控导入，不提供第三方用户提交入口。审核和上下架仅允许平台管理员。
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/packages` | 提交仿真包(上传 bundle,状态=审核中) |
| GET | `/packages/{id}/preview` | 作者本人查看隔离预览报告与样例教学帧(审核前自测) |
| PATCH | `/packages/{id}` | 更新草稿或已退回的包并重新送审 |

提交和更新都使用 `multipart/form-data`。必填元数据为 `code`、`version`、`name`、`category` 和
`scale_limit`，必填文件为 `bundle`。拒绝未知或重复字段。`scale_limit` 是 JSON 对象，内含正整数
`nodes`（最多 10,000）、`max_tick` 和 `max_events`（各最多 100,000），三个值都必须与包内声明一致。

提交和更新先校验并上传到本次独立对象路径，再在所属租户的普通应用事务中写包、待审记录、响应和 M1 审计；平台级包表仍无租户副本。上传失败不创建或修改包，尚未尝试提交的失败清理本次对象，保留已有包与审核记录；清理失败保留原错误和清理错误并记录日志。数据库提交结果不明时保留本次对象，不以事后查询未命中作为删除依据。更新成功后清理本次替换的旧对象，清理失败记录日志，不把已受理更新返回成失败。

`max_tick` 仅限制时刻推进，`max_events` 限制时刻推进与用户操作的总数，两者独立。用户操作在最大时刻仍可发生，前提是总事件数未耗尽。记录恢复须完整重建，序号不连续、时刻倒退或超限均显式失败，不得截断历史后继续运行。浏览器动作上报同时校验 `at_tick <= max_tick` 与 `at_tick + seq <= max_events`。隔离执行只有在快照确认时刻符合命令结果后才推进本地历史，终态单步未推进时刻不计入事件。

隔离流和审核样例的快照必须携带完整 `state`、`view`、`interaction_availability`、`checkpoint_results`；两个映射即使为空也返回对象，不省略或传 null。描述中的 `narrative`、`interactions` 和 `checkpoints` 必须是完整数组。结构校验从 SDK 类型生成，两端共用，非法输出返回 `42011`；浏览器在渲染入口拒绝损坏数据并保留重试或翻帧出口。
完整包元数据始终返回这三个值。

**请求结构不含 `compute` 与 `backend_adapter`**:执行位置按代码来源派生 —— 本节上传一律
`compute=isolated` 且绑定平台的扩展包运行能力,`author_type`/`author_id`/code 命名空间(`teacher_<account_id>__`)
同样由服务端按登录账号强制。这消掉了「提交一个 `compute=browser` 的扩展包但平台没有任何路径能运行它」
这一整类无效状态,也不接受客户端伪造 `builtin__`、`org_` 或其他作者类型。

API 层必须用 streaming multipart 逐 part 处理,元数据字段累计大小由 `UPLOAD_SIM_BUNDLE_METADATA_MAX_BYTES` 控制,
bundle 文件正文大小由 `UPLOAD_SIM_BUNDLE_MAX_BYTES` 和 `internal/platform/upload.ReadBounded` 控制。
bundle 根目录或唯一顶层目录内必须包含 `sim-package.json`;`sim-package.json` 的完整格式与逐字段校验规则
(`meta` 与上传表单一致并声明 `entry`、`.mjs` 入口约束、`interactions` 提取为操作白名单、`render.protocol=teaching-frame`、
`patterns` 1–3 个带稳定 `id` 的封闭模式、`roles` 取值、拒绝未知字段等)见 `08-可视化SDK与交互协议.md` §1.1,
校验失败统一返回 `41002`。该清单是 manifest 的 SSOT,本接口只描述上传 API 契约,不重复 manifest 字段级规则。

归档根存在清单时以它为准，子目录清单作为普通素材扫描，不因成员顺序覆盖根清单。根无清单时，只接受一个顶层目录，全部普通文件须位于该目录内；入口相对所选包根解析。上传校验与隔离运行器使用同一根目录规则，混合目录或外置入口拒收。

后端必须计算 bundle sha256,不得信任客户端提交的 hash;同时执行危险调用静态扫描。
**静态扫描结果不再作为准入硬门禁的唯一依据**:它拦不住 `globalThis['fe'+'tch']` 这类拼接,
真正的边界是隔离容器(06-安全设计.md §3),故扫描命中在报告中标注并提请审核人重点查看。
扫描无命中为 `passed`，只有危险调用提示为 `warning`；结构或入口损坏为 `failed` 并拒收。删除对象沿用统一存储能力，限定当前租户及包路径。

审核报告的生成、任务领取、续租与失败恢复由[审核流程](05-业务流程与状态机.md#4-仿真包接入审核流程)定义。上传负责静态字段，M4 进程内预览任务只补动态结论及样例帧；管理员不能手工回写预览结果。
`approve` 前必须满足 `metadata_validation=passed`、`determinism_check=passed`、`worker_preview=passed`，
扫描为 `passed` 或带非阻断提示的 `warning`，报告摘要与当前包一致，且样例帧合法；否则返回 `41005`。风险提示须展示给审核人，由人工决定通过或退回，不自动放行上架。

容器 `verify` 响应必须返回包描述、请求指定数量的合法快照（1–32 帧）和明确的 `passed/failed` 确定性结论。确定性比较同时覆盖包描述和快照。预览与运行首帧共用包描述校验。容器快照仅包含 `tick/state/view/current_step/interaction_availability/checkpoint_results`。操作历史由后端保存，在 `apply/restore` 命令中传入。后端严格拒绝未登记的响应字段。

审核报告由进程内任务写入，不提供服务签名回写接口。

`GET /packages/{id}/preview` 仅允许教师包提交者本人读取自己的最新审核报告,响应含四项校验结论与
样例教学帧;平台管理员通过 `/reviews` 查看待审列表和同一报告。任意教师或学校管理员不得按 package id
横向读取其他作者的待审报告。

匿名公开回放 `GET /shared/{code}` **只运行内置包**:扩展包属所属租户教学资产,分享码只暴露可复现剧本;
且匿名请求不得触发隔离容器创建,那是零成本资源耗尽入口。分享剧本的 `package_code` 为扩展包时,
公开页明确不可回放,不降级渲染;完整回放走登录后的租户内授权路径。

### 2.3 审核 `[平台管理员]`

通过、退回、下架和重新上架均在原应用事务内构造响应并写 M1 平台审计；状态变更、审核结论、审计及响应校验任一步失败时整体回滚。提交后直接返回已构造的结果，不补写审计或重新读取。

上下架先锁定包行，再检查当前状态和更新；并发的同类操作只有一个成功并写入审计，后续请求按锁后状态拒绝。审核结论沿用数据库 `result=待审` 条件更新，禁止重复决策。

退回必须填写说明；通过、下架与重新上架不要求说明。自动校验与生命周期准入由服务端执行。
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/reviews?result=pending` | 待审核列表(含四项校验结论与样例教学帧);每条带提交教师姓名 `submitter_name`,经身份契约一次批量解析 |
| POST | `/reviews/{id}/approve` | 通过 → 上架 |
| POST | `/reviews/{id}/reject` | 退回 + 意见 |

作者预览与管理员审核决策都返回 `{ package, review }`。提交和更新保留包元数据顶层字段，并附带 `review`。

> 自动校验回答"能不能跑、是否确定性",回答不了"这个算法实现对不对"。故审核列表必须携带隔离容器渲出的
> 样例教学帧,让管理员有具体内容可判断,而不是只看两个 `passed` 徽章。

### 2.4 生命周期管理 `[平台管理员]`
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/packages/{id}/archive` | 已上架包下架,不删除历史会话与回放 |
| POST | `/packages/{id}/republish` | 已下架包重新上架 |

> 下架只影响新会话创建和普通列表可见性;历史会话、操作序列、分享剧本仍按会话权限与分享码读取。重新上架仅允许从已下架状态恢复,不得绕过审核把草稿、审核中或退回包直接发布。

## 3. 仿真会话 `[内部/用户]`

### 3.1 创建会话
`POST /internal/sessions` `[内部]`
请求:
```json
{ "package_code": "builtin__pow-longest-chain", "version": "1.0.0",
  "seed": 20260529, "init_params": { "minerCount": 10 },
  "owner_account_id": "1001",
  "scope_ref": "experiment:2026:instance:55:run:1",
  "authorized_account_ids": ["1002", "1003"] }
```
响应:`{ "session_id": "7001", "compute": "browser" }`
> `compute=browser`(平台内置包):前端在隔离 Worker 中运行仿真包内核,后端只记录会话与操作序列。
> `compute=isolated`(教师/第三方扩展包):后端在隔离容器中执行,前端经 `WS /sessions/{id}/stream`
> 接收完整教学快照并只做渲染。响应不含 bundle 引用 —— 内置包按 `package_code` 在 Worker 内装配,
> 扩展包 bundle 从不下发到浏览器。
> 内部服务接口必须使用服务签名头携带稳定 `source_ref`,并在请求体显式提交本次 `scope_ref`;单会话操作会校验会话归属和组合快照,批量回收按 `scope_ref` 且再次匹配 `source_ref`,禁止调用方用合法服务签名篡改其他来源或其他生命周期的会话。
> 创建和批量回收的 HTTP 请求体不接受 `tenant_id` 或 `source_ref`，两者只取服务签名上下文；即使正文值与签名相同也按未知字段拒绝。API 转换为 `internal/contracts` 后由同一个服务入口执行，模块契约直接保留已授权身份，不经 HTTP DTO 回转。
> 创建 `compute=isolated` 会话时校验本租户并发上限,超限返回 `42005`。

会话只持久化可用与已归档两态，创建直接写可用。初始化、断线、执行失败和达成目标属于运行过程，不另写会话状态；断线回收本次临时环境，重连按已登记操作恢复。来源结束或显式回收时归档，归档后只读回放，不能恢复执行。

会话创建在同一租户事务中写入会话、构造响应并记录 M1 审计，任一步或提交失败均不留下新会话。单个及按作用域归档也与 M1 审计统一提交，审计失败不释放运行资源。提交后再关闭执行连接、回收外部资源；回收失败保留已归档状态和审计，重复调用继续清理该来源的已归档资源，不重新开放执行。

隔离会话创建先取得租户级事务 advisory lock，再单独读取可用会话数并建行；计数与创建共用该锁直到提交，不能用同一普通事务中的无锁计数代替串行化。可用的隔离会话占配额，包括当前未连接的会话；归档后不再计入。该额度限制可用会话数，外部资源删除仍可能失败，须显式返回并允许重试。

实际隔离环境也受同一租户上限约束，执行和已归档回放共同计数，平台预览使用租户 `0`。创建命名空间前在租户 Redis 租约内检查现存环境数并创建；终止中或清理失败的环境仍计入，不能通过归档绕过容量。达到上限返回 `42005`。

执行与回放使用不同的资源作用域及 Redis token 租约(`SIM_BACKEND_SESSION_LEASE_DURATION_SECONDS`)，归档清理只等待并回收原执行，不影响只读回放。按有效期的三分之一续租，覆盖执行及独立清理；续租失败取消执行及阻塞读。每次执行使用独立命名空间；启动只清理申请租约前已列出的同作用域残留资源，删除携带 UID 前置条件，旧执行只回收自己的环境。租约用于协调副本，不充当数据库写入凭据；动作追加在会话行锁内复核授权、状态和重放时读取的末尾序号，历史已推进时拒绝旧执行继续追加。

### 3.1.1 同租户共享授权 `[内部]`
`UpdateSessionAuthorizedAccounts` 只接受服务签名携带的稳定 `source_ref`、目标租户和会话编号,原子替换 `shared_account_ids`。
M7 成员变更和实例资源最终落库前都调用该契约;M4 只校验账号属于当前租户,不读取 M7 表。授权集合收缩成功提交后,按 `sim:<session_id>` 作用域关闭被撤销账号的在线仿真流;集合更新失败则事务不提交,调用方必须重试。

### 3.2 上报操作 `[用户]`
`POST /sessions/{id}/actions`
请求:`{ "seq": 12, "at_tick": 34, "event_type": "launch-51", "payload": { "blocks": 6 } }`
> 前端运行时把用户操作异步上报,用于回放/分享/判分;不阻塞交互。
> `seq` 在同一会话内必须连续递增;重复上报同一 `seq` 且内容一致视为幂等成功,内容不同返回 `42004`。
> `compute=isolated` 的会话由服务端在执行成功后自行登记操作序列,前端不重复上报同一动作。
内置包仅在 Worker 确认执行成功后上报，动作类型、参数和时刻取确认事件，不取页面旧快照。客户端按操作发生顺序串行提交；失败后停止追加该会话的后续记录，刷新并读取服务端回放后再继续。失败只提示记录中断，不撤销本地已执行的仿真操作。销毁 Worker 必须拒绝所有等待命令，终止后不得再发送。

`max_tick` 只限制时刻推进，`max_events` 限制时刻事件与用户操作的总数。第 `seq` 条用户操作必须满足 `at_tick <= max_tick` 且 `at_tick + seq <= max_events`；允许在最大时刻继续执行仍在事件额度内的用户操作。恢复时拒绝序号缺口、时刻倒退及超过规模的记录，不截断历史。容器确认时刻后才追加事件，终态单步未推进时不虚构时刻事件。

### 3.3 回放数据
`GET /sessions/{id}/replay`
响应:`{ "package_code": "...", "version": "1.0.0", "seed": 20260529, "init_params": {...}, "actions": [ ... ], "read_only": true }`
`read_only` 从当前会话状态派生：已归档只读，可用允许继续执行。内置包的归档工作台与公开分享复用同一回放运行时，只开放播放、回退和从头回放，不提供操作注入、换条件、版本切换或新分享。

恢复内置会话时，全部历史命令确认成功后才开放运行时与自动播放；失败保留错误画面，不进入可操作态。只读回放一条命令确认前不接收重复控制输入，避免按旧快照重复发送同一条记录；进度仍从 Worker 事件日志派生。销毁期间取消的初始化不应写回卸载后的页面或污染下一次装配。

### 3.4 分享剧本
- `POST /sessions/{id}/share` → 生成分享码。
- `GET /shared/{code}` → 取 `(package, version, seed, init_params, actions)` 复现。

创建请求必须提供 JSON 对象。`{}` 表示不自动过期，也可传 `{ "expire_at": "2027-01-01T00:00:00Z" }`；非零时间必须晚于服务端当前时间。仅可用且当前账号有权访问的会话可创建分享。

创建响应为 `{ "code": "...", "expire_at": "2027-01-01T00:00:00Z", "status": "active" }`。不自动过期时，`expire_at` 序列化为 Go 零时间 `"0001-01-01T00:00:00Z"`。

公开回放响应:
```json
{
  "package_code": "builtin__pow-longest-chain",
  "version": "1.0.0",
  "seed": 20260529,
  "init_params": {},
  "actions": []
}
```
> 公开分享剧本只返回复现所需的公开参数。`init_params` 和 action `payload` 中的答案、flag、token、密钥、凭据、私有字段以及 `_` 开头内部绑定字段必须过滤;完整回放仍只能通过租户内授权接口读取。

### 3.5 回收会话 `[内部]`
- `DELETE /internal/sessions/{id}` `[内部]`:回收单个仿真会话(归档操作序列,释放隔离执行资源)。
- `POST /internal/sessions/recycle` `[内部]`:按正文 `scope_ref` 批量回收；稳定 `source_ref` 只取服务签名，用于归属校验，两者不得混用。
> 前端运行的内置包无后端常驻资源,回收主要归档会话状态;`compute=isolated` 的会话同时删除隔离执行命名空间。M7 实例回收时调用本接口释放其引用的仿真会话。M7 成员撤销不是回收会话,而是通过共享授权契约更新集合并关闭被撤销账号的在线流。

归档先阻止后续执行，再通过 `sim.sessions.changed` 通知所有在线副本复核当前会话；归档关闭执行流，授权变更关闭当前已无权访问的执行流和只读回放流。两类流使用独立作用域，延迟归档通知不得关闭仍获授权的回放流。信号只携带租户及会话编号，重复或延迟投递按当前数据库状态处理。归档限时等待执行权并回收资源；每次读取命令和写入动作仍复核权威授权。归档不代表外部删除成功；单会话与作用域回收都可重试，批量尝试全部会话并合并错误。重试不另建任务、状态或数据库结构。

## 4. 隔离容器执行 `[用户]`(compute=isolated)

教师与第三方扩展包在后端隔离容器内执行,经 WS 推送完整教学快照。M4 只使用自有受控执行能力,
不直接调用 M2 沙箱接口,以满足《工程目录设计》中 `sim/sandbox/content` 同层互不依赖的边界。

能力目录由 `SIM_BACKEND_STDIO_ADAPTERS_JSON` 登记,当前一项:

| 能力编号 | 镜像 | bundle 投递 | 承载 |
| --- | --- | --- | --- |
| `sim-package-runner` | `sim/package-runner` | 会话建立时经 k8s exec stdin 推入归档字节,容器内校验 sha256 后按 `meta.entry` 装配 | 全部教师/第三方扩展包 + 隔离预览 |

扩展包的隔离预览和正式会话都使用数据库保存的对象引用、归档哈希与入口文件。扩展包缺少入口或归档时拒绝执行。

当前包类型与执行范围以[需求规格](01-需求规格.md#3-职责边界)和[数据模型](02-数据模型.md#21-sim_package--仿真包含版本)为准。

标准适配器不接受教师自定义 `backend_config`;镜像、命令、受控环境变量、资源、超时和输入输出限制
只由能力目录控制。任何未登记能力或超出租户并发上限统一返回 `42005`,
不得以空适配器、回显实现或回落到前端执行兼容。

**没有运行能力查询接口**:执行位置与运行能力都由服务端按作者类型派生 —— 教师与第三方提交的包
一律绑定 `sim-package-runner`。
提交者没有任何可选项,一个「可用能力列表」对他没有可作用的内容,故不保留这条无消费者的查询入口。

`WS /sessions/{id}/stream`
- 浏览器客户端通过 M1 `POST /api/v1/auth/ws-ticket` 为该 WS path 换取短时 `ticket`,不得在 URL 中携带 access token。
- 服务端从会话状态决定模式，帧均带 `read_only`。可用会话继续执行；已归档会话只在临时隔离环境重算已保存的事件前缀，不追加记录、不改变会话状态，连接结束回收环境。两者复用同一受控适配器、租约机制、租户容量与输出校验，扩展包正文不下发浏览器。只读模式只接受 `step/back/restart`；`step` 复现下一条已记录事件，抵达末尾后停止，`event` 一律拒绝。
- 浏览器收到合法 `ready` 帧后才开放控制与自动播放；同一命令确认前不再发送下一条。重连清空旧帧和协议错误，重新以首帧恢复；首帧前连接关闭也必须显示重试入口，不能一直停留在准备态。未知帧类型、缺少计数和未就绪的快照不得作为成功帧接受。
- 客户端发四种受控命令,除此之外一律拒绝:
  ```json
  { "type": "step" }                                              // 推进一个推演时刻
  { "type": "event", "event_type": "...", "payload": {...} }        // 注入一次包内声明的交互
  { "type": "back" }                                               // 回退一步
  { "type": "restart" }                                            // 回到初始状态
  ```
  只有 `event` 过 `interaction_schema` 白名单,并在**容器执行成功后**才登记进操作序列 ——
  一条被包拒绝的事件不该留在只追加的记录里。时刻推进由 seed 决定、可复算,不入记录。
  `back`/`restart` 之后本连接不再登记新操作 —— 操作序列只追加,表达不了「撤回一步」,
  继续追加会让记录描述一个从未发生过的过程(与浏览器内置包同一条规则)。
- 服务端推:首帧 `ready` 带包自描述信息,其后 `snapshot` 只带快照
  ```json
  { "type": "ready", "read_only": false, "event_count": 0,
    "descriptor": { "meta": {...}, "interactions": [...], "narrative": [...],
                    "codeTrace": {...}, "checkpoints": [...] },
    "snapshot": { "tick": 0, "state": {...}, "view": {...}, "current_step": {...},
                  "interaction_availability": {...}, "checkpoint_results": {...} } }
  ```
> **为什么首帧要带包自描述信息**:浏览器不执行扩展包代码,拿不到包内声明,而「可用操作」的名称与
> 参数字段、教学步骤标题、教学步骤总数都是渲染工作台的必要材料 —— 只推快照的话页面能画舞台却画不出操作面板。
> 服务端验证包描述的结构和身份。交互事件须与入库的 `interaction_schema` 一一对应，控件 ID、类型、目标和参数约束须一致。缺失、重复或不一致时拒绝预览或首帧。包描述只随首帧下发。
>
> **`event_count` 由服务端给**:过程由服务端持有(容器每次从初始状态重放),刷新重连后服务端会按已登记操作
> 把过程重放回上次位置,前端自己数不准,故回退按钮的可用性以服务端计数为准。
>
> **为什么推完整快照而非仅 state**:`render` 是仿真包自己的函数,扩展包的 `render` 属外部代码,
> 浏览器不得执行(06-安全设计.md §2)。容器内完成 `reducer` + `render` + 叙事命中 + 检查点求值,
> 前端拿到的已是纯数据帧,交给平台自己的封闭模式渲染器绘制 —— 前端因此只有一条渲染路径,
> 不在页面复制 reducer、舞台、时间线或检查器。
>
> **快照是不可信输入**:服务端在转发前必须按 TeachingFrame 协议校验(`patterns` 1–3 个且带稳定 `id`、
> `mode` 属七类封闭集、`layout` 只引用当帧存在的 pattern `id`、规模字段不超包声明 `scale_limit`),
> 校验不过返回 `42011` 并终止会话,不把不合协议的帧透传给前端。

## 5. 典型时序

### 5.1 内置包(浏览器运行)

```
M7 → CreateSession 契约（HTTP 对应 POST /internal/sessions），tenant/source 取服务签名上下文
M4 → session_id + compute=browser
前端 → 按 code 在 Worker 内装配内置包内核,本地运行状态机
学生 → 交互(滑块/按钮/注入攻击)→ 本地即时演化
前端 → 异步 POST /actions 上报操作序列
来源结束或显式回收 → 会话归档，只读回放；已有分享继续按原有效期读取
```

### 5.2 扩展包(隔离容器运行)

```
教师 → POST /packages(bundle + meta,compute 由服务端派生为 isolated)
M4  → 计算 sha256 + 静态扫描 + manifest 协议校验 → 写对象存储 → 待审
M4 预览任务 → 隔离容器装配 bundle → 同 seed 跑两遍比对 + 渲样例帧
            → 写入 determinism_check / worker_preview / preview_frames
平台管理员 → GET /reviews 看四项结论与样例帧 → approve → 上架

M7 → CreateSession 契约（HTTP 对应 POST /internal/sessions）→ M4 校验租户并发上限 → session_id + compute=isolated
前端 → 换 ws-ticket → WS /sessions/{id}/stream
M4  → 建隔离命名空间 + Pod → exec stdin 投 bundle → 校验 hash → 装配
    → 按会话已登记操作重放到上次位置 → 推 ready 帧(含包自描述信息与完整快照)
学生 → 交互事件 → 服务端 schema 白名单 → 容器执行 → 登记操作 → 推 snapshot 帧
学生 → 回退/从头再来 → 服务端按本连接选定的历史前缀重算，不删除持久化操作 → 此后不再登记新操作
断线或执行失败 → 删除本次环境，保留可用会话以便重连
来源结束或显式回收 → 归档会话并回收执行环境；只读回放另建受容量约束的临时环境
```
