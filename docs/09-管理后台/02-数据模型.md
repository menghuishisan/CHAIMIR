# M9 管理后台 — 数据模型

> PostgreSQL。M9 只拥有运维元数据;业务数据与审计日志归各模块,M9 聚合只读。
> 建模遵循:消灭数据冗余、表合并有度。
> 最后更新:2026-11-27

---

## 1. 表清单总览

| 表名 | 用途 | 范围 |
| --- | --- | --- |
| `alert_evaluation` | 每规则、每学校的持续异常判定 | 租户 |
| `alert_rule` | 业务级告警规则 | 混合 |
| `alert_event` | 告警事件 | 混合 |
| `platform_statistics` | 统计快照(看板加速) | 混合 |
| `backup_record` | 备份任务记录 | 全局 |
| `audit_export_request` | 审计导出请求(筛选快照) | 混合 |

> 消灭冗余/合并说明:
> - **不建审计表,统一共用 M1 的 `audit_log`**:全平台只有一张审计表(M1 定义),各模块产生关键操作时写入这张共享表(带 `tenant_id` + `action` 动作码 + `target_type` 区分来源模块)。M9 的"统一审计查询中心"是对**这张共享表的多维查询**(按 actor/action/target_type/time 过滤),不是跨多张表聚合。各模块只需在产生审计事件时写 M1 audit_log,无需各建表。
> - **看板数据不落库**:实时看板由跨模块聚合查询即时计算;仅"周期统计快照"落 `platform_statistics` 加速大盘趋势(避免每次全表扫)。
> - **告警规则与事件分两表**:规则是配置(少、稳定),事件是流水(多、增长),分开。

## 3. 告警

### 3.1 alert_rule — 告警规则(业务级)

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| scope | SMALLINT | 1全局 / 2租户 |
| tenant_id | BIGINT NULL | |
| name | VARCHAR(128) | |
| metric | VARCHAR(64) | 下列八类已实现指标之一 |
| condition | JSONB | 统一为 `{"operator":"gt\|gte\|lt\|lte","threshold":数值,"duration_seconds":非负整数}` |
| level | SMALLINT | 1提示/2警告/3严重/4紧急 |
| enabled | BOOLEAN | |
| created_at / updated_at | TIMESTAMPTZ | |

`metric` 与 `condition` 使用固定契约,不保存前端无法解释的自由字段。当前允许的 `metric` 为:
`sandbox.active_count`、`sandbox.pending_seconds`、`sandbox.failed_rate`、`judge.queue_length`、
`judge.failed_rate`、`account.login_failed_count`、`transfer.failed_count`、`grade.warning_count`。
失败率使用 0 到 1 的比例，例如 0.2 表示 20%；等待时间以秒计，其余为数量。
其中 `duration_seconds=0` 表示条件达到阈值后立即触发;实验环境等待时间规则使用
`metric=sandbox.pending_seconds`、`operator=gt`、`threshold=180`、`duration_seconds=0`。

### 3.2 alert_event — 告警事件

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| rule_id | BIGINT | |
| tenant_id | BIGINT NULL | |
| level | SMALLINT | |
| message | VARCHAR(500) | |
| status | SMALLINT | 1待处理/2已处理/3已忽略 |
| handler_id | BIGINT NULL | |
| triggered_at / handled_at | TIMESTAMPTZ | |

> 告警触发后经 M10 通知相关管理员。

### 3.3 持续判定与通知

- 平台规则逐校评估，事件归对应学校，通知该校有效管理员；平台管理员在全平台告警列表查看。
- alert_rule.revision 每次修改递增。alert_evaluation 以 (rule_id, tenant_id) 为主键，保存规则修订、最后采样时间、异常起点和是否已触发；锁定规则与评估行后，同事务更新状态并创建事件，拒绝旧规则和乱序采样。恢复正常后才可再次触发，人工处理不重置异常期。
- alert_event 同时保存通知追踪编号、投递次数、租约、下次尝试时间、成功时间及脱敏失败原因；多副本以租约和 CAS 领取，稳定请求编号交给 M10 去重。重试达到配置上限后保留失败事实并记录日志。
- 运行数、最长准备时间、待判队列取快照。失败率、登录失败和导入导出失败统计 [from, to] 滑动窗口；无终态样本时失败率为 0。学业预警只计当前学期未知悉记录。指标读取失败不写正常样本；恢复采样后重新累计尚未触发的异常期，已触发的异常仍须观察到恢复才可再次触发。
- M1 记录可归属学校的密码或短信认证失败，不保存凭证；未识别账号及平台登录不归入学校指标。
- 采样间隔、指标窗口、通知批量、租约和重试上限由 ADMIN_ALERT_* 及 ASYNC_OUTBOX_MAX_ATTEMPTS 环境变量管理。
- 当前状态按已有租户状态索引读取；窗口失败统计按租户及事件时间读取，避免每次采样遍历全部历史任务。沙箱成功/失败取窗口内每个环境最后一条结果事件，暂停、清理、租约更新不改写该结果。

## 4. 统计与备份

### 4.1 platform_statistics — 统计快照

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| scope | SMALLINT | 1平台 / 2租户 |
| tenant_id | BIGINT NULL | |
| stat_date | DATE | 统计日期 |
| metrics | JSONB | 各项指标快照(用户数/课程数/活跃/资源等) |
| created_at | TIMESTAMPTZ | |

唯一约束:`(scope, tenant_id, stat_date)`。

> 周期任务生成快照,加速大盘趋势查询;实时数据仍走聚合查询。

### 4.2 backup_record — 备份记录

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| type | SMALLINT | 1全量 |
| storage_ref | VARCHAR(255) | 成功时必须为备份清单引用，失败时为空；后台不向前端暴露 |
| size_bytes | BIGINT | |
| status | SMALLINT | 1成功/2失败 |
| started_at / finished_at | TIMESTAMPTZ NOT NULL | 执行方传入真实起止时间，结束不得早于开始 |

> 当前仅实现每日全量备份的结果记录，不维护运行中任务。成功时 `storage_ref` 指向备份桶中的 `manifest.json`，清单记录 PostgreSQL dump 和业务对象桶复制前缀；失败不要求生成任何对象，原始错误由任务日志记录。对象存储失败不阻断数据库失败结果的写入；结果写入失败仍使任务失败并保留原始错误链。

### 4.3 audit_export_request — 审计导出请求

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| transfer_task_id | BIGINT PK | 关联 transfer 通用任务 |
| tenant_id | BIGINT NOT NULL | 发起租户，CHECK >= 0；0为平台作用域 |
| account_id | BIGINT NOT NULL | 发起账号 |
| query_snapshot | JSONB NOT NULL | 完整授权筛选快照 |
| next_check_at | TIMESTAMPTZ NOT NULL | 默认now()；下一次扫描时间，不复制任务状态 |
| created_at / updated_at | TIMESTAMPTZ | |

> 审计 CSV 导出请求由本表保存完整筛选快照与发起账号(见 `03-接口设计.md` §4 与 `05-业务流程与状态机.md` §3)。M9 worker 按 `transfer_task_id` 领取通用任务后重放 `query_snapshot` 生成 CSV,经统一文件服务产出;任务状态、重试和下载产物只由 transfer 管理,本表不存储任务执行状态,避免与 transfer 双写。

## 5. 聚合查询(无表,说明)

- **统一审计查询中心**:查询全平台共享的 `audit_log`(M1 定义的单表,各模块写入),按 actor/action/target_type/time 多维过滤,M9 不存审计副本。
- **运营看板**:跨模块只读聚合(M1 用户、M6 课程、M7 实验、M8 竞赛、M2 资源用量),即时计算 + 统计快照加速。

## 6. 多租户与索引

- 告警/统计的租户级数据带 `tenant_id` + RLS;全局级(scope=1)仅平台管理员可访问。
- 私有化:无平台级数据,均为本租户。
- 关键索引:
  - `alert_event(tenant_id, status, triggered_at)`
  - `platform_statistics(scope, tenant_id, stat_date)` UNIQUE
