# M9 管理后台 — 接口设计

> RESTful。鉴权沿用 M1 JWT。看板/审计/统计为聚合只读;告警为 M9 自有数据。
> 最后更新:2026-11-27

---

## 1. 通用约定

- Base:`/api/v1/admin`
- 统一响应体同 M1。错误码段:`9xxxx`(91xxx 看板/92xxx 审计/93xxx 监控与备份/94xxx 告警)。
- 权限:`/platform/*` 仅平台管理员(SaaS);`/school/*` 学校管理员。

---

## 2. 平台看板与管理 `[平台管理员]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/platform/dashboard` | 全局看板(学校数/用户数/活跃/资源,聚合只读) |
| GET | `/platform/statistics?from=YYYY-MM-DD&to=YYYY-MM-DD` | 平台趋势统计;`from/to` 必填 |

看板的 `resource_quota_snapshot` 是固定结构 `{ max_concurrent_sandbox, max_cpu, max_memory_mb }`,三项均为整数;不得作为开放配置对象扩展字段。

> 审核/租户变更的业务严格归 M1 自有接口;租户列表与入驻申请列表也一并归 M1(`GET /api/v1/platform/tenants`、`GET /api/v1/platform/applications`),M9 不再复制同名只读路由。M9 只展示看板与统计聚合结果、记录自身操作审计,不充当跨模块命令代理。

## 3. 学校看板 `[学校管理员]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/school/dashboard` | 本校看板(师生/课程/竞赛/实验/资源,聚合只读) |
| GET | `/school/statistics?from=YYYY-MM-DD&to=YYYY-MM-DD` | 本校运营趋势;`from/to` 必填 |

统计起止日期均计入范围。“近 N 天”包含今天，共 N 个自然日；自定义范围须为有效日期且开始不晚于结束。地址中的无效自定义范围回到近 30 天，表单始终以当前有效范围初始化，查询后写入地址。
统计响应的 `date` 为 `YYYY-MM-DD` 自然日，显示规则见[前端规范](../总-前端设计规范.md)。
图表只登记实际生成的指标；实验环境数量与学习时长分别展示，时长标明秒。少于四个时间点显示最新数值摘要，同时保留完整数据表。

## 4. 统一审计查询中心 `[平台/学校管理员]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/audit?tenant_id=&actor_id=&action=&target_type=&from=&to=` | 跨模块审计聚合查询(分页);`tenant_id` 只对平台身份生效(指定学校时走该校的租户事务,省略时按平台权限查询全平台含平台自身记录),学校身份固定为本校;`facets.action` 按动作分组计数,套用学校、操作人、对象类型与时间范围,不套用动作筛选;每条带 `actor_name`(学校账号另带 `actor_no`):学校身份解析本校账号,平台身份只解析平台管理员,不跨校读取学校人员姓名(学校的操作人在平台审计里只显示身份) |
| GET | `/audit/export` | 创建审计 CSV 导出任务并返回 transfer 任务快照 |

查询与导出均在服务层重新校验管理员身份。规则新增、规则更新、告警处理与导出请求必须和 M1 审计同事务提交；导出请求、pending transfer 任务和审计一起提交或回滚。平台请求使用平台普通事务，学校请求使用本校普通事务。告警实时推送在提交成功后发送。

> 查询 M1 的 `audit_log`(全平台唯一审计表);平台管理员看平台级与全租户,学校管理员限本校(RLS)。`/audit/export` 先将完整筛选快照写入 M9 自有导出请求表,随后返回 pending transfer 任务;M9 worker 重放快照生成 CSV。任务状态、重试和下载产物只由 transfer 管理。这是审计的唯一 HTTP 查询入口,M1 不注册 `/audit`。

每次导出租约使用独立对象路径；生成或上传失败时限时补偿，清理脱离请求取消，保留原错误与清理错误。调用 transfer 完成登记后若结果不明，保留产物；失败回写不能覆盖已成功任务，后续由现有请求扫描对账。


审计的`action`和`target_type`均按生产者写入值精确匹配，不做别名转换。学校与平台筛选的账号对象为`identity.account`，学校为`identity.tenant`，租户登录会话为`identity.auth_session`，平台登录会话为`identity.platform_auth_session`；课程与作业分别为`teaching.course`、`teaching.assignment`。账号状态操作使用`account.status.update`，入驻审核使用`tenant.application.approve/reject`，学校状态使用`tenant.status.update`。界面以中文标签展示，查询与导出使用相同筛选快照，不能因省略模块前缀返回假空态。

清空筛选同时清除学校、对象、动作、操作人与时间条件。详情中的状态按记录的 `target_type` 使用对应领域标签，不按查看者角色解释；未登记对象或状态不展示原始状态值。

## 6. 告警 `[平台管理员/学校管理员]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST/PATCH | `/alert-rules[/{id}]` | 业务级告警规则 |
| GET | `/alert-events?status=&level=` | 告警事件列表，逐条返回已授权规则名 `rule_name`；不由客户端跨范围查规则目录 |
| POST | `/alert-events/{id}/handle` | 处理/忽略;租户级告警经 M10 `tenant:{tenant_id}:alert` 推送刷新,平台级告警不构造旧式无租户 topic,由列表查询/监控入口保证可见 |

`level` 省略或0表示不筛选，1–4分别为提示、警告、严重、紧急；非法范围拒绝，列表与总数共用相同筛选。运行配置由环境变量和所属模块维护，M9不提供旧 `/configs` CRUD、历史或回滚入口。

告警规则请求与响应中的 `condition` 使用固定结构:
`{"operator":"gt|gte|lt|lte","threshold":数值,"duration_seconds":非负整数}`。
`metric` 只能使用数据模型中登记的指标键;缺少任一条件字段、使用旧的 `op/value` 字段或使用未登记指标时,
接口返回告警规则参数错误。`duration_seconds=0` 表示达到阈值后立即触发。
告警站内信进入校管端 `/school-admin/system-alerts`，与学业预警 `/school-admin/alerts` 分开。
学校与平台共用的规则表单必须原样回显合法的数值0;60秒仅为新建规则的初始值,不能覆盖已保存的0秒。阈值与持续时间输入为空或仅含空白时须明确拒绝,不得在转换数字时把空输入当作0提交。显式填写0仍按上述合法数值处理。

规则名称、阈值和持续时间按本节参数校验；指标统计窗口、阈值单位与持续告警触发规则由服务端统一执行。

## 7. 监控入口 `[平台管理员]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/platform/monitoring/panels` | 返回受控外部监控入口(服务健康/资源)，仅平台管理员可读 |

> 基础设施监控数据来自外接体系，M9 不存监控时序数据、不内嵌第三方页面。入口由环境配置注入，服务端按允许的来源校验 HTTPS 地址，拒绝 URL 用户信息、查询串和片段；前端复核后在独立窗口打开，并设置 `noopener,noreferrer`。外部监控由其自身认证，不接收平台会话或令牌。

## 8. 备份 `[平台管理员]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/platform/backups` | 备份记录列表,支持 `status` 筛选(省略或 0 表示不筛),筛选与 `total` 同口径 |

> 实际备份执行由受控运维任务/CronJob 完成并写入 `backup_record`;M9 HTTP API 不提供手工触发、下载直链或存储位置写入入口。

备份只返回已结束的结果：`status=1` 成功、`status=2` 失败；省略或 `0` 不筛选。`started_at`、`finished_at` 均为真实执行时间，必定返回，不展示运行中分段。

最近成功备份独立读取，失败时展示用户向错误、后端追踪编号及重试入口，不能显示为“尚无成功备份”。

## 9. 典型时序(全局看板)

```
平台管理员 → GET /platform/dashboard
M9 → 并行聚合只读:
      M1 用户/租户数、M6 课程数、M7 实验活跃、M8 竞赛数、M2 资源用量
   → 合并 + 统计快照加速 → 返回看板
   (全程不写任何业务模块)
```

平台查询与处理学校告警时，M9 在已认证的平台事务内设置局部 `app.admin_platform=true`；该 RLS 例外仅适用于 M9 告警表，不放宽其他模块，也不在租户事务设置。平台处理学校事件及其平台操作审计保持同一普通应用事务。
