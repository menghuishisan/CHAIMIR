# 技术选型

> 最后更新:2026-11-27

本文登记平台采用的技术及其职责。业务边界见[平台蓝图](00-平台总体蓝图.md)，代码归属见[工程目录](总-工程目录设计.md)，视觉与交互见[前端规范](总-前端设计规范.md)。依赖版本以清单和锁文件为准，不在设计文档另存补丁版本表。

## 1. 控制面与数据

| 能力 | 选型 | 职责与依据 |
| --- | --- | --- |
| 后端 | Go 模块化单体 | 11 个业务模块经 contracts 交互；控制面统一 Go，不可信执行单元独立隔离 |
| HTTP | Gin | 模块 api 层注册路由，统一鉴权、绑定与响应 |
| 数据库 | PostgreSQL | 业务持久化、事务、JSONB、RLS 租户隔离 |
| 数据访问 | sqlc + pgx | SQL 生成类型安全查询，模块 repo 管理事务与租户上下文 |
| 数据库迁移 | golang-migrate | `backend/cmd/migrate` 执行嵌入的版本化 SQL、角色授权及模块初始化 |
| 配置 | 环境变量 + Go 标准库 | `platform/config` 读取并在启动时校验；键定义在 `deploy/config/chaimir.env`，后端模板在 `backend/.env.example` |
| 缓存与协调 | Redis | 限频、缓存、在线状态和分布式租约；会话及业务任务以所属模块数据库记录为权威 |
| 业务事件 | NATS JetStream | 持久发布确认、durable 消费、显式 ACK、重投和死信，交付语义见蓝图 |
| 对象存储 | S3 兼容接口，默认 RustFS | 统一文件服务经 S3 SDK 访问；业务模块不依赖 provider 私有 API |
| 鉴权 | JWT + HttpOnly refresh cookie | 短期 access token 仅在前端内存；刷新轮转与会话撤销由 M1 维护 |
| 实时通信 | WebSocket | M10 统一业务通知；终端和隔离仿真交互由所属引擎承载 |

后端直接依赖由 [go.mod](../backend/go.mod) 与 [go.sum](../backend/go.sum) 锁定。Excel、PDF、加密、JSON Schema 等能力使用已登记的成熟库；复用与新增条件遵循[开发规范](总-开发规范与要求.md)。

判题与对局调度通过所属模块 PostgreSQL 队列、行锁、租约和有限重试执行，事件交付交给 JetStream。任务状态不在 Redis、NATS 与数据库之间维护多份权威副本。

## 2. 前端与仿真

| 能力 | 选型 | 职责 |
| --- | --- | --- |
| 应用 | React + TypeScript | `apps/web` 单 SPA，公共认证与四端按角色懒加载 |
| 工程 | pnpm workspace + Turborepo + Vite | 共享包管理、检查与构建 |
| 路由 | React Router | 路由装配、角色守卫和深链 |
| 设计系统 | Tailwind CSS + Radix Primitives + CVA | 仓内组件、语义令牌、交互与无障碍；令牌源为 `packages/ui/src/tokens/theme.css` |
| 字体 | Fontsource 自托管字体 | Display 站酷庆科黄油体、Body Noto Sans SC Variable、Data JetBrains Mono Variable |
| 图表 | Recharts | 经 `packages/ui/src/charts` 统一呈现与无障碍降级 |
| 编辑器 | Monaco 官方 ESM | 按需加载，语言能力使用官方贡献，Worker 经 Vite 输出为同源资源 |
| 终端 | xterm.js | 经 M2 授权通道连接 Kubernetes exec PTY |
| 仿真 | TypeScript 协议、Worker、平台 TeachingFrame 渲染器 | 内置包在浏览器 Worker 执行；教师/第三方扩展包在后端隔离容器执行，浏览器只画纯数据快照 |

当前 M4 只支持上述两类包；执行协议、审核与装配约束见[模块架构](04-仿真可视化引擎/07-架构设计.md)。仿真包不得携带自定义 DOM 渲染器或绕过平台的封闭模式。

工作区工具版本与 Node/pnpm 要求见 [frontend/package.json](../frontend/package.json)，各包直接依赖见所属 `package.json`，解析后的版本统一由 [pnpm-lock.yaml](../frontend/pnpm-lock.yaml) 锁定。

## 3. 容器、部署与供应链

| 能力 | 选型 | 职责 |
| --- | --- | --- |
| 编排 | Kubernetes；私有化使用 k3s | client-go 访问集群；Namespace、NetworkPolicy、配额与 Pod 安全策略隔离执行单元 |
| 平台清单 | Kustomize | `deploy/base`、`components`、`overlays` 维护唯一平台部署定义 |
| 第三方组件安装 | 官方 Helm chart + 固定 values | 仅维护必要的可审计补丁，不复制平台清单 |
| 镜像仓库 | Harbor | 构建产物分发与私有化离线导入 |
| 供应链 | Trivy + SBOM + Cosign | 扫描、签名、证明与不可变 digest 晋升；门禁见镜像规范 |
| CI/CD | GitHub Actions | `.github/workflows` 是工作流入口；共享构建 action 位于 `deploy/ci` |
| 基础设施监控 | Prometheus + Grafana | 外接监控；M9 只维护受控入口与本模块业务告警 |
| 日志 | Go slog 结构化日志 | 统一脱敏与 trace 上下文；集中采集由部署环境接入 |

执行容器内使用各链官方工具与声明的判题器，不以插件语言改变控制面语言或模块边界。具体镜像职责、安全控制和离线闭包见[镜像规范](总-镜像与容器设计.md)，环境与运维入口见[部署规范](总-部署架构设计.md)。

## 4. 版本与变更

- Go 语言及 toolchain 由 `backend/go.mod` 定义，CI 和 `images/base/go-builder` 与其一致；Node 主版本遵循前端 engines 与 `images/base/node-builder`。
- 中间件及执行镜像的上游版本和来源由各镜像 `manifest.yaml`、Dockerfile 或固定 chart 锁定；生产镜像引用只取 `images/image-digests.lock` 的已晋升 digest。
- 升级时同步依赖清单、锁、构建基座、CI 与受影响调用者，并按[验收标准](总-验收标准.md)验证；清单或镜像存在不表示已通过运行验收。
