# M8 竞赛 — 接口设计

> RESTful + WebSocket(排行榜/对局状态)。鉴权沿用 M1 JWT。复用 M2/M3/M5。
> 最后更新:2026-11-27

---

## 1. 通用约定

- Base:`/api/v1/contest`
- 统一响应体同 M1。错误码段:`8xxxx`(81xxx 赛事/82xxx 报名/83xxx 解题/84xxx 对抗/85xxx 漏洞源)。
- 报名、邀请码入队、锁队、解题提交和参战物提交的 M8 写入与 M1 审计在主办学校的同一租户事务中提交；任一步失败均回滚本次 M8 变更，不返回成功对象。审计归主办学校，`actor_id` 保留真实操作者，`detail.actor_tenant_id` 记录其学校，均取服务端身份。工作区归档、M3 任务创建和提交后的榜单推送仍是独立操作，不承诺跨模块事务回滚。
- 赛事名称和漏洞题标题最多 255 个 Unicode 码点，漏洞来源名称最多 128 个；先去除首尾空白，再校验非空和字符数，与数据库文本列一致。前后端不得按 UTF-8 字节或 UTF-16 编码单元误算长度。

## 2. 赛事管理 `[教师/管理员]`

赛事只配置赛制、匹配方式、参赛形式、报名与比赛时间、封榜时长。提交频率与答错冷却由平台统一配置，对局执行时限由锁定的 M3 判题配置控制；不提供逐赛事的重复提交、冷却或每轮时长配置。动态分仍由赛题的 `dynamic_score` 定义。

封榜时长为非负 INT 整数分钟，0 表示不封榜，空值、小数与越界值须在表单提交前提示。人工与自动封榜统一使用 `[结束时刻 − N 分钟, 结束时刻)`，保留时刻精度；N 覆盖整场比赛时，比赛进入运行态即可封榜，不因时长换算溢出改变窗口。

代码查重按当前赛题与阈值计算字段提示，显式阈值必须严格位于0与1之间，NaN、无穷及非法格式在业务查询前拒绝；未指定时使用平台配置。字段纠正立即更新错误，接口失败独立保留。草稿与归档禁用规则、指纹过滤与相似提交结果沿用原契约。

赛事基本信息仅允许在草稿或报名中修改,其中赛制与参赛形式只在草稿态可改(发布后赛题按赛制锁定、报名按参赛形式组队,改了会对不上,服务端拒绝);赛题及其锁定的 M5/M2 快照仅允许在草稿态编排。防作弊处理依赖实际参赛数据,草稿态只允许组织者查看空记录,不得查重或登记处理;报名开始后可按可见参赛数据审查,归档后只读。服务端必须拒绝草稿态和归档态的防作弊写入。

人工发布、开赛、封榜和结束的状态、锁队、榜单快照或授权撤销与对应 M1 审计在同一租户事务中提交；审计失败不生效，不返回成功对象。发布前的 M5 引用登记仍在事务外；结束后的连接关闭与广播在提交后执行，清理失败显式报错并保留已提交的结束状态、撤权和审计。

定时推进使用相同的租户事务与审计边界；跨校扫描只定位待处理学校，各校独立提交。审计、业务写入或提交失败均回滚该校本轮推进，其他学校继续处理；错误统一汇总，调用取消后不启动后续学校事务。仍按既有结束、开赛、封榜顺序与行锁检查当前状态，不根据扫描快照直接改状态。

人工与自动归档共用租约和收尾流程，最终榜单快照、归档状态与 M1 审计在同一租户事务中提交。人工归档只记录真实教师的 `contest.archive`，定时任务只记录系统的 `contest.archive.auto`。此前的撤权、连接关闭及 M2 资源回收独立生效；最终提交或审计失败时保留结束态，沿现有租约重试，不恢复已回收资源。

赛题编排的依赖校验可以在事务外执行，但最终保存必须锁定所属赛事行，重读草稿状态和赛制，再按唯一题目引用更新；校验期间已经发布或变更赛制的请求不得写入旧快照。赛事基本信息更新、发布、人工状态流转和定时推进共用该赛事行锁；基本信息更新须在锁定读取后判断结构可编辑性，不能依据旧草稿修改已发布的赛制或参赛形式。发布的M5引用登记保持在M8事务外幂等执行，避免跨模块写事务嵌套耗尽连接池；登记后必须在最终锁定事务中重验当前状态和时间窗口，并比对赛制及完整题目集合，发生变化则拒绝本次发布，不写入状态。定时任务只领取仍满足时间和状态条件且未被其它执行者锁定的赛事。人工封榜、自动封榜和归档使用同一完整榜单读取流程；非零总数却读到空页时明确失败，不继续空转或保存不完整快照。

M8 选题必须遵守 M5 内容类型映射：解题赛可引用竞赛题与能够由 J7 自动判分的理论题，对抗赛仅可引用竞赛题；简答题的竞赛人工评分目标尚未形成执行闭环，当前选题、发布与提交入口须明确拒绝，不送入 J7 或产生零分成功结果。实验模板只供 M7 实验引用。前端选择器必须按赛制过滤,服务端在读取题目快照后、组合编译和持久化前再次校验类型,不能依赖前端过滤作为授权或数据完整性边界。

赛题分值、序号与每队衰减为正整数，动态最低分不得超过分值；关闭动态分后不提交其专属字段。违规登记必须有目标队伍和判定依据，仅扣分动作要求正数扣分值；结构化证据与对抗规则遵循所属契约。

同一赛事中的题目以 M5 编码和版本唯一引用；重复编排更新原记录的分值、题序和赛内配置，保留原赛题编号，不新建副本。题序允许在草稿态修改，服务端及建表约束均拒绝非正数；列表按题序、赛题编号排序。

对抗题请求只需提供 `battle_rule`，不接收 `battle_config`，且必须省略解题赛专用的 `dynamic_score`。私有访问边界由赛制确定，参战角色由对局规则确定，完成对局统一保存完整回放；前端不重复生成这些规则，接口和数据库也不保存其副本。组合摘要、初始化引用和判题配置仍由锁定题目版本校验并冻结。

编排只读取一次 M5 锁定版本的完整正文，类型校验和组合编译复用该快照；运行阶段只消费已持久化的组合快照，不再访问 M5 或重新编译。题目引用失败的内部错误链必须区分内容读取、类型匹配、组合声明缺失/编码/解析/规范化、M2编译与M3判题模式校验阶段，并保留租户和赛事编号及原始原因，供统一结构化日志关联本次trace。响应仍只返回原统一错误码、用户向文案和trace，不输出组合正文、私有初始化材料或判题配置；诊断信息不能替代准入校验。

## 3. 报名与组队 `[学生]`

个人赛与组队赛都必须有参赛名称，去除首尾空白后为 1–128 个 Unicode 字符；个人赛报名可预填姓名并允许修改。创建队伍与邀请码加入分别校验请求，报名窗口、人数及授权由服务端决定。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/student/contests?status=&keyword=&page=&size=` | 本校或本人当前已入队的跨校非草稿赛事分页(`status BETWEEN 2 AND 6`);支持 `status` 筛选和按名称检索(省略或 0/空表示不筛),筛选与 `total` 使用同一可见范围 |
| GET | `/student/contests/{id}` | 单条赛事详情,门槛与列表逐字一致(草稿态对学生不可见) |
| POST | `/contests/{id}/signup` | 报名(个人/创建队伍) |
| POST | `/contests/{id}/join-team` | 用队长分享的邀请码加入本赛事队伍(可跨校);请求体只含 `invite_code`,由 M8 受控跨租户事务按码定位队伍并签发成员授权 |
| GET | `/teams/{id}` | `[学生/教师/校管]` 按当前成员或管理范围读取队伍信息 |
| POST | `/teams/{id}/lock` | 锁定队伍(或开赛自动锁) |

报名、入队和手动锁队在同一事务中先持有赛事行锁，再检查报名窗口、已有队伍和名单状态；与开赛自动锁队共用该锁。同一账号在一场赛事内只能属于一队，重复报名返回已有队伍。邀请码仅在指定赛事与组织租户内查询，允许不同赛事使用相同邀请码；个人赛不生成邀请码。

学生独立入队页 `/student/contests/:contestId/join` 只提交邀请码，不预读赛事详情、题面或队伍；成功后进入赛事详情，仍由当前成员鉴权。队伍分享链接仅包含赛事编号，邀请码单独分享，不放进 URL 或本地存储。列表通过 M8 受控跨租户只读查询，学校与账号均取当前会话；退出队伍后外校赛事不再可见，不放宽 RLS 或其他接口权限。

学生详情的报名按钮、邀请码表单和赛程使用同一报名窗口：报名开始前提示尚未开始，起止时刻均允许报名，截止后关闭。页面可见时自动更新；已打开的报名弹窗保留输入并提示截止，停止提交。列表在报名开始前提示距开始的时间，服务端仍执行最终时间校验。

教师赛事列表筛选覆盖状态1–6,学生赛事列表筛选覆盖状态2–6,均另有“全部”;前端从同一 `ContestStatus` 枚举生成选项并复用状态文案。封榜中(4)不得归入进行中(3),已归档(6)不得归入已结束(5),查询始终按状态精确匹配;学生不显示草稿筛选。无该状态记录时展示空态,不能省略状态入口。

学生列表的赛事与本人参赛记录共同读取，全部成功后才展示报名标记、排序和摘要；任一失败显示错误态，重试重读两者。状态计数覆盖当前可见或可管理的完整结果；前端分页越界时显示最后有效页，筛选与搜索变更仍重置地址页码。

> 加入队伍使用邀请码，服务端据此解析队伍；学生无需获取或填写内部队伍编号。

## 4. 解题赛 `[学生]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/contests/{id}/problems` | `[学生/教师/校管]` 公开题目摘要列表(序号、标题、分值和类型);不返回完整题面、组合声明或判题字段,未报名学生可读取 |
| GET | `/contests/{id}/problems/{pid}` | 当前参赛队伍成员读取单题安全题面;服务端校验竞赛、队伍成员和已发布题目后返回 M5 face,过滤答案、判题配置、组合私有参数和初始化引用 |
| GET | `/contests/{id}/problems/{pid}/env` | 按服务端稳定 `request_ref` 恢复当前队伍仍未销毁且当前成员grant有效的实操环境;环境或授权不存在时返回通用资源不存在以保留准备入口;已撤销/过期或来源不符拒绝访问;不创建资源或授权 |
| POST | `/contests/{id}/problems/{pid}/env` | 起实操题环境(调 M2);请求只含题目上下文和业务幂等键,服务端读取 `contest_problem` 锁定快照,拒绝运行时、镜像、工具、初始化和网络字段;跨校队员由 M8 为该沙箱签发 grant |
| POST | `/contests/{id}/problems/{pid}/submit` | 提交(flag/代码/理论答案)→ 调 M3 判;代码题只提交当前本题实操环境 `sandbox_ref`，M8 校验当前成员 grant 与题目/队伍/竞赛来源后经 M2 保存工作区，使用服务端生成的对象引用和哈希调 M3；学生不得提交 `code_storage_key` 或 `code_hash` |
| GET | `/contests/{id}/problems/{pid}/submission` | 当前参赛队伍读取该题最近一次解题提交;无提交返回提交不存在,不返回其他队伍记录 |
| GET | `/submissions/{id}` | 查看判定结果 |

学生工作台的交互状态按赛事与题目隔离。环境恢复读取与创建请求仅接收当前题目的最新响应,旧读取不得覆盖后续创建结果或关闭已经就绪的提交门禁;最近提交读取不得覆盖随后成功提交的新结果。切换题目后重新从服务端恢复环境与最近提交,不沿用上一题的答案、角色、错误或沙箱状态。

提交、最近提交和单条读取统一返回 M3 当前 `judge_status`；读取在 M8 鉴权事务结束后进行，任务来源必须匹配该提交，读取失败显式返回判题不可用。`passed` 只表示当前已完成任务的通过结论；`score` 为可空数值，非完成态不显示旧分，完成未通过按当前原始结果归一，通过后沿用 M8 已结算的动态分，尚未结算返回 `null`。页面分别显示排队、评测中、通过、未通过、执行失败和已取消；执行失败与取消提示重新提交，不当作答错。

M3 同步返回完成态时，M8 在创建提交后按该任务结论写入结果，不能依赖新建行默认的 `passed=false/score=0` 决定是否结算；通过同步更新榜单，未通过保留归一后的得分。

M3 受理后，M8 写入提交前锁定赛事父行，并在同一事务复核当前赛态、题目版本/组合、提交者队伍和提交频率。只有进行中或封榜中仍可提交；期间结束、题目或成员变化以及并发请求已占用限频窗口时，不得写入提交、分数、榜单或提交审计。提交前与锁内共用同一上下文校验；M3 任务仍保留独立事务边界。

### 4.1 竞赛沙箱授权网关 `[学生]`

学生工作台的代码提交和参战提交先写入编辑器当前修改,再调用 M8 提交接口固化快照。切题、退出与打开回放先写入并归档;失败、冲突或保存期间有新编辑则保留现场并停止后续动作。所有文件操作仍走 M8 授权网关,不改用 M2 租户入口;环境就绪不额外生成归档。

解题赛和对抗赛学生实操环境统一使用以下 M8 网关；所有路径均以当前会话主体查询 `contest_access_grant`，每个请求重新校验 `status`、`expires_at`、`grant_version`、成员租户/账号、沙箱和 `source_ref`。浏览器不得改用 M2 `/api/v1/sandbox` 路径，更不得传入组织方 `tenant_id`。

同一成员重复准备同一环境时,授权能力、来源、有效期和状态均未变化的grant复用原`grant_version`;权限、来源或有效期变化以及停用后重新签发才推进版本。撤销仍立即推进版本并关闭原有长连接。不得因队友的幂等准备请求使正在保存的合法提交在二次授权校验时失效。

M2 返回准备结果后，授权事务先锁定赛事并复验当前可参赛状态、申请人的队伍与最新成员列表，再写授权；赛事已结束或成员范围变化不得按准备前的快照继续授权。授权失败保留原共享沙箱与业务幂等键，重试沿用同一入口，回收仍由既有生命周期负责。

首次启动或个性化初始化失败的环境统一返回失败生命周期，不能永久停在初始化中。学生点击同一“重新准备环境”入口时，M8 重新校验赛事、题目和队伍，撤销该失败沙箱的全部 grant 并关闭其连接，再经 M2 精确回收该沙箱编号，按原业务幂等键创建新环境和新授权；不得按整个稳定作用域误删并发请求刚创建的新环境。GET 仍只读且可显示失败态，不自动重放初始化脚本。工作台详情中的 `resource_usage` 与 M2 同为完整摘要或 `null`，用量不可读不阻断生命周期和授权查询。

已保存代码从 M2 按租户和稳定业务来源读取最近的持久化公开归档，包含已销毁的历史沙箱记录。回收旧环境后新建失败或请求中断，下次同一入口仍能重新取得该归档，不以一次请求内存作为唯一恢复依据。M8 不读 M2 表，M2 不删除历史归档指针或提交引用，也不返回私有脚本。

| 方法 | 路径 | 必需 grant 能力 | 说明 |
| --- | --- | --- | --- |
| GET | `/sandboxes/{id}` | `workspace.read` | 读取不含 Namespace 的运行时摘要 |
| GET/PUT | `/sandboxes/{id}/files` | `workspace.read` / `workspace.write` | 读取、列目录或写公开工作区文件 |
| POST | `/sandboxes/{id}/files/save` | `workspace.write` | 立即保存工作区,仅向学生返回工作区修订号,不暴露内部对象引用或哈希 |
| WS | `/sandboxes/{id}/progress` | `workspace.read` | 进度订阅，M8 先核 grant 再订阅 M2 主题 |

> M8 将已验证的 grant 主体、版本、成员身份、目标组织租户和 `source_ref` 作为内部受控主体契约传给 M2；终端在 WebSocket 会话登记后再次读取 grant，确认与升级前编号和版本一致，才启动 PTY。M2 再校验沙箱来源绑定；两层均未通过不得执行。grant 到期、撤销或竞赛结束后，所有新请求立即拒绝，已建立的终端和进度连接通过全副本广播关闭。

工作区写文件沿用M2 §4.2的内容与修订号契约:`content_base64`须显式提供字符串,允许空字符串写入零字节;缺失、`null`或非法编码仍拒绝。M8只校验请求边界和当前grant,不自建写入实现,仍由M2执行路径隔离、版本冲突检查与原子写入。

竞赛工作台持续按 M2 详情的 `phase=2/4` 且 `status=ready/running/idle` 判断可操作性,初始化中、暂停、回收中、终态或读取失败时关闭代码提交及参战提交。共享工作台使用同一状态变化回调通知业务层,不把首次就绪缓存为永久可提交。后台对局和预验证等待沿用同一阶段与生命周期约束。

> 提交流程:M8 收提交 → 对代码题核验当前成员的竞赛/队伍/题目沙箱 grant 并经 M2 保存工作区 → 调 M3(仅使用 M2 返回的代码对象引用与哈希,带 M5 题目引用 + 沙箱状态)→ 回写 → 更新排行。答案题只提交题目声明的答案内容,不接收沙箱或对象存储引用。代码对象 key/hash 不由学生请求指定。环境创建、对局、恢复和预拉取均只认 `contest_problem` 锁定的组合快照;旧的 `{runtime_code,runtime_image_version,tool_codes}` 请求或持久化形状不再接受。M3 复用判题必须使用创建该竞赛沙箱时的同一 `source_ref`。
> 解题赛经 M3 `GetJudgeInputRequirements` 取得锁定题目所需输入：代码判题保存本次可信归档并使用 `fresh`，答案题提交声明字段；无执行步骤的链状态断言使用 `reuse`，只传经 M8 核验的当前题目环境和真实来源，不采集伪代码归档。现场提交必须核验当前成员授权、赛事、队伍、题目、组合摘要和就绪状态。对抗赛先恢复双方参战物到对局沙箱再使用 `reuse`，继续按下节联动契约执行。
> 是否采集代码由 M3 `GetJudgeInputRequirements` 按锁定题目决定，查询失败时停止提交。环境声明只决定是否提供实操环境，不代表代码输入；带 `submit_key` 的答案题保留答案输入与可选实操环境，提交只携带声明字段，不要求环境就绪。没有答案键的代码或现场状态题才提交受控沙箱引用。页面提交期间关闭答案输入，避免提交内容与当前显示内容分离。
> 解题结果事件先核验 M3 当前任务来源与终态，迟到且已不符合当前状态的事件直接确认，不覆盖结果；读取失败保留重投。回写锁定提交行，完成未通过或执行失败同样重算队伍榜单并推送，撤回失效得分。重复完成事件保留该提交已结算的动态得分，不因重复投递再次衰减。
> 提交限频与答错冷却分开：冷却只在配置窗口内存在 M3 当前已完成但未通过的任务时生效，系统执行失败、取消和未完成任务不算答错。任务引用读取限定组织租户、赛事、题目、队伍与时间窗口，M3 状态在 M8 事务外读取；状态不可读时显式返回判题不可用，不伪造答错。
> M8 题目摘要和单题题面必须经 M5 题面接口读取。摘要接口不得成为完整题面的旁路;单题题面接口必须再次校验当前队伍成员身份。M5 题面契约不可用时返回 M8 专用错误码,不能返回无题面或未过滤数据。实操题环境创建、解题提交和工作区全部必须以当前参赛队伍成员为前提,缺必需契约时显式失败。

## 6. 排行榜(实时)

- `GET /contests/{id}/ladder` 复用已发布竞赛的读取规则：本校账号可读，跨校账号必须是该赛事当前队员。先鉴权再读取实时排名、封榜/归档快照和队名；跨校非队员返回竞赛不存在，成员查询失败直接报错。
- M8 赛事响应的 `leaderboard_topic` 使用主办方租户：`tenant:{organizer_tenant_id}:contest:{id}:leaderboard`。客户端直接订阅该值，不按当前学生租户拼接主题；主题本身不授予权限。
- M10 在每次订阅时调用 M8 只读契约 `AuthorizeLeaderboardSubscription(ctx, organizerTenantID, contestID)`。M8 检查当前账号租户已启用竞赛、赛事已发布，以及该账号在该赛事的当前队员资格；同校非队员也不放行。错误即拒绝订阅，不把主办方租户写进账号会话。
- 判分、重判、扣分或取消资格重算排名时，在同一事务标记该赛事榜单待推送；请求只返回业务提交结果。后台复用撮合轮询间隔与批量配置，按赛事编号分页扫描，在普通租户事务中锁定仍待推送的赛事，核验赛态并发布 `notify.push.requested`，持久确认成功后才清除标记。消息只携带 `{contest_id}`，客户端重读权威 HTTP 榜单，不发送未被使用的排名副本。发布失败、提交失败或进程退出保留待推送状态；重复投递不重复处罚或结算。M10 统一封装并推送，主题仍归主办学校；封榜、结束或归档只清理待推送标记，不发布实时内容。
- 持锁发布受现有 NATS 请求超时限制；用每赛事一个待投递标记合并变化，避免新增事件副本、投递表和租约状态。
- 工作台区分榜单加载、失败和空数据；失败显示用户向原因、服务端报障编号与重试入口。首次订阅或重连收到目标主题的订阅确认后，立即重读权威 HTTP 榜单并标为实时，补齐订阅建立前或断线期间的变化；连接失败或断开可重新连接，不按未确认连接推断订阅成功。冻结和归档不建立实时榜单连接。
- 封榜后停止推送实时变化；`GET /contests/{id}/ladder` 固定读取进入封榜时的服务端快照，不能通过刷新页面或直接请求 URL 窥探后续判定。
- 榜单字段按赛事赛制解释:解题赛的 `score`、`solved_count`、`last_solve_at` 分别表示总分、解题数和末次解题时间;对抗赛的 `score` 表示 ELO,`solved_count` 固定为 `0` 且 `last_solve_at` 为空。对抗赛只按 ELO 降序排名,不得把解题统计展示为对局统计。
- 实时分页直接读取随计分事务维护的名次，排除已取消资格的队伍；不在每页重新排序全榜。无名次变化的刷新不改写队伍更新时间，得分变化仍更新该队并触发既有推送。封榜与归档继续读取对应快照。

## 8. 真实漏洞源

### 8.1 租户能力 `[出题教师/学校管理员]`

漏洞源同步与漏洞题转化是**租户内**的出题工作流,产物落本租户题库:

列表返回平台共享源和本校源，以派生字段 `is_shared` 区分。教师可以同步两类来源，但只能修改本校配置；共享源配置仅平台维护。同步共享源只写本校草稿及审计，不更新共享记录。`last_sync_at` 仅表示本校来源成功同步时间，共享源不返回此字段，两端页面均不展示共享源的学校同步时间。

来源按全局唯一 `id` 创建或更新,更新必须与记录原有租户归属一致,平台全局归属为数据库 `NULL`;不得将全局来源转为学校来源或覆盖其它学校来源。更新配置和启停保留原有创建及同步时间。未成功同步过的来源响应不包含 `last_sync_at`,页面显示“尚未同步”,不计入曾同步数量。

配置整份替换。敏感字段回传 `已配置` 时，只保留同一记录、同一路径的现有密文；新值替换，删除字段或填空值清除，新建或无原值时禁止占位值。更新在所属记录的行锁内读取密文并保存，不能复用其它来源的密钥。两端表单完整编辑 `headers` 与 `body`，不把脱敏占位当成新密钥。

来源同步按租户、来源和外部标识去重，只新增或更新草稿；更新草稿清除旧预验证结果和冻结引用。已固化或废弃的记录保持全部字段及时间戳不变，批量同步跳过这些记录，继续处理其他案例，并只返回本次写入的草稿。手工录入只新建；新建或编辑的案例标识重复时返回 `85012`，提示更换编号，不覆盖既有记录，也不作为版本冲突处理。编辑必须按草稿 ID 更新。已固化题目更新须另行定义新版本流程。

草稿允许未完成的题面、步骤、断言和判题配置；标题、分级、复现方式和字段存储边界仍校验。可执行性在预验证前校验，不能为了暂存而要求填完所有内容。详情、列表和保存结果均返回 `updated_at`；`PUT` 接收完整草稿和必填 `expected_updated_at`，仅本校同 ID、草稿态且时间匹配时写入。冲突返回统一状态冲突，保留本机输入，由教师读取最新版本后选择继续编辑；不能自动重试覆盖新版本。修改、预验证与固化共用现有更新时间约束，不新增表或版本字段；修改原子清除验证明细、快照和内容引用，并与审计同事务提交。

`updated_at` 同时承担草稿版本比较；来源同步的冲突更新、手工编辑、预验证和固化每次写入均必须严格递增，取数据库当前时刻与原值加一微秒的较大值。同一同步事务重复出现某案例、数据库时钟回退或旧事务稍后写入时，也不得复用或倒退版本；较早返回的草稿、验证或导入结果不能据旧版本覆盖后续内容。

工坊用地址参数 `draft` 定位编辑记录，刷新后先读取服务端再恢复表单。表单编辑自动串行写回，保存期间的新编辑接续同步；未完成的输入保存在现有 `draft_body`，不另存一份编辑正本。格式尚未合法或写回失败的输入仅作为按租户、账号和草稿隔离的本机恢复记录，明确提示未同步，不能代替服务端草稿执行验证或固化。服务器版本变化时不自动应用本机内容。环境组合也在草稿编辑中保存，预验证只执行已经保存的内容。

连接检查证明只在表单内存使用，不算内容修改，不触发保存或撤销预验证。链实例改名同步更新步骤、断言和组合初始化引用，连续保存仍保持关联；已命名实例的别名被清空时先在本机暂存，填写新名称后再写回，避免丢失关联。版本冲突时明确说明覆盖服务器草稿或丢弃本机修改的后果，由教师主动选择。

实例名称暂时为空或重复时保留最后一个有效引用名，不迁移已有连接或工作区；全部名称有效且唯一后统一更新引用，不能写回尚未完成的更名或重名。草稿组合允许运行时和连接未填完，恢复时缺省文本显示为空、连接启动标记缺省为否。组件引用必须有非空编码和明确的 `explicit/auto` 选择，已提供的参数必须为对象、启动标记必须为布尔值；不能接受保存后会被表单静默丢弃的结构。

编辑窗口关闭后，其在途请求可以完成，但不再修改本机恢复记录或发起后续保存，避免覆盖重开窗口的新输入。关闭前留下的记录仍绑定原读取版本；若服务端已变化，重开时按版本冲突处理。

租户来源配置、草稿导入、来源同步和预验证结果写回，各自的数据库变更与统一审计在同一租户事务提交；审计失败时回滚本次写入。来源同步完整校验案例列表后才写入草稿及同步时间，格式错误不能当成空列表或丢弃错误项后继续成功。

固化时，M5 系统导入仍使用独立模块事务；M8 固化状态、内容引用与统一审计在同一租户事务提交。审计失败不得留下已固化状态；该事务不回滚已经完成的 M5 导入。

M8 失败后重试同一固化请求由 M5 复用完全相同的已导入内容；不同内容不能覆盖既有版本。M8 最终写入必须匹配导入前读取的 `updated_at`，重新预验证或同步过的草稿拒绝绑定旧导入结果，即使仍处于预验证通过状态或正文相同。失败不写成功审计、不改变固化状态；已导入的 M5 不可变版本仍保留，后续不同内容需使用新版本。

来源保存与同步共用配置解析：地址、方法和路径必须为文本，方法省略或空文本时为 GET；映射必须为文本路径对象且包含案例编号、标题和正文路径。去掉地址与路径两端空白，方法统一大写；不把数字路径转成文本或忽略非法可选字段。完整规则见专题设计 §漏洞源。

草稿创建使用 `POST /vuln-problems`；读取与编辑按草稿 ID 定位，来源仅由可选 `source_id` 表达。

`runtime_mode=2` 的预验证从已保存组合提取完整历史状态提供者与私有 RPC link，并把 `fork_block` 和四项链身份冻结到工作区参数。缺材料、身份不符、连接不完整或固化时仍是旧普通链快照，返回 `85005`；不导入 M5、不写成功审计。草稿仍可保存，已固化记录的幂等返回保持可用。具体边界见专题设计“两种运行时”。

预验证是同步返回最终结果的有界长操作。客户端统一使用已有 `postLongRunning`,不使用普通页面请求超时截断沙箱准备和链步骤。正反向分别使用独立运行作用域,创建后经 M2 contract 等待沙箱达到真实可执行阶段再运行链步骤;等待复用 M8 后台执行准备窗口 `CONTEST_BATTLE_SANDBOX_READY_TIMEOUT_SECONDS` 和 `CONTEST_BATTLE_SANDBOX_READY_POLL_INTERVAL_MS`,与对局共用同一等待实现。回收精确绑定本次作用域,请求取消后也使用独立的有界清理上下文,不因客户端断开而跳过回收。

预验证执行失败时,`prevalidate_detail.error` 只保存统一应用错误的用户向文案,`trace_id` 保存本次执行的报障编号;页面重新打开后仍可提供该编号。原始错误链仅写结构化日志,附租户、漏洞题和正反向阶段,不得把错误码、链工具输出或内部原因写入用户详情。

预验证结果只可写回执行开始时读取的草稿版本。执行期间来源重新同步、草稿修改或另一轮预验证已写回时，本次旧结果不得覆盖当前内容和结论，返回预验证失败，由教师重新读取后再验证；复用现有 `updated_at` 校验，不新增状态或版本字段。

漏洞题表单保留断言期望值的 JSON 类型：文本、数字、布尔、`null`、数组和对象按实际类型提交，不统一转成字符串。除 `exists` 外须提供合法且数值有限的 JSON 值，空字符串填写为 `""`；至少保留一条断言。来源请求内容、链步骤参数和断言期望值共用同一 JSON 解析入口，嵌套数值溢出同样拒绝。前端先校验再提交，判定仍由共享链断言能力执行。

初始化与攻击步骤中的 `query` 必须填写字符串 `target`，分别由环境准备和正向预验证实际执行；失败立即中止该次执行，不能当成空操作。动作标识统一使用小写 `deploy/tx/query/reset`，不转换其它拼写。正式判题只执行断言查询，回放记录目标及脱敏结果；页面使用同一有序动作协议展示查询及其它判题方式执行的部署、交易和重置。

漏洞题草稿、编辑和执行的初始化只有 `composition.init_chain_steps` 一份来源，初始化归档也只使用组合内字段；拒绝顶层 `init_steps/init_code_ref/init_script_ref`。预验证只读取服务端草稿组合，不从请求接收另一份执行配置。初始化步骤、`positive_steps` 和 `assertions` 以可选 `runtime_instance` 选择链，省略时使用冻结的工作区实例；显式值必须为非空文本，不接受空白、`null` 或其它类型。目标必须是本沙箱的命名 runtime，由 M2 继续校验来源、实例和能力，不接受端点地址或跨沙箱引用。正反向环境均先完成同一初始化；只有正向追加 `positive_steps`。固化正文仅保留不带访问场景的完整组合声明与正式断言，删除 `positive_steps`、`assertions`，正式 `expectation` 不含 `chain_steps`。官方攻击仅保留在 M8 出题草稿用于预验证，正式判题查询学生现场。

预验证执行前解析完整步骤和断言数组：`composition.init_chain_steps`、`positive_steps` 可以省略，提供时必须为对象数组；`assertions` 必须为非空对象数组。类型错误、`null` 或空对象项立即失败，不过滤后继续，也不创建沙箱。草稿保存不因此强制补全可执行内容。

### 8.2 平台能力 `[平台管理员]`

平台只维护**全局漏洞源目录**(`tenant_id=0`),不代租户同步、不生成租户草稿:

全局来源列表及保存均使用普通平台应用事务；事务内显式设置 `app.tenant_id=0`，数据库共享源仍保存 `tenant_id IS NULL`。保存与 M1 平台审计在同一事务提交，读取、加密、写入、审计或提交失败均不返回成功对象；不使用 M8 维护事务写平台配置或单独补审计。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/platform/vuln-sources` | 全局漏洞源列表,只返回 `tenant_id=0` 的记录 |
| POST | `/platform/vuln-sources` | 创建或更新全局漏洞源,不产生租户漏洞题草稿 |

⇒ 前端平台管理端「漏洞题源」页只做全局源的查看与新增/更新;同步、预验证、固化只出现在教师端。

学校与平台来源表单的 `config.endpoint` 统一由原生 `URL` 解析，只接受 HTTP(S) 且不含用户名/密码的地址；残缺地址、非法主机或端口在字段处提示，不发送保存请求。校验和提交共用同一解析结果，以原生 `href` 写入请求，不保留协议前缀判断或原文本提交路径。公网可达性与出站地址限制仍由服务端统一校验。

```
学生 → 查看已归档的动作序列与结果回放
```
