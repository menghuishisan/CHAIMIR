## 2. 赛事管理 `[教师/管理员]`

代码查重按当前赛题与阈值计算字段提示，阈值仍严格位于0与1之间；字段纠正立即更新错误，接口失败独立保留。草稿与归档禁用规则、指纹过滤与相似提交结果沿用原契约。

赛事基本信息仅允许在草稿或报名中修改;赛题及其锁定的 M5/M2 快照仅允许在草稿态编排。防作弊处理依赖实际参赛数据,草稿态只允许组织者查看空记录,不得查重或登记处理;报名开始后可按可见参赛数据审查,归档后只读。服务端必须拒绝草稿态和归档态的防作弊写入。

赛题编排的依赖校验可以在事务外执行，但最终保存必须锁定所属赛事行，重读草稿状态、赛制及当前题目引用；校验期间已经发布或变更赛制的请求不得写入旧快照。赛事发布、人工状态流转和定时推进共用该赛事行锁。发布的M5引用登记保持在M8事务外幂等执行，避免跨模块写事务嵌套耗尽连接池；登记后必须在最终锁定事务中重验当前状态和时间窗口，并比对赛制及完整题目集合，发生变化则拒绝本次发布，不写入状态。定时任务只领取仍满足时间和状态条件且未被其它执行者锁定的赛事。人工封榜与自动封榜使用同一完整榜单读取流程，快照不得在固定页大小处截断。

M8 选题必须遵守 M5 内容类型映射:解题赛可引用竞赛题和理论题,对抗赛仅可引用竞赛题;实验模板只供 M7 实验引用。前端选择器必须按赛制过滤,服务端在读取题目快照后、组合编译和持久化前再次校验类型,不能依赖前端过滤作为授权或数据完整性边界。

赛题编排与违规登记复用统一前端字段校验:失焦或提交后按当前值计算提示,纠正字段立即更新对应提示与无效状态,服务端失败单独展示。赛题分值与序号为正整数,动态最低分不得超过分值,每队衰减为正整数;关闭动态分后只移除相关提示。违规登记分别校验队伍与判定依据,仅扣分动作校验正数分值,切回其它动作不保留扣分错误;结构化证据和对抗规则载荷保持原契约。

题目引用失败的内部错误链必须区分内容读取、类型匹配、组合声明读取/编码/解析/规范化、M2编译与M3判题模式校验阶段，并保留租户和赛事编号及原始原因，供统一结构化日志关联本次trace。响应仍只返回原统一错误码、用户向文案和trace，不输出组合正文、私有初始化材料或判题配置；诊断信息不能替代准入校验。

## 3. 报名与组队 `[学生]`

创建队伍与邀请码加入各自管理共享字段校验范围，提交其中一张表单不激活另一张表单的错误；个人赛不校验队伍名称。队名与邀请码纠正后提示立即更新，报名与加入的接口失败独立呈现；报名窗口、队伍人数及授权准入仍由服务端决定。

学生工作台的交互状态按赛事与题目隔离。环境恢复读取与创建请求仅接收当前题目的最新响应,旧读取不得覆盖后续创建结果或关闭已经就绪的提交门禁;最近提交读取不得覆盖随后成功提交的新结果。切换题目后重新从服务端恢复环境与最近提交,不沿用上一题的答案、角色、错误或沙箱状态。

### 4.1 竞赛沙箱授权网关 `[学生]`

解题赛和对抗赛学生实操环境统一使用以下 M8 网关；所有路径均以当前会话主体查询 `contest_access_grant`，每个请求重新校验 `status`、`expires_at`、`grant_version`、成员租户/账号、沙箱和 `source_ref`。浏览器不得改用 M2 `/api/v1/sandbox` 路径，更不得传入组织方 `tenant_id`。

同一成员重复准备同一环境时,授权能力、来源、有效期和状态均未变化的grant复用原`grant_version`;权限、来源或有效期变化以及停用后重新签发才推进版本。撤销仍立即推进版本并关闭原有长连接。不得因队友的幂等准备请求使正在保存的合法提交在二次授权校验时失效。

首次启动或个性化初始化失败的环境统一返回失败生命周期，不能永久停在初始化中。学生点击同一“重新准备环境”入口时，M8 重新校验赛事、题目和队伍，撤销该失败沙箱的全部 grant 并关闭其连接，再经 M2 精确回收该沙箱编号，按原业务幂等键创建新环境和新授权；不得按整个稳定作用域误删并发请求刚创建的新环境。GET 仍只读且可显示失败态，不自动重放初始化脚本。工作台详情中的 `resource_usage` 与 M2 同为完整摘要或 `null`，用量不可读不阻断生命周期和授权查询。

已保存代码从 M2 按租户和稳定业务来源读取最近的持久化公开归档，包含已销毁的历史沙箱记录。回收旧环境后新建失败或请求中断，下次同一入口仍能重新取得该归档，不以一次请求内存作为唯一恢复依据。M8 不读 M2 表，M2 不删除历史归档指针或提交引用，也不返回私有脚本。

| 方法 | 路径 | 必需 grant 能力 | 说明 |
| --- | --- | --- | --- |
| GET | `/sandboxes/{id}` | `workspace.read` | 读取不含 Namespace 的运行时摘要 |
| GET/PUT | `/sandboxes/{id}/files` | `workspace.read` / `workspace.write` | 读取、列目录或写公开工作区文件 |
| POST | `/sandboxes/{id}/files/save` | `workspace.write` | 立即保存工作区,仅向学生返回工作区修订号,不暴露内部对象引用或哈希 |
| WS | `/sandboxes/{id}/progress` | `workspace.read` | 进度订阅，M8 先核 grant 再订阅 M2 主题 |
| WS | `/sandboxes/{id}/terminal` | `terminal` | 受控 PTY；复用M2终端字节流、背压和连接context约定；撤销 grant 必须精确关闭该连接并取消关联exec |
| `*` | `/sandboxes/{id}/tools/{tool_code}/*` | `web_tools` | 浏览器工具反向代理，短时票据仅用于换路径 Cookie |
| POST | `/sandboxes/{id}/command-tools/{tool_code}/run` | `command_tools` | 仅工具声明的 argv 白名单 |
| POST/GET | `/sandboxes/{id}/chain/deploy\|tx\|query?runtime_instance=` | `chain` | 按命名 runtime 实例调用统一链能力；不暴露 reset 给学生 |

> M8 将已验证的 grant 主体、版本、成员身份、目标组织租户和 `source_ref` 作为内部受控主体契约传给 M2。M2 再校验沙箱来源绑定；两层均未通过不得执行。grant 到期、撤销或竞赛结束后，所有新请求立即拒绝，已建立的终端和进度连接被关闭。

工作区写文件沿用M2 §4.2的内容与修订号契约:`content_base64`须显式提供字符串,允许空字符串写入零字节;缺失、`null`或非法编码仍拒绝。M8只校验请求边界和当前grant,不自建写入实现,仍由M2执行路径隔离、版本冲突检查与原子写入。

竞赛工作台持续按 M2 详情的 `phase=2/4` 且 `status=ready/running/idle` 判断可操作性,初始化中、暂停、回收中、终态或读取失败时关闭代码提交及参战提交。共享工作台使用同一状态变化回调通知业务层,不把首次就绪缓存为永久可提交。后台对局和预验证等待沿用同一阶段与生命周期约束。

> 提交流程:M8 收提交 → 对代码题核验当前成员的竞赛/队伍/题目沙箱 grant 并经 M2 保存工作区 → 调 M3(仅使用 M2 返回的代码对象引用与哈希,带 M5 题目引用 + 沙箱状态)→ 回写 → 更新排行。答案题只提交题目声明的答案内容,不接收沙箱或对象存储引用。代码对象 key/hash 不由学生请求指定。环境创建、对局、恢复和预拉取均只认 `contest_problem` 锁定的组合快照;旧的 `{runtime_code,runtime_image_version,tool_codes}` 请求或持久化形状不再接受。M3 复用判题必须使用创建该竞赛沙箱时的同一 `source_ref`。
> M8 题目摘要和单题题面必须经 M5 题面接口读取。摘要接口不得成为完整题面的旁路;单题题面接口必须再次校验当前队伍成员身份。M5 题面契约不可用时返回 M8 专用错误码,不能返回无题面或未过滤数据。实操题环境创建、解题提交和工作区全部必须以当前参赛队伍成员为前提,缺必需契约时显式失败。

| 方法 | 路径 | 说明 |

| GET | `/contests/{id}/battle/replay-window?page=&size=` | 本队已完成对局有序回放窗口 `[学生]`,响应 data 为 `{list,total,pending,checkpoint}`;通用对局列表分页不得用于推导回放全场状态,前端只用检查点加窗口内事件推进时间轴 |
| GET | `/contests/{id}/ladder` | 天梯排名 |

对局列表师生同路由按身份分视角:赛事组织者与学校管理员见本赛事**全部**对局(实时监控要看
「哪一局卡住了」),其余账号退回**本队**对局(时空回溯器要的是本队记录),未报名者读不到任何对局。
同一张表的分页查询只有一份 SQL,按 `team_id` 是否为 0 分叉;不为教师另开一条同义列表路由。
回放取件仍限参赛队伍成员(`authorizedBattleReplay`),组织者可见对局状态但不等于可下载他人轨迹。

对局列表和数据库中的 `score_delta` 使用同一固定结构,不得以无类型对象或数字 ID 双轨保存:`team_a/team_b` 使用公开雪花 ID 字符串,`rating_a_before/rating_b_before/rating_a_after/rating_b_after/delta_a/delta_b/k_factor` 为数字,`result` 使用对局结果枚举;对局尚未结算时数据库保存 `{}`,接口省略该字段。回放归档的 `match_id/task_id/initial_state.contest_id/initial_state.problem_id` 同样全部使用雪花 ID 字符串;动作序列只保存在顶层 `actions`,不得在 `result` 内重复保存;`initial_state.entry_a/entry_b.role` 必须接受攻方、防方和博弈策略三种已登记角色,解析器对未知枚举、缺失字段或类型错误直接拒绝,不得猜测默认值。

> 提交参战物 → 进对战池 → 撮合调度器异步起对局(M2)→ 判定 → 按标准 ELO 公式更新天梯 → 通知。ELO 初始分与 K 因子统一来自 `CONTEST_BATTLE_ELO_INITIAL_SCORE`、`CONTEST_BATTLE_ELO_K_FACTOR`,不得在代码或 SQL 中写死。学生提交只提供 `problem_id`、当前竞赛实操环境的 `sandbox_id` 和题目允许的 `role`;不得提交或指定对象存储 `artifact_ref`、内容 `code_hash`。M8 必须验证当前登录成员的活动授权同时绑定当前组织租户、竞赛、队伍和沙箱，且沙箱来源对应指定题目，再经 M2 授权工作区保存接口生成参战物引用与 SHA256；M8 只持久化该可信返回值，用于复现、审计和查重。对局判题先通过 M2 `RestoreSandboxArchive(expected_hash=code_hash)` 校验并恢复双方参战物到对局沙箱的角色路径(攻防型 `battle/attack`、`battle/defense`;博弈型 `battle/entry_a`、`battle/entry_b`),再用 M3 reuse 模式读取 M5 锁定题目版本的组合快照和判题配置;正式对局使用 `contest-battle` 私有访问配置,不得向参赛者暴露终端、文件、工具代理或 judge-private 容器。M8 不把参战物伪装成 M3 代码提交字段。

## 6. 排行榜(实时)

- 经 M10 统一通道:M8 判题/对局后调 M10 `POST /notify/push(tenant_id, topic=tenant:{tenant_id}:contest:{id}:leaderboard)`;客户端订阅 M10 `WS /api/ws` 的该 topic。
- 封榜后停止推送实时变化；`GET /contests/{id}/ladder` 固定读取进入封榜时的服务端快照，不能通过刷新页面或直接请求 URL 窥探后续判定。
- 榜单字段按赛事赛制解释:解题赛的 `score`、`solved_count`、`last_solve_at` 分别表示总分、解题数和末次解题时间;对抗赛的 `score` 表示 ELO,`solved_count` 固定为 `0` 且 `last_solve_at` 为空。对抗赛只按 ELO 降序排名,不得把解题统计展示为对局统计。

| GET | `/students/{id}/contest-achievements` `[内部]` | 供 M11 独立聚合"竞赛成就"(与 GPA 分离,只读) |

> 竞赛结束(已结束→已归档)时生成 `result-snapshot` 成绩快照存档,避免战绩只活在 ladder_rank/battle_match 流水里。`final_ranking` 每项固定为 `{ team_id, score, solved_count, last_solve_at, rank, updated_at }`,其中 `team_id` 是雪花 ID 字符串,不得退化为无类型对象数组;解题赛的 `last_solve_at` 按无解题记录省略,对抗赛固定为 `solved_count=0` 且省略 `last_solve_at`。学生竞赛战绩独立展示,不混入学业 GPA。

## 8. 真实漏洞源

### 8.1 租户能力 `[出题教师/学校管理员]`

漏洞源同步与漏洞题转化是**租户内**的出题工作流,产物落本租户题库:

来源按全局唯一 `id` 创建或更新,更新必须与记录原有租户归属一致,平台全局归属为数据库 `NULL`;不得将全局来源转为学校来源或覆盖其它学校来源。更新配置和启停保留原有创建及同步时间。未成功同步过的来源响应不包含 `last_sync_at`,页面显示“尚未同步”,不计入曾同步数量。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/vuln-sources` | 本租户漏洞源配置(SWC/情报/CVE) |
| POST | `/vuln-sources/{id}/sync` | 同步拉取漏洞案例,按配置映射生成漏洞题草稿 |
| GET | `/vuln-problems?source_id=&status=&page=&size=` | 漏洞题草稿分页列表,响应 data 为 `{list,total,page,size}` |
| POST | `/vuln-problems` | 录入一条漏洞题草稿(手工录入,或按来源案例分级后落草稿) |
| POST | `/vuln-problems/{id}/prevalidate` | 预验证(正向+反向);通过时保存组合快照、初始化引用和判题配置 |
| POST | `/vuln-problems/{id}/finalize` | 导入即固化 → 调 M5 `system-import` 存入 M5(自包含) |

> 草稿录入只有 `POST /vuln-problems` 一条路径。原先另有 `POST /vuln-sources/import`,
> 两者绑同一个 handler、同一个请求体(`ImportVulnProblemRequest` 带可选 `source_id`),
> 是同一件事的两条路由;`source_id` 本身已经表达了「这条草稿来自哪个来源」,
> 不需要再用路径区分手工录入与来源导入。故收敛到 `/vuln-problems`,不保留同义路径。

### 8.2 平台能力 `[平台管理员]`

预验证是同步返回最终结果的有界长操作。客户端统一使用已有 `postLongRunning`,不使用普通页面请求超时截断沙箱准备和链步骤。正反向分别使用独立运行作用域,创建后经 M2 contract 等待沙箱达到真实可执行阶段再运行链步骤;等待复用 M8 后台执行准备窗口 `CONTEST_BATTLE_SANDBOX_READY_TIMEOUT_SECONDS` 和 `CONTEST_BATTLE_SANDBOX_READY_POLL_INTERVAL_MS`,与对局共用同一等待实现。回收精确绑定本次作用域,请求取消后也使用独立的有界清理上下文,不因客户端断开而跳过回收。

预验证执行失败时,`prevalidate_detail.error` 只保存统一应用错误的用户向文案,`trace_id` 保存本次执行的报障编号;页面重新打开后仍可提供该编号。原始错误链仅写结构化日志,附租户、漏洞题和正反向阶段,不得把错误码、链工具输出或内部原因写入用户详情。

平台只维护**全局漏洞源目录**(`tenant_id=0`),不代租户同步、不生成租户草稿:

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/platform/vuln-sources` | 全局漏洞源列表,只返回 `tenant_id=0` 的记录 |
| POST | `/platform/vuln-sources` | 创建或更新全局漏洞源,不产生租户漏洞题草稿 |

⇒ 前端平台管理端「漏洞题源」页只做全局源的查看与新增/更新;同步、预验证、固化只出现在教师端。

## 9. 典型时序

### 解题赛提交
```
学生 → 起环境(M2) → 提交 → M8 调 M3 判(取 M5 配置, judge 沙箱)
M3 → 回写结果 → M8 更新 ladder_rank → WS 推排行榜
```

### 对抗赛对局
```
学生 → 提交参战物 → 进对战池
撮合调度器 → 选对手 → 起对局沙箱(M2) → 跑对局 → M3 判定
→ M3 持久化 M2 链能力结果 → M8 写报告桶回放归档并记 battle_match.replay_ref → 更新 ELO → WS 推天梯
学生 → 看对局回放(交易序列重放)
```
### 对抗赛回放时间窗

`GET /api/v1/contest/contests/{id}/battle/replay-window?page=&size=` 只返回当前队伍已完成对局的有序窗口。响应包含 `list`、已完成 `total`、`pending`、窗口开始前的 `checkpoint`（胜负、积分与积分变化），以及每局服务端确定的本队方向和生效参战物摘要。通用对局列表分页不得用于推导回放全场状态；前端只能用检查点加窗口内事件推进时间轴。
