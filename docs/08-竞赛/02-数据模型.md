# M8 竞赛 — 数据模型

> PostgreSQL,租户级(tenant_id + RLS);跨校组队为受控例外。建模遵循:消灭数据冗余、表合并有度。
> 最后更新:2026-11-27

---

## 1. 表清单总览

| 表名 | 用途 |
| --- | --- |
| `contest` | 竞赛(赛制/赛程/参赛形式) |
| `contest_problem` | 竞赛题目引用(指向 M5) |
| `team` | 参赛队伍(个人=单人队) |
| `team_member` | 队员 |
| `contest_access_grant` | 跨校竞赛受控访问授权(仅作用于竞赛、队伍和指定沙箱) |
| `solve_submission` | 解题赛提交 |
| `battle_entry` | 对抗赛参战物(合约/脚本/策略) |
| `battle_match` | 对抗对局(撮合结果 + 回放引用) |
| `ladder_rank` | 天梯/排行榜积分 |
| `contest_ladder_snapshot` | 封榜/归档排行榜快照 |
| `cheat_record` | 作弊判定记录 |
| `vuln_source` | 真实漏洞外部源配置 |
| `vuln_problem` | 漏洞题转化草稿/预验证记录 |

> 消灭冗余/合并说明:
> - **题目正本在 M5**,`contest_problem` 只存引用 + 锁版本 + 竞赛内分值/配置。
> - **个人赛复用 team**(单人队),不单设个人参赛表;单人队的 `name` 是选手报名时填写的参赛名称(排行榜上显示)。
> - **对局回放不存全量状态**:`battle_match.replay_ref` 只保存统一报告桶归档引用;归档正文由 M3 持久化的 M2 链部署/交易结果序列组成,不在 M8 重复实现链执行或伪造提交归档。
> - **解题/对抗提交分两表**:语义与字段差异大(解题判 flag/断言,对抗是参战物进对战池),分开清晰。
> - **漏洞源拉取的题目固化进 M5**,M8 只存源配置 `vuln_source`,不存漏洞题正本(在 M5)。

### 2.2 contest_problem — 竞赛题目引用

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| tenant_id | BIGINT | |
| contest_id | BIGINT | |
| item_code | VARCHAR(96) | M5 题目 code |
| item_version | VARCHAR(32) | 锁版本 |
| score | INT | 分值 |
| dynamic_score | JSONB NULL | 动态分固定结构:`{min_score, decay_per_solve}`;未启用时为 NULL |
| battle_rule | SMALLINT NULL | 对抗题对局规则:1攻防型 / 2博弈型(仅 mode=对抗赛时用,题目级配置) |
| seq | INT | 正整数题序，草稿态可修改；同序按赛题编号排序 |
| composition_digest | VARCHAR(128) | M2 编译快照摘要;发布前生成,发布后不可变 |
| composition_snapshot | JSONB | M2 完整组合快照;与摘要必须一致,运行时只读此字段 |

`dynamic_score` 使用固定结构，前后端和持久化层共同拒绝未声明字段：

- `dynamic_score`:仅解题赛允许；启用时必须同时给出正整数 `min_score`、`decay_per_solve`,且 `min_score <= score`;未启用或对抗赛时为 NULL。
- 动态得分为 `max(min_score, score - 已解出队伍数 × decay_per_solve)`；达到下限后直接取最低分，不因中间乘积越界拒绝合法结算。计分参数的整数范围由请求类型与初始建表共同约束。
- 数据库初始建表用 CHECK 约束上述对象形状；应用读取使用严格类型解码。

对抗题只选择 `battle_rule`。访问边界由对抗赛固定为 `contest-battle`，入场角色及配对由对局规则决定，已完成对局始终保存完整回放；这些派生规则不另存配置。初始化材料和完整环境组合来自 M5 锁定版本的 `composition`，判题器与已审核执行程序来自其 `judge_config`；运行时只读锁定快照。

### 5.2 battle_match — 对局

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| tenant_id | BIGINT | |
| contest_id | BIGINT | |
| problem_id | BIGINT NOT NULL | 对局赛题 |
| source_ref | VARCHAR(128) NOT NULL | 本局稳定来源，租户内唯一 |
| scope_ref | VARCHAR(128) NOT NULL | 资源作用域，租户内唯一 |
| judge_task_ref | VARCHAR(64) NULL | 当前M3任务 |
| status | SMALLINT NOT NULL | 1待执行/2执行中/3完成/4失败 |
| entry_a_id / entry_b_id | BIGINT | 对阵双方参战物 |
| sandbox_ref | VARCHAR(64) NULL | 对局M2沙箱引用，启动前为空 |
| result | SMALLINT NULL | 1A胜/2B胜/3平；未产生结果时为空 |
| score_delta | JSONB | 双方积分变化(ELO),固定结构保存双方队伍、赛前分、赛后分、增量、K 因子与结果;`team_a/team_b` 必须是十进制字符串雪花 ID,未结算时为 `{}` |
| replay_ref | VARCHAR(255) | 回放数据(交易序列)引用 |
| matched_at / finished_at | TIMESTAMPTZ | |
| attempt_count | INT | 撮合启动尝试次数;达到 `ASYNC_OUTBOX_MAX_ATTEMPTS` 后转失败终态,不再无限重试 |
| lease_token / lease_until | VARCHAR(64) / TIMESTAMPTZ | 撮合启动阶段的租约 CAS;仅持有有效令牌的 worker 可创建沙箱并提交判题 |
| finalized_at | TIMESTAMPTZ NULL | 终态后的资源回收和审计均已交付的时间；榜单由赛事待推送标记独立交付；未完成则周期补偿继续执行，不再次结算积分 |

> 对局启动把“创建沙箱、恢复参战物、提交判题”视为短租约阶段。`CONTEST_MATCHMAKER_LEASE_DURATION_MS` 至少为 3000 毫秒。worker 在执行前先以当前 `lease_token` CAS 续租,确认租约仍有效后才开始外部调用;执行期间按租约时长的三分之一持续续租,间隔限制在 1 到 30 秒。续租或启动 CAS 未命中即停止操作且不回收共享 `source_ref` 资源。启动 CAS 成功后清除该租约,进入等待判题结果的可恢复状态;启动阶段崩溃或租约过期可按 `attempt_count` 受控重领。达到上限后转失败终态并由运维处理,禁止永久 `running`。归档 claim 只在没有活动对局时取得独立归档租约,归档期间禁止新对局进入,最终快照必须通过归档租约 CAS 才能将竞赛置为已归档。

> 判题终态的事务只结算一次积分，并留下赛事榜单待推送标记。事件处理和周期扫描共用终态交付函数，复用对局的短租约字段认领回收与审计；两者成功且仍持有租约时才写 `finalized_at`。榜单沿赛事统一待推送流程独立恢复，不再同时由对局交付。崩溃或失败后租约到期可恢复，失败启动的无判题任务对局同样纳入回收。外部交付为至少一次：回收按 M2 作用域幂等，审计允许交付成功到完成标记之间崩溃时重记，不承诺跨模块事务的恰好一次。扫描使用 ID 游标和固定本轮时间边界，单局失败不阻塞后续对局。

### 5.3 ladder_rank — 天梯/排行

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| tenant_id | BIGINT | |
| contest_id | BIGINT | |
| team_id | BIGINT | |
| score | NUMERIC(10,2) | 解题赛总分 / 对抗赛 ELO;新队伍初始 ELO 来自 `CONTEST_BATTLE_ELO_INITIAL_SCORE` |
| solved_count | INT | 解题赛解题数;对抗赛固定为 0,不作为解题进度或排名依据 |
| last_solve_at | TIMESTAMPTZ NULL | 解题赛末次解题时间;对抗赛保持 NULL,不记录对局时间 |
| rank | INT | 名次 |
| updated_at | TIMESTAMPTZ | |

唯一约束:`(contest_id, team_id)`。

排名顺序按赛制确定:解题赛按总分、解题数、末次解题时间排序;对抗赛按 ELO 分降序,再按队伍 ID 稳定排序。对抗赛的 ELO 更新不得写入解题统计字段。

得分、取消资格和名次在持有赛事父行锁的同一事务中维护；`rank` 是实时榜单的权威名次，分页按现有 `(tenant_id, contest_id, rank)` 索引读取，不再次计算全榜排名。刷新只改写名次变化的行及其 `updated_at`；得分变化由得分写入更新该队时间，名次未变也必须留下榜单待推送标记。

### 5.4 contest_ladder_snapshot — 封榜/归档排行榜快照

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| tenant_id | BIGINT | |
| contest_id | BIGINT | |
| snapshot_status | SMALLINT | 4封榜快照 / 6归档最终快照 |
| ranking | JSONB | 对应状态的榜单快照(队伍/名次/得分/ELO) |
| generated_at | TIMESTAMPTZ | 进入封榜或归档时生成 |

> 进入封榜时固化公开榜单，封榜期间后续判定仍落真实榜单但学生读取固定快照；"已结束→已归档"时再生成最终快照，供归档结果与个人战绩展示。唯一约束为 `(contest_id, snapshot_status)`，同一阶段只保留一个权威快照。
> **个人战绩档案**(`GET /my/contest-records`)为**派生查询**:跨竞赛聚合该学生所属队伍的 `ladder_rank` + 快照,不另建表(消灭冗余)。

### 6.2 vuln_source — 真实漏洞外部源配置

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| tenant_id | BIGINT NULL | 平台级源可空 |
| type | SMALLINT | 1SWC/2漏洞情报/3CVE链上事件 |
| name | VARCHAR(128) | |
| config | JSONB | 源接入参数(端点/密钥加密) |
| default_level | SMALLINT | 默认分级 A/B/C |
| enabled | BOOLEAN | |
| last_sync_at | TIMESTAMPTZ NULL | 本校来源末次成功同步；平台共享源不记录学校同步时间 |

平台共享源（`tenant_id IS NULL`）配置仅平台可写，教师可同步为本校 `vuln_problem` 草稿，不更新共享源。接口由归属派生 `is_shared`，不新增存储字段；共享源不返回 `last_sync_at`。草稿经预验证后才固化到 M5。

共享读取与写入采用独立 RLS 策略：学校可读共享源，只能锁定、修改或删除本校源；普通平台事务显式设置 `app.tenant_id=0`，只可写共享源，不取得学校源权限。平台源保存与 M1 平台审计沿用同一应用事务，失败一并回滚。

### 6.3 vuln_problem — 漏洞题转化草稿

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| tenant_id | BIGINT | |
| source_id | BIGINT NULL | 来源配置;手工导入可空 |
| external_ref | VARCHAR(128) NULL | 外部案例标识 |
| title | VARCHAR(255) | |
| level | SMALLINT | 1=A / 2=B / 3=C |
| runtime_mode | SMALLINT | 1 isolated / 2 forked |
| draft_body | JSONB | 题面、初始化交易、断言、PoC、fork 锁定区块与完整历史状态身份;固化时注入锁定组合与 `judge_config` |
| composition_digest | VARCHAR(128) NULL | 预验证通过后写入的 M2 组合快照摘要 |
| composition_snapshot | JSONB NULL | 预验证通过后写入的 M2 完整组合快照 |
| prevalidate_status | SMALLINT | 1未验证 / 2通过 / 3失败 |
| prevalidate_detail | JSONB | 正向/反向验证结果与失败原因 |
| content_item_code | VARCHAR(96) NULL | finalize 后写入 M5 的题目 code |
| content_item_version | VARCHAR(32) NULL | finalize 后锁定版本 |
| status | SMALLINT | 1草稿 / 2已固化 / 3废弃 |
| created_at / updated_at | TIMESTAMPTZ | |

> `vuln-problems/{id}/prevalidate/finalize` 的 `{id}` 指向本表。只有组合编译、正向/反向验证和判题配置校验全部通过才允许写入快照;初始化代码、脚本与链步骤只保存在组合快照中；finalize 必须把锁定 `composition` 和只读断言 `judge_config` 写入 M5 正文,再写入 `content_item_code/version`。已固化记录不允许重新预验证或修改快照。

> 同一租户、来源、外部标识的案例同步只更新草稿；跳过已固化或废弃记录。手工录入不覆盖已有案例，编辑按 ID 和 `updated_at` 更新草稿并清空旧验证、快照和内容引用。`draft_body` 允许未完成内容，执行前再校验；不新增草稿表、编辑副本或版本列。

> 本表 `updated_at` 是既有乐观版本；每次更新取 `GREATEST(clock_timestamp(), 原 updated_at + interval '1 microsecond')`，保证同一事务或时钟回退下仍严格递增。插入继续使用默认时间，不增加版本字段。

> 草稿初始化步骤和归档只保存在 `draft_body.composition`，编辑直接读写 `init_chain_steps/init_code_ref/init_script_ref`，不再接受顶层副本。组件引用编码及选择标记完整，运行时和连接可未填完；已提供字段的类型必须能被编辑器完整恢复。

> 验收种子在编译快照前构造完整初始化声明，草稿与快照使用同一组合；只写本表实际字段，不恢复已删除的初始化引用列。
