## 1. 通用约定

- 租户任务列表按 M1 返回的启用来源模块在 SQL 分页前过滤，列表与总数同口径；详情、人工评分、用户重判和新进度连接按已保存的 `source_ref` 校验。平台判题器治理及已受理任务执行、结果回写、资源清理沿用原有服务授权，不受用户入口开关影响。

- Base:`/api/v1/judge`
- 统一响应体同 M1。错误码段:`3xxxx`(31xxx 判题器/32xxx 任务/33xxx 查重)。
- `[内部]` HTTP 接口统一位于 `/internal`，供 M6/M7/M8 服务间调用，`tenant_id`、`source_ref` 取服务签名；模块内使用 `internal/contracts`。

## 2. 判题器管理 `[平台管理员]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/judgers` | 判题器列表 |
| POST | `/judgers` | 注册判题器 |
| PATCH | `/judgers/{id}` | 更新配置 |
| POST | `/judgers/{id}/selftest` | 在已锁定组合的临时私有沙箱中执行判题器 manifest `selftest.commands`,完成后回收资源；容器判题器仍须另行完成真实下游评测 |

平台管理端必须按判题器类型提供字段级资源编辑器，并提交一次性 `composition` 声明和受控 `resource_spec` 执行策略；不得要求管理员手写原始 JSON，也不得用空对象构造服务端必然拒绝的请求。人工评分不声明运行命令；测试用例和静态检查必须显式声明固定运行时、镜像版本、创世状态、受控命令、执行组件、资源上限、超时与重试策略。

运行型判题器创建或更新请求必须提交组合声明和执行策略:
```json
{
  "composition": {
    "id": "judge:testcase-evm",
    "runtimes": [{ "instance_code": "source-chain", "runtime_code": "evm-hardhat", "image_version": "sha256-<digest-prefix>" }],
    "infra": [],
    "tools": [{ "code": "terminal", "params": {} }],
    "links": [],
    "access_profile": "judge-private"
  },
  "resource_spec": {
    "genesis_ref": "runtime-image:sha256-<digest-prefix>:baked-genesis",
    "init_script_ref": "s3://chaimir-code/judgers/init.sh",
    "command": ["npm", "test", "--", "--reporter", "json"],
    "timeout_sec": 60,
    "max_retries": 2
  }
}
```
服务端在保存前通过 M2 组合编译器生成完整不可变 `composition_snapshot`，然后只把该快照写入 `judger.resource_spec`；响应中的 `resource_spec` 是持久化事实，不是可回传编辑输入。判题任务不得接受运行时、镜像版本、工具或初始化旁路字段，也不得用当前默认镜像替代锁定快照。

平台目录同步在依赖运行时尚未通过自检时,可以仅在唯一 `composition_snapshot.spec` 中保留待编译声明,此时 `composition_digest` 为空且不可执行。平台判题器列表和编辑弹窗统一以非空 `composition_digest` 识别已冻结事实;尚未冻结时显示「判题环境尚未准备完成」,不展示空白环境、零锁定镜像或「已冻结」详情。已有摘要但自检失败时仍保留实际冻结环境和镜像详情,可用性继续由自检/目录状态决定;不得通过隐藏失败环境或伪造摘要改变可用状态。

### 2.1 判题器目录 `[教师/学校管理员/平台管理员]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/catalog` | 可用判题器的最小字段目录 |

教师配置实验检查点时要选判题方式,而 §2 的管理接口是平台面(`RequirePlatformIdentity`),把它放开会连带暴露 `resource_spec` 里的判题镜像版本、受控命令与执行组件 —— 那是判题私密面,不是编排输入。故与 M2 编排目录同一处理方式,单独出一条只含编排必需字段的目录:

```json
{ "judgers": [{ "code": "testcase-evm", "name": "测试用例", "type": 1 }] }
```

只回 `status=可用` 的判题器;**不回** `id`、`executor_ref`、`resource_spec`、`runtime_required`、`default_timeout_sec`、`selftest_status`。平台管理端仍走 §2 的完整接口。

## 3. 提交判题 `[内部]`

### 3.1 提交
`POST /internal/tasks` `[内部]`
请求:
```json
{
  "judger_code": "",              // 可空;为空时使用 M5 锁定题目版本的 judge_config.judger_code
  "item_code": "prob-2031",        // M5 题目 code(统一格式,见 §3.2)
  "item_version": "1.0.0",         // M5 题目锁定版本
  "code_storage_key": "s3://.../submission", // 仅代码类判题器必填
  "code_hash": "64位sha256hex",                 // 仅代码类判题器必填
  "submitter_id": "1001",
  "submitter_tenant_id": "10", // 提交者真实所属学校，跨校参赛时不可省略
  "source_owner_id": 1001,         // 来源归属账号;教师侧查询/重判/人工评分必须据此防越权
  "source_course_id": 0,           // 教学来源必填课程 ID,其他来源可为 0
  "source_scope": "experiment",    // teaching/experiment/contest 等来源类型
  "sandbox_mode": "fresh",         // fresh=新起干净judge沙箱 / reuse=复用现场沙箱
  "target_sandbox_ref": null,      // sandbox_mode=reuse 时必填,指向调用方现有 M2 沙箱
  "sandbox_source_ref": "",        // reuse 时必填目标沙箱的真实来源
  "sandbox_composition_digest": "", // 私有对局必填 M8 锁定组合摘要
  "extra_input": {},               // J3 flag/J5 checkpoint/J7 理论题答案等非代码输入,只用于本次输入快照
  "priority": 2
}
```
响应为跨模块契约 `contracts.JudgeTaskInfo`:`{ "task_id": 8801, "status": 1 }`,状态含义见[任务状态机](05-业务流程与状态机.md#2-判题任务状态机)；用户向查询与进度接口返回字符串状态。

单任务状态读取复用平台同数据库、同租户的只读事务能力，调用方已在事务中时不重复申请连接；跨数据库或跨租户上下文直接拒绝。此读取不取得任务写锁，不承诺与同时重判互斥。

内部 HTTP 调用的 `tenant_id` 与 `source_ref` 来自服务签名头(`X-Chaimir-Tenant-Id` / `X-Chaimir-Source-Ref`),请求体不得再携带第二份来源标识;Go 模块内同步调用仍通过 `contracts.JudgeSubmitRequest.SourceRef` 传递同一契约字段。

`source_owner_id`、`source_course_id`、`source_scope` 是 M3 访问控制的一等契约字段,不得放入 `extra_input` 隐式传递。教学来源必须传课程教师账号与课程 ID;实验来源传实例归属账号与课程 ID(无课程时为 0);解题赛来源传提交者，私有对局传主办学校的组织教师，课程 ID 为 0。私有对局的提交者租户/账号与沙箱归属统一为主办学校及其组织教师，不随队长或成员变化。

Go 跨模块 `JudgeSubmitRequest.RequiresOutcome` 只由 M8 按锁定题目规则设置；博弈为 `true`，攻防为 `false`。M3 在任务入队前校验它与 M5 唯一结果断言及真实沙箱访问类型一致，HTTP 请求不得设置该字段。

`judger_code` 为空时,M3 必须使用 M5 锁定题目版本的判题配置;理论题由 M5 解析为固定 `theory-question` 内置策略,其他类型使用锁定版本 `judge_config.judger_code`。调用方不得为了解题赛、作业或实验硬编码模块内判题器别名。若调用方显式传入 `judger_code`,M3 必须与 M5 判题配置逐字匹配,不一致即拒绝提交。

`code_storage_key`/`code_hash` 仅代码类判题器使用。J1 测试用例、J4 静态检查、fresh 模式 J2 链上断言必须携带二者;J3 Flag、J5 仿真检查点、J6 人工评分、J7 理论题、reuse 模式 J2 链上断言必须留空,不得上传空归档或伪代码对象作为旁路。Flag 提交值必须按 `flag_input_key` 直接放入 `extra_input`,仿真检查点必须放入 `extra_input.checkpoint`;理论题使用 `extra_input.student_answer`。

模块间统一调用 `GetJudgeInputRequirements`：M3 按锁定题目版本和预期访问类型、沙箱模式校验能力，返回模式与是否需要代码归档。调用方按结果准备输入，不复制判题器类型判断；能力读取失败不得归档或提交。预期访问类型只用于配置校验，不授予执行权限。

### 3.2 两种判题沙箱模式

| sandbox_mode | 说明 | 适用 |
| --- | --- | --- |
| `fresh`(默认) | M3 向 M2 申请全新干净 judge 沙箱,注入代码+套件判定,用后即毁 | 测试用例判题、独立判定;学生不可见判题环境 |
| `reuse` | 使用调用方传入的 `target_sandbox_ref`，权限由 M2 冻结访问类型决定 | 学生现场只读断言；私有对局执行锁定程序后检查结果 |

> M3 `GetJudgeInputRequirements` 返回锁定题目所需模式与是否需要代码归档。未指定模式时，私有对局使用 `reuse`，其他场景的 J2 无 `chain_steps` 使用 `reuse`，其余使用 `fresh`。学生现场禁止非空 `chain_steps`；私有对局必须声明含部署或交易的 `chain_steps`，不能只读取初始状态就结算。竞赛不按判题器编码推断。

> `chain_steps` 与 `assertions` 以可选 `runtime_instance` 选择本沙箱的命名链实例，省略时使用工作区实例；显式值必须是非空文本，空白、`null` 和其它类型均为配置非法。现场模式的默认实例来自 M2 当前环境，不能使用平台判题器组合的同名或首项实例。M2 仍校验每次操作的沙箱来源、目标实例和能力，未知实例使执行失败，不回退到工作区链。

> reuse 提交及 worker 执行前共用同一校验：从 M2 读取沙箱身份、租户、来源、就绪状态、工作区实例和冻结访问类型。`experiment/contest-solve` 只读断言；`contest-battle` 还必须匹配本局任务来源、主办学校组织教师和调用方冻结的组合摘要，才可按锁定题目的 `chain_steps` 执行。访问类型和执行步骤不从 `extra_input` 接受，不注入测试套件或官方漏洞攻击。
>
> 私有对局每个任务仅执行一次，不在已改变的环境上自动重试或原地重判；执行、超时或租约失败走现有失败事件、结算与回收。需要再次对战时由 M8 创建新对局。学生只读判分与 fresh 独立沙箱仍保留既有重试策略。
> item_code/item_version 统一对应 M5 的 `(code, version)`,M3 据此调 M5 `GET /items/{code}/{version}/full` 取判题配置与答案。
> fresh 模式下,只有代码类判题器必须读取 `code_storage_key` 指向的对象,校验对象内容 SHA-256 与 `code_hash` 一致,按 `JUDGE_INPUT_ARCHIVE_MAX_FILES` / `JUDGE_INPUT_ARCHIVE_MAX_UNPACKED_BYTES` 校验归档成员并重打包后注入 judge 沙箱;不得直接把原对象引用作为沙箱 `InitCodeRef`。非代码判题器即使使用 fresh 模式,也必须通过结构化 `extra_input` 或人工评分接口传入判定输入。

### 3.3 判题器 `expectation` 约定

M5 通过 `ContentJudgeSpec.Expectation` 给 M3 提供黑盒判题配置。M3 不保存题目正本,只把本次锁定版本写入 `input_snapshot`。

| 判题器 | expectation 关键字段 | 说明 |
| --- | --- | --- |
| J1 测试用例 | `command_result=json` | 判题命令 stdout 必须输出 `{passed,score,max_score,details}`;`details` 为非空数组,每项至少含 `passed` 和 `case/source/target` 之一 |
| J2 链上断言 | `chain_steps[]`、`assertions[]` | `chain_steps` 支持 `deploy/tx/query/reset`;Foundry deploy 可显式使用 `contract_ref`、`compile:true` 和 `constructor_args:[{"type":"address","target_ref":"..."}]`,tx 可显式使用 `target_ref`;引用必须来自同一沙箱已完成部署,不允许隐式文本替换;fresh 先注入学生代码，reuse 按上述访问类型约束执行;`assertions` 支持 `eq/ne/contains/exists`;无断言为配置非法;失败详情只含 `expected_label`/`actual`,不得返回完整期望结构 |
| J3 Flag | `flag_hash`、`flag_input_key`(位于 `judge_config.expectation`) | M5 只提供已固化的 64 位 HMAC-SHA256 `flag_hash`;M3 不接收明文 flag 或 HMAC secret;worker 运行时只接受 `flag_hash`;提交值入库前统一固化为 `submitted_flag_hash` |
| J4 静态检查 | `command_result=json` | 与 J1 一样解析结构化 stdout,但不要求链运行时 |
| J5 仿真检查点 | `checkpoint` | 与 `extra_input.checkpoint` 做结构化相等比较;结果详情只含 `expected_label`/`actual`,不得返回完整标准检查点 |
| J6 人工评分 | 无 | 不进 worker,教师接口写入结果;`details` 结构化保存 `comment/score/max_score/passed` |
| J7 理论题 | `q_type`、`answer` | M3 内置后端策略按 M5 锁定版本比较 `extra_input.student_answer`;单选/判断/多选/填空严格按对应形状与规范比较,简答不进入 J7;结果详情不得包含标准答案或学生原文 |

`chain_steps` 的 `query` 步骤必须提供非空字符串 `target`，按选定 runtime 调用 M2 `ChainQuery`，禁止跳过查询直接成功。查询失败使本次执行失败，不继续后续步骤或断言；成功时按执行顺序记录 `op=query`、`payload.target` 和脱敏后的 `output`。缺失或未知 `op` 为配置非法，不能作为空操作。

私有博弈对局在唯一一条断言中声明 `outcome: true`、`op: "exists"` 和非空 `field`。锁定程序执行后，M3 从该次查询原始对象的指定字段读取严格枚举 `a_win/b_win/draw`，写入对应结果明细的 `outcome`；缺失、null、其它类型或枚举、重复声明均拒绝。声明只允许用于 `contest-battle`，配置在任何链写入前校验；查询失败或任一断言未通过时按执行失败处理，不产生胜负。`actual` 继续作为脱敏展示摘要，不参与结算。结果通过既有 details JSON 持久化，公开 DTO、跨模块契约和回放保留同一枚举，不新增结果表或列。赛题能力查询通过 `JudgeInputContext.RequiresOutcome` 区分博弈与攻防，博弈必须有结果声明，攻防不得混用。

断言读取现场状态的查询也按同一协议进入回放，接续已有步骤的序号；所有动作均记录实际 `runtime_instance`，查询记录目标和脱敏结果，不记录标准答案。页面单独显示目标链，不把平台路由字段混入交易入参。

链断言和仿真检查点按精确 JSON 结构比较：对象忽略键顺序、数组保留顺序，数值按十进制值比较，`1`、`1.0`、`1e0` 相等，相邻大整数或不同高精度小数不得因浮点舍入而相等。输入、快照和链查询保留原始 JSON 数值，数值与字符串不混同。

链断言由共享 `chainassert` 解析：除 `exists` 外必须显式提供 `value`，省略操作符按 `eq` 同样校验。实际结果必须包含 `field` 指定的字段，省略 `field` 时用 `target`；字段缺失时断言不通过，不作为执行错误。显式 JSON `null` 是合法值，按原值比较；`exists` 只检查字段是否存在，值为 `null` 也算存在。正式判题和漏洞预验证遵守同一规则。

`chain_steps` 可以省略；提供时必须为数组，`null`、对象、文本或其它类型均为配置非法，不能当作空步骤继续判分。动作标识统一使用小写 `deploy/tx/query/reset`，预验证与正式判题不转换另一套拼写。

J3 配置 `flag_chain_target` 时，同样使用冻结组合明确指定的工作区 runtime 和任务所属沙箱来源进行查询；缺少运行时声明为配置非法，查询失败为执行失败。仅比较提交凭证摘要时无需链运行时。

J2、J5 和命令型判题拒绝非零的 `random`、`wall_clock`、`external_network` 标记；缺失、`null` 和零值不启用该标记，校验不得因此崩溃。快照及执行配置保留各自的顶层副本，执行期恢复全量期望不能改写持久化的脱敏摘要。

判题器命令输出必须是结构化 JSON,不得把完整测试套件或答案回传给学生端。J2/J5 的 `expected_label` 只能是教师配置的断言标签、目标字段、操作符或脱敏短文本,不能直接放标准答案结构。J3 只允许 M5 提供已固化 `flag_hash`,M3 在构建 `input_snapshot` 时只保存学生提交值的 `submitted_flag_hash`;重判使用快照中的 hash,不再读取或保存答案正本。

J2 断言的 `label` 可选；未填写时，结果名称统一为“链上状态检查”，不得因缺少展示标签而使有效断言执行失败。

### 3.4 进度(WebSocket)
`WS /tasks/{id}/progress`
服务端校验任务归属后订阅 `tenant:{tenant_id}:judge:{task_id}:progress`,禁止使用旧式 `judge:{tenant_id}:{task_id}:progress` 主题。
浏览器客户端通过 M1 `POST /api/v1/auth/ws-ticket` 为该 WS path 换取短时 `ticket`,不得在 URL 中携带 access token。
推送:`{ "status": "judging", "message": "正在 judge 沙箱中执行测试" }`

## 6. 查重能力 `[内部]`

> M3 提供能力,M8 做作弊判定。
> `submission_fingerprint.sim_vector` 由 M3 在提交入队前读取 `code_storage_key` 指向的代码对象生成,不接受前端上传的相似度向量,避免伪造查重特征。
> 归档中的空源码文件合法，不贡献 token；不得使包含正常代码的整个项目无法提交。文件超限、损坏或读取失败仍拒绝处理。
> `threshold` 未指定或内部请求取零值时使用 `JUDGE_SIMILARITY_DEFAULT_THRESHOLD`；显式非零值必须严格大于 0、小于 1，拒绝 NaN、无穷及负数。默认值由部署配置进入 `platform/config`，不得在 M3 service 内写死。
> 相似度比较只读取同租户、同题目且属于调用方已授权 `source_refs` 集合的已存指纹，查询时同时应用 `exclude_source_ref`。空集合或未提供集合均返回空结果，不回退到全租户。提供 `code_hash` 时仅在该范围内选择基准，未找到返回 33001；否则使用范围内最新指纹。不接收或读取额外对象引用。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/internal/fingerprints/exact?problem_ref=&code_hash=` | 精确哈希查重(完全相同提交) |
| POST | `/internal/fingerprints/similarity` | 按题目及可选代码哈希选择已存指纹，返回达到阈值的相似提交 |

## 7. 典型时序(竞赛提交判题)

```
M8 → 内部 JudgeSubmitRequest(item_code/item_version+source_ref+code或answer, priority=高)
M3 → task_id, queued
前端 → WS /progress
M3 worker → 申请 judge 沙箱 → 注入 → 判定 → 销毁
M3 → status=done, 回写 result
M3 → 发布判题完成事件,M8 据此更新排行榜
```
