# M7 实验 — 数据模型

> PostgreSQL,全部租户级(tenant_id + RLS)。建模遵循:消灭数据冗余、表合并有度。
> 最后更新:2026-08-23

---

## 1. 表清单总览

| 表名 | 用途 |
| --- | --- |
| `experiment` | 实验定义(组件编排 + 说明 + 协作设置) |
| `experiment_instance` | 实验实例(一次做实验) |
| `experiment_group` | 多人协作小组 |
| `group_member` | 小组成员 + 角色 |
| `checkpoint_result` | 检查点判分结果 |
| `experiment_report` | 实验报告 |
| `experiment_event_outbox` | 实验绑定与得分事件的唯一事务 outbox，持久化事件主题、载荷、聚合编号和修订号，复用同一租约、重试及发布任务 |

> 消灭冗余/合并说明:
> - **组件编排(沙箱/仿真/检查点列表)以 JSONB 存进 `experiment.components`**,不为每类组件单建表——组件是配置而非独立实体,且引用的内容正本在 M5/M2/M4。
> - **实验模板内容不拷贝**:`experiment` 只存 M5 模板引用 + 课程内编排差异,题目/判题配置正本在 M5。
> - **单人实验无小组**:`experiment_group`/`group_member` 仅多人实验用;单人实例 `group_id` 为空,不强制建组。
> - **检查点定义在 components 里**,`checkpoint_result` 只存某实例某检查点的判分结果(引用 M3 判题任务),不重复存检查点定义。

## 2. 实验定义

### 2.1 experiment — 实验定义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| tenant_id | BIGINT | |
| course_id | BIGINT NULL | 所属课程(独立实验任务可空) |
| author_id | BIGINT | 教师 |
| template_ref | VARCHAR(96) NULL | M5 实验模板引用(锁版本) |
| template_version | VARCHAR(32) NULL | |
| name | VARCHAR(255) | |
| description | TEXT | 实验说明 |
| components | JSONB | 教师保存的声明经 M2 编译后的实验组件事实:环境保存完整 `SandboxCompositionSnapshot`、初始代码引用和生命周期参数,仿真(M4包+参数)/检查点(M3判题+分值)列表 |
| collab_mode | SMALLINT | 1单人 / 2小组 |
| group_config | JSONB NULL | 小组配置:组大小、角色定义 |
| require_report | BOOLEAN | 是否要求实验报告 |
| wizard_step | SMALLINT | 向导当前步骤(草稿自动保存/恢复) |
| status | SMALLINT | 1草稿 / 2已发布 / 3已下架 |
| created_at / updated_at | TIMESTAMPTZ | |

> `components` 是实验定义中唯一的组合来源,不再另存工具列表、兼容矩阵或部署 YAML。服务端成功编译后,持久化环境只保存完整 `composition_snapshot` 及其 `composition_digest`,不再把声明字段和编译闭包并列保存;教师不能填写或修改摘要。组件中环境/仿真/检查点的 ID 必须稳定且唯一(不按数组顺序派生,调整顺序不改变资源归属)。
> `components` 的请求契约(显式稳定 `id`、长度 1–64 小写字母数字连字符、envs/sims/checkpoints 结构、`infra`/`tools` 对象形式、`links` 与编译后只存 snapshot)见 `03-接口设计.md` §2.1(SSOT)。

分阶段时,每个环境/仿真组件必须且只能归属一个阶段;同一组件 ID 不能重复列入多个阶段。阶段创建的运行资源按该稳定 ID 归属,阶段间传递结果使用参数绑定;需要相同配置的独立资源时应建立不同 ID 的组件。不分阶段时全部组件同时启用。向导在阶段选择时标明其他阶段已占用的组件,进入下一步前校验完整分配,服务端继续执行相同的引用与唯一性校验。

### 4.3 experiment_event_outbox — 实验绑定与得分事件 outbox

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| tenant_id | BIGINT | |
| experiment_id | BIGINT | 实验定义 |
| aggregate_id | BIGINT | 得分事件为实例编号，来源事件为定义编号 |
| event_revision | BIGINT | 同主题同聚合的递增修订 |
| subject | VARCHAR(64) | 绑定或得分事件主题 |
| payload | JSONB | 与业务同事务固化的唯一载荷 |
| occurred_at | TIMESTAMPTZ | 原业务事件时间 |
| trace_id | VARCHAR(64) | 请求或后台任务追踪号 |
| status | SMALLINT | 1待发布/2发布中(持有租约)/3已发布/4发布失败(可重试或达到上限) |
| retry_count | INT | 发布尝试次数;达到 `ASYNC_OUTBOX_MAX_ATTEMPTS` 后不再自动领取 |
| last_error | TEXT NULL | 最近一次发布失败原因,仅供运维排查 |
| created_at / updated_at | TIMESTAMPTZ | |
| lease_token / lease_until | VARCHAR / TIMESTAMPTZ NULL | 发布 worker 的租约;ACK 只接受当前有效 token |

> 实验定义创建、草稿保存、发布或下架在同一 M7 事务写入 `experiment.course-source.changed`；绑定带课程、名称、可选状态、权威满分及单调 `source_revision`。定义更新时间使用数据库时钟与前一值加一微秒的较大值，防止等待行锁后倒退。实验完成、报告批改等得分落定时，同一实例锁内生成递增 `score_revision` 并写入同一 `experiment_event_outbox`，载荷包含课程绑定修订、实际成员、原始分与该实例满分。后台任务只发布已持久化载荷，不在重试时读取最新名称、绑定或成绩替换历史事件。M10 仍以原得分事件 ID 派生通知幂等键。

> 当前处于开发测试阶段，最终结构直接定义在原模块建表文件 `0006_teaching` 与 `0007_experiment`；不新增历史转换迁移，不保留旧得分 outbox、旧 worker 或旧配置别名。结构变更后按最终 schema 重建开发数据库并重新初始化，课程绑定与得分只走同一事务事件通道。

> 验收初始化的已完成实例以已有 `finished_at` 同时记录得分事件的 `occurred_at` 和载荷 `scored_at`，不引用实例表未定义的更新时间字段。初始化成功仍不代表真实判分流程通过。

## 5. 多租户与索引

- 全部表 `tenant_id` + RLS(同 M1),策略必须同时包含 `USING` 与 `WITH CHECK`,防止写入跨租户行。
- 关键索引:
  - `experiment(tenant_id, course_id, status)`、`experiment(author_id)`
  - `experiment_instance(tenant_id, experiment_id, owner_account_id)`、`experiment_instance(status, last_active_at)`(回收扫描)
  - `experiment_instance(tenant_id, source_ref)` UNIQUE
  - `experiment_instance(group_id)`
  - `group_member(group_id, student_id)` UNIQUE
  - `checkpoint_result(instance_id)`、`experiment_report(instance_id, student_id)`
  - `experiment_event_outbox(status, created_at)`
  - `experiment_event_outbox(tenant_id, subject, aggregate_id, event_revision)` 唯一
