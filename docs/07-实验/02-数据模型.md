# M7 实验 — 数据模型

> PostgreSQL,全部租户级(tenant_id + RLS)。建模遵循:消灭数据冗余、表合并有度。
> 最后更新:2026-08-23

---

## 1. 表清单总览

| 表名 | 用途 |
| --- | --- |
| `experiment` | 实验定义(组件编排 + 说明 + 协作设置) |
| `experiment_instance` | 实验实例(一次做实验) |
| `experiment_group` | 多人协作小组 |
| `group_member` | 小组成员 + 角色 |
| `checkpoint_result` | 检查点判分结果 |
| `experiment_report` | 实验报告 |
| `experiment_score_outbox` | 实验得分事件 outbox,用于可靠发布 `experiment.scored` |

> 消灭冗余/合并说明:
> - **组件编排(沙箱/仿真/检查点列表)以 JSONB 存进 `experiment.components`**,不为每类组件单建表——组件是配置而非独立实体,且引用的内容正本在 M5/M2/M4。
> - **实验模板内容不拷贝**:`experiment` 只存 M5 模板引用 + 课程内编排差异,题目/判题配置正本在 M5。
> - **单人实验无小组**:`experiment_group`/`group_member` 仅多人实验用;单人实例 `group_id` 为空,不强制建组。
> - **检查点定义在 components 里**,`checkpoint_result` 只存某实例某检查点的判分结果(引用 M3 判题任务),不重复存检查点定义。

## 2. 实验定义

### 2.1 experiment — 实验定义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| tenant_id | BIGINT | |
| course_id | BIGINT NULL | 所属课程(独立实验任务可空) |
| author_id | BIGINT | 教师 |
| template_ref | VARCHAR(96) NULL | M5 实验模板引用(锁版本) |
| template_version | VARCHAR(32) NULL | |
| name | VARCHAR(255) | |
| description | TEXT | 实验说明 |
| components | JSONB | 教师保存的声明经 M2 编译后的实验组件事实:环境保存完整 `SandboxCompositionSnapshot`、初始代码引用和生命周期参数,仿真(M4包+参数)/检查点(M3判题+分值)列表 |
| collab_mode | SMALLINT | 1单人 / 2小组 |
| group_config | JSONB NULL | 小组配置:组大小、角色定义 |
| require_report | BOOLEAN | 是否要求实验报告 |
| wizard_step | SMALLINT | 向导当前步骤(草稿自动保存/恢复) |
| status | SMALLINT | 1草稿 / 2已发布 / 3已下架 |
| created_at / updated_at | TIMESTAMPTZ | |

> `components` 中的环境、仿真、检查点组件都必须提供显式稳定 `id`,长度 1–64,仅允许小写字母、数字和连字符。环境与仿真组件 ID 在同一实验内全局唯一;阶段、检查点和参数绑定只能引用已声明的 ID。组件 ID 不得根据数组顺序派生,调整组件顺序不得改变资源归属。
>
> `components` 请求结构(最终契约;旧的 `runtime_code`+`tools` 平面结构不再接受):
> ```json
> { "envs": [{ "id": "env-hardhat", "runtimes": [{ "instance_code": "source-chain", "runtime_code": "evm-hardhat", "image_version": "sha256-<digest-prefix>" }], "infra": [{ "code": "postgres-graph", "selection": "auto" }], "tools": [{ "code": "code-server", "params": {} }], "links": [], "access_profile": "experiment", "init_code_ref": "..." }],
>   "sims": [{ "id": "sim-pow-mining", "package_code": "builtin__pow-mining", "version": "1.0.0", "params": {...} }],
>   "checkpoints": [{ "id":"cp1", "judger":"testcase", "item_code":"prob-2031", "item_version":"1.0.0", "score":40 }] }
> ```

环境请求中的 `infra` 和 `tools` 必须使用对象形式,保存选择来源(`explicit` 或 `auto`)及经 `config_schema` 校验的参数;`links` 保存源/目标组件与端点、协议、启动前置、访问范围和配置绑定。服务端成功编译后,持久化环境只保存完整 `composition_snapshot` 及其 `composition_digest`,不再把声明字段和编译闭包并列保存。教师不能填写或修改摘要。`components` 是实验定义中唯一的组合来源,不再另存工具列表、兼容矩阵或部署 YAML。

### 3.2 group_member — 组成员

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| tenant_id | BIGINT | |
| group_id | BIGINT | |
| student_id | BIGINT | |
| role | VARCHAR(64) | 扮演角色(如某机构/某节点/攻方/守方) |

唯一约束:`(group_id, student_id)`。

成员由 M7 的加入/改角色/移除接口维护;移除不是软删除,删除前必须按小组行锁收回活跃实例授权,避免已离组账号继续访问共享沙箱或仿真会话。当前共享实例的 `owner_account_id` 在实例结束并回收前不可移除,因为 M2/M4 始终保留 owner 权限。

### 4.3 experiment_score_outbox — 实验得分事件 outbox

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| tenant_id | BIGINT | |
| instance_id | BIGINT | 实验实例 |
| student_id | BIGINT | 得分归属学生 |
| score | NUMERIC(5,2) | 本次发布的实验得分 |
| score_revision | INT | 实例得分修订号;同一实例同一修订只允许一条 outbox |
| trace_id | VARCHAR(64) | 请求或后台任务追踪号 |
| status | SMALLINT | 1待发布/2发布中(持有租约)/3已发布/4发布失败(可重试或达到上限) |
| retry_count | INT | 发布尝试次数;达到 `ASYNC_OUTBOX_MAX_ATTEMPTS` 后不再自动领取 |
| last_error | TEXT NULL | 最近一次发布失败原因,仅供运维排查 |
| created_at / updated_at | TIMESTAMPTZ | |
| lease_token / lease_until | VARCHAR / TIMESTAMPTZ NULL | 发布 worker 的租约;ACK 只接受当前有效 token |

> 实验完成、报告批改等写入最终得分时,必须在同一 M7 事务内写入 `experiment_score_outbox`。后台任务领取 outbox 后发布带 `event_id=outbox.id` 的 `experiment.scored`,失败只回写 outbox 状态并重试,不得把事务后的即时事件发布作为唯一投递路径。M10 消费该事件并以同一 outbox 雪花 ID 派生通知幂等键;M7 不在同一 outbox 内再发布第二个通知主题。

## 5. 多租户与索引

- 全部表 `tenant_id` + RLS(同 M1),策略必须同时包含 `USING` 与 `WITH CHECK`,防止写入跨租户行。
- 关键索引:
  - `experiment(tenant_id, course_id, status)`、`experiment(author_id)`
  - `experiment_instance(tenant_id, experiment_id, owner_account_id)`、`experiment_instance(status, last_active_at)`(回收扫描)
  - `experiment_instance(tenant_id, source_ref)` UNIQUE
  - `experiment_instance(group_id)`
  - `group_member(group_id, student_id)` UNIQUE
  - `checkpoint_result(instance_id)`、`experiment_report(instance_id, student_id)`
  - `experiment_score_outbox(tenant_id, status, created_at)`
  - `experiment_score_outbox(tenant_id, instance_id, student_id)`
