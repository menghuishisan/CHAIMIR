# M7 实验 — 接口设计

> RESTful。鉴权沿用 M1 JWT。M7 编排引擎,内部调用 M2/M3/M4/M5。
> 最后更新:2026-11-27

---

## 1. 通用约定

- Base:`/api/v1/experiment`
- 学生列表与详情页一次只处理一个进入请求；请求期间保留当前加载提示、阻止重复或切换目标提交，失败后展示原因并允许重试。该限制不替代服务端实例创建幂等与小组归属校验。
- 统一响应体同 M1。错误码段:`7xxxx`(71xxx 实验定义/72xxx 实例/73xxx 协作/74xxx 结果)。其中 `73005` 表示协作小组人数已满,`73006` 表示当前共享实例发起人暂不能移除,`74007` 表示实验要求先提交报告才能完成,`74008` 表示已触发的检查点仍在判分,不得复用同段通用错误码动态改文案。

## 2. 实验配置 `[教师]`

课程克隆通过仅供 M6 的 `ExperimentCloneService` 准备独立草稿，不开放跨校详情或新 HTTP 接口。复制来源课程的全部实验与课时引用的来源教师未绑定实验，重绑目标课程和教师；不复制实例、小组、提交或成绩。M5 本地化模板和检查点版本，M2 复制初始化素材并登记保持原镜像闭包的冻结快照，M4 校验原包精确版本。检查点输入、仿真参数与阶段常量中的对象由 M7 复制至目标租户独占前缀；只允许来源租户代码/附件和平台素材，按既有附件大小限制校验，并在批次内去重。所有目标记录、引用、事件 outbox 和审计随课程事务提交，失败只补偿本次对象。

环境声明的 `init_chain_steps` 与工作区运行时实例均随草稿读取、编辑保存和 M2 编译完整保留。初始化步骤只存于冻结组合，不维护第二份字段；首次启动及恢复行为遵守 M2 初始化契约。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/experiments?course_id=&status=&keyword=` | 实验列表;`keyword`按名称或说明检索 |
| GET | `/experiments/{id}` | 读取本人实验定义；校管可读本租户定义，含可编辑声明及只读冻结摘要 |
| POST | `/experiments` | 创建实验(可基于 M5 模板) |
| PATCH | `/experiments/{id}` | 编辑组件编排 |
| POST | `/experiments/{id}/validate` | 发布前校验(依赖完整性/M5 锁定版本/分值合理) |
| POST | `/experiments/{id}/publish` | 发布 |
| POST | `/experiments/{id}/unpublish` | 下架 |

实验创建、编辑、发布和下架与 M1 审计及课程绑定事件在同一租户事务提交。发布前的依赖校验和镜像预拉取在事务外执行；正式提交先按已校验版本更新状态，再经 M5 现有引用契约在同一普通租户事务登记模板和检查点，随后写事件与审计。版本已变、引用登记、事件、审计或提交失败时，定义与引用一起回滚；成功响应只在提交后返回。预拉取的镜像缓存不属于业务写入，无需因业务回滚删除。

预验证和发布使用同一依赖检查：每个仿真组件由 M4 按锁定编号、版本检查可运行状态；每个检查点除 M5 题面外，还经 M3 `GetJudgeInputRequirements` 校验题目实际判题配置、判题器和执行模式。任一失败都形成阻断项，不能仅凭服务已装配或题面可读取而发布；检查过程不创建仿真会话、判题任务或容器。

检查点只锁定题目编号与版本，不重复选择或保存判题方式。M3 统一使用该题目在 M5 固化的判题配置，编排仅配置检查点名称、分值、组件绑定和执行模式；题目校验与正式提交使用同一配置来源。

创建和编辑实验时,`components.envs[]`、`components.sims[]`、`components.checkpoints[]` 必须提交显式稳定 `id`;环境与仿真组件 ID 在同一实验内全局唯一,阶段与参数绑定按该 ID 引用。ID 使用 1–64 位小写 ASCII 字母、数字或连字符,首尾必须是字母或数字,例如 `attack-node`;这是机器引用键,不是面向学生显示的组件名称。环境请求只提交声明式组合,服务端编译后在现有 `experiment.components` JSONB 中保存完整 `SandboxCompositionSnapshot`;实例启动、阶段激活、恢复和发布校验只消费该快照,不按当前目录重新编译或用 digest 重拼快照。服务端拒绝空 ID、重复 ID、非法格式和悬空引用,不会按数组顺序生成或补齐 ID。

`stages[].param_bindings[]` 的目标必须是该阶段启用的仿真组件,环境组件或其他阶段的仿真组件不能作为目标;这样每条绑定都能在阶段激活时被实际应用。`constant_value` 是 JSON 值并保留其类型,例如数值 `120`、字符串 `"120"`、布尔值 `true` 是不同输入;教师界面按 JSON 语法录入,检查点来源则使用已持久化的绑定输出。

`components.stages[]` 使用 `{stage,title,description,components:{envs:[id],sims:[id]},unlock_condition,param_bindings:[]}`。`stage`为不重复的正整数，`title`必填且最长128，每阶段至少含一个环境或仿真。`unlock_condition` 可省略，或为 `{type:"manual"}`、`{type:"checkpoint",checkpoint_id,min_score}`；检查点必须存在，最低分非负。参数绑定使用 `{target_component,target_param,source_type,source_ref,source_path,constant_value}`；`source_type` 仅 `constant/checkpoint`，检查点来源须存在。学生投影保留阶段、名称、组件及解锁条件，剔除参数注入规则。

检查点分值必须为大于 0 的有限数字；解锁所需的最低得分可省略，填写时必须为非负有限数字。参数固定值必须能解析为合法 JSON，保持解析后的类型。

校验响应示例:
```json
{ "ok": false, "issues": [
  { "level": "error", "message": "运行时 evm-hardhat 不可用" },
  { "level": "warning", "message": "检查点分值合计 90,非 100" } ] }
```

向导草稿的 `wizard_step` 固定为1–4，分别对应基础信息、环境与仿真、实验阶段、检查点；数据库和请求校验使用同一范围。

### 2.1 组件编排请求结构

`POST /experiments` 与 `PATCH /experiments/{id}` 的 `components` 请求体为最终契约(旧的 `runtime_code`+`tools` 平面结构不再接受):

```json
{ "envs": [{ "id": "env-hardhat", "runtimes": [{ "instance_code": "source-chain", "runtime_code": "evm-hardhat", "image_version": "sha256-<digest-prefix>" }], "workspace_runtime_instance": "source-chain", "infra": [], "tools": [{ "code": "code-server", "selection": "explicit", "params": {} }], "links": [], "access_profile": "experiment", "init_code_ref": "..." }],
  "sims": [{ "id": "sim-pow", "package_code": "builtin__pow-longest-chain", "version": "1.0.0", "seed": 42, "params": {} }],
  "checkpoints": [{ "id":"cp1", "item_code":"prob-2031", "item_version":"1.0.0", "score":40 }] }
```

环境请求中的 `infra` 和 `tools` 必须使用对象形式,请求仅保存显式选择(`selection=explicit`)及经 `config_schema` 校验的参数；编译快照另标记推导出的 `auto` 支撑组件;`links` 保存源/目标组件与端点、协议、启动前置、访问范围和配置绑定。服务端成功编译后,只持久化完整 `composition_snapshot` 及其 `composition_digest`,不再把声明字段和编译闭包并列保存。教师读取草稿时返回可编辑声明，包括 `resource_profile`、`network_profile`，以及只读的 `composition_digest`。学生视图只返回工作台所需字段。

教师新增或修改环境前通过M2连接预览选择目标,只有当前声明预览成功且必需连接完整时才能加入环境并保存草稿。请求中的组件选择来源必须为`explicit`,自动支撑组件由同一M2编译器重新展开,不把旧快照的`auto`项冒充教师输入。预览不代替PATCH成功;保存失败保留未同步编辑态和明确错误,不得显示为已保存。成功后离开重开从服务端快照恢复连接和配置。

仿真场景种子必须显式填写正安全整数，不以默认值替代空白或非法输入；版本必须属于所选场景。环境保存仍受连接预览约束，保留和快照时长按各自开关校验。

## 3. 实验实例 `[学生]`

### 3.0 学生可见实验

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/student/experiments?course_id=&keyword=&page=&size=` | 学生可做实验分页列表;`keyword`按名称或说明检索;开始过的实验带本人进度 `my_progress{status,score,passed_checkpoints}` |
| GET | `/student/experiments/{id}` | 单个已发布实验的学生视图 |

两条接口共用同一学生投影(剔除 `init_code_ref`/`init_script_ref`/`judger_code`/`extra_input`,受 `student_access_test.go` 守护)并共用「实验已发布」门槛。每个检查点还返回对应 M5 已发布题面的安全 `face` 正文,用于展示题面、提交约束、公开验收条件和公开材料;服务端不得把 `composition`、初始化引用、判题配置或答案字段放进该学生投影。单读只是同一投影的单条形态,不新增权限范围。单读的存在理由是前端实验详情页必须支持深链与刷新恢复,且沉浸式工作台退出后回落到该页,不能依赖列表态在内存中的残留。

### 3.1 发起实例
`POST /experiments/{id}/instances`
请求:`{ "group_id": null }`(小组实验传组 id)
流程:M7 在事务内按协作模式查询活跃实例;命中则直接返回,未命中才读 components → 调 M2 起沙箱 + 调 M4 起仿真 → 返回实例。单人按 `owner_account_id` 幂等,小组按 `group_id` 幂等,活跃实例状态为 creating/running/paused/released；error 可从已有工作台恢复，补偿失败时可能保留待清理资源。创建小组资源时,M7 必须把当前 `group_member.student_id` 全量投影为 M2/M4 `authorized_account_ids`;两引擎去重并剔除 owner 后分别保存到原有实例表的 `shared_account_ids`,不反向读取 M7 表。

创建互斥键与上述查询使用同一主体：租户、实验及单人账号，或租户、实验及小组；小组键不包含点击者账号。同组不同成员并发发起时，检查与首次实例落库共用同一事务锁。只有该事务新建实例的请求继续编排引擎资源；命中已有 `creating` 也只返回原实例与当前进度，不重复起沙箱、仿真或创建审计。失败实例的恢复仍走既有 `resume` 生命周期入口。

共享实例首次受理还须锁住小组行，使成员校验和 `creating` 记录与移除成员串行；创建审计随该记录提交，失败不开始引擎编排。首次完成将审计、检查点终态、得分及事件 outbox 一次提交；回收重试不重复审计或结算。编组写响应的成员档案在提交前读取，失败整体回滚。
响应:`{ "instance_id": "8001", "status": 1 }`（`1` 表示准备中）。

学生视图 `GET /student/experiments` 的 `my_progress` 是本人在该实验里最近一次实验的实例状态、得分与已通过的检查点数(小组实验看本人所在小组的实验),与列表同页一次聚合;从没开始过的实验不带该字段,页面写「还没开始」。教师的实例列表 `/instances` 仍只对教师开放,学生不经它读别人的实例。

学生视图 `GET /student/experiments` 返回的每条实验含 `my_group_id`(学生在本实验所属小组;单人实验或尚未分组时省略),由后端按 `group_member`⋈`experiment_group` 批量解析,前端据此在发起小组实例时携带 `group_id`,`my_group_id` 为空则提示"等待教师分组"、不发起请求。学生无独立小组发现接口,`my_group_id` 是学生获取自身 `group_id` 的唯一来源。

授权边界:
- M7 校验同租户、实验已发布、小组实验的成员关系、实例归属。
- 课程/课时是否授予学生由 M6 教学入口负责;M7 不直接依赖同层 M6,避免违反工程目录设计的同层禁止互依赖规则。
- 教师调整成员时对小组行加锁;M7 先尝试让全部活跃沙箱和仿真会话回到 owner-only,再同步最新成员集合。任一跨模块清空或授予失败都不提交成员事务,已成功收回的资源保持 owner-only,其余资源由重试继续收敛;成功后 M2 关闭被移除成员的终端/进度连接,M4 关闭其仿真流。

### 3.2 实例工作台
`GET /instances/{id}`
响应:沙箱工具接入地址(M2)、仿真会话(M4)、实验说明、公开检查点题面、检查点状态、得分。

检查点定义由实验题面的 `components.checkpoints` 提供，实例 `checkpoints` 只返回真实判分记录。创建、读取和阶段激活均不为尚未判过的检查点补造零分结果；前端用定义展示全部检查点，缺少结果显示待判，不解释为未通过。

教师实例监控 `GET /instances?status=&page=&size=` 支持 `creating/running/paused/error/released` 状态筛选;`error` 用于查看环境创建或运行失败的实例，不能据此判断资源已清理。M2 阶段一异步启动失败发布 `sandbox.failed`,M7 通过 `source_ref` 对账实例并补偿回收本次 `scope_ref` 资源后落入 `error`;事件尚未到达时,实例读取和教师监控也会按 M2 权威状态完成同一对账,不把失败环境继续显示为准备中。

失败补偿仅回收原快照的运行作用域；补偿完成后，在实例锁内复核该 `scope_ref` 与当前状态。期间已重建、完成或释放的实例保持当前状态，旧失败不得覆盖新环境；加锁读取或状态写入失败显式返回。
```json
{ "instance_id": "8001", "experiment_id": "7001", "status": 2,
  "sandboxes": [{ "component_id":"env-hardhat", "stage":1, "sandbox_id":"9001", "runtime_code":"evm-hardhat", "tools": [{ "code":"code-server","endpoint":"..." }] }],
  "sims": [{ "component_id":"sim-pow", "stage":2, "session_id":"7001", "package_code":"builtin__pow-longest-chain", "version":"1.0.0", "compute":"browser" }],
  "checkpoints": [{ "id":"cp1", "passed": false }] }
```

### 3.3 进度
`GET /instances/{id}/progress`:返回实例进度订阅元信息,如 `topic=tenant:{tenant_id}:experiment:{id}:progress`。

`GET /instances` `[教师/学校管理员]`:教师实时监控活跃实例。普通教师只返回本人创建实验下的
`creating/running/paused/error/released` 实例,学校管理员返回本租户同范围实例；可按 `status` 过滤并分页。
该接口只读实验模块自有表,不通过课程列表反推实例,列表与总数必须使用同一筛选口径。

- 业务实时广播统一走 M10 `WS /api/ws` 订阅 topic,不由 M7 私建 WebSocket Hub。
- M7 返回实例进度 topic 元信息。M10 的 experiment/progress 订阅经 M7 只读契约复核同一租户及当前拥有者或小组成员；没有契约、跨租户或成员被移除时拒绝订阅。
- M7 在实例状态、阶段资源、检查点绑定及终态结果、报告和报告评分成功提交后发布统一 `notify.push.requested`，主题为 `tenant:{tenant_id}:experiment:{instance_id}:progress`，负载仅为 `{ "type": "instance.changed" }`。过期判题结果、无变化分支及事务失败不发送。M10 只转发刷新信号，工作台经原授权接口重新读取，不从推送恢复业务状态。
- 刷新提示为瞬时消息，发布失败记日志，不撤销已提交业务或将其返回为失败；重新进入和手动刷新仍读取权威记录。订阅后撤销成员收到的提示不含实例数据，后续读取由 M7 重新鉴权；不为刷新提示新增持久化表、修订或重投路径。

### 3.4 控制
- `POST /instances/{id}/pause` / `resume`
- 暂停仅适用于 `running` 实例;前端须依据实例当前状态和 M2 沙箱实时状态展示操作入口,不能用实例中持久化的工具接入摘要判断沙箱生命周期。检查点判分仅适用于 `running` 或 `paused` 实例;实例引用了 M2 沙箱时,其当前阶段沙箱必须处于可进入状态,否则前端不得开放判分操作。服务端仍通过 M2 保存当前工作区并由 M2 校验沙箱归属/可执行性,前端门禁不替代服务端校验。
- `resume` 同时用于 `paused`、`released` 和启动任一阶段失败后的 `error` 实例;错误实例只有在本次作用域资源补偿回收成功后才允许按同一 `source_ref` 生成新 `scope_ref` 重建,避免重复占用或复用失败沙箱。已持久化公开代码与实验进度保留，初始化失败不自动重试私有脚本。
- 暂停与恢复的引擎调用在事务外执行；完成后锁实例，复核原状态、运行代次与当前访问权限，变化则拒绝旧操作。重建的新作用域、资源引用和运行状态一次提交，响应返回新引用；落库失败只补偿本次新作用域，并保留补偿错误。创建中的实例不得通过恢复接口提前进入运行态。
- 释放态与错误态重建前均清理旧作用域，避免 M2 已释放而 M4 会话仍存活；没有沙箱引用时不读取工作区归档，纯仿真实验不依赖 M2 文件能力。清理统一尝试 M2 和 M4，两边错误合并返回 `72007`，任一失败均不得创建新代次或落为已回收。
- `POST /instances/{id}/stages/{stage}/activate`:显式激活已解锁阶段。该接口是阶段资源创建的唯一写入口;`GET /instances/{id}` 只读返回阶段状态,检查点判分和判题事件回调只更新 `checkpoint_result`,不得隐式创建后续阶段沙箱或仿真会话。
- 只有进行中的实例可以创建尚未激活的阶段资源。已暂停实例尝试激活新阶段时返回状态冲突，学生须先通过 `resume` 恢复全部现有沙箱；已绑定阶段的读取保持暂停态，不改变实例生命周期。
- 检查点解锁仅接受 M3 当前任务的完成态和当前得分；最低分为 0 也不放行排队、执行、失败或取消任务。读取和激活共用当前结果投影，参数绑定使用同一投影。阶段资源绑定前须在实例锁内复核运行代次、解锁条件和绑定参数；变化或读取失败时补偿释放本次资源，不挂入实例。
- 新增资源补偿、重复阶段资源清理与实例作用域回收在事务外执行，保留身份、追踪与资源归属，独立于请求取消或超时；M2/M4 共用 `EXPERIMENT_CLEANUP_TIMEOUT_SECONDS` 限制整次清理，任一清理失败仍尝试另一引擎并合并错误。该配置同时约束检查点绑定失败后的任务取消，替换原判题取消专用配置，不保留旧键。
- `POST /instances/{id}/finish`:完成前先确认所有已触发检查点均已进入 M3 终态;仍在排队或判分时返回 `74008`,不会固化不完整得分。得分落定后按本次 `scope_ref` 通知 M2/M4 释放资源,并以稳定 `source_ref` 校验归属。得分事务一旦提交,后续重复调用必须只续跑资源回收并返回同一实例终态,不得重复汇总得分或重复生成 `experiment.scored` outbox;实例已回收时直接幂等返回成功。
- 首次结算在实例锁内读取当前 M3 结果，完成态按配置分值归一，失败或取消撤回旧结果；这些检查点结果、报告汇总、实例得分与 outbox 同事务提交，读取或写入失败整体回滚，不能等待异步事件修正已固化的缓存分数。

**没有手动回收接口。** 引擎资源的释放有三条自动路径,都不需要用户按一个不可逆的销毁按钮:

| 触发 | 路径 |
| --- | --- |
| 学生完成实验 | `finish` 内部在得分落定后回收(`reason=finished`) |
| 暂停超时 / 空闲超时 | 后台 `RunRecycleOnce` 扫描认领并回收(`reason=lifecycle_recycle`) |
| 课程结束或归档 | M6 在手动/自动结束或归档时持久化回收请求，由后台可靠发送 `teaching.course.ended`；M7 幂等回收课内仍占资源的实例，失败由事件重投(`reason=course_ended`,需求 D3) |

若 `finish` 在得分已落库后因引擎暂时不可用而返回失败,M2 的可靠 `sandbox.recycled` 事件和学生后续重试都必须继续同一条回收流程。事件处理只有在实例引用的全部 M2 沙箱都为已销毁态后才可继续回收 M4 并把实例推进到已回收,不得以单个组件完成代替整实例回收完成。

完成、定时扫描、课程结束和完成态事件补偿共用同一回收落库入口。引擎调用后锁实例，核对状态、运行作用域和两类资源引用；期间已暂停、完成其他阶段、重建或新增资源时返回状态冲突，保留当前实例供重试，不把未回收的新资源标成已回收。同代已回收则幂等返回；期间结算或修订的得分保持当前值。扫描认领只更新时间，不代替最终行锁复核。

课程结束扫描全部尚未进入 `recycled` 的实例，包括仍待清理的 `finished` 和 `error`；结果保留，不能以业务完成或失败代替资源释放。

`sandbox.recycled` 必须先确认事件的 `sandbox_id` 仍属于当前实例的资源引用；稳定 `source_ref` 仅用于定位实例，不能据此把旧运行代次的迟到事件应用到新环境。创建中、进行中和已暂停实例的环境释放对账均在当前实例行锁内重新读取全部沙箱权威状态，全部销毁后才进入 `released`。进入入口的旧快照同样必须在行锁内核对当前 `scope_ref` 和状态，不能覆盖已经完成、回收或重建的实例；依赖读取失败显式返回，供可靠事件重投。

## 4. 检查点判分 `[学生/系统]`

`POST /instances/{id}/checkpoints/{cp}/judge`
流程:M7 → M3内部提交契约(带M5题目引用及当前输入) → M3判分 → 回写checkpoint_result。
请求体可省略或为 `{code_storage_key?,code_hash?,extra_input?,binding_output?}`。有绑定现场沙箱的代码判题以M2保存的权威快照为准；无现场沙箱时显式代码引用与SHA256必须成对满足M3要求。`extra_input`为当前非代码判题输入，合并规则由锁定检查点配置约束；`binding_output`为后续阶段需要的小型JSON对象，不作标准答案。
检查点声明 `env_id` 时,当前工作区快照和 M3 复用目标必须指向该 `component_id` 对应的实例沙箱;指定环境尚未激活或引用缺失时必须拒绝,不得静默改用其他环境。未绑定环境的检查点沿用整体产出语义。

工作台与检查点按钮统一按 M2 当前 `phase=2/4` 且 `status=ready/running/idle` 开放操作。共享工作台在就绪、失效及状态读取失败时通知业务页面当前可操作性,不缓存一次就绪结论。判分先写入编辑器当前修改,再由 M7 固化对应检查点环境的权威快照;页面不在环境就绪时额外归档或维护重复的代码引用。退出、切换环境/阶段、打开仿真、暂停和完成前先写入并归档当前工作区;失败或保存期间有新编辑则停止后续动作,保留编辑。没有现场沙箱时接口的显式代码引用能力不变。沙箱状态读取仅接受当前环境的最新请求。
请求可带 `binding_output` JSON 对象,用于后续阶段 `param_bindings` 的参数来源。后端只接受小型对象并持久化到 `checkpoint_result.binding_output`;判题完成事件回写得分时不得覆盖已有绑定输出。

M7 在准备输入前通过 M3 `GetJudgeInputRequirements` 确认锁定题目与模式的要求。代码判题从绑定工作区保存快照，无现场沙箱时要求显式代码引用。非代码判题不保存代码归档。复用现场时提交目标沙箱引用和实验实例的稳定来源，用于校验归属。显式环境绑定缺失或能力查询失败时停止操作。

每次学生判分生成独立的 `experiment:<year>:judge:<instance_id>-<submission_id>-<checkpoint_id>`，同一检查点再次判分、不同检查点引用同一题目均创建新任务。代码归档与 M3 提交在 M7 事务外执行；绑定时锁实例并复核运行代次和状态，以提交 ID 比较写入当前检查点，较早提交不能覆盖较新提交。回调按来源定位实例与检查点，锁内核对提交 ID 和任务绑定；先于绑定的事件返回错误供重投，已被替代的事件直接确认。绑定失败后，在 M7 事务外尝试取消该次任务；清理保留身份与追踪信息，独立于请求取消，受 `EXPERIMENT_CLEANUP_TIMEOUT_SECONDS` 限制。取消仅适用于 M3 仍排队的任务，失败保留绑定与清理两段错误链，不承诺强停执行中的任务。教师历史复核继续使用原输入重判。
小组判分绑定先锁小组，再锁实例，并按最新成员重新鉴权；成员调整使用同一小组锁。准备输入期间已被移除的成员不得写入检查点，成员读取或加锁失败同样停止绑定并尝试取消任务。个人实例沿用拥有者检查，实例读取与提交复用同一权限规则。
判分、实例读取和阶段激活响应中的检查点带 `judge_status`，使用 M3 任务状态值：1 排队、2 执行、3 完成、4 执行失败、5 取消。状态与当前分数从 M3 读取投影，不在 M7 新存状态；只有完成态使用任务结果，排队或执行不得展示成答错，执行失败与取消分别提示重试。原结果尚未回写时也不展示旧分数。前端刷新后仍按该状态显示，不能只靠按钮点击期间的内存状态。
响应示例:`{ "id": "cp", "judge_task_ref": "...", "judge_status": 1, "passed": false, "score": 0, "binding_output": { ... } }`。

## 5. 实验报告 `[学生/教师]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/instances/{id}/report` `[学生]` | `multipart/form-data`,字段 `file`;上传并提交 PDF、Markdown 或纯文本报告 |
| GET | `/instances/{id}/report` `[学生]` | 读取本人报告的提交/批改结果;只返回安全结果投影,不返回对象存储引用 |
| GET | `/experiments/{id}/reports` `[教师]` | 报告列表,支持 `status` 筛选(省略或 0 表示不筛),筛选与 `total` 同口径 |
| POST | `/reports/{id}/access` `[教师]` | 校验实验管理权限后签发报告文件的一次性下载授权 |
| POST | `/reports/{id}/grade` `[教师]` | 批改报告(必填分数+评语);分数为 0 到 100,显式 0 分合法 |

已完成或已回收实例的报告批改，与首次完成共用当前检查点结算规则：在实例锁内读取 M3 当前终态，更新检查点后汇总报告和实例得分，再写得分 outbox，整段同事务提交。判分仍在排队或执行时返回 `74008` 供稍后重试；读取或落库失败回滚本次批改，不重新发布缓存旧分。进行中实例只保存报告批改，完成时再统一结算。

报告提交和批改的 M1 审计、响应所需账号资料读取均在业务事务内完成，任一步失败均回滚；提交成功后不再做可能改变响应成败的补查。批改取得实例锁后重读当前报告，避免把等待锁之前的提交状态用于本次结算。事务提交后仅尽快投递已持久化事件、清理被替换的对象，失败记录日志并保留原有重试方式。

重新提交保留报告编号，清空原评分和评语，提交时间使用数据库时钟并严格递增。待批改响应省略 `manual_score` 和 `comment`；已批改时返回实际分数，包括合法零分。已完成实例重交时，同一实例锁内撤销旧报告分、生成 `pending=true` 的成绩修订与 outbox；即使原评分为零，也必须通知课程侧恢复待批改。批改表单按报告编号与提交时间恢复当前提交，不能沿用上一份报告的评分输入。

批改请求为 `{ manual_score, comment, submitted_at }`，`submitted_at` 必须原样携带当前报告响应中的时间，不经浏览器日期格式化。服务端完成管理权限校验后，在实例锁内比较该时间与最新提交；不匹配返回 `11006` 并提示刷新、重新审阅，不写评分、审计或成绩事件。缺失或非法时间拒绝提交，不接受未绑定具体提交的批改。

报告提交接口不接受客户端传入 `content_ref`:M7 先校验当前学生对实例的访问权,再复用统一文件服务完成
大小、扩展名、声明 MIME、内容签名和病毒扫描校验,最后写入报告桶并保存服务端生成的对象引用。对象 key 固定为
`{tenant_id}/experiment/report/{instance_id}/{student_id}/report-{upload_id}.{ext}`;单文件上限由
`UPLOAD_EXPERIMENT_REPORT_MAX_BYTES` 配置。只在尚未尝试提交引用时限时补偿本次新对象；提交结果不明则保留，避免删除可能已引用的报告。替换成功提交后清理旧对象，清理规则见安全设计 §7。客户端不能构造对象 key,也不能提交跨实例、跨学生或路径穿越引用。
教师读取报告必须先走 `/reports/{id}/access` 换取与当前账号、租户、实例和对象引用绑定的一次性授权,
再由统一文件服务投放;所有报告响应均省略对象存储引用。

## 6. 多人协作 `[教师/学生]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/experiments/{id}/groups` `[教师]` | 创建分组 |
| GET | `/experiments/{id}/groups` `[教师]` | 本实验分组列表(含各组成员与角色) |
| POST | `/groups/{id}/members` | 加入成员 + 分配角色 |
| DELETE | `/groups/{id}/members/{student_id}` `[教师]` | 移除成员并立即收回其资源权限 |
| GET | `/groups/{id}` | 组信息(成员/角色/共享实例) |

> 小组实验:同组成员访问同一实例的共享沙箱;各自有角色入口;通过链上状态交互。

分组列表与 `GET /groups/{id}` 的关系:后者按小组编号读单组并附带共享实例,是学生进入协作实验的入口;
前者是**教师编组视角**,一次返回本实验全部分组及成员角色,不附带实例(编组时实例尚不存在)。
教师通过分组列表重新定位小组并管理成员。分组归属经 `ensureTeacherCanManage`
校验(实验作者或学校管理员),成员一次性按实验批量取回,不逐组调用避免 N+1。

删除成员与加入/改角色使用同一条小组行锁流程:先把活跃实例的 M2 沙箱和 M4 仿真会话授权收回到 owner-only,再删除成员并按剩余成员集合重新授权。当前共享实例的 `owner_account_id` 不能被移除,因为 M2/M4 合同必须始终保留 owner 权限;需要先结束并回收该实例。跨模块同步失败时事务不提交,已成功收回的资源保持 owner-only,后续重试继续收敛。

小组成员与实验报告的响应都带 `student_name`/`student_no`:`group_member`、`experiment_report`
只存 `student_id`,而编组与批改界面必须显示人名,故由 M7 经
`contracts.IdentityService.BatchGetAccounts` 一次批量解析后随响应下发 ——
让客户端自己再拉一份账号目录既越权(那是学校管理员能力)也会 N+1。
教师端挑选待入组学生走 M1 `GET /org/classes/{id}/students`(教师只读,只出编号/姓名/学号)。

## 7. 结果读取与聚合 `[内部]`

`GET /internal/instances/{id}/score` `[内部]`

- 租户边界来自服务间签名头 `X-Chaimir-Tenant-Id`,不得用查询参数覆盖。

`GET /internal/stats?course_id=` `[内部]`
- 供 M9 看板聚合:实验数、活跃实例数等只读统计;租户边界来自服务间签名头 `X-Chaimir-Tenant-Id`。

## 8. 典型时序(学生做混合实验)

```
学生 → POST /experiments/{id}/instances
M7 → 读 components → 调 M2 起沙箱(运行时+工具)→ 调 M4 起仿真
M7 → instance(creating);WS 转发 M2 启动进度
环境就绪 → 学生在工作台:沙箱写合约/部署、仿真注入操作
学生 → 触发检查点 → M7 调 M3 判(取 M5 配置)→ 回写结果
学生 → 提交报告 → finish
M7 → 汇总得分 → 发布 experiment.scored → 后续成绩流程按事件或上层编排消费
完成 → M7 调 M2/M4 回收
```
