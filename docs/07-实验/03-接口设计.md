# M7 实验 — 接口设计

> RESTful。鉴权沿用 M1 JWT。M7 编排引擎,内部调用 M2/M3/M4/M5。
> 最后更新:2026-08-05

---

## 1. 通用约定

- Base:`/api/v1/experiment`
- 统一响应体同 M1。错误码段:`7xxxx`(71xxx 实验定义/72xxx 实例/73xxx 协作/74xxx 结果)。其中 `73005` 表示协作小组人数已满,`73006` 表示当前共享实例发起人暂不能移除,`74007` 表示实验要求先提交报告才能完成,`74008` 表示已触发的检查点仍在判分,不得复用同段通用错误码动态改文案。

报告提交、报告批改、小组创建和成员选择的字段校验统一复用 `useFormValidation`。失焦/提交后按当前输入重算,字段修正即时更新,其他错误独立保留；切换班级仍清空已选学生并重新提示。批改中已有零分按零分回填,空白评分不得转换成零分。选取报告后清除本地必选提示,取消文件选择保留原文件；服务端提交或批改失败单独显示,编辑或重新选文件不能将其伪装成已成功恢复。

## 2. 实验配置 `[教师]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/experiments?course_id=&status=&keyword=` | 实验列表;`keyword`按名称或说明检索 |
| POST | `/experiments` | 创建实验(可基于 M5 模板) |
| PATCH | `/experiments/{id}` | 编辑组件编排 |
| POST | `/experiments/{id}/validate` | 发布前校验(依赖完整性/M5 锁定版本/分值合理) |
| POST | `/experiments/{id}/publish` | 发布 |
| POST | `/experiments/{id}/unpublish` | 下架 |

创建和编辑实验时,`components.envs[]`、`components.sims[]`、`components.checkpoints[]` 必须提交显式稳定 `id`;环境与仿真组件 ID 在同一实验内全局唯一,阶段与参数绑定按该 ID 引用。ID 使用 1–64 位小写 ASCII 字母、数字或连字符,首尾必须是字母或数字,例如 `attack-node`;这是机器引用键,不是面向学生显示的组件名称。环境请求只提交声明式组合,服务端编译后在现有 `experiment.components` JSONB 中保存完整 `SandboxCompositionSnapshot`;实例启动、阶段激活、恢复和发布校验只消费该快照,不按当前目录重新编译或用 digest 重拼快照。服务端拒绝空 ID、重复 ID、非法格式和悬空引用,不会按数组顺序生成或补齐 ID。

`stages[].param_bindings[]` 的目标必须是该阶段启用的仿真组件,环境组件或其他阶段的仿真组件不能作为目标;这样每条绑定都能在阶段激活时被实际应用。`constant_value` 是 JSON 值并保留其类型,例如数值 `120`、字符串 `"120"`、布尔值 `true` 是不同输入;教师界面按 JSON 语法录入,检查点来源则使用已持久化的绑定输出。

阶段与检查点弹窗复用同一 `useFormValidation`：失焦或提交激活提示,阶段名称/组件/进入条件/参数传递和检查点名称/判题方式/题目/分值分别按当前值重算。切换进入条件只移除不适用的检查点与最低分提示,不隐藏其它错误；修正固定值或移除失效绑定后不残留旧提示。最低得分可留空,填写时须为非负有限数字；检查点分值必填且大于0。参数固定值只在解析成功后按原JSON类型写入草稿,不以字符串或默认值替代非法输入。

校验响应示例:
```json
{ "ok": false, "issues": [
  { "level": "error", "message": "运行时 evm-hardhat 不可用" },
  { "level": "warning", "message": "检查点分值合计 90,非 100" } ] }
```

### 2.1 组件编排请求结构

`POST /experiments` 与 `PATCH /experiments/{id}` 的 `components` 请求体为最终契约(旧的 `runtime_code`+`tools` 平面结构不再接受):

```json
{ "envs": [{ "id": "env-hardhat", "runtimes": [{ "instance_code": "source-chain", "runtime_code": "evm-hardhat", "image_version": "sha256-<digest-prefix>" }], "infra": [{ "code": "postgres-graph", "selection": "auto" }], "tools": [{ "code": "code-server", "params": {} }], "links": [], "access_profile": "experiment", "init_code_ref": "..." }],
  "sims": [{ "id": "sim-pow-mining", "package_code": "builtin__pow-mining", "version": "1.0.0", "params": {...} }],
  "checkpoints": [{ "id":"cp1", "judger":"testcase", "item_code":"prob-2031", "item_version":"1.0.0", "score":40 }] }
```

环境请求中的 `infra` 和 `tools` 必须使用对象形式,保存选择来源(`explicit` 或 `auto`)及经 `config_schema` 校验的参数;`links` 保存源/目标组件与端点、协议、启动前置、访问范围和配置绑定。服务端成功编译后,只持久化完整 `composition_snapshot` 及其 `composition_digest`,不再把声明字段和编译闭包并列保存。

教师新增或修改环境前通过M2连接预览选择目标,只有当前声明预览成功且必需连接完整时才能加入环境并保存草稿。请求中的组件选择来源必须为`explicit`,自动支撑组件由同一M2编译器重新展开,不把旧快照的`auto`项冒充教师输入。预览不代替PATCH成功;保存失败保留未同步编辑态和明确错误,不得显示为已保存。成功后离开重开从服务端快照恢复连接和配置。

环境和仿真场景弹窗的标识、组合完整性、保留/快照时长及场景/版本统一按当前输入校验。失焦或提交激活提示后即时重算；关闭保留或快照开关只移除对应时长错误,不隐藏其它错误。场景种子明确填写正整数并在安全整数范围内,空白或非法输入不得默认替换为1；场景切换仍清除旧版本,当前版本重新选择后立即移除旧必选提示。组合保存继续受同一连接预览门禁约束。

## 3. 实验实例 `[学生]`

### 3.0 学生可见实验

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/student/experiments?course_id=&keyword=&page=&size=` | 学生可做实验分页列表;`keyword`按名称或说明检索 |
| GET | `/student/experiments/{id}` | 单个已发布实验的学生视图 |

两条接口共用同一学生投影(剔除 `init_code_ref`/`init_script_ref`/`judger_code`/`extra_input`,受 `student_access_test.go` 守护)并共用「实验已发布」门槛。每个检查点还返回对应 M5 已发布题面的安全 `face` 正文,用于展示题面、提交约束、公开验收条件和公开材料;服务端不得把 `composition`、初始化引用、判题配置或答案字段放进该学生投影。单读只是同一投影的单条形态,不新增权限范围。单读的存在理由是前端实验详情页必须支持深链与刷新恢复,且沉浸式工作台退出后回落到该页,不能依赖列表态在内存中的残留。

### 3.1 发起实例
`POST /experiments/{id}/instances`
请求:`{ "group_id": null }`(小组实验传组 id)
流程:M7 在事务内按协作模式查询活跃实例;命中则直接返回,未命中才读 components → 调 M2 起沙箱 + 调 M4 起仿真 → 返回实例。单人按 `owner_account_id` 幂等,小组按 `group_id` 幂等,占用运行资源的状态为 creating/running/paused/released;error 实例不再占用资源,但可从已有工作台恢复。创建小组资源时,M7 必须把当前 `group_member.student_id` 全量投影为 M2/M4 `authorized_account_ids`;两引擎去重并剔除 owner 后分别保存到原有实例表的 `shared_account_ids`,不反向读取 M7 表。

创建互斥键与上述查询使用同一主体：租户、实验及单人账号，或租户、实验及小组；小组键不包含点击者账号。同组不同成员并发发起时，检查与首次实例落库共用同一事务锁。只有该事务新建实例的请求继续编排引擎资源；命中已有 `creating` 也只返回原实例与当前进度，不重复起沙箱、仿真或创建审计。失败实例的恢复仍走既有 `resume` 生命周期入口。
响应:`{ "instance_id": 8001, "status": "creating" }`

学生视图 `GET /student/experiments` 返回的每条实验含 `my_group_id`(学生在本实验所属小组;单人实验或尚未分组时省略),由后端按 `group_member`⋈`experiment_group` 批量解析,前端据此在发起小组实例时携带 `group_id`,`my_group_id` 为空则提示"等待教师分组"、不发起请求。学生无独立小组发现接口,`my_group_id` 是学生获取自身 `group_id` 的唯一来源。

授权边界:
- M7 校验同租户、实验已发布、小组实验的成员关系、实例归属。
- 课程/课时是否授予学生由 M6 教学入口负责;M7 不直接依赖同层 M6,避免违反工程目录设计的同层禁止互依赖规则。
- 教师调整成员时对小组行加锁;M7 先尝试让全部活跃沙箱和仿真会话回到 owner-only,再同步最新成员集合。任一跨模块清空或授予失败都不提交成员事务,已成功收回的资源保持 owner-only,其余资源由重试继续收敛;成功后 M2 关闭被移除成员的终端/进度连接,M4 关闭其仿真流。

### 3.2 实例工作台
`GET /instances/{id}`
响应:沙箱工具接入地址(M2)、仿真会话(M4)、实验说明、公开检查点题面、检查点状态、得分。

教师实例监控 `GET /instances?status=&page=&size=` 支持 `creating/running/paused/error/released` 状态筛选;`error` 用于查看环境创建或运行失败的实例,不代表错误实例仍占用引擎资源。M2 阶段一异步启动失败发布 `sandbox.failed`,M7 通过 `source_ref` 对账实例并补偿回收本次 `scope_ref` 资源后落入 `error`;事件尚未到达时,实例读取和教师监控也会按 M2 权威状态完成同一对账,不把失败环境继续显示为准备中。
```json
{ "instance_id": 8001, "status": "running",
  "sandboxes": [{ "ref": "sbx-9001", "tools": [{ "code":"code-server","endpoint":"..." }] }],
  "sims": [{ "ref": "sim-7001", "bundle_url": "..." }],
  "checkpoints": [{ "id":"cp1", "passed": false }] }
```

### 3.3 进度
`GET /instances/{id}/progress`:返回实例进度订阅元信息,如 `topic=tenant:{tenant_id}:experiment:{id}:progress`。

`GET /instances` `[教师/学校管理员]`:教师实时监控活跃实例。普通教师只返回本人创建实验下的
`creating/running/paused/error/released` 实例,学校管理员返回本租户同范围实例；可按 `status` 过滤并分页。
该接口只读实验模块自有表,不通过课程列表反推实例,列表与总数必须使用同一筛选口径。

- 业务实时广播统一走 M10 `WS /api/ws` 订阅 topic,不由 M7 私建 WebSocket Hub。
- M7 返回实例进度 topic 元信息;M10 负责客户端连接、订阅鉴权和后续进度事件聚合推送。

### 3.4 控制
- `POST /instances/{id}/pause` / `resume`
- 暂停仅适用于 `running` 实例;前端须依据实例当前状态和 M2 沙箱实时状态展示操作入口,不能用实例中持久化的工具接入摘要判断沙箱生命周期。检查点判分仅适用于 `running` 或 `paused` 实例;实例引用了 M2 沙箱时,其当前阶段沙箱必须处于可进入状态,否则前端不得开放判分操作。服务端仍通过 M2 保存当前工作区并由 M2 校验沙箱归属/可执行性,前端门禁不替代服务端校验。
- `resume` 同时用于 `paused`、`released` 和启动任一阶段失败后的 `error` 实例;错误实例只有在本次作用域资源补偿回收成功后才允许按同一 `source_ref` 生成新 `scope_ref` 重建,避免重复占用或复用失败沙箱。已持久化公开代码与实验进度保留，初始化失败不自动重试私有脚本。
- `POST /instances/{id}/stages/{stage}/activate`:显式激活已解锁阶段。该接口是阶段资源创建的唯一写入口;`GET /instances/{id}` 只读返回阶段状态,检查点判分和判题事件回调只更新 `checkpoint_result`,不得隐式创建后续阶段沙箱或仿真会话。
- `POST /instances/{id}/finish`:完成前先确认所有已触发检查点均已进入 M3 终态;仍在排队或判分时返回 `74008`,不会固化不完整得分。得分落定后按本次 `scope_ref` 通知 M2/M4 释放资源,并以稳定 `source_ref` 校验归属。得分事务一旦提交,后续重复调用必须只续跑资源回收并返回同一实例终态,不得重复汇总得分或重复生成 `experiment.scored` outbox;实例已回收时直接幂等返回成功。

**没有手动回收接口。** 引擎资源的释放有三条自动路径,都不需要用户按一个不可逆的销毁按钮:

| 触发 | 路径 |
| --- | --- |
| 学生完成实验 | `finish` 内部在得分落定后回收(`reason=finished`) |
| 暂停超时 / 空闲超时 | 后台 `RunRecycleOnce` 扫描认领并回收(`reason=lifecycle_recycle`) |
| 课程结束或归档 | M6 发 `teaching.course.ended`,M7 订阅后级联回收课内仍占资源的实例(`reason=course_ended`,需求 D3) |

若 `finish` 在得分已落库后因引擎暂时不可用而返回失败,M2 的可靠 `sandbox.recycled` 事件和学生后续重试都必须继续同一条回收流程。事件处理只有在实例引用的全部 M2 沙箱都为已销毁态后才可继续回收 M4 并把实例推进到已回收,不得以单个组件完成代替整实例回收完成。

`sandbox.recycled` 必须先确认事件的 `sandbox_id` 仍属于当前实例的资源引用；稳定 `source_ref` 仅用于定位实例，不能据此把旧运行代次的迟到事件应用到新环境。创建中、进行中和已暂停实例的环境释放对账均在当前实例行锁内重新读取全部沙箱权威状态，全部销毁后才进入 `released`。进入入口的旧快照同样必须在行锁内核对当前 `scope_ref` 和状态，不能覆盖已经完成、回收或重建的实例；依赖读取失败显式返回，供可靠事件重投。

之前存在的 `DELETE /instances/{id}` 已删除:它对学生是不可逆销毁(退出动作应是「保存并退出」与「暂停」),
对教师又会越过实例归属去销毁他人环境,而三条自动路径已覆盖全部真实场景。

## 4. 检查点判分 `[学生/系统]`

`POST /instances/{id}/checkpoints/{cp}/judge`
流程:M7 → 调 M3(`POST /judge/tasks`,带 M5 题目引用 + 当前沙箱/仿真状态)→ M3 判 → 回写 checkpoint_result。
检查点声明 `env_id` 时,当前工作区快照和 M3 复用目标必须指向该 `component_id` 对应的实例沙箱;指定环境尚未激活或引用缺失时必须拒绝,不得静默改用其他环境。未绑定环境的检查点沿用整体产出语义。

工作台与检查点按钮统一按 M2 当前 `phase=2/4` 且 `status=ready/running/idle` 开放操作。共享工作台在就绪、失效及状态读取失败时通知业务页面当前可操作性,不缓存一次就绪结论;工作区引用只在可操作时通过正式保存接口恢复,失效时清除页面中的引用。恢复引用与沙箱状态读取仅接受当前环境的最新请求;切换环境、实例卸载或手动保存后,旧请求不得覆盖当前代码引用和可操作性。
请求可带 `binding_output` JSON 对象,用于后续阶段 `param_bindings` 的参数来源。后端只接受小型对象并持久化到 `checkpoint_result.binding_output`;判题完成事件回写得分时不得覆盖已有绑定输出。
响应:`{ "passed": true, "score": 40, "detail_ref": "...", "binding_output": { ... } }`。

## 5. 实验报告 `[学生/教师]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/instances/{id}/report` `[学生]` | `multipart/form-data`,字段 `file`;上传并提交 PDF、Markdown 或纯文本报告 |
| GET | `/instances/{id}/report` `[学生]` | 读取本人报告的提交/批改结果;只返回安全结果投影,不返回对象存储引用 |
| GET | `/experiments/{id}/reports` `[教师]` | 报告列表,支持 `status` 筛选(省略或 0 表示不筛),筛选与 `total` 同口径 |
| POST | `/reports/{id}/access` `[教师]` | 校验实验管理权限后签发报告文件的一次性下载授权 |
| POST | `/reports/{id}/grade` `[教师]` | 批改报告(必填分数+评语);分数为 0 到 100,显式 0 分合法 |

报告提交接口不接受客户端传入 `content_ref`:M7 先校验当前学生对实例的访问权,再复用统一文件服务完成
大小、扩展名、声明 MIME、内容签名和病毒扫描校验,最后写入报告桶并保存服务端生成的对象引用。对象 key 固定为
`{tenant_id}/experiment/report/{instance_id}/{student_id}/{filename}`;单文件上限由
`UPLOAD_EXPERIMENT_REPORT_MAX_BYTES` 配置。数据库写入失败时必须删除本次新对象;替换报告成功后必须删除旧对象,
不得留下无主报告。客户端不能构造对象 key,也不能提交跨实例、跨学生或路径穿越引用。
教师读取报告必须先走 `/reports/{id}/access` 换取与当前账号、租户、实例和对象引用绑定的一次性授权,
再由统一文件服务投放;报告列表不返回可直接访问的对象存储 URL。

## 6. 多人协作 `[教师/学生]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/experiments/{id}/groups` `[教师]` | 创建分组 |
| GET | `/experiments/{id}/groups` `[教师]` | 本实验分组列表(含各组成员与角色) |
| POST | `/groups/{id}/members` | 加入成员 + 分配角色 |
| DELETE | `/groups/{id}/members/{student_id}` `[教师]` | 移除成员并立即收回其资源权限 |
| GET | `/groups/{id}` | 组信息(成员/角色/共享实例) |

> 小组实验:同组成员访问同一实例的共享沙箱;各自有角色入口;通过链上状态交互。

分组列表与 `GET /groups/{id}` 的关系:后者按小组编号读单组并附带共享实例,是学生进入协作实验的入口;
前者是**教师编组视角**,一次返回本实验全部分组及成员角色,不附带实例(编组时实例尚不存在)。
小组编号只在创建响应里出现过一次,没有列表则教师刷新页面后无法再定位已建分组,
`POST /groups/{id}/members` 与 `DELETE /groups/{id}/members/{student_id}` 对教师即成为不可达接口。分组归属经 `ensureTeacherCanManage`
校验(实验作者或学校管理员),成员一次性按实验批量取回,不逐组调用避免 N+1。

删除成员与加入/改角色使用同一条小组行锁流程:先把活跃实例的 M2 沙箱和 M4 仿真会话授权收回到 owner-only,再删除成员并按剩余成员集合重新授权。当前共享实例的 `owner_account_id` 不能被移除,因为 M2/M4 合同必须始终保留 owner 权限;需要先结束并回收该实例。跨模块同步失败时事务不提交,已成功收回的资源保持 owner-only,后续重试继续收敛。

小组成员与实验报告的响应都带 `student_name`/`student_no`:`group_member`、`experiment_report`
只存 `student_id`,而编组与批改界面必须显示人名,故由 M7 经
`contracts.IdentityService.BatchGetAccounts` 一次批量解析后随响应下发 ——
让客户端自己再拉一份账号目录既越权(那是学校管理员能力)也会 N+1。
教师端挑选待入组学生走 M1 `GET /org/classes/{id}/students`(教师只读,只出编号/姓名/学号)。

## 7. 结果读取与聚合 `[内部]`

`GET /internal/instances/{id}/score` `[内部]`
- 供上层聚合或受控内部流程读取实验得分。
- 租户边界来自服务间签名头 `X-Chaimir-Tenant-Id`,不得用查询参数覆盖。
- M7 实验得分 = 检查点得分汇总 + 报告批改分。
- 为遵守第2层同层模块不得直接依赖,M7 不直接调用 M6;完成/重算得分后发布 `experiment.scored` 事件。
- 事件携带持久化的 `event_id`、`instance_id`、`student_id`、`score`、`score_revision` 与 `scored_at`;同一 outbox 重投使用同一事件 ID、得分和修订号,不同实例的修订号分别递增,不能把后收到的旧修订当成新成绩。

`GET /internal/stats?course_id=` `[内部]`
- 供 M9 看板聚合:实验数、活跃实例数、资源占用等只读统计;租户边界来自服务间签名头 `X-Chaimir-Tenant-Id`。

## 8. 典型时序(学生做混合实验)

```
学生 → POST /experiments/{id}/instances
M7 → 读 components → 调 M2 起沙箱(运行时+工具)→ 调 M4 起仿真
M7 → instance(creating);WS 转发 M2 启动进度
环境就绪 → 学生在工作台:沙箱写合约/部署、仿真注入操作
学生 → 触发检查点 → M7 调 M3 判(取 M5 配置)→ 回写结果
学生 → 提交报告 → finish
M7 → 汇总得分 → 发布 experiment.scored → 后续成绩流程按事件或上层编排消费
完成 → M7 调 M2/M4 回收
```
