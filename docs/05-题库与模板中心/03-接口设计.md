# M5 题库与模板中心 — 接口设计

> RESTful。鉴权沿用 M1 JWT。取题面与取答案接口分离;判题取全量为内部接口。
> 最后更新:2026-11-27

---

## 1. 通用约定

- Base:`/api/v1/content`
- 统一响应体同 M1。错误码段:`5xxxx`(51xxx 内容/52xxx 版本/53xxx 共享/54xxx 组卷)。
- `51014` 表示分类仍有活动子分类或未删除题目引用,删除被拒绝;仅空分类可删除。
- 删除已不存在或已删除的分类返回 `51008`;数据库读取错误返回通用内部错误,不伪装成分类校验失败或引用冲突。
- 内容、版本、共享库、题面、试卷和引用维护的数据库故障统一返回通用内部错误；查询条件、正文和试卷参数错误仅用于输入校验。已有业务错误保留其公开语义，外层操作说明及并列失败原因完整保留在内部错误链中。
- `[内部]` 供 M2/M3/M4/M6/M7/M8 调用。
- 普通题库入口允许教师/校管,写操作仍校验作者与租户,不开放他人内容审核。`full` 仅教师作者或受鉴权内部服务可读。学生经 M6/M7/M8 获取已授权题面,平台管理员无跨校题库治理入口。
- 列表与总数由同一组 SQL 筛选条件计算,私有归属和共享状态在分页前过滤,不在仓储转换时再次丢弃行。

## 2. 内容管理 `[教师/校管]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/items?type=&category=&difficulty=&tag=&kp=&keyword=&visibility=&author=&status=&page=&size=` | 内容检索(分页);作业与试卷共用选题器固定status=2,按服务端分页和关键词检索已发布版本 |
| POST | `/items` | 创建内容(类型 + 元信息 + 内容体,草稿) |
| GET | `/items/{code}/{version}` | 取本校内容**题面**(过滤敏感字段) |
| GET | `/items/{code}/{version}/full` `[内部/作者]` | 取全量(含答案/判题配置) |
| PATCH | `/items/{id}` | 编辑草稿 |
| POST | `/items/{id}/publish` | 发布(定版) |
| POST | `/items/{id}/deprecate` | 弃用 |
| DELETE | `/items/{id}` | 软删(无引用时) |
| POST | `/items/system-import` `[内部]` | 系统/外部源自动建题入口(B10):M8 真实漏洞转化固化后调此入库,只允许 `author_type=系统/外部源`,带固化内容、预验证结果 |

系统建题 JSON 字段由 `backend/api/paths/content.yaml` 的 `contentSystemImport` 完整定义：内容编号/版本/类型/标题、分类和难度、标签/知识点、作者、可见范围、正文与敏感路径，另含 `auto_publish` 和 `system_import_note`。`author_type` 省略或 `0` 时为系统（`2`），只接受系统或外部源（`3`），不接受教师来源；`auto_publish` 省略或 `false` 进入草稿，`true` 经发布校验后直接定版。`system_import_note` 是写入建题审计 detail.note 的 JSON 对象，不写入题面。HTTP 租户只取服务签名上下文。

试卷和作业共用选题器：同一题目编号在本次选择中只出现一次，再次选择即取消；桌面表格和移动列表共用选择动作，连续操作按最新选择状态计算，不在待更新的界面状态上重复追加。

列表参数 `author` 是作者账号的字符串 ID，与 `author_type` 来源枚举无关；SDK 按统一 `SnowflakeID` 契约传递。

> **系统建题入口**:除教师手动创建外,M5 支持"系统/外部源自动建题"——M8 真实漏洞外部源经分级+预验证后,调 `system-import` 把固化的自包含题目写入 M5(`content_item.author_type` 标记来源)。该内部入口不得接受请求体伪装成教师来源,未传 `author_type` 时按系统来源处理,显式来源只能是系统或外部源。跨模块 contracts 调用必须保证请求 `tenant_id` 与服务端鉴权上下文租户一致,不得用请求体覆盖租户边界。入库的漏洞题已通过预验证,默认进草稿待人工审核或按来源级别自动发布。

系统建题在同一租户事务内写入内容外壳、正文和 M1 审计，并构造返回快照。任一步失败时回滚本次导入，成功提交后才返回快照。

系统导入支持安全重试：相同租户、编号与版本已存在时，仅当不可变内容、摘要、作者及来源类型、当前状态和可见范围均相同时返回原内容，并记录复用审计；不覆盖原正文、重建附件或重复创建内容。存在差异返回版本冲突，读取失败保留真实错误。普通新建、新版本和克隆仍拒绝重复版本；活动版本冲突由数据库 `ON CONFLICT DO NOTHING` 表达，使系统导入能在同一有效事务内读取并核对已存在内容。

教师与校管写入口采用同一提交边界：内容创建/编辑、状态/共享变更、新版本/克隆、分类维护及组卷与其 M1 审计在同一租户事务内提交；返回快照在提交前构造。审计或快照失败不得留下已生效的写入。克隆附件不参与数据库事务，仅在尚未尝试提交时限时补偿本次目标对象；提交报错后保留，查询未命中也不能证明最终未提交。源对象不变。

草稿表单只覆盖其负责的正文字段，保留已读取的运行声明、初始化材料、仿真引用、判题和对局配置，以及已有敏感路径；修改标题等字段不能清除未展示的内容。显式移除附件、关闭环境或更换理论题型时，删除对应受控字段，不保留已失效的配置。

内容新建、新版本、克隆和系统导入共用仓储的版本冲突判断：仅活动内容的 `(tenant_id, code, version)` 唯一约束冲突返回 `52001`。数据库连接、其他约束及事务提交故障返回通用内部错误，保留原始原因；不指引用户通过修改版本号处理基础设施故障。

教师和校管路由完成角色授权后，HTTP 入口从服务端身份及 M1 账号摘要解析一次审计主体快照，沿用公共审计角色优先级，显式传给写服务。服务不重复查询身份，仍校验快照与当前租户、账号一致，并保留作者和可见范围校验。身份解析失败返回 `11009`，角色不允许返回 `11002`，均不产生写事务或附件副作用。审计写入失败返回 `11013` 并保留原始原因，不归类为内容参数错误。

## 3. 版本 `[教师/校管]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/items/{code}/versions` | 本校同编号的版本列表，不混入外校共享内容 |
| POST | `/items/{code}/new-version` | 基于现有版本创建新版本草稿 |

> 业务引用锁定 `(code, version)`;弃用版本不可被新引用,旧引用仍有效。

新版本建议统一使用内容域的空闲版本计算：保持主、次版本，只递增修订号并跳过已占用版本；数字段使用精确整数，不因浏览器数字精度而返回原版本或停在同一候选值。建议只初始化输入，不覆盖用户已编辑的版本号，提交仍由服务端检查冲突。

作业与试卷复用同一选题器,只列当前租户有权引用的已发布版本,支持跨页选择和搜索/清空恢复。草稿与已弃用版本不可选择;搜索不以首100条代替全库。提交时仍由M5校验当前状态与归属;选后被弃用等状态变化返回52004,提示先发布或重新选择,不自动发布也不放宽版本门禁。

## 4. 复用 `[教师/校管]`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/items/{id}/clone` | 按所选内容 ID 克隆为独立草稿(新 code,不带引用/统计) |
| POST | `/items/{id}/share` | 设为共享库(visibility=shared) |
| POST | `/items/{id}/unshare` | 取消共享(仅停止被新克隆;已克隆副本独立不受影响) |
| GET | `/shared?type=&keyword=` | 浏览跨校共享库 |
| GET | `/shared/{id}` | 按所选内容 ID 预览已发布共享题面(过滤敏感字段) |

共享预览与克隆按内容 ID 精确定位来源，禁止以编号和版本回退到本校或其他学校的同名内容。共享预览仅接受当前仍已发布且共享的内容；克隆允许本校有权读取的已发布内容，或仍已发布且共享的外校内容。克隆审计记录源 ID、源租户、编号和版本。本校题面、全量配置、版本历史及教学、实验、竞赛的锁定引用均按当前租户的编号和版本读取，不跨校回退。

> **共享撤回语义**:克隆是**深拷贝**——他校克隆瞬间即生成独立新 code 的副本,与源完全解耦。因此:① 取消共享(unshare)仅使该内容**不再出现在共享库、不可被新克隆**,已克隆的副本不受任何影响;② 源内容发新版本,已克隆副本也不自动更新(克隆即独立)。与"版本化:旧引用锁版本不受影响"不冲突——版本锁针对的是**同租户内引用**,克隆针对的是**跨租户复制**,二者是不同机制。
> 分类属于各自学校：本校克隆保留原分类；跨校克隆创建未分类草稿，由教师在本校重新归类，不复制分类树或保存源学校的分类编号。版本摘要按目标草稿计算。

克隆附件使用统一对象存储的服务端复制，不经应用下载后重新上传；同一来源对象在单次克隆中只复制一次，正文中的重复引用指向同一独立副本。复制结果仍校验非空与附件大小上限；复制或元数据确认失败时限时清理本次目标，不删除来源对象。
> **共享发布约束**:创建/编辑草稿只允许 `private/tenant`;跨租户共享只能对已发布内容调用 `share` 显式进入共享库。共享库浏览、按 ID 预览和克隆的跨租户读取都只放开 `visibility=shared && status=published` 的内容，版本历史只列本校。

分享与撤回只改变可见范围,不修改不可变版本内容或 `version_hash`;内容读取与克隆仍独立检查当前可见范围。

## 5. 分类与组卷 `[教师/校管]`

分类排序使用有符号 32 位整数，显式零值原样提交，省略时由界面建议排序；非法数字明确拒绝。

分类支持多级,列表与父分类选项展示完整路径。父分类必须是本租户未删除节点,不能选择自身或任一下级。仅无活动子分类、无未删除题目引用的空分类可删除;有引用时不改变子树、题目或版本摘要并返回51014,分类不存在或已删除时返回51008。分类结构变更与内容设置非空分类共用租户内事务锁,随后读取最新状态校验,防止并发互设父级或在删除时新增引用。沿用 PostgreSQL 事务锁与现有分类表,不新增状态或关系表。

手动组卷须有题目清单与逐题分值，随机组卷须有抽题条件、题数与每题分值；题数和分值均为正整数。切换方式保留已有编辑内容，只提交当前方式适用字段；题目版本与服务端准入沿用本节契约。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST/PATCH/DELETE | `/categories[/{id}]` | 分类树维护 |
| GET | `/papers` | 卷列表 |
| POST | `/papers` | 创建卷(手动选题 或 按条件随机抽题) |
| GET | `/papers/{id}` | 卷详情(题目引用 + 分值,题面视角);展开私有题仍校验当前教师为题目作者 |
| POST | `/papers/{id}/regenerate` | 试卷作者按条件重新抽题;非作者返回卷不存在且不改变引用 |

随机抽题请求示例:
```json
{ "name": "第3章测验", "gen_mode": 2,
  "gen_criteria": { "type": 3, "knowledge_points": ["共识","哈希"], "difficulty": [2,3], "count": 10, "default_score": 10 } }
```

抽题条件中的难度与知识点为可选筛选，省略、`null` 和空数组均表示不限；条件保存后重新读取，语义保持一致。重生成沿用已保存的条件重新随机抽样，不要求整卷题目与上次全部不同。手动选题和随机抽题均只接受当前租户已发布、未删除且当前教师可见的版本：私有题仅作者可新选入，本校公开题可复用；随机抽题在限制数量前过滤私有归属，不能抽取后再丢弃。候选数量不足时返回54006，保留原有题目引用、顺序和分值。

随机组卷必须提供正整数 `count` 和 `default_score`，每题初始分值取 `default_score`。`type` 省略或 `0` 表示不限制，非零仅接受内容类型 `1/2/3`；难度值沿用 `1入门/2基础/3进阶/4挑战`。

## 6. 正文附件 `[教师/校管]`

题目正文的配图、说明文档与示例数据经统一文件服务存取,正文只保存对象引用。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/attachments` | 上传附件(multipart:`file` + 可选 `resource_id`),返回 `{ object_ref, file_name, size }` |
| POST | `/attachments/download-grant` | 传已保存内容的 `resource_id`(题目 ID)与正文 `object_ref`;后端校验题目可见性及正文引用后签发 `{ token, expires_at }` |

口径:

- 三种内容类型共用 body 里的 `attachments: [{ object_ref, file_name, size }]`(见架构设计 §2.2),
  不按类型另起字段名。新建题目时 `resource_id` 可省略(尚无内容 id,对象落在草稿前缀下),
  编辑已有题目时传该题 id。
- 每次上传的对象路径为 `{tenant_id}/content/attachment/{resource_id或draft}/{upload_id}/{file_name}`，上传编号由服务端生成，原文件名保留。同名上传也产生独立引用，不覆盖已有正文或已发布版本引用的对象；审计失败仅删除本次新对象。
- 返回的 `object_ref` 必须原样写进 `attachments`;正文内联 `data:` 或外部 `http(s)://` 直链会被
  `51xxx` 拒绝(`validateContentBodyRefs` 递归校验,数组元素同样受约束)。
- 取件流程固定为「读题面/全量 → 取 `attachments[].object_ref` → 换授权 → `GET /api/v1/storage/download?token=`」,
  平台不返回对象存储直链、不暴露内部 grant 结构。
- 下载授权不信任客户端单独提交的对象引用:`resource_id` 必须对应已持久化题目,且 `object_ref` 必须精确存在于该版本正文的 `attachments` 数组;私有或草稿内容仍受作者边界约束。
- 允许的附件类型与大小由 `internal/platform/upload` 统一裁定(图片/PDF/文本/CSV/JSON),
  含病毒扫描;M5 只把通用失败原因映射成自己的错误码。
- 上传缺少文件、空文件、大小超限、文件名/类型/内容不合规或命中病毒时返回 `51013`,
  提示重新选择符合要求的附件;统一文件服务用 `upload.ErrInvalidFile` 标记文件校验拒绝,
  M5 用错误链判断,不匹配技术错误文本、不重复执行校验。
- 文件读取、扫描服务或对象存储不可用仍返回 `51012`;不得将服务故障伪装成文件不合规,
  也不得将正常的文件校验拒绝显示为服务暂不可用。原始原因只进入日志,响应保留用户提示与 trace_id。
- 附件写入后审计失败，补偿删除本次新对象并返回原审计错误；补偿失败记录结构化日志，不把未审计上传当作成功。
- 附件上传完成后追加到当前清单，不覆盖上传期间的移除操作。上传与保存共用表单忙碌状态：上传完成前不提交或关闭，保存期间不修改附件清单；文件选择由可聚焦的可见按钮触发。

## 7. 内部取用 `[内部]`

供引擎/业务按引用取内容:

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/items/{code}/{version}/full` | M3 判题取判题配置 + 答案;M7/M8 取已锁版本的声明式 `composition`、仿真/判题引用;M2 只接收组合编译请求,不从 M5 读取或解释第二套部署清单 |
| POST | `/items/batch` | 批量取(组卷展开) |

> `full` 接口强制内部服务鉴权 + 角色校验,绝不对学生开放。

`ContentReadService.ReplaceUsageRefs` 经 M5 自有仓储复用调用方同数据库、同租户的普通应用事务，引用集合、计数与业务记录一起提交或回滚；没有外层事务时自行开启租户事务。不复用跨租户、平台或特权维护事务，不让业务模块直接访问 M5 表。

## 8. 典型时序(实验引用模板)

```
M7 创建实验 → GET /items/{code}/{version}/full(取模板声明与锁版本)
M7 → 把 `CompositionSpec` 声明交 M2 唯一组合编译器并锁定 digest
M7 → 把 sim_package_ref 交 M4 跑仿真
学生提交 → M3 → GET /items/{code}/{version}/full(取判题配置+答案)→ 判题
被引用 → 调用 `internal/contracts.ContentReadService.ReplaceUsageRefs` 幂等替换来源引用集合
```
