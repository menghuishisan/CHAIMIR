# M5 题库与模板中心 — 架构设计

> 核心:统一外壳 + 类型化内容体、版本化、克隆/共享、组卷、与各模块的供给关系。
> 最后更新:2026-08-23

---

## 1. 总体架构

```
┌──────────────────────────────────────────────────────────┐
│  引用方                                                     │
│  M7 实验(引用实验模板) │ M8 竞赛(引用竞赛题) │ M6 作业(引用理论题) │
│  M2/M3/M4 引擎(取运行时配置/判题配置/仿真包引用)             │
└─────────────────────────┬────────────────────────────────┘
                          │ 按 (内容引用 + 锁定版本) 取用
┌─────────────────────────▼────────────────────────────────┐
│  M5 题库与模板中心(Go + PostgreSQL)                        │
│  ┌────────────┬──────────────┬──────────┬──────────────┐ │
│  │ 内容外壳    │ 类型化内容体  │ 版本管理  │ 检索/组卷     │ │
│  │ (统一元信息)│ (实验/竞赛/理论)│         │              │ │
│  ├────────────┴──────────────┴──────────┴──────────────┤ │
│  │ 克隆引擎 │ 共享库 │ 权限(答案隔离) │ 复用统计          │ │
│  └──────────────────────────────────────────────────────┘ │
│  大文本/附件 → S3 对象存储                                        │
└───────────────────────────────────────────────────────────┘
```

## 2. 统一外壳 + 类型化内容体(核心)

### 2.1 内容外壳(共性元信息,一套)

```
ContentItem {
  id, tenant_id, type,           // type: experiment_template | contest_problem | theory_question
  code, version,                 // 版本化标识
  title, category_id, difficulty,
  tags[], knowledge_points[],
  author_id, visibility,         // private | tenant | shared(共享库)
  status,                        // draft | published | deprecated
  body_ref,                      // 指向类型化内容体
  usage_count,                   // 复用统计
  created_at, updated_at
}
```

### 2.2 类型化内容体(差异,各承载)

`body` 以 JSONB 按类型存专有结构:

| type | body 结构要点 |
| --- | --- |
| 实验模板 | `composition`(一个或多个 M2 环境的 `CompositionSpec` 声明)+`init_code_ref`+`sim_package_ref`(M4)+`judge_config`(M3)+`description`+`init_script` |
| 竞赛题 | `statement`+`composition`(解题/对抗环境声明)+`judge_config`(测试用例/断言/flag)+`init_contracts`+`ad_config`(对抗赛)+`submit_key` |
| 理论题 | `statement`+`q_type`(选择/判断/填空/简答)+`options[]`+`answer`+`explanation` |

**三种类型共用一个附件字段** `attachments`:`[{ object_ref, file_name, size }]`。
它是所有类型的正文附件唯一落点 —— 按类型各起一个名(`lab_files`/`problem_images`/…)就是三套同义结构,
检索、克隆、删除保护都得各写一遍。约束:

- `object_ref` 只接受统一文件服务对象引用;正文不得内联 `data:` 或外部直链(由 `validateContentBodyRefs`
  递归强制,数组内的引用同样被校验)。附件的上传、授权换取与下载流程是接口契约,见 `03-接口设计.md` §6(SSOT)。
- 附件不进 `sensitive_fields`:它是题面的一部分,学生取题面时需要看到;答案配图属于 `explanation`
  的一部分,由 `explanation` 的敏感标注统一剥离。

> 检索/克隆/版本/权限只对外壳实现一套;内容体只在创作与取用时按类型解析。这是"消灭冗余、合理合表"的落地。

### 2.3 敏感字段标注

内容体中 `answer` / `judge_config.testcases` / `flag` 等标记为**敏感字段**,经权限层过滤(见 §6)。

### 2.4 运行环境组合归属

M5 是已发布竞赛题的环境组合权威。题目版本中的 `composition` 必须包含每个环境的全部命名 runtime 实例、显式工具/基础设施、依赖展开结果、类型化连接、访问配置和 M2 编译快照 digest;发布后这些字段与题面、判题配置一起不可变。M7 实验可以引用后在课程范围内生成新的实验组合草稿,但 M8 竞赛不得复制或改写题目的完整组合。

M2 是唯一组合编译器和 WorkloadSpec 生成者。M5 只保存声明与锁定引用,不保存第二份部署 YAML;M8 的 `contest_problem` 只引用 M5 的 `item_code + item_version`,不再维护 `runtime_code`、工具列表或镜像版本旁路字段。学生取题面接口永远过滤组合中的私有参数、Secret、判题器和答案信息。

## 3. 版本化

```
内容 = (code, version)
发布即定版(版本内容不可变)
业务引用时锁定具体 version
改内容 → 发新 version → 旧引用仍指向旧版本
```

- 与 M2 运行时、M4 仿真包同一版本哲学,全平台一致。
- 已被引用的版本不可删,只能弃用(deprecated),保证旧实验/旧竞赛稳定可复现。

## 4. 克隆与共享

### 4.1 克隆

```
克隆源(自己的/共享库的)→ 复制外壳 + 内容体 → 生成新草稿(新 code)
不带:引用关系、学生数据、提交记录、复用统计(归零)
```

### 4.2 共享库

- `visibility=private`:仅作者可见;`visibility=tenant`:本租户教师可浏览题面;`visibility=shared`:已发布后通过显式 share 进入跨校共享库,全平台题面可见可克隆。
- 共享为**只读 + 可克隆**,他人克隆后成自己的独立内容,与原内容无关联。
- 可随时取消共享(已克隆的副本不受影响)。

## 5. 检索与组卷

- **分类树**:多级内容分类。
- **多维筛选**:标签 / 难度 / 知识点 / 类型 / 作者 / 可见范围。
- **组卷**:按条件(知识点+难度+数量)随机抽题,或手动选题,生成"卷"(题目引用集合 + 各题分值)。组卷结果被 M6 作业 / M8 竞赛引用。

---

## 6. 权限层(答案隔离)

```
取内容接口分两类:
  GET .../content      → 题面 + 非敏感内容(学生可用,过滤掉 answer/testcases/flag)
  GET .../content/full → 全量含敏感字段(仅教师/M3 内部判题鉴权可用)
```

- 学生侧任何路径都拿不到敏感字段。
- M3 判题经内部鉴权取 full,在隔离 judge 沙箱使用,不下发学生。

---

## 7. 与各模块供给关系

| 模块 | 取用 |
| --- | --- |
| M7 实验 | 取实验模板:运行时/工具/初始代码/仿真引用/判题配置 |
| M8 竞赛 | 取竞赛题 + 组卷 |
| M6 作业/理论赛 | 取理论题 + 组卷 |
| M2 | 实验或题目版本中的 `composition` 交唯一组合编译器并按快照起沙箱 |
| M3 | 按题目引用取 judge_config + 答案判题 |
| M4 | 实验模板里的 sim_package_ref 交 M4 跑仿真 |

> M5 只提供内容数据,不执行;执行由各引擎负责。

---

## 8. 多租户

- 内容外壳带 `tenant_id` + RLS;仅 `visibility=shared && status=published` 时跨租户只读可克隆。
- 私有化:`tenant_id` 恒定;共享库内容可随离线包分发。
