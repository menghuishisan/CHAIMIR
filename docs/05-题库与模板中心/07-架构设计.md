# M5 题库与模板中心 — 架构设计

> 核心:统一外壳 + 类型化内容体、版本化、克隆/共享、组卷、与各模块的供给关系。
> 最后更新:2026-11-28

---

## 1. 总体架构

```
┌──────────────────────────────────────────────────────────┐
│  引用方                                                     │
│  M7 实验(引用实验模板) │ M8 竞赛(引用竞赛题) │ M6 作业(引用理论题) │
│  M2/M3/M4 引擎(取运行时配置/判题配置/仿真包引用)             │
└─────────────────────────┬────────────────────────────────┘
                          │ 按 (内容引用 + 锁定版本) 取用
┌─────────────────────────▼────────────────────────────────┐
│  M5 题库与模板中心(Go + PostgreSQL)                        │
│  ┌────────────┬──────────────┬──────────┬──────────────┐ │
│  │ 内容外壳    │ 类型化内容体  │ 版本管理  │ 检索/组卷     │ │
│  │ (统一元信息)│ (实验/竞赛/理论)│         │              │ │
│  ├────────────┴──────────────┴──────────┴──────────────┤ │
│  │ 克隆引擎 │ 共享库 │ 权限(答案隔离) │ 复用统计          │ │
│  └──────────────────────────────────────────────────────┘ │
│  大文本/附件 → S3 对象存储                                        │
└───────────────────────────────────────────────────────────┘
```

## 2. 统一外壳 + 类型化内容体(核心)

### 2.1 内容外壳(共性元信息,一套)

```
ContentItem {
  id, tenant_id, type,           // type: experiment_template | contest_problem | theory_question
  code, version,                 // 版本化标识
  title, category_id, difficulty,
  tags[], knowledge_points[],
  author_id, visibility,         // private | tenant | shared(共享库)
  status,                        // draft | published | deprecated
  usage_count,                   // 复用统计
  created_at, updated_at
}
```

### 2.2 类型化内容体(差异,各承载)

正文存于独立 `content_body`，通过 `(tenant_id, item_id)` 与外壳一对一关联；外壳不另存正文引用列。

`body` 以 JSONB 按类型存专有结构:

| type | body 结构要点 |
| --- | --- |
| 实验模板 | `composition`(一个或多个 M2 环境的 `CompositionSpec` 声明)+`init_code_ref`+`sim_package_ref`(M4)+`judge_config`(M3)+`description`+`init_script` |
| 竞赛题 | `statement`+`composition`(解题/对抗环境声明)+`judge_config`(测试用例/断言/flag)+`init_contracts`；代码类题补充 `submission_contract`，对抗赛补充 `battle`，Flag 题才补充 `submit_key` |
| 理论题 | `statement`+`q_type`+题型对应的 `options[]`/`blank_count`+`answer`+`max_score`+`explanation` |

非理论题的判题配置只从 `judge_config` 读取，不使用正文顶层字段补齐。`judger_code` 和正整数 `max_score` 必填；`expectation` 省略时为空对象，显式提供时必须是对象。返回快照与存储对象隔离，调用者修改快照不得影响原内容。

理论题不重复存 `judge_config`。M5 `ContentJudgeReadService.GetJudgeSpec` 按锁定版本从 `q_type`、`answer`、`max_score` 派生判题快照,并使用共享契约中的 `theory-question` 判题器标识;答案只返回 M3 内部判题调用,不进入题面、M6 作业记录或用户响应。

理论题的题型、选项、空格数、整数满分与答案结构统一由 `pkg/question` 校验,M5/M6/M3 不各自维护判型规则。M5 将定义和标准答案放入既有 `ContentJudgeSpec.expectation`,不增加第二组答案字段;M3 使用同一定义规范化学生答案后比较。学生可保留未填完的空格,空串按原位置保留,不得过滤后导致后面的答案前移。

**三种类型共用一个附件字段** `attachments`:`[{ object_ref, file_name, size }]`。
它是所有类型的正文附件唯一落点 —— 按类型各起一个名(`lab_files`/`problem_images`/…)就是三套同义结构,
检索、克隆、删除保护都得各写一遍。约束:

- `object_ref` 只接受统一文件服务对象引用;正文不得内联 `data:` 或外部直链(由 `validateContentBodyRefs`
  递归强制,数组内的引用同样被校验)。附件的上传、授权换取与下载流程是接口契约,见 `03-接口设计.md` §6(SSOT)。
- 附件不进 `sensitive_fields`:它是题面的一部分,学生取题面时需要看到;答案配图属于 `explanation`
  的一部分,由 `explanation` 的敏感标注统一剥离。

> 检索/克隆/版本/权限只对外壳实现一套;内容体只在创作与取用时按类型解析。这是"消灭冗余、合理合表"的落地。

### 2.3 敏感字段标注

内容体中 `answer` / `judge_config.testcases` / `flag` 等标记为**敏感字段**,经权限层过滤(见 §6)。漏洞题正式正文只携带组合初始化与黑盒状态断言，官方攻击只保留在 M8 出题草稿。题面统一剥离初始化步骤、资产和对象引用及判定依据，不改变教师和引擎读取的原始内容。

### 2.4 运行环境组合归属

M5 是已发布题目环境声明的权威。`composition` 保存命名 runtime 实例、明确镜像版本、显式工具/基础设施、类型化连接、参数和初始化声明，与题面、判题配置一起定版，不包含访问场景或编译摘要。M7 结合课程编排生成实验草稿；M8 从锁定题目读取同一声明，按赛制确定访问边界后交 M2 编译，不能另写一份题目环境配置。

M2 是唯一组合编译器和 WorkloadSpec 生成者。M5 只保存声明与锁定引用,不保存第二份部署 YAML;M8 的 `contest_problem` 只引用 M5 的 `item_code + item_version`,不再维护 `runtime_code`、工具列表或镜像版本旁路字段。学生取题面接口永远过滤组合中的私有参数、Secret、判题器和答案信息。

## 3. 版本化

```
内容 = (code, version)
发布即定版(版本内容不可变)
业务引用时锁定具体 version
改内容 → 发新 version → 旧引用仍指向旧版本
```

- 与 M2 运行时、M4 仿真包同一版本哲学,全平台一致。
- 已被引用的版本不可删,只能弃用(deprecated),保证旧实验/旧竞赛稳定可复现。
- `version_hash` 只覆盖不可变内容(字段见数据模型),可见范围不参与摘要;分享与撤回不改变版本完整性。

## 4. 克隆与共享

### 4.1 克隆

```
克隆源(自己的/共享库的)→ 复制外壳 + 内容体 → 生成新草稿(新 code)
不带:引用关系、学生数据、提交记录、复用统计(归零)
```

### 4.2 共享库

- `visibility=private`:仅作者可见;`visibility=tenant`:本租户教师可浏览题面;`visibility=shared`:已发布后通过显式 share 进入跨校共享库,全平台题面可见可克隆。
- 共享为**只读 + 可克隆**,他人克隆后成自己的独立内容,与原内容无关联。
- 可随时取消共享(已克隆的副本不受影响)。

## 5. 检索与组卷

- **分类树**:多级内容分类。
- **多维筛选**:标签 / 难度 / 知识点 / 类型 / 作者 / 可见范围。
- **组卷**:按条件(知识点+难度+数量)随机抽题,或手动选题,生成"卷"(题目引用集合 + 各题分值)。题目集合替换先锁定当前租户的父试卷行，再删除旧集合并写入新集合；同一试卷的并发重抽串行提交，失败时保留原集合，其他试卷和普通读取不争用该锁。集合、返回快照和审计在同一事务内完成。组卷结果被 M6 作业 / M8 竞赛引用。

---

## 6. 权限层(答案隔离)

```
取内容接口分两类:
  GET /api/v1/content/items/{code}/{version}      → 教师/校管按可见范围读取题面
  GET /api/v1/content/items/{code}/{version}/full → 教师作者或受鉴权内部服务读取全量
```

- 学生侧任何路径都拿不到敏感字段。
- 学生经 M6/M7/M8 的业务授权读取题面,不直接检索题库。校管管理本人内容,平台无跨校题库治理入口。
- M3 判题经内部鉴权取 full,在隔离 judge 沙箱使用,不下发学生。

## 7. 与各模块供给关系

| 模块 | 取用 |
| --- | --- |
| M7 实验 | 取实验模板:运行时/工具/初始代码/仿真引用/判题配置 |
| M8 竞赛 | 取竞赛题 + 组卷 |
| M6 作业 | 只取理论题 + 仅含理论题的组卷;M6 不引用 `contest_problem` |
| M2 | 实验或题目版本中的 `composition` 交唯一组合编译器并按快照起沙箱 |
| M3 | 按题目引用取 judge_config 或理论题答案快照;理论题由 M3 后端内置 J7 判分 |
| M4 | 实验模板里的 sim_package_ref 交 M4 跑仿真 |

> M5 只提供内容数据,不执行;执行由各引擎负责。

## 8. 多租户

- 内容外壳带 `tenant_id` + RLS;仅 `visibility=shared && status=published` 时跨租户只读可克隆。
- 纯读取经 M5 仓储的 `TenantReadTx`，复用平台 `WithTenantReadTxID`：已有同数据库、同租户普通事务时直接查询，不再次申请连接或自行提交；独立读取自行开启租户事务。禁止跨数据库或租户借用调用方事务，来源克隆读取仍在来源租户事务内完成。正文、引用和审计的写入分别遵循现有写事务、引用事务及课程复制事务契约，不能通过只读入口执行。
- 内容变更以 PostgreSQL 外壳行锁串行化校验与写入，正文更新在草稿条件更新成功后执行；状态流转的业务约束见[业务流程](05-业务流程与状态机.md#1-内容创作与发布)。引用写事务入口先取得当前租户的 PostgreSQL 事务级 advisory lock，再锁定并检查引用版本的已发布状态、读取旧集合和替换集合、刷新计数，使同来源替换、不同来源计数和内容弃用遵循一致的事务顺序；不用进程内锁。事务可借用调用方，锁和引用数据随外层事务结束，不提前释放或提交。
- 私有化:`tenant_id` 恒定;共享库内容可随离线包分发。
