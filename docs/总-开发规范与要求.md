# Chaimir 开发规范与要求总览

> 本文是 Chaimir 的执行型规范总览，用于开发、审查、修复和验收时的统一核对。
> 它汇总现有规范中的共同硬规则，不替代专项设计文档。专项文档对具体领域有更细约束时，以专项文档为准；发现文档冲突时必须先停止实现、提交证据并澄清，不得自行选择方便的一侧。
>
> 依据：AGENTS.md、CLAUDE.md、总工程目录设计、总前端设计规范、总 API 接口总览、总数据库表总览、总后端层能力索引、总技术选型、总验收标准及各模块专项文档。

## 1. 规范优先级与开发流程

### 1.1 规范来源

1. 用户明确要求和当前任务范围优先，但不能违反安全、数据隔离和公开契约硬约束。
2. AGENTS.md 与 CLAUDE.md 是代理入口和铁律索引，正文必须保持同步。
3. 总工程目录设计约束目录、分层、模块边界和文件职责。
4. 总 API 接口总览约束 HTTP/WS 契约、ID、鉴权、错误码和跨模块调用。
5. 总数据库表总览约束表、字段、ID、RLS、索引和数据归属。
6. 总前端设计规范约束前端架构、视觉令牌、组件、无障碍、交互、文案和验收。
7. 总后端层能力索引约束后端共享能力的唯一使用方式。
8. 各模块文档约束本模块业务语义、安全边界、状态机和验收场景。

### 1.2 编码前必须完成

- 读取与任务直接相关的总览文档、模块专项文档、当前实现和调用链。
- 明确成功标准、影响范围、不在范围内的事项和验证命令。
- 涉及 DTO、枚举、错误码、数据库、迁移、事件、对象 key、配置或页面时，检查全部消费者。
- 遇到歧义或文档冲突，列出解释、影响和推荐方案并先澄清，不得默默兼容两套语义。
- 先查已有共享能力和成熟库，禁止在已有能力旁边再造窄实现。

### 1.3 实现原则

- 生产级实现：禁止占位、假实现、临时 shim、静默降级和“先能跑再说”。
- 单一路径：同一能力全平台统一，不保留旧新双轨或永久兼容分支。
- YAGNI：抽象必须消除真实重复或满足明确边界；不为以后可能使用而加层、配置或扩展点。
- 精准修改：只改任务直接涉及的代码，删除本次产生的死导入、变量、分支和导出。
- 错误显式处理：任何错误都必须返回、记录并进入可恢复路径，或转换成稳定业务错误。
- 注释说明职责和非显然原因，不用注释掩盖错误设计。
- 设计变化先改文档，再同步代码、迁移、OpenAPI、SDK 和前端消费者。

## 2. 总体架构

- 单仓 Monorepo：backend、frontend、images、deploy、docs、scripts。
- 后端是 Go 模块化单体，11 个业务模块强边界；沙箱、判题、对局和扩展仿真在隔离 Kubernetes Pod 执行。
- 前端是 React + TypeScript 单 SPA，承载公共认证页、学生、教师、学校管理员和平台管理员视图。
- 基础设施是 PostgreSQL + RLS、Redis、NATS、S3 对象存储、Kubernetes/k3s、WebSocket、Prometheus/Grafana。
- 核心理念是“业务薄、引擎厚”：链、判题器、仿真、赛制等可扩展能力通过声明式配置、插件和隔离执行承载。

### 2.1 后端依赖层

    第 0 层：identity
    第 1 层：sandbox / judge / sim / content
    第 2 层：teaching / experiment / contest
    第 3 层：admin / grade / notify
    横切基础设施：pkg / internal/platform / contracts

- 高层可依赖低层，低层不得依赖高层。
- 同层业务模块不得直接 import 彼此；反向通知使用 NATS 事件。
- 模块间只通过 internal/contracts 的接口、DTO 和事件交互。
- 模块只能读写自己的表；跨模块数据通过接口或事件获取。
- admin、grade 只读聚合，不跨模块写业务表。
- 审计统一写 identity 的 audit_log；通知统一进入 notify。

### 2.2 业务模块职责

| 模块 | 负责 | 明确不负责 |
| --- | --- | --- |
| identity（M1） | 租户、账号、认证、授权、组织和审计表 | 具体课程、实验、竞赛业务 |
| sandbox（M2） | 沙箱编排、运行时适配、工具接入和 K8s 调度 | 判题规则、课程流程 |
| judge（M3） | 判题器、判题调度、结果和查重能力 | 题目权威内容、课程成绩聚合 |
| sim（M4） | 仿真包管理/审核、扩展包隔离执行和重计算 | 课程、评分和页面业务 |
| content（M5） | 题库、模板、版本、分类和共享 | 判题执行、运行环境和成绩 |
| teaching（M6） | 课程、作业、进度和单课程成绩 | 题目权威存储、跨课程 GPA |
| experiment（M7） | 实验定义、实例编排、协作和报告结果 | 引擎能力本身、跨课程聚合 |
| contest（M8） | 竞赛、赛制、报名、撮合、排行和漏洞题流程 | 引擎能力本身、课程成绩 |
| admin（M9） | 平台/学校看板、配置、告警和审计查询 | 业务数据写入、业务命令转发代理 |
| notify（M10） | 通知模板、多通道、站内信、未读和统一实时推送 | 业务数据和业务状态机 |
| grade（M11） | 跨课程聚合、GPA、审核、申诉和预警 | 单课程成绩计算、直接写 teaching |

模块接口实现必须由组合根装配和注入；不得通过导入另一个模块的 package 绕过 contracts。

    apps/web/src/
    ├── app/          Provider、错误边界、路由树、API 实例、运行配置
    ├── routes/       路由清单、懒加载、角色守卫和导航装配

    ├── features/     与后端 11 模块 1:1 的领域页面、组件和逻辑

    ├── hooks/        应用级通用 Hooks
    ├── utils/        会话、错误、应用工具和用户文案

- features/transfer 是唯一横切例外，只承载任务、产物状态和下载。
- 域内复用组件放 features/module/components；跨业务且只属于 web 的组件才放 apps/web/src/components。
- utils/labels/module.ts 只放用户文案映射，按模块拆分；不得放状态 tone、类型、选项数组或业务规则。

- 页面不得直接 fetch、axios、原生 WebSocket 或散落 API 路径。

## 4. 共享能力复用

新增实现前必须查阅总后端层能力索引。统一入口如下：

| 能力 | 统一入口 | 禁止重复实现 |
| --- | --- | --- |
| 错误/响应 | pkg/apperr、platform/response、platform/httpx | 模块自定义信封、随意错误码 |
| 日志/脱敏 | pkg/logging、pkg/privacy | 裸打印、敏感原文 |
| ID/时间/分页 | ids、snowflake、timex、pagex | 自建格式、time.Now、重复上限 |
| JSON/PG 类型 | jsonx、pgtypex | 重复数字转换、静默深拷贝 |
| HTTP/SSRF | httpx、netx | http.Get、默认客户端、私有 SSRF 规则 |
| DB/RLS | platform/db | service 持 DB、绕过 RLS |
| 事件/Redis/WS | eventbus、redis、ws | 自建客户端、私有重试/Hub |
| 文件/上传 | storage、upload | 直连 S3 对象存储、私有 token、重复魔数校验 |
| 导入导出 | transfer | 第二套任务状态机和下载授权 |
| 审计/配置 | audit、config | 自建审计、硬编码环境配置 |
| K8s/工作负载 | k8s、workload | 自建 client、重复 argv/shell 黑名单 |
| 后台任务 | background | 各模块复制 ticker/recover 循环 |

基础层只提供通用机制，业务语义、资源权限、业务错误码和状态机留在业务模块；不能为复用把业务模型泄漏到基础层。

## 5. 前后端契约

### 5.1 响应、ID 和 JSON

- 公开响应统一为 code、message、trace_id、data 语义；错误 body 不暴露 SQL、堆栈、内部字段、连接串或第三方原始错误。
- Snowflake ID 在 JSON、path、query、WS payload 和 JSONB 对外 DTO 中使用十进制字符串。
- 后端内部可以使用 int64；HTTP DTO 使用 ids.ID/字符串；前端 SDK 使用 SnowflakeID = string。
- 前端不得对资源 ID 使用 Number、parseInt、算术或隐式数值比较。
- 已知 JSON 字段必须结构化；动态 JSON 只用于明确扩展字段，并在边界严格收窄。
- JSON 严格解析拒绝尾随内容、未知关键字段和非有限数；不能把坏数据静默改成空对象。

### 5.2 路径、枚举、分页

- 动态 path segment 统一使用 encodePathSegment，防止斜杠、问号和井号改变路由。
- 后端 enum.go、公开 DTO、backend/api/paths、openapi.yaml、api-client constants、types 和页面标签一次同步。
- 只有公开枚举进入 api-client；页面不得硬编码后端状态、角色、任务状态、错误码或协议字符串。
- 分页默认值和上限是公开协议约束，集中在后端 pagex 和 SDK constants；页面只使用统一常量。
- API SDK 只能封装浏览器可调用公开接口，不得封装 internal 或 service 守卫接口。

### 5.3 鉴权

- access token 只在内存；refresh token 使用 Secure、HttpOnly、SameSite=Strict Cookie。
- refresh 不进 URL、localStorage、sessionStorage 或路由 state。
- WebSocket 先用当前登录态换短时路径绑定 ws-ticket，再以 query ticket 建连；普通 WS URL 不放 access token。
- iframe/Web 工具使用 browser-ticket，后端换路径受限 HttpOnly Cookie 并清除 query；token 不透传工具容器。
- 角色来自服务端会话，不能信任客户端参数。
- 内部 HTTP HMAC 绑定 method、path、tenant、source、时间和 trace，并校验时间窗口。

公开错误码必须使用 API 总览的固定段，不得新建未归属的错误码：

| 段 | 归属 |
| --- | --- |
| 110xx、11503–11508 | 通用、鉴权和服务装配依赖 |
| 116xx | transfer 导入导出与下载任务 |
| 117xx | storage 下载授权消费与文件读取 |
| 12xxx–14xxx | identity 账号、租户、组织和导入 |
| 2xxxx | sandbox |
| 3xxxx | judge |
| 4xxxx | sim |
| 5xxxx | content |
| 6xxxx | teaching |
| 7xxxx | experiment |
| 8xxxx | contest |
| 9xxxx | admin |
| A0xxx | notify |
| B0xxx | grade |

同一错误码不得动态代表多种用户文案；新增场景必须在所属段增加稳定错误码并同步 API 文档、后端错误定义和前端交互。

## 6. 数据、配置和后端运行

### 6.1 数据库

- 表、字段、索引用小写蛇形；主键统一 BIGINT Snowflake。
- 时间使用 UTC TIMESTAMPTZ；业务数据软删，默认排除 deleted_at。
- 租户表必须有 tenant_id NOT NULL、索引和 PostgreSQL RLS；每请求设置 app.tenant_id。
- 平台表明确全局范围并限制平台维护角色；私有化仍保持同一 RLS 逻辑。
- 枚举用 SMALLINT + Go 常量；金额/绩点用 NUMERIC；大文本和二进制进对象存储，表中只存引用。
- 外键和查询字段建必要索引，避免重复和过度索引；一个事实只存一份。
- 迁移必须有 up/down、RLS、索引和文档；SQL 改动后重新生成 sqlc，不手改生成文件。

### 6.2 配置

- 端口、连接串、密钥、外部端点、超时、资源上限、重试次数和运行阈值统一环境变量注入。
- 新配置同步 backend/.env.example、deploy/config/chaimir.env 和部署模板，并在启动时校验范围。
- JWT、加密密钥、数据库和中间件凭据走 K8s Secret/KMS，不入代码、镜像、日志或仓库。
- 前端只能读取公开运行时配置，不得下发后端 Secret、K8s 配置或数据库配置。

## 7. 安全要求

### 7.1 输入、输出和网络

- 外部输入在 API 边界校验；SQL 参数化；禁止动态 SQL 拼接。
- 外部 HTTP 统一使用 netx 公网客户端、超时、响应上限和解析后重校验；拒绝 loopback、私网、CGNAT、link-local、benchmark 和保留地址。
- 上传统一做大小、魔数、MIME、文件名、归档路径、文件数量、展开大小和病毒校验；不信任客户端 Content-Type。
- 富文本和用户输入不得进入 HTML sink；React 禁止 dangerouslySetInnerHTML，除非经过集中可审计 sanitizer。
- 下载必须经过资源权限、对象引用、统一 grant、TTL 和统一 endpoint；不返回 S3 对象存储 直链或自签 token。

### 7.2 不可信代码与资源耗尽

- 学生代码、判题器、对局和扩展仿真在隔离 Pod 执行；NetworkPolicy deny-all，配额、超时、输出上限、回收和用后即毁齐全。
- K8s exec、终端、命令工具、文件读取和 HTTP 响应必须有界，不能先完整缓冲再限制。
- 命令工具校验完整 argv 模板，不只校验可执行文件；禁止 shell、解释器入口和控制字符。
- worker、队列、重试和租约有最大尝试、过期回收、失败终态；不允许永久 pending 或 running。

### 7.3 浏览器

- CSP、HSTS、X-Content-Type-Options、Referrer-Policy、Permissions-Policy、frame-ancestors 统一配置，预览环境与生产边界一致。
- 外部导航只允许明确 HTTPS 白名单；新窗口使用 noopener、noreferrer。
- iframe 使用固定工具 origin、最小 sandbox、no-referrer；不透传用户数据和 token。
- 禁止 eval、new Function、HTML 注入、任意 postMessage、未审计 service worker 和第三方脚本。
- Web Storage 只放非敏感 UI 偏好或短期入口标记；密码、验证码和 token 永不持久化。
- Worker 封锁 DOM、网络、嵌套 Worker、存储和真实随机源；扩展包不在浏览器执行。

## 8. 错误、日志和文案

### 8.1 后端

- 错误码按 API 总览分段；同一错误码不能代表多种用户语义。
- 详细原因只进结构化日志，使用 %w 保留错误链；日志含真实 trace、tenant、操作上下文并脱敏。
- 数据库、角色、存储、事件和补偿错误不得被当成“无数据”或“无权限”吞掉。
- 审计失败必须可观测；敏感操作不能在审计失败后伪装成功。

### 8.2 前端

- ApiError 展示后端 message 和 trace_id，按 code 决定交互，不二次改写业务文案。
- 前端自身错误使用场景化文案，不显示 error.message、堆栈、SQL、内部状态或技术术语。
- console 只写结构化安全摘要，不写 Axios config、Authorization、响应 body 或 token。
- 文案自然、可理解、可操作；禁用 emoji 和开发术语。
- 页面必须有 loading、empty、error、retry/恢复路径；重要错误使用可访问 alert/status。

## 9. 前端设计与组件

- 单一浏览器入口；登录后按角色进入首个功能页；个人中心走顶栏，不占侧栏。
- 全站共用墨色底层、宣纸光面和沉浸态；不可做成互不相干的三套壳。
- 颜色、字体、间距、圆角、阴影和动效全部走 packages/ui/src/tokens/theme.css；组件禁止裸 hex 和任意颜色。
- 墨、玉、朱砂、宣纸按语义使用；朱砂不用于错误，错误使用冷红。
- 图标统一 Lucide；组件不硬编码业务文案；UI 包不发请求。
- WCAG AA：正文 4.5:1、大字/图形 3:1；焦点可见、键盘可达、信息不能只靠颜色；尊重 reduced-motion。
- 资源页统一 FilterBar、Pagination、三态和恢复路径；总量使用服务端 total/聚合，不用当前页近似。
- 枚举进度使用 ChainProgress；图表提供文字/表格降级和可访问说明。
- 多步骤有会话流程服务端草稿为权威；浏览器只保留未同步编辑态，服务端失败不得切换本地草稿提交。
- 四端角色路径固定为 student、teacher、school-admin、platform-admin；登录后直接进入该角色首个功能页，不增加独立工作台落地页。
- 学生、教师、学校管理员端顶栏提供租户内通知收件箱；平台管理员端是公告发布方，不显示租户收件箱，公告位于系统公告页。
- 认证页使用裸露底层，普通业务页使用宣纸光面，实验/仿真/答题进入沉浸式全屏；三种状态共享同一设计令牌和视觉世界。
- 品牌图、校徽和课程封面只使用平台对象引用和统一 ImageUploadField；不接受任意外链图片，不放宽 CSP。
- UI 包只接收已解析的图片地址，不知道 API；地址解析和下载授权由应用/feature 层完成。

## 10. 异步、事件、实时和文件

### 10.1 事件

- 跨模块反向通信使用 eventbus 和 contracts 事件类型。
- 事件带真实 tenant_id、trace_id、来源和幂等标识；消费失败进入统一重试/死信。
- 单向通知进入 notify 事件；终端、判题和仿真字节流等双向交互使用模块自身 WS。

### 10.2 transfer

- transfer 只管理任务状态、租约、重试、产物引用和下载，不保存模块私有业务 payload。
- 业务模块在自己的表保存可重放请求快照，由所属 worker 通过 RunXOnce 领取执行。
- Claim、Complete、Fail 使用 lease token CAS；过期可重领，旧 worker 不能覆盖新结果。
- 每次租约使用唯一临时对象 key；CAS 失败只删除自己的对象。
- 跨表创建失败条件删除未领取 task；补偿失败结构化记录，不伪装成功。

### 10.3 storage

- 对象 key 使用 tenant/module/resource_type/resource_id 层级；平台任务显式使用平台作用域。
- 统一 NewServiceFromConfig 装配扫描、TTL、签名和下载模式；业务模块只使用窄接口。
- 业务模块先验证具体资源访问权，再签下载授权；所有授权只由统一 storage download endpoint 消费。

## 11. 代码质量和重复清理

- 导出符号必须有真实消费者；无消费者的函数、类型、接口、常量和旧 shim 应删除或明确记录为预留。
- 同一协议常量只有一个真相源：后端公开枚举在 enum.go，前端公开枚举在 api-client constants，用户标签在 app labels。
- 域内重复逻辑可放 feature 共享文件；跨域稳定能力才提升到 package/platform。
- 不强行合并具有不同安全边界、生命周期或领域语义的实现。
- 测试文件、本地审查产物、生成物和密钥不进入发布提交；生成文件由生成器更新。

### 11.1 功能验收最低要求

- 所有模块：跨租户访问被 RLS 拦截；统一响应和错误码正确；敏感操作写 audit_log；业务数据软删或状态归档；SaaS 与私有化逻辑同构。
- M1：入驻审核、学校管理员初始化、导入预览/提交、双 Token 轮转、单端登录、SSO/LDAP、RBAC、密码哈希、失败锁定和账号状态机完整。
- M2：独立 Namespace、deny-all 网络、资源硬限、分阶段启动、运行时/工具声明式接入、代码和快照持久化、三重回收和回收事件闭环完整。
- M3：判题器自检、学生与判题沙箱隔离、答案黑盒、确定性重判、逐用例结果、优先级队列、失败终态、查重限频完整。
- M4：自描述插件、确定性 Worker、通用交互、回放/分享、检查点、扩展包后端隔离执行和会话回收完整。
- M5：内容类型化、草稿/发布/弃用、版本锁定、答案与题面分离、深克隆、共享库和组卷完整。
- M6：课程状态机、成员/邀请码、章节课时、作业草稿、判题和教师批改、进度、讨论公告、单课程成绩和导出完整。
- M7：组件组合向导、发布校验、并行实例编排、检查点判分、报告、协作、失败补偿和 experiment.scored 事件完整。
- M8：解题/对抗赛、实时排行、撮合、回放、报名组队、封榜、防作弊、漏洞源导入固化和双向预验证完整。
- M9：平台/学校只读看板、统一审计查询、乐观锁配置、告警通知、监控嵌入和备份记录完整，不跨模块写业务表。
- M10：模板渲染、多通道通知、站内信、未读计数、公告已读、WS 鉴权/心跳/重连/单端互斥、重试和死信完整。
- M11：跨课程只读聚合、等级/GPA、审核锁定、申诉解锁改分重算重锁、学业预警、成绩单和批量导出完整。

## 15. 后续复审执行规范

当新会话要求“全面审查、不要遗漏、检查目录职责和重复实现”时，必须按以下方式执行：

1. 主 agent 负责范围拆分、读取审查报告、判断冲突和实施修复，不把自己的主观扫描结论当成审查结果。
2. 只读审查由子 agent 分工完成；优先使用实际可用的 gpt-5.6-luna。若模型不可用，必须如实记录，不得声称已完成该模型审查。
3. 审查 agent 不修改代码、不创建迁移、不创建测试上传物；只输出证据报告。主 agent 只能根据报告实施最小正确修复。
4. 审查必须以实际文件内容、目录结构、导入关系、调用链、装配入口和文档契约为依据。脚本只能作为补充验证，不能替代文件阅读、职责判断和安全边界分析。
5. 每条发现必须包含：严重性、绝对或仓库相对路径、行号、实际代码证据、违反的规范、影响/攻击路径、唯一推荐方案、涉及的消费者和验证命令。
6. 审查范围必须覆盖生产文件清单，而不是抽样：backend/cmd、internal/modules、internal/platform、pkg、db、api、frontend/apps/web、frontend/packages、deploy 配置、OpenAPI、契约和相关文档；生成文件需单独标记并检查是否被错误手改。
7. 目录审查必须逐文件判断“应该放在哪里、为什么当前位置错误、移动后所有引用是否同步”，同时检查文件职责混杂、跨层依赖、业务代码进入共享层、公共代码未复用和域内重复实现。
8. 契约审查必须逐项追踪后端路由/DTO/enum/error code/迁移到 OpenAPI、api-client、页面、事件和存储消费者；不得只比较名称或运行脚本结果。
9. 安全审查必须覆盖低风险问题，不得只筛高风险：鉴权、越权、RLS、SSRF、XSS、CSRF、CSP、URL 导航、令牌/存储、上传下载、资源耗尽、命令 argv、K8s 隔离、日志泄露、错误吞没、依赖漏洞和供应链边界。
10. 发现文档与代码矛盾、公开契约矛盾或用户要求矛盾时，先停止对应修复并报告证据；不能通过兼容分支、双轨实现或注释掩盖矛盾。
11. 修复阶段只改确定问题和必要消费者，遵守文件职责、复用已有基础能力、保持单一路径；不顺手重构无关代码，不新增没有明确用途的抽象。
12. 修复后必须重新进行一次基于实际文件的只读复审，再运行类型检查、Lint、构建、单元测试、race、vet、gosec、govulncheck、依赖审计、契约审计、目录边界审计和 diff 检查，并分别报告实际覆盖范围。

新会话提示词应明确要求：审查 agent 只读出报告；主 agent 只依据报告修复；脚本不是审查结论；所有发现必须有文件证据；最终必须列出已审文件清单、未覆盖范围、修复文件、验证命令和剩余风险。
