# Chaimir 开发规范与要求

> 本文定义跨层工程标准。具体契约和验收条件由专项文档维护，文档更新与清理遵循[文档治理](文档治理规范.md)。更新：2026-11-27。

## 代码与注释

- **先确定行为，再动手。** 沿真实入口查清调用、状态写入和副作用，写明预期结果及验证方式。修 bug 先复现；重构前后验证同一行为。规范与实现冲突时，按已确认的目标修正；影响行为的歧义先确认。
- **做最小完整实现。** 先看代码能否省掉，再查现有能力、标准库、平台原语和已用依赖。官方自带功能或配置能满足需求时，直接使用，只保留必要的业务适配；替换时同步移除重复实现。只有现有能力无法满足已明确的功能、安全、性能或模块边界时，才在设计文档说明缺口并自行实现。只加当前需求所需的分支、类型和层级，读懂代码比缩短行数重要。业务结果、失败路径和安全边界必须完整。
- **保持一条正式路径。** 同一业务规则只由所属模块定义；一个状态只有一个权威来源，能直接推导的值不另存。当前阶段不保留旧逻辑或旧数据的兼容路径；切换时同步全部调用者、契约和配置，删除被替代的入口、字段、兜底和双轨实现。清理按实际归属处理，保留无关数据与未提交工作。重复代码确实共享语义和边界时才抽取。
- **用结构约束重复错误。** 先通过 API、类型和模块边界消除误用，再用格式化、lint、测试或运行时校验拦截。规则难以自动判断时才写入文档；变更设计先更新相应契约。
- **用命名说清做什么，注释补充为什么。** 注释保留非显然的约束、不变量和取舍；Go 导出声明按[官方文档注释规范](https://go.dev/doc/comment)写清调用契约。私有代码无需逐文件、逐函数补注释；注释随行为更新或删除。

## 后端、契约和数据

- 模块经 `internal/contracts` 交互，只访问自己的表；上层依赖下层，反向通知走事件。聚合层不直接写业务表，审计统一进入 identity，通知统一进入 notify。细则见[工程目录](总-工程目录设计.md)与[共享能力索引](总-后端层能力索引.md)。
- API、事件和 WebSocket 变更检查全部消费者；按权威契约更新 SQL、生成代码、SDK 和页面。业务错误统一用 `code`、`message`、`trace_id` 表达；保留原始错误和补偿失败的错误链，脱敏后记录上下文。见 [API 规范](总-API接口总览.md)。
- HTTP JSON 请求复用统一绑定入口，严格解析与字段校验同时执行；不要维护字段白名单或普通/严格两条路径。领域值的自定义编解码仍由其类型负责。
- 统一错误转换保留外层操作说明和并列原因；公开错误码与文案沿用原应用错误，内部原因只供日志及错误识别使用。
- SQL 参数化，按需使用事务；租户表保留 PostgreSQL RLS 和事务内租户上下文。用 sqlc 与版本化迁移；本阶段没有旧数据迁移需求，直接修订初始建库 SQL。见[数据库规范](总-数据库表总览.md)。
- 运行参数经环境变量注入并在启动时校验；密钥由 Secret/KMS 管理。任务和事件消费必须幂等；重试、租约、清理和失败终态必须有界。见[平台蓝图](00-平台总体蓝图.md)与[部署规范](总-部署架构设计.md)。

## 安全边界

- 按服务端身份鉴权，在边界校验不可信输入；上传、下载、富文本和外部访问复用统一平台能力。客户端不得取得内部答案、判题配置或密钥。敏感数据不进日志、镜像或未授权的第三方服务。
- 不可信代码在隔离环境执行，默认拒绝网络访问，并限制权限、资源、时间、输入输出与生命周期。浏览器保留安全头、工具 iframe 限制及凭证隔离。具体控制由模块安全设计、[镜像规范](总-镜像与容器设计.md)和[部署规范](总-部署架构设计.md)定义。

## 前端

- 布局服务于角色、任务和数据量；使用共享组件、令牌、Lucide 图标和 WCAG AA 要求。用用户语言展示结果和下一步，报障编号只用服务端 `trace_id`。见[前端设计规范](总-前端设计规范.md)。
- 接口细节集中在 SDK，页面负责交互和组合。派生状态在渲染时计算，用户操作在事件里处理；[Effect 用于同步外部系统](https://react.dev/learn/you-might-not-need-an-effect)。
- 可分享的筛选、搜索和分页进 URL。有会话的多步骤流程以服务端草稿为准，本地只保存未同步编辑；匿名入驻草稿在本机暂存，提交成功后清除。凭证不进 Web Storage。

## 评审与验收

评审沿调用链查职责、边界、失败路径和副作用。风险逻辑验证正常与失败场景；改动按需运行 `git diff --check`、`node scripts/audit/index.mjs --source-only`、Go 定向测试、前端类型检查与构建。评审证据、构建、镜像就绪和真实业务结果分别记录为 `PASS`、`FAIL`、`NOT_RUN` 或 `UNVERIFIED`。

镜像验收先核对入口、配置和依赖，再启动真实组合，最后完成所承诺的业务操作并检查输出、联动和资源回收。页面改动用真实角色在浏览器操作。详见[验收标准](总-验收标准.md)。
