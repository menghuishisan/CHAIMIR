## 0. 文档定位与铁律

### 0.1 这份文档解决什么问题

2026-07 全量审查结论:117 个前端文件约 1010 条问题,范式组件零引用、动效令牌值错误、视觉无辨识度。根因是**设计没有可执行的单一真相源、实现与规范脱节**。本文把重构后的设计沉淀为**可检索、可校验、可落地**的单一标准:`frontend/packages/ui` 照此实现,四端页面照此组装,验收照附录 C 检查。

### 0.2 前端铁律(违反即不可合并)

| # | 铁律 | 依据 |
| --- | --- | --- |
| FE-1 | **全令牌化**:组件零裸 hex、零任意色值。颜色/间距/圆角/阴影/动效/层级一律经 Tailwind 主题令牌(单一真相源 `packages/ui/src/tokens/theme.css`)。 | §2 |
| FE-2 | **无障碍达标**:关键文字/控件对比度 ≥ WCAG AA(正文 4.5:1、大字/图形 3:1);焦点可见、键盘可达、尊重 `prefers-reduced-motion`、信息不靠颜色单一传达。 | §3 |
| FE-3 | **禁用 emoji**:界面/文案/代码一律不用 emoji,图标统一 **Lucide**(单一图标族、描边一致)。 | CLAUDE.md §10 |
| FE-4 | **文案面向用户**:可见文字用用户能懂的自然语言,不暴露开发术语(`null`/`timeout`/字段名/`error_code`)。每条文案斟酌。 | CLAUDE.md §8/§10 |
| FE-5 | **无独立工作台落地页**:四端登录后直达该角色侧栏的第一个功能页。 | 蓝图 §8 |
| FE-6 | **底层曝光系统**:全站只有一块「墨色底层」;认证页底层全裸露、日常页浮起「宣纸光面」(**底层只在导航侧曝光**,不四周留缝)、工作台回到全屏底层。三种状态共用同一世界,禁止做成互不相干的三套壳。 | §1.2 |
| FE-7 | **已填内容刷新不丢**:多步骤/长表单的已填内容在刷新、关闭重开后必须还在。有会话的流程以服务端草稿为权威(本地只留未同步编辑态),匿名表单(仅学校入驻申请)在本机保存即满足。 | CLAUDE.md §9 |
| FE-8 | **错误分层暴露**:前端只展示友好文案 + `trace_id`,绝不显示堆栈/SQL/内部字段。按 `code` 决定交互,文案取后端 `message`。前端自身错误只展示场景文案、**不生成编号**(§6.7)。 | CLAUDE.md §8 |
| FE-9 | **窗口自适应(响应式)必做**:所有页面在常见视口与任意缩放下正常可用、无横向滚动、无遮挡错位;沉浸式工作台同样自适应。 | §6.4 |
| FE-10 | **动效有目的**:每个动画必须回答「为什么动」;高频路径不动或极快,装饰性持续动画禁止;全站统一曲线与时长令牌。 | §4 |

### 0.3 设计气质一句话

**账本的庄重 × 开发者工具的精确 × 教学产品的亲和。** 平台的一切视觉隐喻来自区块链本身:墨色底层是账本,玉色是链的生命信号,朱砂是「落印」(签名与确权),宣纸承载阅读。克制、可信、有学科代入感;明确避免 AI 紫粉渐变、霓虹玻璃拟态、装饰性持续动画。

## 1. 设计理念与品牌(墨玉体系)

### 1.1 四色各有含义:墨 · 玉 · 朱砂 · 宣纸

| 色 | 含义 | 用途 | 禁用 |
| --- | --- | --- | --- |
| **墨**(含绿的暖墨,非纯黑) | 账本底层,全站的「世界」 | 底层背景、深色面板、沉浸工作台 | 不做纯黑 `#000` |
| **玉**(jade,青绿) | 链的生命信号 | 主交互色:CTA/导航激活/焦点/进度/成功/在线 | 不大面积铺底 |
| **朱砂**(cinnabar,暖红) | 落印 —— 签名、确权、能量 | 品牌章、登录/提交类「盖章」动作、竞赛对抗能量、通知角标;另有一处登记例外见 §1.3(课程类型 MIXED 的封面题识与注册线) | **不用于错误**(错误另有冷红);同屏与玉保持约 9:1 克制比例,仅竞赛/结算场景允许放大 |
| **宣纸**(暖白) | 阅读面 | 日常页内容光面、表格/表单底 | 不做冷灰白 |

- **换主色 = 改令牌**:品牌色点位全部引用语义令牌,调整只动 `theme.css`。
- **错误色独立**:danger 用冷红(crimson),与朱砂在色相和用途上分离,避免「品牌色=报错色」的语义污染。

### 1.2 底层曝光系统(FE-6,全站结构总纲)

全站只有一块连续的**墨色底层**(substrate),所有界面是它的三种曝光状态:

| 状态 | 场景 | 形态 |
| --- | --- | --- |
| **全裸露** | 公共认证页、品牌页、结算/高光时刻 | 无光面。文字、刻线、氛围光直接生长在底层上;表单无卡片盒,输入框只有底线 |
| **光面态** | 日常页(列表/看板/表单/详情) | 导航留在底层上;内容浮起一张**宣纸光面**。缝只留在**导航侧**(顶 8 / 左 8),右下出血到视口边;圆角只左上 10;投影只从顶左透出 |
| **沉浸态** | 实验/仿真/答题/回放四工作台 | 光面退场,回到全屏底层 + 深色工具面板(`z-immersive`) |

**约束**:

- 两个区域之间**不用边线/色块分隔**,用光晕、密度、暗化渐变过渡(参照登录页:表单侧只是底层被压暗一档)。
- **光面不做成一张四周悬空的卡片**。缝、圆角、投影三样只在**挨着导航的那一侧**成立(顶 8 / 左 8、
  圆角只左上、投影只从顶左透出),右下直接长出视口 —— 纸因此有落点。四周等宽的缝把内容读作
  「被装进一个容器」,那是隔离感不是层次。
- **内容短不补版面**。纸的下边缘在视口之外,内容不足时下方留白即「纸还没到头」;
  不得为填满而加装饰块、空 Callout 或撑高的空态框。
- 页面/路由转场动效 = **光面的展开/收起/退场**,底层恒定不动(§4.4)。
- 认证页布局:约 60/40 非对称双区,同一底层;左区为面向用户的真实介绍内容(价值主张 + 能力点 + 可感数据),右区表单;底部一条页脚横贯全宽收拢两区。
  **主 CTA(登录/提交)用玉,不用朱砂** —— 朱砂只给品牌章与落印类动作(§2.1 玉:朱砂 9:1);
  登录按钮是全页最大色块,用朱砂等于把这个比例反过来。

### 1.3 Logo 与品牌章

品牌资产已定稿,组件在 `frontend/packages/ui/src/brand/`,是平台默认视觉资产的唯一来源;业务组件不自绘品牌图形、不各写默认图路径。

- **主标志(mark)**:**缺口环 + 环内注册点**。32×32 网格,笔画 3.2,圆角 3,缺口开在右边中段(y 10.9→21.1),注册点 r=2 @ (20.5,16)。读作「输入进入 → 经过规则 → 留下可复核的点」:缺口表示过程还能继续验证,点表示已留下的痕迹。只有 2 个几何元素,禁止渐变、阴影、第二个颜色。颜色走 `currentColor`,由消费方用令牌类给色。
  - **光学间隙 7.0 是全族常量**(缺口净宽 10.2 减笔画 3.2)。`public/favicon.svg` 与 `public/app-icon.svg` 是同一几何的像素级优化版(笔画 3.6、缺口 10.6),加粗时同步加宽缺口以守住这个 7.0 —— 直接缩放会因像素网格取整让缺口忽宽忽窄。改主标志几何时这两个文件必须同步。
  - favicon 与应用图标是唯一允许硬编码颜色的资产:它们由浏览器与操作系统在 React 之外加载,取不到 CSS 变量。
- **品牌章(seal)**:**同一个环,缺口被合上**,反白挖在朱砂实心方印里。开口表示「还能继续验证」,合上表示「已落印、不可逆」—— 一个记忆点两个用途,但形式可区分(描线开口环 vs 实心朱砂方印)。只承担签名、确权、结算、发布语义与认证页入场;入场时以「盖印」动效落下(§4.5),不作导航图标、不替代主标志。**错误状态永不使用品牌章**(错误走 danger 冷红)。
- **锁定组合(lockup)**:主标志 + `Chaimir`,名称用 `--font-display`(站酷庆科黄油体,已自托管),不另做定制字形。三档:wide(认证页/宽屏顶栏)、narrow(侧栏)、paper(导出/打印)。组合旁不加角色名、课程名或第三方 Logo;业务页不重复 tagline。这是布局约定而非图片,文本走 DOM,故字体缩放与多语言天然生效。
- **租户徽记(crest)**:**不做默认徽记图形**。有校徽显示校徽(`object-fit: contain`,透明底不加白框),没有则显示学校名首字(`display_name || name`)。理由:图形版所有学校长得一样,徽标位退化成纯装饰;首字块每个租户都不同且都正确,且不存在图片加载失败、不需第二层兜底。学校名文本始终并列显示,身份不依赖图形传达。
- **校徽与封面只收平台自己的图片**:`tenant.logo_ref` 与 `course.cover_ref` 存**对象引用**而非 URL,由 `POST /tenant/logo` 与 `POST /courses/cover` 上传取得。两条独立理由:生产安全头把 `img-src` 限定为 `'self' data: blob:`,外链图片会被浏览器拦掉;且 §7「不外传数据」不允许把师生的 IP 与访问时间暴露给第三方站点。**不得为此放宽 CSP** —— 放宽等于为一个字段打开一条追踪通道。两个字段都不是「填地址」而是「选文件上传」,共用 `components/ImageUploadField`(选文件 → 上传换引用 → 本地预览),预览形态由调用方给(徽记块 / 16:9 封面)。
  - **校徽只在私有化部署显示,内联下发,上传即生效**:SaaS 登录页面对的是未确定的租户,没有校徽可显示;私有化部署只有一个租户,故 `GET /tenant/brand` 免鉴权且不接受任何租户标识,前端按 `appConfig.deploymentMode` 决定是否调用。校徽以 data URI 随品牌 JSON 内联返回,不签发投放授权 —— 投放授权两端都绑登录账号,而登录页没有账号;`img-src` 本就允许 `data:`,体积由上传上限约束。校徽在租户配置页**选好即刻生效**(`POST /tenant/logo` 同一请求落库),不参与该页表单的保存动作,故助手文案必须说明这一点,避免用户以为还要点保存。
  - **封面走鉴权投放,两步提交**:封面只对课程内成员可见,故不设公开路径。上传先落教师暂存位,随创建/编辑课程提交后由服务端搬到该课程正式位——新建课程时还没有课程 id,只能这样。课程详情页与编辑表单换 `mode=stream` 授权显示真实封面;**课程列表缩略图固定用纸材质加题识** —— 列表接口已按可见性筛过课程,逐行再换一次授权不产生新的鉴权判断,只是把一次渲染变成二十多个请求。
  - **UI 包不发请求**:`TenantCrest.logoSrc` 与 `CoverImage.coverSrc` 收的都是**已解析好的地址**,解析(读 `logo_image` / 换封面授权)留在页面层。UI 包不认识后端接口,组件只负责显示与回落。
  - **上传控件的无障碍口径**:`components/ImageUploadField` 里真实的 `input[type=file]` 是唯一可聚焦控件(用 `sr-only` 而非 `hidden` —— 后者会被移出无障碍树,`FormField` 的标签就指不到任何控件),可见按钮只是鼠标视觉入口,故 `aria-hidden` 且不进 Tab 序列;上传进度放在常驻 `role="status"` 里,失败文案带 `role="alert"`。字段 id 由页面传入并同时给 `FormField` 的 `htmlFor`。
- **内容封面(cover)**:四张宣纸材质图 + SVG 题识 + 语义色注册线。材质里零可识别图形,因此一套通吃课程、实验、竞赛;题识与注册线色按业务类型给,登记在各模块的 labels 文件(如 `courseTypeCover()`),不在页面各写一遍。题识用 SVG 文字而非烘焙进图片:图像模型渲染不出可靠汉字,且烘焙的字无法翻译、无法随业务改名、读屏取不到、裁切时会被切断。**封面上的文字一律用 `--color-ink`**,不用 `ink-sub`(后者在干净宣纸上只有 5.10:1,任何墨晕都会压穿);阴影不计入 WCAG 对比度,不用它补救。
- **朱砂的一处登记例外**:课程类型 MIXED(理论与实验)的封面题识与注册线用朱砂,出现在课程列表这类日常页而非落印动作。原因是四类课程需要四个互相可分且不撞错误色的颜色,玉、蓝、墨灰之外没有第四个。单屏内朱砂仅一条 4px 竖线加一枚 20% 透明度题识,仍在 §1.1 的克制比例内。除此之外朱砂用途不变。
- 不臆造第三方品牌 Logo;引用外部标识遵守其使用规范。

## 2. 设计令牌(Design Tokens)

> 技术底座:**Tailwind CSS v4(CSS-first `@theme`)**。令牌以 CSS 自定义属性形式定义在 `packages/ui/src/tokens/theme.css`,是唯一真相源;组件消费受约束的工具类(`bg-surface`、`text-ink-sub`),**禁止任意值语法**(`bg-[#...]`、`w-[123px]` 之类,lint 卡)。原始色阶(primitive)→ 语义令牌(semantic)两层,组件只引用语义层。

### 2.1 颜色 — 原始色阶(关键锚点,全部经对比度校验)

| 色族 | 档位 | 值 | 校验锚点 |
| --- | --- | --- | --- |
| **墨 ink** | 1000 / 950 / 900 / 850 / 800 / line | `#0A100E / #0D1512 / #121B17 / #16211B / #1A2620 / #1F2D26` | 底层与深色面板梯度 |
| **墨上文字** | text / sub / faint | `#EDF3EF / #96A69E / #51625A` | 对 ink-950:≈15:1 / ≈6.8:1 / faint 仅装饰**不承载信息** |
| **玉 jade** | 300 / 400 / 500 / 600 / 700 | `#7EE7C7 / #3FD2A8 / #23BC92 / #0E9873 / #0B7A5D` | 400 对 ink-950 ≈9:1(深底点睛);**700 对白字 ≈5.1:1**(浅区实底按钮/文字);600 仅大字/图形(对白 3.7:1) |
| **朱砂 cinnabar** | 400 / 500 / 600 / 700 | `#E96B52 / #DF4B34 / #C13A26 / #A32E1D` | **600 对白字 ≈5.8:1**(实底按钮);500 只用于深底装饰/大字/品牌章;400 深底点睛 |
| **宣纸 paper** | bg / card / sunken / line / line-strong | `#F7F5EF / #FFFFFF / #EFEBE0 / #E7E3D7 / #D8D3C4` | 光面梯度:抬起片(card)与凹陷井(sunken)各向两侧拉开一档,见下注 |
| **纸上文字 ink-on-paper** | text / sub / faint | `#1C2420 / #5F6B64 / #8B948D` | 对 paper:≈14:1 / ≈5.2:1 / faint 仅占位禁用 |
| **危险 crimson** | 600 / bg / border | `#CE2C31 / #FDECEC / #F5C6C8` | 与朱砂色相分离;600 对白 ≈5.6:1 |
| **警示 amber** | 700 / bg / border | `#A16207 / #FBF3E0 / #EDD9A8` | 700 对白 ≈4.6:1 |
| **信息 blue** | 600 / bg / border | `#2E5FCC / #EBF1FC / #C4D4F5` | 600 对白 ≈5.4:1 |

> **新增颜色必须先查对比度表再入令牌**;组件层出现任何不在表内的色值即违反 FE-1。
>
> **光面梯度必须拉得开**:抬起片、光面底、凹陷井三档相邻明度差不得小于 8/255。
> 差得太小时「比地面浅一档 + 落影」表达不出抬起、「深一档」表达不出凹陷,矩形只能靠轮廓被认出来,
> 与 §6.5.1「容器不画边框」直接冲突。故 card 取纯白(在暖白纸上读作「新的一张」)、
> sunken 压到 `#EFEBE0`,并配 §2.4 的双层 `--shadow-xs`。canvas / line / line-strong 不变。

### 2.3 字体(三层字体栈,各司其职)

| 层 | 字体 | 用途 | 加载 |
| --- | --- | --- | --- |
| **Display** | 站酷庆科黄油体(ZCOOL QingKe HuangYou) | 页面大标题、统计大数字、高光时刻(结算/出块) | 自托管分片(`unicode-range` 按需下载),`font-display: swap`,回退 Noto Sans SC |
| **Body** | Noto Sans SC Variable(可变字重 100–900)+ 系统中文回退 | 一切正文、界面文字、表单 | 自托管分片,`swap` |
| **Data** | JetBrains Mono Variable(可变字重 100–800) | 代码、哈希、地址、trace_id、数据列、计时 | 自托管分片,`swap` |

- **Body/Data 必须用可变字体包**(`@fontsource-variable/*`,家族名带 ` Variable` 后缀):一份 `@font-face` 覆盖全字重。按 400/500/700 分别导入会把同一批汉字分片声明三遍,仅字体声明就能占产物 CSS 五十万字节;可变包同时只发 woff2,不产出 woff 双份资源。Display 层无可变包,只导 400。

- **字号阶梯**:`xs 12 / sm 13 / base 14 / md 15 / lg 16 / xl 18 / 2xl 22 / 3xl 28 / 4xl 38`。正文基准 14(数据密集后台);移动端正文 ≥16 防 iOS 自动缩放。
- **行高**:`tight 1.3 / normal 1.5 / relaxed 1.65`。
- **数字列必用等宽数字**(`font-variant-numeric: tabular-nums`):统计、成绩、计时、表格数字列。
- Display 字体**只用于**标题与大数字,禁止排正文;kicker/小标签用 Data 层等宽 + 大写 + 字距 `.2em`。

### 2.4 间距 · 圆角 · 阴影 · 层级 · 布局

| 维度 | 令牌 | 值 |
| --- | --- | --- |
| **间距**(4/8 节奏) | Tailwind v4 刻度类(`--spacing` 默认 0.25rem) | `p-1`=4 … `p-4`=16 … `p-16`=64;**只用刻度类,不写带方括号的任意值**。刻度是乘数不是枚举令牌,故没有 `--space-*` 变量可引用;令牌层与全局样式表(`base.css`)里的裸 px 属定义点,不算违规 |
| **圆角** | `--radius-sm/md/lg/pane` + Tailwind `rounded-full` | 6/8/10/14(lg=抬起片与**光面左上角**;pane=大面:浮层面板/底部 sheet/品牌块;`full` 用 Tailwind 内置,不另立令牌) |
| **阴影** | `--shadow-xs/sm/md/lg/pane` | 低透明多层叠加;`xs` 为抬起片专用双层落影 `0 1px 2px rgb(16 24 20/.06), 0 2px 6px rgb(16 24 20/.05)`;`pane` 为光面专属**单向**投影 `-3px -3px 14px -5px rgba(0,0,0,.38)`(只从顶左透出,§1.2);深色系阴影基于纯黑,浅色系基于 ink |
| **层级 z-index**(只许引用令牌阶) | `--z-below/ground/base/sticky/dropdown/drawer/immersive/modal/toast` | -1/0/1/50/60/80/100/120/200 |
| **布局尺寸** | `--topnav-h/sidebar-w/sidebar-w-collapsed/pane-inset` | 56/220/64/8px(pane-inset=光面到底层的缝,**只作用于顶与左**) |
| **工作台栏宽**(沉浸态) | `--wb-aside-w/wb-stream-w/wb-rail-w` | 300/320/40(rail=侧栏收起后的把手宽,§7.1) |

> **`--content-max` 已废止**。全局限宽在宽屏上把内容缩成居中一根柱子,两侧空白复现外壳刚去掉的隔离感。
> 光面内容按纸宽铺满,靠 §6.4 分档内距控制呼吸。**唯一例外是「学习阅读族」的正文**(§6.5.3 第 ⑦ 族):
> 该族任务是读,行宽必须受限;限宽写在该族骨架里,不做成全局令牌。

**复合工具类**(`@utility`,定义在 `packages/ui/src/tokens/theme.css`):`pane-frame`(光面外框的顶左缝)、
`well`(凹陷井,§6.5.1)、`metric-band`(看板族 Stat 指标带,`auto-fit` + `minmax(13rem,1fr)`)、
`pressable`(按压反馈)、`hit-target`(触达区外扩)、`skeleton-shimmer`。

> **`metric-band` 而不是定列数栅格**:项数与列数不一定整除 —— 两项摊进四列会各自拉成半屏宽的巨卡,
> 五项会在第二行留三个空位。auto-fit 让卡宽随内容在下限以上自适应,项数变化时不产生空版面(§6.5.0 通则 3)。

> 与 Tailwind 同名组的自定义类(`rounded-pane`、`shadow-pane`、`duration-*`、`z-*`、`animate-*`、`w-wb-*`)
> 以及会被原生类接管的复合类(`pane-frame` 被 `p-*` 接管、`metric-band` 被 `grid-cols-*`/`display` 接管)
> **必须登记进 `lib/cn.ts` 的 twMerge 配置**,否则消费方经 `className` 覆盖时胜负会落到样式表生成顺序上。
> 取值由规范锁定的复合类(`well`/`pressable`/`skeleton-shimmer`)不登记冲突 —— 它们的正确答案是**拒绝覆盖**,
> 由静态门禁拦截,而不是让覆盖确定性地生效。

### 2.5 动效令牌(FE-10 的物质基础)

```
--ease-out:     cubic-bezier(.23, 1, .32, 1);    /* 入场/交互反馈:先快后稳 */
--ease-in-out:  cubic-bezier(.77, 0, .175, 1);   /* 屏内位移/形变 */
--ease-drawer:  cubic-bezier(.32, .72, 0, 1);    /* 抽屉/大面板 */

--t-press: 120ms;    /* 按压反馈 */
--t-fast:  160ms;    /* hover/焦点/小元素 */
--t-base:  200ms;    /* 下拉/弹层/Tab */
--t-slow:  280ms;    /* 模态/抽屉/光面转场 */
--t-entrance: 550ms; /* 低频页入场单元素上限 */
```

- **禁止** `ease-in` 用于任何 UI 动效;禁止 linear(仅加载指示与进度类可用)。
- 出场时长 = 入场的 60–70%。
- 所有时长/曲线经令牌引用,组件内写裸 `cubic-bezier`/裸毫秒即违规。

## 3. 无障碍基线(WCAG AA,强制)

### 3.1 对比度

| 元素 | 标准 | 本规范落点 |
| --- | --- | --- |
| 正文文字 | ≥ 4.5:1 | 纸上 `text` ≈14:1、`text-sub` ≈5.2:1 |
| 大字(≥24px/粗18.5px)、图形/图标 | ≥ 3:1 | 状态点、指示条、图标达标 |
| 实底按钮文字 | ≥ 4.5:1 | 玉实底用 jade-700(≈5.1:1);朱砂实底用 cinnabar-600(≈5.8:1);危险用 crimson-600 |
| 深底文字 | 主 ≥4.5:1 / 次 ≥3:1 | `dark-text` ≈15:1;`dark-text-sub` ≈6.8:1 |
| 焦点环 / 装饰 | ≥ 3:1 | jade-400 在深浅底均达标 |

### 3.2 焦点 · 键盘 · 动效 · 颜色

- **焦点可见**:全局 `:focus-visible` 焦点环(2px `--color-accent` + 2px offset),绝不 `outline:none` 不补替代;鼠标点击不显示焦点环。
- **键盘可达**:Tab 顺序 = 视觉顺序;模态/抽屉/向导提供 Esc/取消逃生路径;拖拽给键盘替代。Radix 原语的键盘行为不得覆盖破坏。
- **跳过链接**:`.skip-link` 跳主内容;`.sr-only` 读屏文本。
- **reduced-motion**:全局把位移/缩放动画降到 ~0,保留必要的透明度反馈;流式图表冻结、保留当前值大字。
- **颜色非唯一**:状态必带图标或文字;图表系列用线型/纹理补。
- **图标按钮**:必带 `aria-label`;触达区 ≥44×44 —— 视觉尺寸可以更小,但必须经 `hit-target` 工具类(透明伪元素外扩命中区)补足到 44。
- **表单**:`label[for]` 显式关联;`aria-invalid`;错误 `role="alert"`;提交后聚焦首错;Toast `aria-live="polite"`。
- **标题层级**:`h1→h6` 顺序不跳级。

### 3.3 无障碍验收清单(每页过)

- [ ] 文字/控件对比度达标(§3.1)
- [ ] 仅键盘可完成核心流程,焦点全程可见
- [ ] reduced-motion 下无信息丢失、无布局错乱
- [ ] 状态/图表不靠颜色单一传达
- [ ] 图标按钮有 `aria-label`,图片有 alt
- [ ] 表单错误就近、读屏可感知、自动聚焦首错

## 4. 动效系统(全站统一,含签名时刻)

> 动效按**频率→目的→曲线→时长**四问决策。原则:高频不动、低频克制、签名时刻集中花预算;只动 `transform/opacity`;全部可中断、不阻塞输入;reduced-motion 全量适配。

### 4.1 频率决定是否动

| 频率 | 判定 | 处理 |
| --- | --- | --- |
| 极高频(键盘触发、命令面板、切 Tab 键) | 每天 100+ 次 | **不动** |
| 高频(hover、菜单、下拉、行展开) | 每天数十次 | ≤`--t-base`,或仅透明度 |
| 中频(模态、抽屉、Toast、页面切换) | 偶发 | 标准动效(§4.3) |
| 低频(登录入场、结算揭晓、首次引导) | 每天 ≤1 次 | 允许编排(总时长 ≤1.1s,全程可交互) |

### 4.2 每个动效必须有目的

合法目的:空间连续(从哪来回哪去)、状态表达(进度/判定/保存)、操作反馈(按下/成功/失败)、防突变(内容替换渐变)。「好看」不是目的;装饰性持续动画(无限脉冲/呼吸/旋转,除加载指示外)一律禁止。

### 4.3 标准动效表(参考起点,开发实测微调)

| 场景 | 动效 | 时长/曲线 |
| --- | --- | --- |
| 按钮/可点卡按压 | `scale(.97)` | `--t-press` / `--ease-out` |
| hover(卡片/行/导航项) | 背景/边框/阴影过渡,不位移或 ≤2px | `--t-fast` |
| 下拉/Popover/Tooltip | 从触发源缩放淡入(`transform-origin` 对齐触发点;`scale(.96)+opacity`,**禁止 scale(0)**) | `--t-base` / `--ease-out`;键盘打开即时 |
| 模态 | 居中 `scale(.97)+translateY(8px)` 淡入;scrim 40–60% | `--t-slow` / `--ease-out` |
| 抽屉/Bottom-sheet | 位移入场 | `--t-slow` / `--ease-drawer` |
| Toast | 从堆叠方向进出,同向可滑动关闭 | sonner 内置动效(登记例外:不经令牌,行为符合本表原则) |
| Tab 指示条 | 滑动跟随(非整条重绘) | `--t-base` / `--ease-in-out` |
| 列表批量入场 | 逐项错峰 40–60ms,总时长 ≤600ms,不阻塞交互 | `--ease-out` |
| 骨架屏 | shimmer(属于加载指示,允许循环) | 1.6s linear |
| 数字变化(统计/比分) | 计数滚动 ≤900ms,ease-out;高频刷新的数字**不滚动**直接替换 | — |

**浮层 transform 所有权(强制)**:经 Floating UI/Radix 定位的浮层,定位外层独占库写入的 `transform`;视觉动效只做在内层(opacity/scale)。同一元素不得同时承担坐标与动画 transform。

### 4.4 光面转场(路由级动效)

- 同壳内切页:光面内容区 `opacity + translateY(8px)` 交替,`--t-base`;底层与导航不动。
- 进入沉浸态:光面向四周展开至全屏消隐(`--t-slow`),底层显露,工作台条自顶滑入;退出反向。**方向语义**:进=展开,退=收拢,保持空间连续。
- reduced-motion:全部退化为直接切换 + 短透明度过渡。

### 4.5 签名时刻(全站动效预算集中花在这里)

| 时刻 | 动效 | 说明 |
| --- | --- | --- |
| **落印** | 品牌章 1.5 倍缩小盖下 + 短暂过冲 + 一圈墨晕散开;「盖章」类主按钮按压时从点击处渗出印泥圈 | 认证页入场、签名/确权类提交;WAAPI 实现可中断 |
| **铸块** | `ChainProgress` 新区块从右滑入接上链尾 + 一次玉色脉冲(单次,非循环) | 检查点通过、步骤完成、竞赛得分 —— 全站进度语言(§5.4) |
| **入场编排** | 低频页逐层浮现(60–90ms 阶梯 + blur 6px→0 显影) | 仅认证页/结算页;日常页只做单层淡入 |
| **结算揭晓** | 大数字计数滚动 + display 字体 + 玉色辉光(静态阴影非动画) | 竞赛结算全屏 |

### 5.2 React 组件契约(强制)

- **零裸 hex、零任意值**:只用主题工具类;新颜色/尺寸先入 `theme.css` 再用;ESLint 卡任意值语法。
- **状态齐全**:交互组件必须实现 hover/focus-visible/active/disabled;异步加 loading;列表类加 empty/skeleton/error。**缺态即不完整**。
- **受控优先**:表单组件受控;校验在 blur;提交 loading→成功/失败就近反馈。
- **props 命名**:`variant/size/loading/disabled/invalid`,不用样式名当 prop;CVA 变体即 props 契约。
- **图标**:统一 Lucide 经 `Icon` 封装注入,尺寸走令牌(16/18/20),描边 1.8 一致;禁裸 SVG 散落(仿真/拓扑画布内的语义图形除外)。
- **可组合**:复合组件用组合(Dialog=Trigger/Content/Head/Foot;Table=列定义驱动)而非巨型 props。
- **文案外置**:组件不硬编码业务文案;用户向文案在应用层 `labels`。

### 5.3 组件化原则

1. 复用 ≥2 处且结构稳定 → `packages/ui` 基础组件。
2. 业务语义强、跨端复用(成绩单元格/沙箱状态灯/检查点判分卡/投票矩阵/攻防拓扑)→ `packages/ui/src/biz` 业务组件。
3. 仅单页用、结构易变 → 留在页面内,不过早抽象。

### 5.4 签名组件:ChainProgress(全站进度语言)

进度条在全站被「链」替代:检查点/步骤/竞赛轮次渲染为一节节区块(方块 + 短链节),已完成=玉实底、当前=玉描边半透、待完成=墨描边、失败=crimson 描边。通过时新区块滑入接上链尾 + 单次玉色脉冲(§4.5 铸块)。**必配** `n/m` 文字与 `aria-label`(如「检查点进度:2/4 已完成」);reduced-motion 下仅状态切换无动画。适用:实验检查点、向导步骤、竞赛轮次、批量任务进度;不适用:不可枚举的百分比进度(仍用 Progress)。

## 6. 信息架构与导航

### 6.1 四端结构

四端**同一浏览器入口、同一外壳、同一组件、不同角色路径与导航配置**。私有化部署无 platform-admin。

| 端 | 登录落点 | 侧栏分组(与实现一致) |
| --- | --- | --- |
| **student** | `/student/courses` 我的课程 | 学习区(我的课程/实验实训/仿真实验室/竞赛参赛/竞赛战绩)· 学业区(成绩中心/学业预警) |
| **teacher** | `/teacher/courses` 课程管理 | 教学 · 实践 · 资源 · 组织与成绩 |
| **school-admin** | `/school-admin/users` 账号管理 | 用户与组织 · 概览 · 教务与成绩 · 系统配置 |
| **platform-admin** | `/platform-admin/schools` 学校管理 | 租户 · 运营 · 底层资源 |

**登录直达该端第一个功能页,四端均无仪表盘/工作台落地页**(FE-5):落点就是上表「登录落点」列的那一个真实功能页,不存在只做汇总的首页。看板类页面(学校看板、平台看板)是侧栏里的普通功能项,不承担落地职责。

**个人中心不进侧栏**:账户相关能力(个人资料、修改密码、登录会话、换绑手机号)统一由顶栏头像菜单进入(见 §6.2 顶栏),侧栏只放角色业务功能,四端一致。

### 6.2 导航规范

- **登录直达功能页**(FE-5)。
- **侧栏在底层上**(非独立面板):分组标题(Data 层等宽 10px 弱色,纯中文短词,不加英文副标)+ 菜单项(Lucide 图标+文字+可选角标)。激活态:玉色浅底 + 左 2px 玉指示条 + 字重升。角标计数用于待办。
- **侧栏名称单一口径**:分组标题与菜单项名称以 `docs/前端后端功能对齐清单.md` §1.4 的四端侧栏表为唯一真相源,代码里的 `<role>Navigation.ts` 必须逐字一致;同一入口不得在代码用短名、文档用长名。
- **图标+文字并存**,绝不纯图标;当前位置必高亮。
- **面包屑**:3+ 层级页必带。
- **导航一致性**:四端侧栏与顶栏的位置/行为一致;顶栏铃铛按 §6.3 的收件箱归属决定该端是否出现,出现时位置与交互完全一致。危险操作(登出)与普通项视觉/空间分离。
- **顶栏(底层上)**:品牌章+名称、任务中心、通知铃铛(仅设有收件箱的端,见 §6.3)、头像菜单。头像菜单是个人中心的唯一入口(个人资料/修改密码/登录会话/退出登录),不在侧栏另开账户分组。搜索放各资源页,由真实列表接口驱动。
- **侧栏底部**:同步状态一行(Data 层等宽,如「● 已同步」),是底层「账本活着」的常驻微表达(静态,非动画)。
- **顶栏派生路径**:壳层按该端 `pathPrefix` 派生三条共享路径 —— 任务与下载 `{prefix}/tasks`、个人中心 `{prefix}/profile`、通知收件箱 `{prefix}/notifications`(仅有收件箱的端注册)。这三条不进侧栏,由顶栏进入,四端路径形态一致。公告发布是**侧栏**功能页 `{prefix}/announcements`,只在 school-admin 与 platform-admin 存在,与收件箱不是同一个页面(一个「收」、一个「发」)。

### 6.3 通知:顶栏铃铛

**通知中心 = 租户内站内信收件箱**,不是公告发布台。因此:

- **铃铛只在 student / teacher / school-admin 三端渲染**:M10 收件箱、未读数、通知偏好、公告标记已读、业务 `WS /api/ws` 都要求租户身份(`notification`、`notification_preference` 表 `tenant_id NOT NULL`),平台管理员没有租户,收不到站内信。
- **platform-admin 端不设通知铃铛**:平台管理员是**公告发布方**而非站内信收信方,其公告能力由侧栏「系统公告」页承载(`system_announcement.tenant_id` 可为 NULL ⇒ 平台级公告成立);平台可读平台范围公告、可发布公告,但无收件箱、无未读角标、无通知偏好、无业务 WS。
- **school-admin 端两者都有**:既有本校范围的公告发布(侧栏「系统公告」),也有自己的站内信收件箱(顶栏铃铛)。
- 铃铛带未读角标(朱砂点,深底上点睛);下拉(Radix Popover):最近通知 + 系统公告 + 「查看全部」。
- 数据经 M10 notify,前端不自建通知存储。是否渲染铃铛由该端导航配置显式声明,壳层不在运行时判角色枚举。

### 6.4 窗口自适应(FE-9)

**断点系统**(Tailwind 主题统一,禁止魔法媒体查询):

| 令牌 | 宽度 | 主要行为 |
| --- | --- | --- |
| `sm` | 640 | 单列;侧栏抽屉化;多列表格转行卡 |
| `md` | 768 | 双列;侧栏可收为图标条;纸内距升到 32×24;光面缝与左上圆角出现 |
| `lg` | 1024 | 侧栏常驻(220↔64 可折叠);多列恢复;双栏骨架(队列+详情 / 目录+正文)成立 |
| `xl` | 1280 | 网格列数上限放开(指标带 auto-fit 可到 5-6 列) |
| `2xl` | 1536 | 留白增大;仅「学习阅读族」正文行宽受限,其余仍铺满 |

**行为约定**:

- 流式优先:`grid`/`flex` + `minmax/auto-fit/clamp`;禁止写死像素宽。**不用全局 `max-width` 居中**(§2.4 `--content-max` 已废止)。
- 侧栏:`≥lg` 常驻可折叠;`<lg` 抽屉(汉堡触发 + 遮罩 `z-drawer` + Esc + 焦点陷阱;遮罩层级必须高于侧栏静置层)。
- 光面:`<md` 时 `pane-inset` 归零、圆角归零(全宽),底层曝光让位于内容空间。
- 沉浸工作台:三区 `<lg` 纵向堆叠(中舞台优先,两侧收成舞台上/下的折叠条且默认收起;`≥lg` 收成 `--wb-rail-w` 竖向把手);画布 `viewBox` 等比缩放;移动端可降级只读但不得报错空白。
- 弹层:Modal `max-width + max-height:88vh`;窄屏底部 sheet。
- 图表:声明 `aspect-ratio` 防 CLS;小屏简化刻度。
- 触控:目标 ≥44×44,间距 ≥8px;hover 仅增强。

#### 6.4.1 移动端四条硬规则(`<md`)

窄屏不是「桌面布局按比例缩小」,四条硬规则:

1. **内距分档**。纸内距 `32×24` 只给 `≥md`;`<md` 用 `16`。
2. **指标带 `<md` 一律降级,禁止竖排大卡**。资源列表族压成 **2×2 内联摘要**(标签与数值同行);
   看板族压成 **2×2 紧凑卡**(数值降到 22px)。
3. **多列表格 `<md` 换行卡**,不做横向滚动表格。行卡 = 主字段一行 + 次要信息一行 + 状态徽标 + 右箭头;
   列优先级在该族骨架里声明。**判据是「375 下会不会溢出」**:列数 ≥4,或任一列承载长文本、
   状态组合、操作按钮时一律换行卡。唯一例外是 **≤3 列的短值对照表**(如「不低于 90 / A / 4.0」
   这类等级映射)—— 它在 375 下本就不溢出,而且它的意义就在于逐行横向对照,
   摊成卡片反而把对照关系拆散了。例外只对「短值」成立,不对「列少但值长」成立。
4. **双栏骨架换两级页面,不压扁成两栏**(此条断点为 `<lg`:队列+详情、目录+正文两栏各自需要 ≥1024 才够用)。
   审阅队列族变「队列页 → 详情页」:详情页顶栏给返回 + 当前对象 + `第 n 条 / 共 m 条`,
   处理动作条钉屏幕底部,「保存并看下一条」**不退回列表**;学习阅读族的目录收成顶部抽屉触发条
   (当前位置常显),右栏沉为底部常驻条,正文此时不再限宽(视口本身已在 40 字/行以内)。

**红线**:任何视口不得出现非预期横向滚动;不得写死宽度导致遮挡截断;不得禁用缩放;固定元素必须为内容预留安全内距。

**验收**:每页 375/768/1024/1440 及任意缩放走查;横竖屏可用;reduced-motion 与大字模式不破版。
**`<md` 附加验收**:首屏必须出现至少一条业务数据(列表族)或一张图(看板族);
指标带不得超过首屏高度的 1/6;不得存在横向滚动的数据表。

### 6.5 页面族谱:光面态按任务分族

> 光面态共 **8 族**,分族依据是**用户在这一页做什么**,不是内容属于哪个模块。
> **同族内骨架必须一致,不同族之间骨架必须不同** —— 前者防「每页布局都不一样」,后者防「每页一个模子」。
> 新增页面先归族(§6.5.3),再按该族骨架组装;不属于任何一族时先补族定义,不得挪用邻族骨架。
> 结构原语由 `PageScaffold` 提供,骨架差异由各族自己的组合表达。

#### 6.5.0 三条通则(八族都适用)

1. **不重复说同一件事**。面包屑最后一节与 `h1` 不得同名,面包屑只到父级;页面没有父级层次时不出面包屑。
   分组标题、页头摘要、分页页脚三处的记录数只留一处。
2. **页面图标不是每页必需**。`h1` 左侧的玉浅底图标块只在该图标能**区分同族页面**时出现;
   它不承载信息,统一给所有页面加只会削弱页面之间的辨识度。
3. **不用空组件撑版面**。「分组标题 + 说明 + 一个 Callout」不构成内容。页面没有主体数据时走
   第 ⑧ 族(引导族)骨架,不得按资源列表族排出骨架再用空 Callout 填充。

#### 6.5.1 光面内的层次:两级容器,容器不画边框

日常页的「套壳感」来自同一件事:光面本身是一个近白圆角矩形,里面又摆一堆**近白圆角描边矩形**,
矩形里再摆矩形。三层轮廓互相嵌套,却没有一层在表达深度 —— 看上去就是壳里套壳。

因此光面内只有两级容器,且**容器一律不用边框表达自己**:

| 层级 | 语义 | 表达 | 用在哪 |
| --- | --- | --- | --- |
| 0 光面 | 宣纸整页 | `bg-canvas` + 左上单角 `rounded-tl-lg` + 单向 `shadow-pane`(壳层给,页面不重复) | MainLayout |
| 1 抬起片 | 一条并列条目 / 一块可操作区 / 一张表 | `bg-surface` + `shadow-xs`,**无边框**(比地面浅一档 + 落影 = 纸片浮在纸上) | Card、Stat、Table、Empty |
| 2 凹陷井 | 抬起片**内部**的字段分组或只读信息块 | `well` 工具类:`bg-surface-sunken` + 圆角,**无边框、无投影**(同一张纸上的凹陷区);内距在调用处写(`p-4` 分组 / `p-3` 信息条) | 表单分组、只读信息条、FilterBar |

**红线**:

- 容器不画边框。`border` 只用于**分隔**(表头下、行与行之间、区块收束线)和**输入控件**自身,不用于圈出一个盒子。
- 不出现第三级。井里不再套井,也不在井里画边框条目 —— 并列条目用 `divide-y` 的分隔线或纯间距表达。
- 井只出现在抬起片内部。直接摆在光面上的分组要么升级为抬起片(Card),要么就是「标题 + 内容」不带容器
  —— 井表达的是「这块纸被压下去了」,没有那块纸时它无所指;摆在光面上只会多出一个与抬起片并列的盒子。
- 分组不等于盒子。PageSection 只给「标题 + 说明 + 右侧动作 + 间距」,它**永远不画容器**。
- **浮层不在这套层次里**:Modal / Drawer / Menu / Popover / Toast 浮在任意内容之上,可以用发丝边把自己
  从未知背景上分离;它们的**内部**仍按上表算 —— 浮层面板本身是抬起片,面板内的分组是井。

> `well` 是工具类而非组件:井只有底色与圆角两条声明,做成组件会让每个字段分组多包一层 JSX
> 却拿不到任何行为。真正带行为的筛选区仍然是组件(`FilterBar`)。

> **只约束光面态**。沉浸态(§7)另有一套成立的语法:壳与手风琴只用**边线分隔**(`border-b/r/l/t`)
> 从不画盒,盒只出现在叶子条目上,因此那边本来就只有一层;而墨色上的发丝线(`dark-line` 比
> `dark-surface` 亮一档)是往后退的,不像近白底上的灰描边会成为区域里对比最高的元素反而抢眼。
> 两边各自成立,**不要把任一侧的写法搬到另一侧**。

#### 6.5.2 筛选区:统一用 FilterBar,不塞进分组标题右侧

筛选控件塞进 `PageSection actions` 会被挤成一行长条:标签、下拉、分段、搜索框、按钮各有各的高度和基线,
窄屏还会与标题抢空间 —— 这是「布局很乱」的主要来源。故:

- **筛选一律不放分组标题右侧**,全部走 `FilterBar`,哪怕只有一个控件 —— 一页里有的筛选在标题右边、
  有的在标题下方,就是「每页布局都不一样」的来源。
- FilterBar 里两类字段共存:即时生效的(下拉/分段控件,`onChange` 即筛选)与需要确认的(搜索词、日期区间)。
  后者由 FilterBar 的 `onSubmit` 统一收口 —— 整条渲染为 `form`,末位出一个提交按钮,输入框里按回车等于点它,
  页面不再各自包一层 `form`。
- 每项必须有**可见标签**(`FilterField`)。只给分段控件配 `aria-label`,视觉用户看不出这排按钮在筛什么。
- `PageSection actions` 只放**该分组的动作**(刷新、导出、新建)和**视图切换**(同一份数据换呈现方式,
  如「图表 / 数据表」);凡是改变「取哪些数据」的都算筛选,进 FilterBar。
- **FilterBar 的井必须落在抬起片内部**,两条出路二选一(§6.5.1 红线第 3 条):
  - **表格型列表页**:进 `DataPanel` 的 `filter` 槽位,与数据表、分页同处一块抬起片。
    筛选井与数据表各成一个盒子并排堆在光面上,即违规。
  - **卡片网格型列表页**:数据区本身就是一排 `Card`(已是抬起片),塞进 `DataPanel` 会成为片里套片
    (§6.5.1 不出现第三级)。此时 FilterBar 传 `bare` —— 去掉井底色只保留字段排布,
    以「标题 + 内容不带容器」的形态直接排在光面上。**问题从来不是「排在光面上」,而是「井色摆在光面上」**:
    凹陷色与光面只差一档,摆上去表达不出凹陷。

**角色与分组表达**:强调色只在玉/朱砂体系内经语义令牌映射;四端同一外壳与交互模型,差异在信息密度/图标/指标语义/数据列,不是四套风格。日常页动效仅限进入、反馈、焦点/按压、进度表达。

#### 6.5.3 八族骨架

| # | 族 | 用户在做什么 | 骨架(桌面) | 关键约束 |
| --- | --- | --- | --- | --- |
| ① | **资源列表** | 在一批同类记录里找一条 | 页头(`h1` + 描述 + 主操作)→ **内联指标摘要**一行 → **一块抬起片**内含 FilterBar 井 + 数据表 + 分页页脚 | 指标不占 Stat 大卡,退为一行摘要;筛选/表/分页同处一片;分组标题不与页头重复 |
| ② | **看板** | 看趋势与总量 | 页头 + 时间范围切换 → **Stat 大卡指标带**(`auto-fit`)→ 图表网格 | 唯一保留 Stat 大卡的族;历史序列先出图(§8.3);无数据表主形态、无 FilterBar |
| ③ | **配置表单** | 改设置 | 页头 → 左分组锚点 + 右分组表单 → **底部粘性保存条** | 无指标带、无数据表;只读信息进井、可改字段进抬起片;保存态(改了几处/存没存)常显 |
| ④ | **详情** | 核对一个对象 | **对象身份区**(名称 + 状态徽标 + 关键属性横排 + 主操作)→ Tabs 分子域 → 当前域内容 | `h1` 由 `ObjectIdentity` 的对象名承担,`PageHeader` 只出面包屑(一页一个 h1,§6.5.0 通则 1);对象属性用横排而非 Stat 卡(属性不是指标);子域用 Tabs 不做长条纵向堆叠 |
| ⑤ | **审阅队列** | 逐条处理完一批 | 页头(标题 + 待办摘要一行)→ **左队列(固定宽)+ 右详情与处理表单** → 右下动作条 | 无指标带;筛选并入队列头;键盘上下切条;提交后自动进下一条 |
| ⑥ | **时间流** | 从新到旧扫一遍 | 页头 → **一块抬起片**内含 FilterBar 井 + 按天分组的事件轴 + 加载更多 | 不用等宽多列表格;每条 = 时间 + 状态点 + 一句用户向主文 + 一行技术细节 |
| ⑦ | **学习阅读** | 读内容 | 页头(课程上下文)→ 左目录 + **限宽正文** + 右进度/动作栏 | 全族唯一限宽正文(约 60–75 字符/行),与其余七族「铺满纸宽」相反 |
| ⑧ | **引导** | 去别处办这件事 | 页头 → **一块抬起片**说明「这里能做什么、为什么不在这里做」+ 明确出口按钮组 | 页面本就没有主体数据,不得排出资源列表骨架再用空 Callout 填;出口必须是按钮不是正文里的链接 |

**归族判据(按先后顺序问)**:主体是一批同类记录吗 → ①;主体是聚合数字与趋势吗 → ②;
主体是可改字段吗 → ③;主体是单个对象的属性吗 → ④;要逐条产出处理结论吗 → ⑤;
主体按时间排序且只读吗 → ⑥;主体是供阅读的长内容吗 → ⑦;页面自身没有主体、只负责导向别处吗 → ⑧。

**族外**:向导走 §6.6,沉浸式工作台走 §7,认证页走 §1.2 全裸露态 —— 三者都不套用本节骨架。

#### 6.5.4 跨族元件规则

**指标(①的内联摘要与②的 Stat 大卡同受此约束)**:

- **只承载可度量的数字**。静态属性(赛制/参赛形式/封榜时长)、筛选状态(「筛选条件 无」)、
  范围常量(「可查询范围 本校」「监控范围 最近 30 条」)不占指标位 —— 它们进 DescriptionList 或分组说明,
  否则 Display 字体被用来排正文(违反 §2.3),整页也看不出哪个数字才要紧。
- **必须是全量口径**。数值只能取服务端聚合或服务端 `total`,**禁止用当前页返回的列表切片统计后当全量展示**
  (第 1 页 20 行算出的「涵盖分类 4」在总量 41 条时就是错数)。拿不到全量聚合就不要这个指标,
  不做近似、不靠「本页」这类前缀把错数合法化。
- 数字用 Display + `tabular-nums`;状态用文字补足颜色;可枚举进度用迷你 ChainProgress。

**三态(每族的数据区都必须齐)**:加载 = 骨架屏预留空间;空态 = 引导 + 行动按钮;错误 = 可恢复 + 报障编号。

**分页**:凡分页数据必接 `Pagination`;**总页数 ≤1 时不渲染分页控件**,只保留记录总数。

**页面级动作**:主操作放页头右侧;分组级动作(刷新/导出/新建)放 `PageSection actions`;
表单类动作区做成可聚焦抬起片(标题 + 说明 + 显式表单标签 + 提交 loading),成功/失败就近反馈,
失败只显示用户向文案 + `trace_id`。

#### 6.5.5 非整页视图单元(八族之外的两类,同样受约束)

八族描述的是**整页**(自带 `PageScaffold` + `PageHeader` 的那一层)。仓库里还有两类不是整页、
但同样承载布局的视图单元 —— 它们不属于任何族,却必须有明确规则,否则「按族重构」会把它们漏在原地。

**A. 浮层表单**(Modal / Drawer 内的表单与确认框):

- 面板本身是抬起片,面板内的分组是井(§6.5.1 已定);面板可用发丝边把自己从未知背景上分离。
- **不出页面头**:没有面包屑、没有 `h1`、没有页面图标 —— 浮层的标题由 `ModalTitle` 承担。
- **不出指标带、不出分页**:需要这两样说明它其实是一页而不是一个浮层,应当改成整页并归族。
- 动作固定在 `ModalFooter`,主操作在右;`<md` 走底部 sheet(§6.4)。
- 字段一律经 `FormField`(显式 `label[for]` + error/helper 关联);只读信息进井。

**B. 页内子视图**(由父页的 Tabs 或分区装载,如课程详情下的章节课时/成员/作业):

- **不得自带页面头、面包屑、指标带** —— 那三样属于父页,子视图再出一遍就是重复(§6.5.0 通则 1)。
- 自己的骨架取它在父页里承担的角色对应的那一族**片段**:列表型子视图用 `DataPanel`
  (筛选井 + 数据区 + 分页同处一片),表单型子视图用「分组 + 底部粘性保存条」,只读属性型用 `DescriptionList`。
- **同一父页下的子视图必须同构**:三个 Tab 里两个用 `DataPanel`、一个手写盒子,
  就是「每页布局都不一样」在页内的翻版。
- 子视图不做自己的三态壳:加载/空/错由父页的资源三态统一给,子视图只负责内容。

> **归属判定(穷尽,没有第七种落点)**:自带 `PageScaffold` → 八族(§6.5.3);
> 在 Modal/Drawer 里 → A;被父页装载 → B;认证页 → §1.2 全裸露态;工作台 → §7;向导 → §6.6。
> 新增视图若都不属于,**先补规则再写代码**。

### 6.6 多步骤流程持久化(FE-7)

- 判定标准:刷新页面或关闭重开后,已经填过的内容必须还在。
- 有会话的流程:每步/定时(参考作业草稿 60s)存服务端,服务端草稿为权威;本地只保存尚未同步的编辑态与最近同步标记,不得在服务端读写失败时替代服务端草稿进入提交链路。进入向导先拉服务端草稿。
- 匿名表单(仅学校入驻申请):没有账号可归属,不调草稿接口;在本机保存已填字段,提交成功后立即清除。
- 登录凭证(密码/验证码)任何场景都不落本地存储与路由状态,只在内存暂存。
- Autosave 组件显示 saving(amber)→saved(玉)。
- 向导步骤用 Steps/ChainProgress,禁止把步进做成手填数字输入。

### 6.7 错误展示规范(FE-8 的落地口径)

> 错误分**两种来源**,展示方式不同;判定依据只有一条:异常是否为 api-client 产出的 `ApiError`。

**A. 后端签发的业务错误(`ApiError`)** —— 后端信封 `{ code, message, trace_id }`:

- 展示 `message`(后端已是用户向文案),**不做前端二次改写**,避免同一错误两地维护。
- `trace_id` 存在时追加「如需帮助,请提供编号 `<trace_id>`」;不存在则不显示编号。
- 交互按 `code` 分派:鉴权失效跳登录、限频提示稍后重试、校验错误定位到字段。
- 唯一实现:`utils/userFacingError.ts` 的 `userFacingErrorMessage()` / `traceIdOf()`。

**B. 前端自身错误(非 `ApiError`:渲染异常、类型错误、Worker 崩溃、脚本加载失败)**:

- 展示**调用方给定的场景化用户向文案**(如「暂时无法获取数据,请稍后重试」「仿真运行失败,请刷新后重试」),**不展示** `error.message`(它是开发向文本)。
- **不显示任何编号**:前端不生成 trace_id。前端自造编号在运维侧查不到,展示它等于把用户挡在报障流程外。
- 技术原因去向:`console.error` 结构化日志(`operation` + `reason` + 原始 `error`),不进界面;**不得静默吞错**。
- 日志字段只写前端真实知道的事实,禁止伪造 `tenant_id`、`trace_id` 等服务端上下文。

**C. 三种展示位选择**:

| 场景 | 展示位 | 组件 |
| --- | --- | --- |
| 页面级数据读取失败 | 内容区替换为错误态 + 重试按钮 | `useAsyncResource` + 资源三态 |
| 表单/动作提交失败 | 就近内联,靠近触发控件 | Callout(冷红) |
| 全局非阻断反馈 | 顶部 Toast,不抢焦点 | `toastError` |
| 路由/子树渲染崩溃 | 整屏错误态 + 返回/重载 | `RouteErrorBoundary` / `AppStatusScreen` |

**D. 颜色**:错误一律用**独立冷红**语义令牌,朱砂不用于错误(§1.1)。信息不靠颜色单一传达,错误态必须有文字与图标。

## 7. 沉浸式工作台范式

> 做实验/仿真/答题/回放进**全屏底层沉浸态**(`z-immersive`),退出回导航态(光面收拢转场,§4.4)。四个工作台是平台创新点与教学引擎门面——必须是**真教学工具,不是空动画**。

### 7.1 通用范式

- **三区骨架(主体优先)**:中间**主舞台**是主体;左**辅助区**放解释与操作,右**事件流**放随时间增长的消息/日志/输出。两侧各自可独立收起为 `--wb-rail-w` 宽的竖向把手,收起后主舞台自适应占满释放的宽度(舞台用 `flex-1`,不做宽度计算)。栏宽一律走令牌(§2.4),折叠状态本机持久化(键名 `chaimir.workbench.*`),把手上保留面板名与未读计数 —— 收起不等于失联。
- **栏位构成按各台主体而定**:壳只统一深色令牌、顶条契约、折叠行为、窄屏堆叠与无障碍;哪一侧放什么由该台的主体决定(仿真与对抗回放是「舞台 + 事件流」;代码实验 IDE 的编辑器与终端**共同**构成主体,辅助只有检查点与链上操作;解题赛是「题列表 → 题面 → 作答」)。**不把同一套栏位强加给四台。**
- **主舞台永不滚动**:舞台内不出现纵向滚动条 —— 图形区取剩余高度并按 `viewBox` 等比缩放,舞台内的清单超长时由清单自身滚动。理由:图形是主体,一旦与增长型内容共用滚动容器,内容一多图形就被顶出视口。
- **状态与事件分流**:**有界元素**(节点/区块/单元格/阶段步骤 —— 数量由系统实体数决定)留在主舞台;**无界元素**(消息/调用/事件 —— 随时间增长)一律进右侧事件流,事件流是全屏内唯一的滚动区。两处清单都保留按钮语义与键盘选择入口(§7.3),分流不削弱画布的文本替代。
- **顶部工作台条**:退出(「保存并退出」,禁止销毁式退出作为唯一出口)、标题、**ChainProgress 进度**、单一主 CTA。
- **深色面板令牌**:`dark-bg/surface/elevated`、`terminal`;点睛 `accent`;面板间用 `dark-line` 细线,不做盒套盒。代码读取 CSS 变量时使用 `--color-terminal` 与 `--color-accent`,不得另造 `terminal-bg`、`on-dark-accent` 等不存在的别名。
- **深色语境的表单控件**:一律用设计系统组件的深色变体(`Input variant="underline"`、`Select onDark`、`Checkbox onDark`、`SegmentedControl onDark`),页面不手拼深色输入框 —— 手拼会让沉浸态的控件质感、焦点环与无障碍语义各页一套。缺变体就补组件,不在页面绕过。
- **WebSocket 实时进度**:长操作经 WS 推进度,前端给进度/状态而非冻结;WS 进度内容必须渲染,不得丢弃后仅 reload。
- **共享与业务边界**:`packages/ui` `WorkbenchShell` 只负责深色壳/槽位/响应式/无障碍(含两侧折叠与本机持久化),槽位内容自带滚动;`packages/ui` `biz/TeachingFrameStage` 负责把 `TeachingFrame` 的**有界元素**按 `layout` 分区渲染成封闭七模式视图,`biz/TeachingFrameStream` 负责把**无界元素**(消息/调用)渲染成右侧事件流(两者都是纯受控展示组件,不含运行时与数据获取,分区规则集中在 `biz/frameLayout` 与 `biz/frameStream`);`packages/ide` 负责 Monaco/xterm 生命周期能力,`packages/sim-sdk` 负责协议类型/校验/确定性 Worker 运行时 —— **两个引擎包都不含 React 视图层**;编辑器/终端/仿真的页面级装配(取数、Worker 生命周期、槽位组合)一律落在 `apps/web` 的 features 页面。能力由后端实例声明驱动,缺失能力不请求接口、不建 WS、不显示操作。
- **凡渲染舞台必同时渲染事件流**:一帧的文本替代 = 舞台的有界清单 + 事件流的无界清单,少一半就漏掉了消息与调用。上架预览、公开回放与学生工作台都按这条规矩摊开同一帧(§7.3 文本替代)。
- **仿真舞台对齐**:节点图/链/树/矩阵/泳道/趋势由真实 `TeachingFrame` 数据驱动;复杂拓扑不硬塞全部边标签;趋势图必须提供数据表替代;选择元素键盘可达。
- **主次结构**:`TeachingFrame.layout.primary` 决定主舞台;`layout.timeline`(消息/调用时序)即右侧事件流;`evidence/metrics/trace/checkpoints` 进左辅助区的手风琴;底部只放时间与播放控制。
- **过程可视化**:`TeachingFrame.focus` 与元素生命周期负责焦点、历史淡化与离场;算法过程是主体。

### 7.2 四个工作台

#### A. 代码实验 IDE(学生·实验)
- 编辑器+终端+检查点判分+链上操作+WS 进度;左栏含「本检查点目标」。
- **创新点①「区块孵化器」**:沙箱准备是活体状态机(创建沙箱→启动链节点→部署合约→就绪),每阶段中文名+实时耗时;当前阶段玉色半透+呼吸(属加载指示,允许);**失败阶段可点开原因**(用户向文案+trace_id)。替代一切转圈 spinner。

#### B. PBFT 共识仿真(学生·仿真)
- 左辅助区:**手风琴阅读区 + 常驻操作区**。阅读区各段(阶段说明 / 观察结论 / 检查点 / 执行追踪 / 证据矩阵)标题常驻,等于一份目录;一次只展开一段并占满剩余高度 —— 执行追踪因此才读得清。「可用操作」钉在底部不参与折叠,保证「做一个动作 → 看结论变化」这个回路不需要来回切换。
- 阶段说明只有两段:**这一步做了什么 / 为什么重要**。不做「看哪里」—— `TeachingFrame.focus` 已经用舞台高亮指出该看哪个元素,再用一段文字复述状态摘要只是重复。
- 中间:按阶段的消息飞线(虚线流动=消息在飞;拜占庭节点 crimson 虚线描边),历史消息按生命周期淡化;节点这类有界元素的文本清单跟在图形下方,不与事件混排。
- 右侧事件流:消息/调用按时刻分组(粘性时刻标题),默认跟随最新;用户上滚即停止跟随并浮出「跳到最新(n)」;支持「只看攻击与失败」筛选;失败与攻击带图标与状态词,不只靠颜色。**时序泳道即此流,不在辅助区重复一份。**
- 交互分四类,按钮配色由类别决定:普通推进=玉实底、**修复/防护=玉实底带盾**、扰动=描边 + amber、攻击=朱砂。把防护动作画成攻击色是反向教学暗示,禁止不分类别一刀切。
- 控制:单步/播放/变速(0.5/1/2/4 倍)/回退/换随机条件/注入拜占庭(单步暂停是无障碍刚需);可扩展 PoW/默克尔/分叉套同一范式。
- **创新点③「对照推演」**:同一场景起两个独立会话,**同 seed 同参数**、共用一个播放时钟 ——
  对照组只吃自动推进(算法自己跑),干预组接学生的全部攻击/扰动操作。舞台仍是**全尺寸单幅**,
  A/B 一键切换谁在台上;底部差异条按当前时刻逐键列出两侧 `metrics`/`checkpointValues` 的 delta。
  它回答学生真正的问题:「这是我这一步造成的,还是算法本来就会这样」。
  不做并排双舞台 —— 半屏放不下 graph/matrix/lane 这类密集模式,人也盯不住两个同时演化的动画,
  而差异恰恰不在画面里、在数字里。仅内置包、仅无会话自由推演(带会话时记录是只追加序列,
  对照组的推进混进去会撞 `seq`)。详见 `docs/04-仿真可视化引擎/02-架构设计.md` §7。

#### C. 对抗赛回放(学生·竞赛复盘)
- 攻防拓扑(守方玉/攻方 crimson——对抗能量可用朱砂点缀,攻击标记本体用 crimson)+ 链上日志流随时间轴构建 + **时间轴回溯条**。
- **创新点②「时空回溯器」**:回溯条绑定**真实区块高度快照/执行 trace**;红刻度=攻击事件锚点可直接跳转;拖动回溯时拓扑/日志/比分全部回到该区块快照。非假动画。
- 两级回溯:外层游标按**对局**回溯当时战绩/积分/生效参战物;内层游标按**执行 trace 的动作序**回溯拓扑与日志。
  平台没有区块高度契约(链能力的 `output` 是运行时自定义开放对象),故绑定的是**执行 trace**,不是编出来的高度。
- 分区按 §7.1 的状态与事件分流:链上动作是无界序列,只在右侧事件流出现并按内层游标增长;
  战绩、榜单、断言结论条数固定,属有界状态,分别在左辅助区与舞台。
- **攻击锚点只标到对局级**:本队为攻方且胜、或为守方且负,即这一局攻方得手;
  逐条动作没有执行方字段(`JudgeReplayAction` 只有 `seq/op/payload/output`),按动作猜攻防归属就是编造。
  锚点除颜色外必须再给一个记号(色弱用户同样要能定位)。
- 攻防角色只写在回放归档的 `initial_state` 里,取件之后才有;取件前如实说明拓扑画不出来,不拿猜出来的角色先画一个。

#### D. 解题赛答题(学生·竞赛)
- 题列表(通过的题铸成玉色)+ 题面 + 沙箱状态/作答区 + 提交判定 + 倒计时;
- **答案黑盒**(安全铁律):题面与全量(答案/判题配置/flag)接口分离,学生端不可见;
- 提交后按钮判定中(禁用+进度),结果就近反馈;通过时列表项铸块动效(§4.5)。

### 7.3 工作台无障碍

- 深色面板文字对比照 §3.1。
- 仿真/回放动画必须支持 reduced-motion(冻结+保留当前态文字)。
- 单步/暂停控制必备,不强制自动播放。

## 8. 数据可视化规范

> 图表库统一 **Recharts**(流式高频监控可用 Canvas 补充);封装在 `packages/ui/src/charts`,带无障碍降级契约。底线:色非唯一、有图例/提示、空/错/载三态、数据表替代。
>
> **两个不走 Recharts 的例外**(自研理由按 CLAUDE.md §4 记此处):`DensityMatrix` 用语义 `<table>` ——
> 矩阵本身就是表格数据,用 table 天然拿到行列表头关联、读屏按行列朗读、键盘可达三项(§8.2),
> 热度只是单元格底色;`TopologyGraph` 用内联 SVG —— Recharts 无拓扑图元,而这里不需要坐标系与比例尺,
> 为一张图引第二个图表库不合算。两者都不引入新依赖、颜色仍走 `useChartColors`。
>
> **选型契约由组件强制**:`ShareDonutChart` 分片不在 2–5 之间、`DensityMatrix` 小于 3×3 或行列数与表头不符、
> `TopologyGraph` 节点超过 20 时**直接抛错**,不静默降级 —— 静默改画另一种图会让同一份代码在不同数据下
> 长出两种形态,静默并类会悄悄改变数据含义。调用方应在业务侧显式聚合或换图形。
> 边的端点指向不存在的节点属**数据一致性问题**(通常来自服务端),按 CLAUDE.md §8 走
> 「结构化告警 + 跳过该边」,不让整页白屏。

### 8.1 图表选型表

**判据是数据形状,不是页面类型。** 先判断这份数据是什么形状,再取对应图形;同一个页面上的
不同位置可以是不同图形,**不得为省事把整页统一成一种图**。

| 数据形状 | 图表 | 组件 | 关键约束 |
| --- | --- | --- | --- |
| 连续时间序列 | 折线 | `TrendLineChart` | <4 点用 Stat;>6 系列拆分;系列用线型(实/虚/点)区分 |
| 连续时间序列 + 仍在变化 | 流式面积 + Ticker | `StreamAreaChart` | **必带暂停**(暂停冻结视图、数据仍在收);当前值大字直读;reduced-motion 不做补间,数值按整帧更新 |
| 离散类别比高低 | 柱状 | `CompareBarChart` | >5 类别不用饼;每根柱直标数值 |
| 部分对整体(≤5 类且可加总为 100%) | 环 | `ShareDonutChart` | 超过 5 类或加不成整体一律退回柱状;中心留给总量 |
| 时间序列但要找离群点 | 高亮折线 | `TrendLineChart` 的异常标记能力 | 异常点用**形状标记 + 数值文字**,不靠变红;画出阈值线作参照 |
| 双维度交叉密度 | 热力矩阵 | `DensityMatrix` | 必带图例刻度 + hover 精确值;小于 3×3 退回分组柱状 |
| 节点与边的关系 | 网络拓扑 | `TopologyGraph` | 节点/边状态用图标或形状 + 文字双载体;>20 节点改邻接矩阵 |

**图表配色**:系列色从令牌派生(玉系为首,amber/blue/purple 为辅),不引入新裸色;danger 语义只用 crimson。
色板出口唯一:`packages/ui/src/charts/palette.ts` 的 `useChartColors`,按 `paper`/`dark` 语境返回。

### 8.2 图表无障碍与降级(强制)

- 色盲友好:不用红绿单一对;补线型/纹理/形状。
- 数据表替代:图表配可切换数据表;`aria` 摘要描述关键洞察。
- 交互:hover/tap 出精确值;图例可点切换;键盘可达。
- 三态齐全:空(引导非空白轴)、载(骨架非空轴框)、错(重试)。
- 数字 locale 感知;时间序列标明粒度可切换。
- reduced-motion:入场动画可关,数据立即可读。

### 8.3 看板的时间序列必须先出图,数据表是等价替代而非唯一形态

四端看板都有一段「按日聚合的历史快照」。把它直接摊成 `日期 × 指标 × 数值` 的长表,
读者要自己在几十行数字里找趋势 —— 这正是图表存在的理由;而「表格是无障碍等价呈现」
说的是**图表旁必须能切到表**(§8.2 已强制且由 `ChartContainer` 提供),不是**只给表**。

故看板的历史序列:

- 主形态是 `ChartContainer` + `TrendLineChart`(按 §8.1:趋势用折线;<4 个时间点时改用 Stat 或柱状对比)。
- 同一份数据同时传给 `dataTable`,读者一键切换;`ariaSummary` 写出关键洞察(区间、最高点、方向)。
- 指标条目多于 6 条时按语义分组成多张图,不把 10 个系列塞进一张折线。
- 当日横截面的多指标对比用 `CompareBarChart`,不用饼图(§8.1:>5 类别不用饼)。

| 阶段 | 范围 | 验证 |

| 2 | 应用壳层(layouts/App/routes)按底层曝光系统重建,根治壳层 P0(S1–S10) | 壳层交互走查 + 断点走查 |

**引擎包视图层现状(阶段 2 清理结果,阶段 3 定型)**:`packages/ide` 与 `packages/sim-sdk` **不含 React 视图层**,两包 `package.json` 均无 react 依赖 —— 前者只有 Monaco/xterm 生命周期装配与类型,后者只有协议类型、校验、确定性 Worker 运行时、authoring 与内置仿真包。两包旧的视图实现(`IdeWorkbench`、`SimulationWorkbench`、`PatternRenderer` 及其 `.css`)引用的是 `packages/ui` 重建前已删除的 API 与已不存在的令牌,按"不保留旧代码"原则在阶段 2 删除,并从各包 `index.ts` 摘除导出。视图层不回迁到引擎包:共享的 `TeachingFrame` 渲染在阶段 3 落到 `packages/ui/src/biz/`,页面级装配(Worker 生命周期、取数、槽位组合)落到 `apps/web` features 页面。

**公开面清单(阶段 2 定档,后续不再扩张)**:后端匿名可达的业务入口只有两组 —— identity 的 13 条匿名认证路由(登录四种、验证码、刷新、重置、激活、CAS 登录/回调、LDAP,以及 SaaS 形态下的入驻申请)和 `GET /api/v1/sim/shared/:code`。前者对应认证域 8 页,后者是唯一不属于任何角色区的**公开沉浸深链** `/sim/shared/:shareCode`:壳层退出契约在阶段 2 登记(退出即回登录,访客无日常页可退),页面本体与所需的 `TeachingFrame` 渲染器在**阶段 3 随认证页一并落地**(公共页面必须先全部可达,再进入阶段 4 日常页)。除此之外不存在其他公共页面。

**公开回放的匿名数据边界(阶段 3 定档)**:`GET /api/v1/sim/shared/:code` 只返回 `package_code`、`version`、`seed`、`init_params`、`actions[{seq, at_tick, event_type, payload}]`,不含租户名、会话归属、创建时间与 bundle 授权。分享的是**一次会话的可复现剧本**:前端用同一包内核 + 同一 `seed` + 同一动作序列在 Worker 内确定性重放,不读原会话任何私有数据。

匿名页**只运行平台内置包**(`package_code` 带 `builtin__` 前缀,经 sim-sdk 内置 registry 在 Worker 内装配)。这是**安全边界而非能力缺口**,有两条独立理由:扩展包(教师 `teacher_<id>__`、第三方 `org_<id>__`)属所属租户的教学资产,分享码只应泄露可复现剧本、不应泄露包本体;且扩展包在后端隔离容器内运行,匿名请求不得触发容器创建 —— 那是零成本资源耗尽入口。因此 `package_code` 非内置时,页面给确定性说明文案 + 单一「返回登录」动作,**不引导换取运行授权、不做降级渲染、不静默留白**。匿名页除 `GET /api/v1/sim/shared/:code` 外不得请求任何需鉴权接口。

**扩展包运行路径(定档:前端只渲染,不执行)**:扩展包(教师 `teacher_<id>__`、第三方 `org_<id>__`)**在后端隔离容器内执行**,归档字节从不下发浏览器,前端**不装配 bundle、不建 Worker、不执行任何第三方代码**,只经 `WS /api/v1/sim/sessions/{id}/stream` 接收服务端已按协议校验过的完整教学快照(`tick`/`state`/`view`/`current_step`/`interaction_availability`/`checkpoint_results`),交给同一套 `biz/TeachingFrameStage` + `biz/TeachingFrameStream` 绘制。详见 `docs/04-仿真可视化引擎/02-架构设计.md` §8 与 `07-安全设计.md` §2。

前端因此**只有一条渲染路径、没有第二条执行路径**:仿真工作台按会话 `compute` 分叉取数(内置走 Worker、扩展走 stream),舞台、事件流、辅助区手风琴(阶段说明/观察结论/执行追踪/证据)与播放控制全部复用,不为扩展包复制 reducer、舞台、时间线或检查器。

原先"把归档交给 Worker 内解包装配"的方案已废弃,不是工作量问题而是安全边界问题:装配外部模块必须先解封 Worker 的动态 import 封锁,等于让第三方代码在**未封锁的 Worker、平台自己的 origin 内**执行一次(它能拿路径受限 Cookie 打平台接口、能 `importScripts` 同源资产,`connect-src 'self'` 挡不住同源行为),且需要把 CSP 的 `script-src` 放开到 `blob:`。**CSP 保持 `script-src 'self'`,`installRuntimeGuards` 的启动即封锁不为任何场景让路**。随之删除的还有 `GET /sim/packages/{code}/{version}/bundle` 及其 SDK 方法 —— 内置包按 `code` 在 Worker 内装配、扩展包 bundle 不下发,这条授权入口没有消费者也不应该有。

```
        tokens/        # theme.css(@theme 令牌唯一真相源)+ fonts.css + base.css(动效原语即 animate-*/pressable 等工具类)

```

### 10.2 样式与构建约定

- **Tailwind v4 CSS-first**:`theme.css` 用 `@theme` 定义全部令牌;应用经 `@tailwindcss/vite` 编译。应用全局 CSS 必须写全三行:`@import "tailwindcss"` + `@import "@chaimir/ui/styles"` + `@source "<指向 @chaimir/ui/src 的路径>"` —— v4 默认不扫描 node_modules,缺 `@source` 则组件类不编译、整库静默无样式。
- **组件样式 = 主题工具类 + CVA**;复杂局部(画布/编辑器)允许组件内 CSS 文件,但值仍引用令牌变量。
- **禁止**:任意值语法、内联 style 传色值、`module.css` 新增(旧体系产物)。
- 字体经 `@fontsource` / `@fontsource-variable` npm 包自托管(声明在 `packages/ui/src/tokens/fonts.css`),`font-display: swap`;三层字体栈一律用带 `unicode-range` 的分片版,不用整体子集版(整体子集任一汉字即触发 1–2 MB 整包下载)。
- **静态资源在构建期预压缩**:镜像构建阶段对 js/css/html/json/svg 产出 `.gz`,Nginx 用 `gzip_static` 直接发送 —— 运行期根文件系统只读,无法在运行期压缩落盘。字体(woff2/woff)本身已压缩,不重复压缩。

### 10.3 应用层约定(承接自工程目录设计,保持有效)

- `apps/web` 按 `app/ routes/ layouts/ features/` 划分;features 强映射后端 11 模块,页面在各模块 `pages/`。
- `apps/web` 只放应用入口/路由/壳/页面/应用级组合;不沉淀通用 SDK、设计系统、仿真引擎、IDE 能力。
- `apps/web/src/utils/labels/` 只放用户文案映射,按后端模块拆分;禁止跨域大杂烩文件。
- 单浏览器入口;角色路径 `/student/ /teacher/ /school-admin/ /platform-admin/`;登录后端定角色直达首功能页。
- 禁止恢复四套独立 Vite app;禁止恢复 `packages/shared/auth/ws-client` 薄包。
- `packages/api-client` 只做后端公开契约 SDK;常量统一 `src/constants/*`;页面不散落硬编码 API 路径与魔法值。

### 10.4 质量卡点

- **零裸 hex/任意值**:ESLint(含 Tailwind 插件规则)卡,CI 阻断。
- **命名**:组件 PascalCase;目录 kebab-case;hooks `useXxx`;令牌 `--color-*` 等。
- **状态管理**:服务端状态用查询库缓存;向导已填内容按 FE-7 处理。
- **错误边界**:每端错误边界随路由重置,错误屏只展示后端 trace_id(不生成前端编号)。
- **可访问性测试**:关键页 axe 自动检查 + 键盘走查纳入验收。
